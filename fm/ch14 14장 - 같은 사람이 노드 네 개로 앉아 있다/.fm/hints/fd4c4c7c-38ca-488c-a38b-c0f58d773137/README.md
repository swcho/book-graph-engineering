# 생존 규칙에서 반드시 지켜야 할 한 줄

**질문** 생존 규칙(survivorship)에서 반드시 지켜야 할 한 줄은 무엇인가?

**답** 빈 값과 자리표시자는 절대 이기지 못하게 하는 것이다. 한 줄인데 사고의 절반을 막는다.

---

## 1. 생존 규칙이 뭘 정하는 자리인가

14장은 「같은 사람이 노드 네 개로 앉아 있다」, 즉 엔티티 해상도(entity resolution)를 다룹니다. 흐름은 이렇습니다.

1. **블로킹** — 전수 비교는 못 하니 후보를 좁힌다 (14.1)
2. **점수 + 두 개의 임계** — 위는 자동, 아래는 무시, 사이는 사람 (14.2)
3. **되돌릴 수 있는 병합** — 원본을 지우지 않고 대표 노드를 가리키게만 (14.3)
4. **임계 조정** — 오병합 비용 대 검토 비용 (14.4)
5. **생존 규칙** — **어느 값을 남길 것인가** (14.5)

생존 규칙은 마지막 단계입니다. "이 둘은 같다"까지 정해진 다음, 이름이 세 개, 대표자가 두 개, 주소가 세 개일 때 **대표 노드에 뭘 적을지**를 정하는 규칙이죠.

장 요약의 문장이 이 카드의 원문입니다.

> 생존 규칙은 필드마다 다르게 정합니다. 그리고 빈 값과 자리표시자는 절대 이기지 못하게 하세요. 한 줄인데 사고의 절반을 막습니다.

두 문장이 붙어 있지만 무게가 다릅니다. 앞은 **설계**(도메인마다 답이 다름), 뒤는 **불변식**(도메인과 무관하게 언제나 지켜야 함)입니다. 카드가 묻는 "반드시 지켜야 할 한 줄"은 뒤쪽입니다.

## 2. 필드마다 규칙이 다르다는 것 — 정답이 하나가 아닌 부분

`code/ex5_survivorship.py`가 필드별 규칙을 코드에 못 박아 둡니다.

```python
SOURCE_TRUST = {"ERP": 3, "CRM": 2, "명함스캔": 1}

RULES = {
    "name": "가장 신뢰도 높은 출처",
    "ceo":  "가장 최근",
    "tel":  "가장 최근 중 비어 있지 않은 것",
    "addr": "가장 긴 값",
}
```

병합 대상은 같은 회사의 세 표기입니다.

| id | 출처 | updated | name | ceo | tel | addr |
|---|---|---|---|---|---|---|
| r01 | ERP | 2024-03-01 | 가온테크 | 김하늘 | 02-1234-5678 | 서울 강남구 테헤란로 1 |
| r02 | CRM | 2026-01-15 | (주)가온테크 | 박서준 | *(빈 값)* | 서울 강남구 테헤란로 1길 22 |
| r04 | 명함스캔 | 2025-07-09 | GAON TECH | *(빈 값)* | 02-1234-5679 | *(빈 값)* |

결과에서 대표자가 **박서준**(CRM, 가장 최근)으로 정해지는 게 눈에 띕니다. 예제의 마무리 설명이 그 이유를 이렇게 갈라 놓습니다.

- 대표자는 **바뀌는** 값이다 → 가장 최근이 맞다
- 사업자번호는 **안 바뀌는** 값이다 → 신뢰도 높은 출처가 맞다

즉 "최근이 이긴다" vs "믿을 만한 출처가 이긴다"는 도메인이 정하는 문제고, 정답이 하나가 아닙니다. 중요한 건 **규칙을 필드마다 정해서 코드에 박아 두는 것**입니다. 규칙이 없으면 개발자가 그때그때 정하고, 6개월 뒤엔 아무도 이유를 모릅니다.

## 3. 그런데 도메인과 무관하게 언제나 참인 한 줄

규칙이 "최근"이든 "신뢰도"이든 "가장 긴 값"이든, **빈 값과 자리표시자는 후보에서 아예 빠져야** 합니다. 예제에서 그 한 줄은 `pick()`의 첫 줄입니다.

```python
def pick(field, rows):
    cand = [r for r in rows if r.get(field)]   # ← 이 한 줄
    if not cand:
        return None, "값이 없다"
    rule = RULES[field]
    ...
```

`cand`를 먼저 걸러내기 때문에, 그 뒤의 `max(...)`가 어떤 기준을 쓰든 빈 값이 이길 길이 없습니다. 이게 없으면 어떻게 되는지 위 표로 확인해 보세요.

- `ceo` 규칙은 "가장 최근"입니다. 필터가 없으면 r04(명함스캔, 2025-07-09)의 **빈 대표자**가 r01(2024-03-01)의 "김하늘"을 이깁니다. 최근이 맞긴 하죠. 값이 없을 뿐입니다.
- `tel` 규칙 이름 자체가 "가장 최근 중 **비어 있지 않은 것**"입니다. 필터가 없으면 r02(2026-01-15)의 빈 전화가 이겨서, 세 레코드를 합쳤는데 전화번호가 사라집니다.
- `addr`은 "가장 긴 값"입니다. 빈 문자열은 길이 0이라 자연히 지지만, 이건 **운이 좋은 경우**입니다. 규칙 하나만 "가장 최근"으로 바꾸면 즉시 깨집니다.

여기서 얻는 교훈이 정확히 카드의 문장입니다. **어떤 필드 규칙이든 그 위에 빈 값 배제가 먼저 걸려 있어야** 합니다. 규칙마다 "비어 있지 않은 것 중에서"를 매번 챙기는 대신, `pick()` 진입부에 한 번 못 박아 두는 게 요점입니다.

### 순서가 곧 안전성이다

`cand` 필터는 반드시 **규칙 적용 전에** 와야 합니다. "일단 max로 고르고 나중에 비었으면 다음 후보를 본다"로 짜면, 규칙이 늘어날 때마다 그 후처리를 빠뜨릴 지점이 늘어납니다. 필터를 앞에 두면 새 규칙을 추가하는 사람이 아무것도 몰라도 자동으로 안전합니다. 이게 "한 줄인데 사고의 절반을 막는다"의 실질입니다.

## 4. 진짜 무서운 쪽은 빈 값이 아니라 자리표시자

빈 문자열과 `None`은 `if r.get(field)`로 걸러집니다. 문제는 **비어 있지 않은 척하는 값**입니다.

| 유형 | 실제로 본 값들 |
|---|---|
| 모름 표기 | `미정`, `미확인`, `해당없음`, `없음`, `N/A`, `NA`, `null`, `NULL`, `unknown`, `-`, `--`, `.` |
| 더미 전화·번호 | `000-0000-0000`, `010-0000-0000`, `02-000-0000`, `999-99-99999` |
| 테스트 잔여물 | `test`, `테스트`, `홍길동`, `가나다`, `asdf`, `aaa` |
| 시스템 기본값 | `default`, `기타`, `Other`, `등록되지 않음`, `확인 후 수정` |
| 마스킹 | `***`, `김**`, `비공개` |
| 서식만 남은 값 | 공백만, 전각 공백, 제어문자, `0`, `1900-01-01` |

이들이 위험한 이유는 파이썬 truthiness를 통과하기 때문입니다. 게다가 자리표시자는 **규칙을 이기기 쉬운 형태**로 들어옵니다.

- `addr` 규칙이 "가장 긴 값"인데 `"주소 미확인 - 담당자 확인 후 수정 필요"`가 들어오면, 실제 주소보다 길어서 **이깁니다**.
- `ceo` 규칙이 "가장 최근"인데 최근 배치가 빈칸을 `"미정"`으로 채워 넣었다면 **이깁니다**.
- 자리표시자는 보통 **자동 유입**(배치·폼 기본값·스캔 OCR 실패)이라 최신 타임스탬프를 달고 옵니다. "가장 최근" 규칙과 최악의 조합이죠.

그래서 필터를 이렇게 강화합니다.

```python
PLACEHOLDERS = {"", "-", "--", ".", "n/a", "na", "null", "none", "unknown",
                "미정", "미확인", "없음", "해당없음", "기타", "test", "테스트"}
PLACEHOLDER_PAT = re.compile(r"^[\s\-_.*]*$|^0+[\-0]*$")

def is_placeholder(v):
    if v is None:
        return True
    s = str(v).strip().lower()
    return (not s) or s in PLACEHOLDERS or bool(PLACEHOLDER_PAT.match(s))

def pick(field, rows):
    cand = [r for r in rows if not is_placeholder(r.get(field))]
    ...
```

포인트 세 가지.

1. **필드별 자리표시자 목록을 따로 둔다.** 전화에서는 `000-0000-0000`이 자리표시자지만, 이름 필드에서는 아닙니다. 반대로 이름에서 `기타`는 자리표시자인데 카테고리 필드에서는 유효한 값일 수 있습니다.
2. **정규화 후에 판정한다.** 앞뒤 공백, 전각/반각, 대소문자를 맞춘 뒤 비교해야 `" N/A "`가 걸립니다.
3. **버리지 말고 기록한다.** "값이 없다"와 "자리표시자였다"는 다른 정보입니다. 후자는 소스 데이터 품질 문제를 알려 주는 신호라, 필드별로 카운트해 두면 상류를 고칠 근거가 됩니다.

## 5. 왜 "사고의 절반"인가

빈 값·자리표시자가 이기는 사고가 유독 나쁜 이유가 있습니다.

- **조용하다.** 예외가 안 납니다. 병합은 성공했고 노드도 하나이며, 그냥 대표자 이름이 `"미정"`으로 바뀌어 있을 뿐입니다. 아무도 알림을 못 받습니다.
- **정보를 파괴하는 방향으로만 작동한다.** 병합의 목적은 흩어진 정보를 모으는 것인데, 이 버그는 그 반대로 갑니다. 세 레코드를 합쳤는데 필드가 더 비어 버립니다.
- **되돌리기와 무관하게 새고 있다.** 14.3의 되돌릴 수 있는 병합(`MergeStore`)은 잘못 **묶은** 것을 풀어 줍니다. 하지만 묶는 판단 자체가 맞았고 대표값 계산만 틀렸다면, `unmerge`할 대상이 없습니다. 원본은 남아 있으니 재계산은 되지만, 그 사이 이 값을 읽어 간 하류 질의·리포트·임베딩은 이미 오염됐습니다.
- **하류로 번진다.** 대표 노드는 정의상 모든 질의가 도달하는 지점입니다. `"N/A"`라는 대표자 이름 하나가 그래프 전체에서 그 회사를 대표합니다.
- **막는 비용이 압도적으로 싸다.** 임계 조정(14.4)은 오병합 비용과 검토 비용을 저울질하는 트레이드오프지만, 이건 트레이드오프가 없습니다. 자리표시자를 남겨서 이득 보는 경우가 없기 때문입니다. 그래서 "한 줄"입니다.

참고로 14.3의 `MergeStore`도 같은 원칙을 다른 자리에서 씁니다.

```python
def _richness(self, nid):
    return sum(1 for v in self.nodes[nid].values() if v)   # 빈 값은 세지 않는다

def view(self, nid):
    for m in sorted(members, key=lambda x: -self._richness(x)):
        for k, v in self.nodes[m].items():
            if v and not merged.get(k):   # 빈 값으로는 덮어쓰지 않는다
                merged[k] = v
```

"정보가 더 많은 쪽을 대표로" 정할 때도, 대표 노드의 병합 뷰를 채울 때도 `if v` 검사가 앞에 옵니다. **빈 값은 후보가 아니다**라는 규칙이 코드 여러 곳에서 같은 형태로 반복됩니다.

한 가지 더. 14.2의 점수 계산도 이 원칙의 사촌입니다.

```python
if not x or not y:          # 한쪽이 비면 그 항목은 «모름»으로 빼둔다
    detail.append((name, None, w))
    continue
```

빈 값을 "0점(=불일치)"으로 처리하지 않고 **가중치 분모에서 빼 버립니다**. 빈 값은 "다르다"는 증거도, "같다"는 증거도 아니니까요. 실제로 r04(GAON TECH)는 이 처리 덕에 0.643으로 애매 구간에 떨어져 사람에게 갔습니다. 빈 값을 0점으로 셌다면 점수가 더 낮아져 무시 구간으로 떨어졌을 겁니다. **빈 값은 어느 방향으로도 이기지 못한다** — 점수에서든 생존 규칙에서든 같은 이야기입니다.

## 6. 실무 체크리스트

- [ ] `pick()`류 함수의 **첫 줄**에서 빈 값·자리표시자를 후보에서 제외한다.
- [ ] 자리표시자 목록을 필드별로 정의하고, 정규화(trim/casefold/전각) 후 판정한다.
- [ ] 규칙 이름에 "비어 있지 않은 것 중"을 적는 데 의존하지 말고, 필터로 강제한다(사람은 잊는다).
- [ ] 후보가 전부 비었으면 **아무 값도 만들지 말고** `None` + "값이 없다"를 남긴다. 억지로 채우면 그게 새 자리표시자가 된다.
- [ ] 고른 값마다 **어디서 왔는지**(출처 레코드 id·소스·타임스탬프)를 같이 저장한다. 예제도 `f"{rule} → {r['id']}({r['src']}, {r['updated']})"`로 근거를 출력합니다. "이 대표자 이름 왜 이래요"라는 문의에 답할 수 있어야 합니다(16장 출처 추적, PROV-O).
- [ ] 회귀 테스트: 각 필드마다 "최근 레코드가 빈 값/자리표시자" 케이스를 넣는다. 이 한 줄을 지우면 반드시 빨개지도록.
- [ ] 자리표시자 탐지 건수를 필드별로 계측한다. 상류 데이터 품질 문제의 조기 경보가 된다.

## 7. 한 줄 요약

생존 규칙의 설계(어느 규칙을 쓸지)는 도메인이 정하지만, **빈 값과 자리표시자는 어떤 규칙에서도 이기지 못한다**는 불변식은 도메인과 무관하게 항상 참입니다. 코드로는 `cand = [r for r in rows if r.get(field)]` 한 줄, 얻는 것은 조용히 정보를 지우는 병합 사고의 절반입니다.
