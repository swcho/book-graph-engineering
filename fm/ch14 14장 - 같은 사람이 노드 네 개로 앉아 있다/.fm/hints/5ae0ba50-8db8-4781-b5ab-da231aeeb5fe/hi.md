> **질문**: 확률적 레코드 연결의 고전적 1차 출처는 무엇인가?
> **답**: Fellegi-Sunter 모델 논문(1969)이다. `[사실상 표준]`으로 분류된다.
>
> 정확히는

「우도비」니 「EM 알고리즘」 같은 대학 용어는 고교 개념에서 하나씩 쌓아 올립니다.

> **필드마다 점수를 매겨 더한다. 그리고 임계선을 두 개 그어서 위는 자동, 아래는 버리고, 사이는 사람에게 넘긴다.**

이 한 문장이 이 문항의 전부입니다. 왜 「두 개」이고, 왜 「점수를 더하는」 형태인지가 아래 내용입니다.

## 2. 표본공간을 두 덩어리로 나눈다

레코드가 $n$개면 쌍은 조합으로 $\binom{n}{2} = \dfrac{n(n-1)}{2}$개입니다.
$n = 100{,}000$이면

$$\binom{100000}{2} = \frac{100000 \times 99999}{2} = 4{,}999{,}950{,}000$$

약 50억 쌍. 이게 14.1절이 「전부 비교할 수는 없다」고 하는 이유고, 블로킹으로 후보를 좁히는 이유입니다.
지금은 후보 쌍 하나를 놓고 판단하는 문제에 집중합시다.

모든 쌍의 집합을 두 사건으로 분할합니다.

- $M$ : 두 레코드가 **정말 같은 실체**인 사건 (match)
- $U$ : **다른 실체**인 사건 (unmatch), 즉 $M$의 여사건

우리가 관측하는 것은 $M$인지 $U$인지가 아니라, **필드 비교 결과**뿐입니다. 이걸 벡터로 적습니다.

$$\gamma = (\gamma_1, \gamma_2, \dots, \gamma_K)$$

$K$는 필드 개수(위 표에서는 5), $\gamma_i$는 $i$번째 필드가 일치했는지입니다.
예를 들어 r01과 r04를 비교하면

$$\gamma = (\underbrace{\text{일치}}_{\text{사업자번호}},\ \underbrace{\text{애매}}_{\text{이름}},\ \underbrace{\text{모름}}_{\text{주소}},\ \underbrace{\text{모름}}_{\text{대표자}},\ \underbrace{\text{모름}}_{\text{전화}})$$

「모름」은 한쪽 값이 비어 있어서 비교 자체가 불가능한 경우입니다.

## 3. 핵심 아이디어: 같은 「일치」라도 값이 다르다

여기가 이 모델의 발상 전환입니다. 이름이 일치했다는 사실과 사업자번호가 일치했다는 사실은
증거로서의 무게가 전혀 다릅니다. 그 무게를 **두 개의 조건부확률**로 정의합니다.

$$m_i = P(\gamma_i = \text{일치} \mid M), \qquad u_i = P(\gamma_i = \text{일치} \mid U)$$

- $m_i$는 **m-확률**: *진짜 같은 두 레코드인데* 필드 $i$가 일치할 확률.
  1이 아닙니다. 오타(`마루상사`/`머루상사`), 개명, 영문 병기(`GAON TECH`)가 있으니까요.
- $u_i$는 **u-확률**: *전혀 다른 두 레코드인데* 우연히 필드 $i$가 일치할 확률.

숫자 감각을 잡아 봅시다.

| 필드 | $m_i$ | $u_i$ | $m_i / u_i$ | 해석 |
|---|---|---|---|---|
| 사업자번호 | 0.90 | 0.000001 | 900,000 | 일치하면 거의 확정 |
| 이름 | 0.80 | 0.001 | 800 | 강한 증거 |
| 주소 | 0.70 | 0.01 | 70 | 중간 |
| 대표자(성명) | 0.85 | 0.02 | 42.5 | 동명이인이 있다 |
| 전화 | 0.60 | 0.005 | 120 | 결측이 많다 |

비 $m_i/u_i$가 클수록 그 필드의 「일치」가 강한 증거입니다.
14장 코드가 사업자번호에 가중치 0.45, 전화에 0.05를 준 것은 이 비율을
사람의 직관으로 눈대중한 값입니다.

```python
FIELDS = [
    ("사업자번호", lambda r: r[2], 0.45, "exact"),
    ("이름",      lambda r: norm_name(r[1]), 0.25, "fuzzy"),
    ("주소",      lambda r: r[3], 0.15, "fuzzy"),
    ("대표자",    lambda r: r[4], 0.10, "exact"),
    ("전화",      lambda r: norm_phone(r[5]), 0.05, "exact"),
]
```

원 논문의 기여는 이 가중치를 **눈대중하지 않고 데이터에서 추정하는 방법**까지 준 것입니다.

## 4. 왜 「비율」인가 — 베이즈 정리로 유도

$\gamma$를 관측했을 때 같은 실체일 확률을 알고 싶습니다. 베이즈 정리를 씁니다.

$$P(M \mid \gamma) = \frac{P(\gamma \mid M)\,P(M)}{P(\gamma \mid M)P(M) + P(\gamma \mid U)P(U)}$$

이 식을 $P(U \mid \gamma)$로 나누면 훨씬 예쁘게 정리됩니다.

$$\underbrace{\frac{P(M \mid \gamma)}{P(U \mid \gamma)}}_{\text{관측 후 승산}}
= \underbrace{\frac{P(\gamma \mid M)}{P(\gamma \mid U)}}_{\text{우도비 } R}
\times
\underbrace{\frac{P(M)}{P(U)}}_{\text{관측 전 승산}}$$

여기서 **승산(odds)**은 확률 $p$에 대해 $\dfrac{p}{1-p}$입니다. 확률이 $0.5$면 승산 $1$,
확률이 $0.9$면 승산 $9$.

그래서 관측이 판단을 바꾸는 정도는 오직 가운데 항

$$R(\gamma) = \frac{P(\gamma \mid M)}{P(\gamma \mid U)} = \frac{m(\gamma)}{u(\gamma)}$$

으로 결정됩니다. 이것이 **우도비(likelihood ratio)**이고, Fellegi-Sunter 모델의 「점수」입니다.
$R$이 크면 같은 쪽, 작으면 다른 쪽입니다. $R = 1$이면 이 증거는 아무 정보도 없습니다.

> **왜 사후확률 대신 우도비를 쓰나?**
> $P(M)$은 「임의로 뽑은 쌍이 같은 실체일 확률」인데, 50억 쌍 중 진짜 쌍은 수만 개라
> $P(M) \approx 10^{-5}$처럼 아주 작고 데이터마다 다릅니다. 우도비는 이 값과 무관하게
> **증거의 세기만** 재기 때문에 다루기 편합니다.

## 5. 곱셈을 덧셈으로 — 로그가 등장하는 이유

$\gamma$ 전체의 확률 $m(\gamma)$를 필드별 확률로 쪼개려면 가정이 하나 필요합니다.

> **조건부 독립 가정**: $M$이라는 조건(또는 $U$라는 조건) 아래에서 각 필드의 일치 여부는 서로 독립이다.

독립이면 확률은 곱이므로

$$R(\gamma) = \prod_{i=1}^{K} \frac{P(\gamma_i \mid M)}{P(\gamma_i \mid U)}$$

곱은 다루기 불편합니다. 아주 큰 수와 아주 작은 수가 섞여 컴퓨터에서 오차가 나고,
사람 눈으로 읽기도 어렵습니다. 로그의 성질 $\log(xy) = \log x + \log y$를 쓰면 덧셈이 됩니다.

$$w(\gamma) = \log_2 R(\gamma) = \sum_{i=1}^{K} w_i$$

$$w_i = \begin{cases}
\log_2 \dfrac{m_i}{u_i} & (\gamma_i = \text{일치}) \\[2ex]
\log_2 \dfrac{1-m_i}{1-u_i} & (\gamma_i = \text{불일치}) \\[2ex]
0 & (\gamma_i = \text{모름})
\end{cases}$$

이 $w(\gamma)$를 실무에서 **매치 웨이트(match weight)** 라고 부릅니다.
로그의 밑을 2로 쓰는 관행은 「점수 1점이 오르면 승산이 2배」라는 해석이 편해서입니다.

세 가지를 확인하세요.

1. **일치는 양수 기여.** 좋은 필드는 $m_i > u_i$이므로 $\log_2(m_i/u_i) > 0$.
2. **불일치는 음수 기여.** $m_i > u_i$이면 $1-m_i < 1-u_i$이므로 $\log_2\frac{1-m_i}{1-u_i} < 0$.
   증거가 반대 방향으로 작동합니다.
3. **모름은 0점.** 점수에 아무 영향을 주지 않습니다. 「없는 정보」와 「불리한 정보」는 다릅니다.

14장의 코드가 3번을 그대로 구현합니다.

```python
if not x or not y:          # 한쪽이 비면 그 항목은 «모름»으로 빼둔다
    detail.append((name, None, w))
    continue
...
return (total / used if used else 0.0), detail
```

`used`는 실제로 비교한 필드들의 가중치 합입니다. `total / used`로 나누어
0과 1 사이로 정규화하죠. Fellegi-Sunter의 로그 우도비 대신 **가중평균**을 쓴 셈인데,
「필드별 기여를 더한다 + 결측은 빼둔다」는 뼈대는 같습니다.

### 계산해 보기: r01과 r04

앞의 표 값을 그대로 쓰면 사업자번호만 비교 가능하고 나머지는 모름/애매입니다.

$$w \approx \log_2 900000 \approx 19.8$$

즉 승산이 약 $2^{19.8} \approx 90$만 배 올라갑니다. 커 보이지만
관측 전 승산이 $10^{-5}$쯤이면

$$\text{관측 후 승산} \approx 10^{-5} \times 9 \times 10^{5} = 9
\quad\Longrightarrow\quad
P(M \mid \gamma) = \frac{9}{1+9} = 0.9$$

90%. 높지만 「자동으로 합쳐 버릴」 만큼은 아닙니다.
14장 코드가 r04에 매긴 점수 **0.643** — 애매 구간 — 이 이 상황의 다른 표현입니다.

## 6. 임계가 왜 두 개인가 — 이 문항의 핵심

점수 하나에 임계 하나를 두면 판단은 둘 중 하나입니다. 같음 / 다름.
Fellegi와 Sunter는 임계를 **둘** 두고 판단을 **셋**으로 나눴습니다.
$T_\lambda < T_\mu$인 두 수를 잡고

$$\text{결정} = \begin{cases}
A_1 : \text{링크(같음)} & R(\gamma) \ge T_\mu \\
A_2 : \textbf{보류 — 사람이 확인} & T_\lambda < R(\gamma) < T_\mu \\
A_3 : \text{비링크(다름)} & R(\gamma) \le T_\lambda
\end{cases}$$

14장 코드가 그대로입니다. `HIGH`가 $T_\mu$, `LOW`가 $T_\lambda$입니다.

```python
HIGH, LOW = 0.85, 0.55
...
if s >= LOW:
    verdict = "자동 병합" if s >= HIGH else "사람 검토"
```

두 종류의 오류를 정의합니다.

$$\mu = P(A_1 \mid U) \quad \text{다른 걸 합쳐 버릴 확률(오병합)}$$
$$\lambda = P(A_3 \mid M) \quad \text{같은 걸 버릴 확률(놓침)}$$

고교 통계의 제1종/제2종 오류와 정확히 같은 구조입니다.
그리고 논문의 **최적성 정리**는 이렇습니다.

> $\mu$와 $\lambda$를 정해 놓았을 때, 위의 우도비 기반 3구간 규칙은
> **사람에게 넘어가는 구간 $A_2$의 확률을 최소화한다.**

즉 「사람 손을 최소한으로 쓰면서 정해진 정확도를 지키는 방법」은
점수를 우도비로 만들고 임계를 두 개 두는 것 **뿐**이라는 뜻입니다.
14장이 성과를 이렇게 표현한 것이 바로 이 정리의 번역입니다.

> "자동화가 할 일은 «다 맞히는 것»이 아니라 «애매한 것을 골라내는 것»이다.
>  여기서는 12개 레코드 중 3쌍만 사람에게 갔다. 그게 성과다."

### 분포 그림으로 보기

`ex4_threshold_tuning.py`는 점수 분포를 정규분포로 흉내 냅니다.

$$\text{같은 쌍의 점수} \sim N(0.86,\ 0.11^2), \qquad
\text{다른 쌍의 점수} \sim N(0.42,\ 0.15^2)$$

같은 쌍 400개, 다른 쌍 9,600개. 두 종모양 곡선이 0.55~0.85 부근에서 **겹칩니다**.
이 겹치는 구간이 존재하는 것이 임계를 두 개 두는 이유입니다.

- 겹침이 없다면 임계 하나로 완벽히 갈랐을 것입니다. 그러면 사람이 필요 없습니다.
- 겹치는 구간에서는 어느 쪽으로 결정해도 반드시 오류가 납니다.
  **그래서 결정하지 않고 사람에게 미룹니다.**

여기서 세 값이 서로 밀고 당깁니다.

| $T_\mu$를 올리면 | $T_\mu$를 내리면 |
|---|---|
| 오병합 $\mu \downarrow$ (안전) | 오병합 $\mu \uparrow$ (위험) |
| 사람 검토 $\uparrow$ (비싸다) | 사람 검토 $\downarrow$ (싸다) |

어디에 그을지는 **수학이 정해 주지 않습니다.** 논문은 $\mu$, $\lambda$를
「주어진 값」으로 놓고 최적 규칙을 유도하니까요. 그 빈칸은 비용으로 채웁니다.
14장이 실제로 계산한 값입니다.

- 사람 검토 1건: 40초 ≈ 400원
- 오병합 1건 수습: 2시간
- 따라서 오병합 1건 ≈ 검토 180건

기대비용을 식으로 쓰면, 검토 건수를 $N_{A_2}$, 오병합 건수를 $N_{fp}$라 할 때

$$\text{총비용}(T_\mu, T_\lambda) = c_{\text{review}} \cdot N_{A_2}(T_\mu, T_\lambda) + c_{\text{merge}} \cdot N_{fp}(T_\mu)$$

$c_{\text{merge}} / c_{\text{review}} \approx 180$이면 임계를 높게 잡는 게 유리합니다.
그런데 14.3절의 「되돌릴 수 있는 병합」을 도입하면 오병합 수습이 2시간에서 5분이 되어
$c_{\text{merge}}$가 24분의 1로 떨어집니다. 그러면 최적 임계가 아래로 내려갑니다.
이것이 "되돌릴 수 있으면 훨씬 공격적으로 자동화할 수 있다"는 문장의 수학적 내용입니다.

## 7. $m_i$, $u_i$는 어디서 구하나 — 라벨이 없는데

정답표가 있으면 그냥 세면 됩니다. 문제는 정답표가 없다는 것이죠.
Fellegi와 Sunter는 필드가 3개일 때 조건부 독립 가정만으로 이걸 풀 수 있음을 보였습니다.

아이디어는 이렇습니다. 미지수는 $m_1, m_2, m_3, u_1, u_2, u_3$과 비율 $p = P(M)$, 총 7개.
한편 관측되는 것은 각 $\gamma$ 패턴의 빈도인데, 필드 3개의 일치/불일치 조합은 $2^3 = 8$가지이고
확률의 총합이 1이므로 독립적인 방정식이 7개 나옵니다. 각 패턴의 확률은

$$P(\gamma) = p \cdot m(\gamma) + (1-p) \cdot u(\gamma)$$

미지수 7개, 식 7개. 원리적으로 풀립니다. 라벨 없이 「어느 필드가 얼마나 믿을 만한지」가
데이터 스스로 드러나는 것입니다.

필드가 더 많으면 식이 비선형이라 손으로 못 풉니다. 표준 해법은 후속 연구인
**EM 알고리즘**(Winkler, 1988)으로, 대략 이런 반복입니다.

1. $m_i, u_i, p$를 아무렇게나 초기화한다.
2. 각 쌍이 $M$일 확률을 현재 값으로 계산한다 (**E 단계**).
3. 그 확률을 가중치로 써서 $m_i, u_i, p$를 다시 센다 (**M 단계**).
4. 값이 안 변할 때까지 2~3 반복.

현대 오픈소스 도구(Splink 등)가 하는 일이 정확히 이것입니다.

## 8. 이 모델이 못 하는 것 — 14장이 덧붙인 것들

### (1) 거부권 규칙: 확률 모델의 구조적 약점

r06/r07을 보세요.

| | r06 | r07 |

| 이름 | 나루소프트 | 나루소프트(주) |

| 주소 | 서울 마포구 월드컵로 2 | 서울 마포구 월드컵로 2 |

주소·대표자·전화가 전부 일치. 사업자번호만 다릅니다. 점수는 **0.550** — 애매 구간 바닥.
합계 방식의 점수는 여러 개의 긍정 증거가 하나의 결정적 반증을 **상쇄**할 수 있습니다.
불일치에 음수 가중치를 주더라도, 유한한 값이라 충분히 많은 양수에 밀립니다.

게다가 조건부 독립 가정 자체가 여기서 깨집니다. 같은 건물에 있으면
주소·전화·대표자는 함께 일치하는 경향이 있으니까요. 독립인 척 곱하면
사실상 같은 증거를 세 번 세는 셈이 되어 점수가 과대평가됩니다.

해결책은 확률 안이 아니라 확률 **위**입니다.

> 사업자번호가 다르면 다른 법인이다. 점수가 얼마든.

수식으로는 조건이 붙은 결정 규칙입니다.

$$\text{결정} = \begin{cases}
A_3 \ (\text{다름}) & \text{거부권 조건 성립 시} \\
\text{위의 3구간 규칙} & \text{그 외}
\end{cases}$$

14장 저자는 임계를 0.55로 내려 모회사와 자회사를 합쳤고, 되돌리는 데 사흘 걸렸습니다.

### (2) 이행성: 쌍 단위 이론의 한계

Fellegi-Sunter는 **쌍 하나**를 판정하는 이론입니다. 그런데 실무는 「같은 실체들의 묶음」이 필요하죠.
$a \sim b$이고 $b \sim c$이면 $a \sim c$로 잇는 것이 이행성(transitivity)이고,
14장은 Union-Find로 이걸 구현합니다.

```python
parent = {k: k for k in BY_ID}
def find(x):
    while parent[x] != x:
        parent[x] = parent[parent[x]]; x = parent[x]
    return x
def union(x, y):
    parent[find(x)] = find(y)
```

문제는 **잘못된 쌍 하나가 군집 전체를 오염**시킨다는 것입니다.
$A$ 그룹 10개와 $B$ 그룹 10개가 잘못된 간선 하나로 이어지면 20개 군집이 되고,
그 안의 모든 $10 \times 10 = 100$쌍이 암묵적으로 「같음」이 됩니다.
오류 하나의 파급이 선형이 아니라 **곱셈**으로 커집니다.
그래서 군집 크기에 상한을 두거나, 커지면 사람에게 보내는 게 안전합니다.

### (3) 되돌리기와 생존 규칙

논문의 범위 밖입니다. 14.3절(원본을 지우지 말고 대표 노드를 가리키게 하기)과
14.5절(필드별 생존 규칙, 빈 값과 자리표시자는 절대 이기지 못하게)이 14장의 독자적 기여입니다.
