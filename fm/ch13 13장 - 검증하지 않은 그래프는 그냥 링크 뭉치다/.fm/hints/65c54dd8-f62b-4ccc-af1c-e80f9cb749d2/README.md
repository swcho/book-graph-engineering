# `shapes.ttl`에서 등급 제약의 심각도가 Warning인 이유는 무엇인가?

> **답**: 등급으로 필터하는 질의가 조용히 빈 결과를 내기 때문이다. 데이터는 들어와도 되지만 알아야 한다.

13장 13.2절 「전부 막으면 아무것도 안 들어온다」에서 정한 **차단 기준 = 「되돌릴 수 없는가」** 를 등급 제약에 적용한 결과입니다.

---

## 1. 제약의 모양

`shapes.ttl`의 해당 블록입니다.

```turtle
ex:CompanyShape a sh:NodeShape ;
    sh:targetClass ex:Company ;

    # 경고 — 등급으로 필터하는 질의가 조용히 빈 결과를 낸다
    sh:property [
        sh:path ex:grade ;
        sh:minCount 1 ;
        sh:in ("A" "B" "C") ;
        sh:severity sh:Warning ;
        sh:message "등급이 없거나 A/B/C 밖이다" ] .
```

읽는 법은 이렇습니다.

| 줄 | 뜻 |
|---|---|
| `sh:path ex:grade` | 검사 대상은 `ex:Company` 노드의 `ex:grade` 값들 |
| `sh:minCount 1` | 등급이 **하나도 없으면** 위반 |
| `sh:in ("A" "B" "C")` | 값이 이 **열거 목록 안에 없으면** 위반 |
| `sh:severity sh:Warning` | 그 위반을 **경고 등급**으로 보고 |
| `sh:message` | 보고서에 찍힐 사람 읽는 문장 |

### `sh:in`에 대해 알아 둘 것

- `sh:in`은 SHACL 코어 제약 컴포넌트입니다. 값이 주어진 **RDF 리스트**(`("A" "B" "C")`는 Turtle의 컬렉션 문법으로, `rdf:first`/`rdf:rest` 체인으로 펼쳐집니다)의 원소 중 하나여야 한다는 뜻입니다.
- 비교는 **RDF 항 단위**입니다. 리터럴은 문자열 값뿐 아니라 **데이터타입과 언어태그까지** 같아야 통과합니다. `"A"`와 `"A"@ko`, `"A"^^xsd:string`이 아닌 다른 타입은 다른 항이라 걸립니다. 코드 값 리스트를 `sh:in`으로 쓸 때 흔히 여기서 물립니다.
- `sh:in`은 **값 하나하나**를 봅니다. 값이 없는 경우는 잡지 못하므로 `sh:minCount 1`을 같이 걸어 「없음」과 「엉뚱한 값」을 한 제약 그룹에서 함께 처리합니다.
- 위반 결과에는 `sh:sourceConstraintComponent sh:InConstraintComponent`가 붙습니다. 보고서를 기계로 분류할 때 이 값으로 「열거 위반」만 골라낼 수 있습니다.
- **`sh:severity`를 안 쓰면 기본값은 `sh:Violation`입니다.** 즉 여기서 `sh:Warning`은 「그냥 놔둔 결과」가 아니라 **명시적으로 강등한 결정**입니다. 이 한 줄이 이 카드의 전부입니다.

`data.ttl`에서 이 제약에 걸리는 건 라온에너지입니다.

```turtle
# 경고 — 등급이 규칙 밖
ex:Raon a ex:Company ; rdfs:label "라온에너지" ;
    ex:bizNumber "222-33-44444" ; ex:grade "Z" ; ex:signed ex:C3 .
```

`"Z"`는 A/B/C 밖이므로 위반이지만, 심각도가 Warning이라 **적재는 됩니다.**

## 2. 「조용히 빈 결과」가 왜 위험한가

`ex:grade "Z"`인 라온에너지가 그래프에 들어간 뒤, 등급으로 필터하는 질의를 돌려 봅시다.

```sparql
SELECT ?c WHERE { ?c ex:grade ?g . FILTER(?g IN ("A","B","C")) }
```

```sparql
SELECT ?c WHERE { ?c ex:grade "A" }   # A등급 거래처 화면
```

라온에너지는 **어느 쪽에도 안 나옵니다.** 그런데 나오지 않는 방식이 문제입니다.

- 질의 엔진은 **에러를 내지 않습니다.** 문법도 맞고 실행도 성공했습니다.
- 대시보드는 **정상 응답 코드**를 받습니다. 200 OK에 결과 0건.
- 화면에는 그냥 **행이 하나 적거나, 표가 빕니다.** 로딩 스피너도 빨간 배너도 없습니다.
- 로그에도 아무것도 안 남습니다. 「없는 것」은 로그를 만들지 않습니다.

이게 **조용한 실패(silent failure)** 입니다. 시스템이 고장 났다고 알려 주는 신호가 어디에도 없고, **답이 틀렸다는 사실을 아는 사람이 없습니다.**

### 시끄러운 실패와의 대비

| | 시끄러운 실패 | 조용한 실패 |
|---|---|---|
| 증상 | 500 에러, 스택 트레이스, 파이프라인 중단 | 표가 한 줄 짧다 |
| 발견 시점 | 즉시 | 몇 주 뒤, 혹은 영영 |
| 발견 방법 | 알림이 온다 | 누군가 「어? 라온에너지 왜 없지」 한다 |
| 신뢰 | 「고장 났다」로 인식 | **「그런 데이터가 없다」로 인식** |

마지막 줄이 제일 나쁩니다. 빈 결과는 **「데이터가 없다」는 사실 주장으로 읽힙니다.** 사용자는 화면을 믿고 「A/B/C 등급 거래처는 이게 전부구나」라고 판단합니다. 거기서 나오는 게 잘못된 계약 결정, 잘못된 리포트, 잘못된 집계입니다. 에러였다면 아무도 그 값을 쓰지 않았을 텐데, 빈 결과는 그대로 소비됩니다.

13.4절의 `ex4_regression.py`가 보여 준 「카테고리 없는 부품」 질의가 빈 답을 내던 장면과 **정확히 같은 실패 양상**입니다. 그쪽은 마이그레이션이 원인, 이쪽은 규칙 밖 값이 원인일 뿐입니다.

그래서 Warning은 「무시해도 되는 것」이 아닙니다. **경고는 「질의가 틀릴 수 있다」는 뜻**이고, 그래서 적재는 하되 **반드시 대시보드에 올려 사람이 보게** 합니다. 조용한 실패를 시끄럽게 만드는 게 Warning의 존재 이유입니다.

## 3. 왜 Violation도 Info도 아닌가 — 「되돌릴 수 없는가」

13장이 정한 차단 기준은 딱 하나입니다.

> **되돌릴 수 없는가.**

이 기준으로 세 등급을 가릅니다.

| 심각도 | 기준 | 처리 | `shapes.ttl` 예 |
|---|---|---|---|
| `sh:Violation` 차단 | **되돌릴 수 없다.** 지금 들이면 나중에 못 고친다 | 적재 거부. 원천을 고쳐야 한다 | 사업자번호 형식 오류 / 고아 계약 |
| `sh:Warning` 경고 | 되돌릴 수 있다. 그런데 **모르면 답이 틀린다** | 적재하고 대시보드에 올린다 | 등급이 A/B/C 밖 / 금액 음수 |
| `sh:Info` 기록 | 되돌릴 수 있고, **몰라도 답은 안 틀린다** | 주간 보고서에 숫자만 | 표시 이름 없음 |

### Violation이 아닌 이유 — 등급은 나중에 고칠 수 있다

`"Z"`인 등급을 뒤늦게 `"B"`로 바꾸는 건 **한 트리플을 갈아 끼우는 일**입니다. 되돌릴 수 있습니다. 원본 값이 지워지지도 않고, 다른 노드와의 연결이 끊어지지도 않습니다.

바로 위 블록의 사업자번호와 비교하면 차이가 선명합니다. 주석이 그 이유를 적어 뒀습니다.

```turtle
# 차단 — 사업자번호가 없으면 이 노드는 다른 것과 병합될 수 없다
sh:property [
    sh:path ex:bizNumber ;
    sh:minCount 1 ; sh:maxCount 1 ;
    sh:pattern "^[0-9]{3}-[0-9]{2}-[0-9]{5}$" ;
    sh:severity sh:Violation ; ... ] ;
```

사업자번호는 **동일성 판정의 열쇠**입니다. 이게 틀린 채로 들어오면 같은 회사가 노드 두 개로 앉고, 각각에 계약과 이력이 따로 붙습니다. 시간이 지나면 어느 쪽이 진짜인지 판정할 근거가 사라지고, **되돌리려면 병합이라는 별도의 프로젝트**가 필요해집니다(14장의 주제입니다). 그래서 차단입니다.

계약의 고아 노드도 같습니다. 어느 회사가 체결했는지 모르는 계약은 나중에 그 정보를 **복원할 출처가 없습니다.** 되돌릴 수 없으니 차단.

등급은 그 어느 쪽도 아닙니다. **원천에 값이 남아 있고, 언제든 갱신하면 끝**입니다. 되돌릴 수 있으면 막지 않는다 — 이게 13.2절의 결론이고, 전부 막았다가 데이터가 안 들어와서 검증을 껐던 실패에서 나온 규칙입니다. 막으면 사람들은 검증을 우회하고, **우회 경로가 주 경로가 되는 게 최악**입니다.

### Info가 아닌 이유 — 모르면 답이 틀린다

Info로 강등한 표시 이름(`rdfs:label`) 제약과 비교해 봅시다.

```turtle
# 기록 — 화면에 빈칸이 보일 뿐
sh:property [
    sh:path rdfs:label ;
    sh:minCount 1 ;
    sh:severity sh:Info ; ... ] .
```

`data.ttl`의 다올은 `rdfs:label`이 없습니다. 그래도 다올은 **모든 질의에 정상적으로 나옵니다.** 회사 목록에도, 계약 집계에도 들어갑니다. 화면에 이름 칸이 비어 URI가 그대로 보일 뿐입니다. **보기 나쁠 뿐, 답은 맞습니다.**

등급은 다릅니다. `"Z"`인 라온에너지는 등급 필터를 쓰는 순간 **집합에서 사라집니다.** 계산 결과 자체가 달라집니다. 「보기 나쁨」과 「답이 틀림」 사이에 선이 있고, 등급은 틀리는 쪽에 있습니다.

세 가지를 한 줄로 세우면 이렇습니다.

```
표시 이름 없음  → 화면이 못생긴다.        답은 맞다.        → Info
등급이 규칙 밖  → 화면이 조용히 빈다.     답이 틀린다.      → Warning
사업자번호 오류 → 노드가 갈라진다.        되돌릴 수 없다.   → Violation
```

## 4. 그래서 Warning은 어떻게 다루나

경고를 「적재는 되니까 괜찮은 것」으로 두면 Info와 다를 게 없습니다. `ex1_shacl_severity.py`가 정리한 운영 규칙은 이렇습니다.

- **차단** → 적재 거부. 사람이 원천을 고쳐야 한다.
- **경고** → 적재는 하고 **대시보드에 올린다. 질의가 틀릴 수 있으니까.**
- **기록** → 주간 보고서에 숫자만. 추세가 나빠지면 그때 본다.

덧붙여 실무에서 챙길 것들입니다.

1. **경고를 절대 개수로 추적한다.** 13.5절의 표에서 경고는 210 → 1,310으로 6배 늘었는데 종합 점수는 좋아 보였습니다. 비율만 보면 속습니다.
2. **경고에 걸린 값을 질의 쪽에서도 방어한다.** 등급 필터를 쓰는 화면에 「분류 불가 N건」을 같이 띄우면, 빈 결과가 더는 조용하지 않습니다.
3. **경고가 만성이 되면 등급을 재검토한다.** 「Z등급」이 계속 들어온다면 규칙이 현실을 못 따라가는 것일 수 있습니다. `sh:in` 목록을 넓히든 원천을 고치든, 결정을 내려야 합니다.

### 함정 — `validate()`의 전체 통과 여부는 쓸 수 없다

`ex1_shacl_severity.py`가 짚은 함정입니다. pySHACL이 돌려주는 `ok`(`sh:conforms`)는 **Info 하나만 걸려도 False**가 됩니다. 이 불리언 하나로 적재를 막으면 「표시 이름이 없다」 때문에 파이프라인이 섭니다. 심각도를 나눈 의미가 통째로 사라집니다.

그래서 보고서를 **`sh:resultSeverity`로 쪼개서** 처리해야 합니다.

```python
for r in report.subjects(URIRef(str(SH) + "resultSeverity"), None):
    sev = str(report.value(r, SH.resultSeverity)).rsplit("#", 1)[-1]
    ...
# 차단 건수만 보고 적재 여부를 결정한다
```

**SHACL이 `sh:severity`를 표준으로 제공하는 이유가 이겁니다.** 통과/실패 두 갈래로는 현실의 파이프라인을 운영할 수 없습니다.

---

## 한 줄 정리

**등급 오류는 되돌릴 수 있어서 막지 않지만, 질의를 조용히 빈 결과로 만들어 답을 틀리게 하므로 반드시 알려야 한다. 그 자리가 Warning이다.**
