# SHACL로 잡기 어려운 그래프 스멜 네 가지

> **Q.** SHACL로 잡기 어려운 그래프 스멜 네 가지는 무엇인가?
>
> **A.** 슈퍼 노드, 사이클, 중복 의심, 다중 소속이다. 세어 봐야 보이고 자동으로 고치면 안 된다.

---

## 한 줄로 기억하기

**SHACL은 「노드 하나를 보고 참/거짓을 정하는」 도구다.** 그런데 이 넷은 그렇게 판정되지 않는다.
전체를 세어 봐야(슈퍼 노드) 알고, 경로를 따라가 봐야(사이클) 알고, 참/거짓이 아니고(중복 의심), 애초에 위반인지조차 도메인이 정한다(다중 소속).

---

## 왜 SHACL로 안 되는가 — 넷의 이유가 각각 다르다

| 스멜 | 잡히지 않는 이유 |
|---|---|
| **슈퍼 노드** | 「평균 차수의 5배 초과」는 **데이터 전체를 봐야 나오는 상대값**이다. SHACL의 `sh:maxCount`는 절대값 상수만 쓸 수 있어서 「평균 대비」를 표현할 수 없다. |
| **사이클** | SHACL에 **「순환 없음」 제약 자체가 없다**. 임의 깊이의 경로 추적은 형태 제약의 표현력 밖이다. |
| **중복 의심** | 「비슷하다」는 **판정이지 참/거짓이 아니다**. 가온테크와 가온테크(주)가 같은 회사인지 SHACL이 결정할 수 없다. |
| **다중 소속** | **위반이 아닐 수도 있다.** 부품이 카테고리 둘에 속하는 게 정상인 도메인도 있다. 도메인이 정한다. |

### 고아 노드는 왜 이 목록에서 빠졌나

예제 코드(`ex3_graph_smells.py`)는 **다섯 가지**를 출력하지만, 고아 노드는 성격이 다르다.
고아 노드는 SHACL로 **잡히긴 한다**. 같은 장의 `shapes.ttl`이 실제로 잡고 있다.

```turtle
ex:ContractShape a sh:NodeShape ;
    sh:targetClass ex:Contract ;
    sh:property [
        sh:path [ sh:inversePath ex:signed ] ;   # 역방향 경로로 「나를 가리키는 게 있나」 검사
        sh:minCount 1 ;
        sh:severity sh:Violation ;
        sh:message "이 계약을 체결한 회사가 없다 (고아 노드)" ] .
```

다만 **종류가 많아 일일이 못 쓴다**는 게 문제다. 클래스마다·관계마다 역경로 shape을 다 적어야 하니 실무에서 유지되지 않는다.
그래서 「SHACL로 **못 잡는**」 넷과 「잡히지만 **다 쓰기 어려운**」 고아 노드는 구분해서 외우면 좋다.

- 원리적으로 불가능: **슈퍼 노드, 사이클, 중복 의심, 다중 소속** ← 카드가 묻는 넷
- 가능하지만 비현실적: 고아 노드

## 세어 봐야 보인다 — 코드로 확인

`ex3_graph_smells.py`는 의존성 없이 파이썬만으로 다섯 스멜을 센다. 핵심은 전부 **집계**라는 점이다.

```python
def smell_supernode(nodes, edges, factor=5):
    d = degrees(edges)
    avg = sum(d.values()) / len(d)          # ← 전체를 봐야 나오는 값
    return [(v, n) for v, n in d.most_common() if n > avg * factor]

def smell_duplicate(nodes):
    def norm(s):
        return (s or "").replace("(주)", "").replace(" ", "").strip()
    # ← 「정규화하면 같다」는 휴리스틱. 참/거짓이 아니다.

def smell_multi_parent(edges, rel):
    cnt = Counter(a for a, r, _ in edges if r == rel)
    return [(v, n) for v, n in cnt.items() if n > 1]   # ← 위반인지는 도메인이 판단
```

예제 데이터(노드 46개, 엣지 47개)에서 잡히는 것:

- **슈퍼 노드**: `hub`(「미분류」 카테고리)에 부품 30개가 몰려 있다
- **사이클**: `n3 → n4 → n5 → n3` 의 `REPLACES`(대체) 순환
- **중복 의심**: `dupA`(가온테크)와 `dupB`(가온테크(주))
- **다중 소속**: `n6`이 `cat1`과 `cat2` 둘에 속함

「미분류」 슈퍼 노드는 특히 흔하다. 데이터 적재할 때 카테고리 없는 걸 임시로 다 밀어 넣은 자리가 그대로 굳는다.

## 자동으로 고치면 안 되는 이유

카드의 후반부 「**자동으로 고치면 안 된다**」가 실무에서 더 중요하다.

- **슈퍼 노드**를 자동으로 쪼개면 → 기존 질의가 답을 못 찾는다. 「미분류」가 진짜 미분류인지, 분류 작업이 안 끝난 건지는 사람만 안다.
- **사이클**을 자동으로 끊으면 → **어느 엣지를 끊을지**를 기계가 정할 근거가 없다. 셋 중 하나를 임의로 지우면 이력이 날아간다.
- **중복 의심**을 자동 병합하면 → 다른 회사를 합쳐 버린다. 병합은 **되돌릴 수 없다**. (14장이 이 문제의 본편이다.)
- **다중 소속**을 자동으로 하나만 남기면 → 정상 데이터를 훼손한다.

그래서 이 장의 결론은 **검증을 두 겹으로** 가는 것이다.

```
1층  SHACL  — 참/거짓이 분명한 형태 제약. 심각도(sh:severity)로 차단/경고/기록을 나눈다.
2층  스멜   — 세어 보고 「이상하면 사람이 본다」. 목록만 뽑아 주는 게 일이다.
```

2층의 산출물은 「고쳐진 그래프」가 아니라 **사람이 볼 목록**이다.

## 함께 묶어 두면 좋은 것

- **13.1 추론기 ≠ 검증기**: OWL은 없으면 「어딘가 있겠지」로 결론 내고, SHACL은 없으면 위반이라고 적는다. 품질 검사에 추론기를 쓰면 안 된다.
- **13.2 차단 기준**: 전부 막으면 아무것도 안 들어오고 사람들이 검증을 우회한다. 차단 기준은 「**되돌릴 수 없는가**」 하나로.
- **13.4 역량 질의 회귀 테스트**: 형태 검사를 다 통과하면서 답이 달라지는 변경이 있다. (「카테고리 없음」을 「미분류」로 채웠더니 「카테고리 없는 부품」 질의가 빈 답을 냈다.)
- **2장 안티패턴 카탈로그** = 여기서 말하는 그래프 스멜.
