# 데이터 품질 차원의 표준 출처

**질문**: 데이터 품질 차원의 표준 출처는 무엇인가?

**답**: **ISO/IEC 25012**다. 13장 「키워드와 1차 출처」 표에서 **[표준]** 으로 분류된다.

---

## 1. 왜 이 질문이 13장에 있나

13장의 마지막 절(13.5)은 「품질을 한 숫자로 만들지 마라」다. 종합 점수 하나로 합치면 안 되는 이유를 말하려면, 먼저 **"품질에는 여러 개의 서로 다른 축이 있다"** 는 근거가 있어야 한다. 그 축의 목록을 공식적으로 정의해 둔 것이 ISO/IEC 25012다.

13장의 상태 라벨 체계에서:

| 상태 | 뜻 |
|---|---|
| **[표준]** | 공식 명세 |
| [사실상 표준] | 명세는 없지만 업계가 널리 쓰는 것 |
| [실험] | 아직 자리를 잡는 중 |

「데이터 품질 차원」은 **[표준]** 이다. 같은 장의 SHACL, sh:severity, SHACL-AF, OWL 2 프로필도 [표준]이지만 이들은 **W3C** 명세이고, ISO/IEC 25012만 **ISO/IEC** 표준이라는 점이 다르다. "그래프 스멜"과 "역량 질의 회귀 테스트"는 [실험]이다 — 이 대비를 같이 외워 두면 헷갈리지 않는다.

- 출처 링크: https://www.iso.org/standard/35736.html

---

## 2. ISO/IEC 25012가 정확히 무엇인가

- 정식 명칭: **ISO/IEC 25012:2008 — Software engineering — Software product Quality Requirements and Evaluation (SQuaRE) — Data quality model**
- **SQuaRE**(ISO/IEC 25000 시리즈)의 일부다. 25010이 *소프트웨어 제품* 품질 모델이라면, **25012는 *데이터* 품질 모델**이다.
- 측정 방법은 자매 표준 **ISO/IEC 25024**(데이터 품질 측정)가 다룬다. 25012는 "무엇을 볼 것인가(차원)", 25024는 "어떻게 잴 것인가(지표)"를 맡는다.
- 대상은 "정형 포맷으로 컴퓨터 시스템 안에 보관되는 데이터".

### 핵심 구조: 15개 특성, 2개 관점

25012는 데이터 품질을 **15개 특성(characteristics)** 으로 나누고, 각각을 두 관점으로 분류한다.

- **고유(inherent) 품질** — 데이터 그 자체의 성질. 값이 맞는가, 빠진 게 없는가. **시스템을 바꿔도 안 바뀐다.**
- **시스템 종속(system-dependent) 품질** — 데이터를 담고 있는 하드웨어·소프트웨어가 만들어 내는 성질. 접근 가능한가, 복구되는가. **데이터가 그대로여도 시스템을 바꾸면 바뀐다.**

일부 특성은 **양쪽 모두**에 걸친다.

| # | 특성 (영문) | 한국어 | 고유 | 시스템 종속 |
|---|---|---|:---:|:---:|
| 1 | Accuracy | 정확성 | O | |
| 2 | Completeness | 완전성 | O | |
| 3 | Consistency | 일관성 | O | |
| 4 | Credibility | 신뢰성 | O | |
| 5 | Currentness | 최신성 | O | |
| 6 | Accessibility | 접근성 | O | O |
| 7 | Compliance | 준수성 | O | O |
| 8 | Confidentiality | 기밀성 | O | O |
| 9 | Efficiency | 효율성 | O | O |
| 10 | Precision | 정밀성 | O | O |
| 11 | Traceability | 추적성 | O | O |
| 12 | Understandability | 이해성 | O | O |
| 13 | Availability | 가용성 | | O |
| 14 | Portability | 이식성 | | O |
| 15 | Recoverability | 복구성 | | O |

암기용 요약: **고유 전용 5개 · 양쪽 걸침 7개 · 시스템 전용 3개 = 15개.**

### 각 특성 한 줄 정의

- **정확성** — 값이 실제 세계의 참값을 올바르게 나타내는가. (구문적 정확성 = 형식/도메인이 맞는가, 의미적 정확성 = 뜻이 맞는가)
- **완전성** — 필요한 속성·레코드가 다 있는가.
- **일관성** — 서로 모순되지 않는가. 다른 곳에 있는 같은 사실이 서로 어긋나지 않는가.
- **신뢰성** — 사용자가 참이라고 믿을 만한가(출처의 권위 포함).
- **최신성** — 용도에 비추어 충분히 최근 값인가.
- **접근성** — 필요한 사람(장애가 있는 사용자 포함)이 실제로 가져올 수 있는가.
- **준수성** — 법규·표준·사내 규칙을 지키는가.
- **기밀성** — 허가된 사람만 볼 수 있는가.
- **효율성** — 요구되는 성능으로 처리·제공될 수 있는가.
- **정밀성** — 요구되는 만큼 세밀한가(소수 자릿수, 구분의 해상도).
- **추적성** — 값의 변경·접근 이력, 즉 출처(provenance)를 남기는가.
- **이해성** — 사람이 읽고 뜻을 알 수 있게 표현·라벨링되어 있는가.
- **가용성** — 필요한 시점에 시스템이 그 데이터를 내어 줄 수 있는가.
- **이식성** — 품질을 잃지 않고 다른 시스템으로 옮길 수 있는가.
- **복구성** — 장애 시 원래 상태로 되돌릴 수 있는가.

## 3. 13장의 지표를 ISO/IEC 25012 차원에 대응시키기

`ex5_quality_metrics.py`가 주차별로 찍는 컬럼은 다섯 종류다: **차단 위반 개수 · 경고 개수 · 기록 개수 · 필수 속성 채움률 · 링크 유효율**. 이걸 25012 차원으로 옮기면 왜 "합치면 안 되는지"가 눈에 보인다.

### 3.1 차단(sh:Violation) 개수

`shapes.ttl`에서 차단으로 잡는 것은 둘이다.

| 규칙 | 예제 데이터 | 대응 차원 |
|---|---|---|
| `ex:bizNumber` `minCount 1` + `pattern "^[0-9]{3}-[0-9]{2}-[0-9]{5}$"` | `ex:Naru`의 `"1234567890"` | **정확성**(구문적) + **완전성**(값 없음일 때) |
| `sh:inversePath ex:signed` `minCount 1` — 고아 계약 | `ex:C9` | **일관성**(참조 무결성) + **완전성** |

모두 **고유 품질**이다. 시스템을 Neo4j에서 GraphDB로 바꿔도 사업자번호는 여전히 틀려 있다. "되돌릴 수 없는가"라는 13장의 차단 기준이 왜 정확성·일관성 쪽에 몰리는지도 여기서 설명된다 — 식별자가 틀리면 병합이 불가능해지고, 그 손실은 나중에 복구되지 않는다.

### 3.2 경고(sh:Warning) 개수

| 규칙 | 예제 데이터 | 대응 차원 |
|---|---|---|
| `ex:grade` `sh:in ("A" "B" "C")` | `ex:Raon`의 `"Z"` | **일관성**(도메인 규칙 위반) + **정확성** |
| `ex:amount` `minInclusive 0` | `ex:C5`의 `-1` | **정확성** + **신뢰성**(집계 결과를 못 믿게 된다) |

13장의 표현으로는 "질의가 조용히 빈 결과를 낸다". 즉 **적재는 되지만 답이 틀리는** 층이고, 이는 25012의 정확성·일관성이 깨졌을 때 나타나는 전형적 증상이다.

### 3.3 기록(sh:Info) 개수

`rdfs:label` 누락(`ex:Daol`)은 **이해성(Understandability)** 이고, 부수적으로 **완전성**이다. 값이 틀린 게 아니라 **사람이 읽을 수 없을 뿐**이다. 25012가 정확성과 이해성을 다른 특성으로 분리해 놓았기 때문에, "표시 이름이 없다"를 차단이 아니라 기록으로 내리는 판단에 표준적 근거가 생긴다. `ex1`이 지적한 함정 — 통과 여부 `False` 하나만 보고 파이프라인을 세우는 것 — 은 서로 다른 차원의 위반을 불리언 하나로 뭉갠 결과다.

### 3.4 필수 속성 채움률 (0.94 → 0.89)

**완전성(Completeness)** 의 직접 측정치다. ISO/IEC 25024가 정의하는 완전성 측정과 같은 형태(존재해야 할 값 중 실제로 채워진 비율)다. 13장에서 6주에 걸쳐 계속 떨어지는 지표이며, 차단 위반이 40→29로 **좋아지는 동안** 나빠진다. 두 지표가 서로 다른 차원(정확성 vs 완전성)이므로 반대 방향으로 움직이는 게 정상이고, 종합 점수는 이 반대 방향을 상쇄시켜 버린다.

### 3.5 링크 유효율 (0.99 → 0.95)

**일관성(Consistency)** — 특히 그래프에서의 참조 무결성 — 이 주 대응이고, 끊어진 링크는 곧 그래프 접근 경로가 사라지는 것이므로 **접근성**에도 걸친다. 13장이 "이게 제일 급하다"고 한 이유는 그래프에서 엣지가 곧 질의 경로이기 때문이다. 링크가 4%p 깨지면 다단계 경로 질의는 그보다 훨씬 크게 무너진다.

### 3.6 그래프 스멜(ex3)의 대응

SHACL로 못 잡는 다섯 가지도 25012 차원에 걸린다. 다만 **"세어 봐야 보이는" 상대값**이라 참/거짓 제약으로 표현되지 않을 뿐이다.

| 스멜 | 대응 차원 | 왜 SHACL로 안 되나 |
|---|---|---|
| 슈퍼 노드 (`hub` 차수 30) | **효율성**(질의 성능), 부수적으로 **정확성**(「미분류」 쓰레기통) | 평균의 5배는 데이터 전체를 봐야 나오는 상대값 |
| 고아 노드 (`orph`) | **완전성**, **일관성** | 형태 제약으로 되긴 하는데 종류가 많아 못 씀 |
| 사이클 (`REPLACES` n3→n4→n5→n3) | **일관성** | SHACL에 「순환 없음」 제약이 없음 |
| 중복 의심 (`가온테크` / `가온테크(주)`) | **정확성**, **일관성**, **정밀성** | 「비슷하다」는 참/거짓이 아님 |
| 다중 소속 (`n6`이 카테고리 2개) | **일관성** 또는 **준수성**(도메인 규칙) | 위반이 아닐 수도 있음 |

25012의 관점에서 보면 자연스럽다. **"차원은 정의돼 있지만 그 차원을 측정하는 방법이 SHACL 하나뿐인 것은 아니다."** 그래서 13장이 검증을 두 겹(1층 SHACL, 2층 스멜)으로 나눈다.

### 3.7 역량 질의 회귀 테스트(ex4)는 어디에 걸리나

여기가 재미있는 부분이다. `migrate()`가 `category: None`을 `"미분류"`로 채우면:

- **완전성**은 **올라간다** (채움률 개선)
- 형태 검사도 통과, 노드 수도 동일
- 그런데 「카테고리 없는 부품」 질의가 빈 답을 낸다

즉 25012의 어떤 특성도 이 사고를 잡아내지 못한다. 굳이 대면 **신뢰성(Credibility)** 이 깨진 것이지만, 값 하나하나는 전부 정상이다. 문제는 **의미(semantics)** 가 바뀐 것이고, 이것은 데이터 품질 모델의 층위가 아니라 **온톨로지·질의 계약**의 층위다. 13장이 「역량 질의 회귀 테스트」를 **[실험]** 으로 라벨한 이유가 이것이다 — ISO/IEC 25012가 표준으로 덮어 주는 영역 **밖**이기 때문에 각자 만들어 쓰는 중이다.

### 3.8 13장 지표에 빠져 있는 차원

| 차원 | 13장에 있나 | 그래프에서 필요한 이유 |
|---|---|---|
| **최신성(Currentness)** | 없음 | 노드별 마지막 갱신 시각. 오래된 노드가 질의 답에 섞이는 게 흔한 사고 |
| **추적성(Traceability)** | 없음 | 값이 어느 원천에서 왔는지. RDF에서는 named graph / provenance |
| **기밀성·접근성** | 없음 | 그래프는 조인이 쉬워서 권한 없는 결합이 쉽게 생김 |
| 가용성·이식성·복구성 | 없음 | 시스템 종속 차원. 저장소 운영 쪽 관심사 |

13장이 재는 다섯 개는 전부 **고유 품질** 쪽에 몰려 있다. 25012 표를 옆에 두면 "우리는 15개 중 4~5개만 보고 있다"는 사실이 바로 드러난다. 표준 출처를 아는 실질적 효용이 이것이다.

## 4. 종합 점수 반대 논거와 25012

`composite()`는 차단×10 + 경고×3 + 기록 을 노드 수로 나눈다. 1주 66.5점 → 6주 75.3점으로 **좋아 보인다**. 하지만 그 안에서:

- 차단 40 → 29 (**정확성** 개선)
- 경고 210 → 1,310 (**일관성** 악화, 6배)
- 채움률 0.94 → 0.89 (**완전성** 악화)
- 링크 유효율 0.99 → 0.95 (**일관성/접근성** 악화)

**ISO/IEC 25012가 애초에 품질을 15개 특성으로 "나눈" 것 자체가, 하나의 숫자로 합칠 수 없다는 표준의 입장 표명이다.** 서로 다른 차원은 서로 다른 원인에서 나오고 서로 다른 처방을 요구하므로, 가중합은 정보를 파괴한다.

13장의 두 규칙을 25012 언어로 다시 쓰면:

1. **지표를 하나로 합치지 않는다** → 차원별로 따로 본다. 25012의 특성 분해가 그 근거다.
2. **절대 개수와 비율을 둘 다 적는다** → 데이터가 늘면 분모가 커져 비율은 좋아지고 절대 개수는 나빠진다. 25024가 측정을 정의할 때 분모를 명시하는 이유와 같다.

## 5. 흔한 혼동 정리

| 헷갈리는 것 | 구분 |
|---|---|
| ISO/IEC **25010** vs **25012** | 25010은 소프트웨어 제품 품질, 25012는 **데이터** 품질 |
| ISO/IEC **25012** vs **25024** | 25012는 차원의 **정의**, 25024는 그 차원의 **측정 방법** |
| ISO/IEC 25012 vs **ISO 8000** | ISO 8000도 데이터 품질 표준이지만 마스터 데이터·교환 품질 중심. 13장이 인용한 것은 **25012** |
| ISO/IEC 25012 vs **DAMA DMBOK** | DMBOK도 품질 차원 목록을 주지만 업계 가이드(사실상 표준). 13장은 **공식 명세**인 25012를 [표준]으로 든다 |
| 정확성 vs 정밀성 | 정확성 = 참값과 맞는가, 정밀성 = 요구되는 만큼 세밀한가 |
| 일관성 vs 신뢰성 | 일관성 = 서로 모순 없는가, 신뢰성 = 믿을 만한 출처인가 |

---

## 6. 한 줄 정리

**데이터 품질 차원의 표준 출처는 ISO/IEC 25012(SQuaRE 데이터 품질 모델)이며, 15개 특성을 고유(inherent)와 시스템 종속(system-dependent)으로 나눈다. 13장의 차단·경고 개수는 정확성/일관성, 필수 속성 채움률은 완전성, 링크 유효율은 일관성(참조 무결성)에 대응하고, `rdfs:label` 누락은 이해성에 해당한다. 표준이 특성을 15개로 나누어 놓았다는 사실 자체가, 품질을 한 숫자로 합치지 말라는 13장 주장의 근거다.**
