# 적재 차단 기준은 무엇 하나로 정하는가?

**답: 「되돌릴 수 없는가」 하나로 정한다. 심각도는 셋으로 나눈다.**

---

## 왜 이 질문이 나왔나

13장의 시작은 실패담입니다.

> 적재를 막았더니 데이터가 안 들어왔습니다.
> 다음 날 저는 검증을 껐습니다. 그리고 3개월 뒤에 다시 켤 때까지, 데이터는 다시 썩었습니다.

여기서 얻는 교훈은 두 가지입니다.

1. **전부 막으면 아무것도 안 들어온다.** 검증이 빡빡하면 파이프라인이 서고, 사람들은 검증을 우회합니다. **우회 경로가 주 경로가 되는 게 최악입니다.**
2. **전부 통과시키면 다시 썩는다.** 검증을 끄면 3개월 만에 원점입니다.

그래서 이분법(막는다/안 막는다)을 버리고, **심각도를 셋으로 나누고** 그중 최상위 등급에만 **딱 하나의 기준**을 적용합니다. 그 기준이 「**되돌릴 수 없는가**」입니다.

---

## 차단 기준: 「되돌릴 수 없는가」

기준을 하나로 못박는 이유는 **논쟁을 끝내기 위해서**입니다. "이건 중요한데요", "우리 팀은 이게 더 급한데요" 식의 주관적 우선순위 싸움을 막고, 누구나 같은 답을 내는 질문 하나로 줄입니다.

판정하는 방법:

> **이 데이터를 일단 넣었다가 나중에 고칠 수 있는가?**
>
> - 나중에 고칠 수 있다 → 넣는다 (경고 또는 기록)
> - 한번 들어가면 되돌릴 수 없다 → **차단**

「되돌릴 수 없다」의 실제 의미는 대개 이렇습니다.

- **식별자가 없거나 깨졌다** — 나중에 다른 노드와 병합하거나 원천을 되짚을 열쇠가 없다. 들어간 뒤에는 어느 실체인지 특정할 수 없어 복구가 불가능하다.
- **연결이 없다(고아 노드)** — 그래프에 떠 있는 노드는 시간이 지나면 출처도 맥락도 사라져서, 나중에 누가 붙여야 할지 알 수 없다.

반대로 표시 이름이 비었거나 등급 값이 이상한 건, **나중에 값만 채워 넣으면 되는** 문제입니다. 되돌릴 수 있으니 차단하지 않습니다.

---

## 심각도 세 단계와 처리 방식

SHACL은 이걸 `sh:severity`로 **표준 지원**합니다 ([SHACL §severity](https://www.w3.org/TR/shacl/#severity)). 명세가 심각도를 세 등급으로 미리 정의해 둔 이유가 바로 이 실무 문제입니다.

| SHACL 값 | 이 책의 이름 | 뜻 | 처리 |
|---|---|---|---|
| `sh:Violation` | **차단** | 되돌릴 수 없는 것 | 적재 거부. 사람이 **원천**을 고쳐야 한다 |
| `sh:Warning` | **경고** | 질의가 틀리는 것 | 적재는 하고 **대시보드에 올린다** |
| `sh:Info` | **기록** | 보기 나쁠 뿐인 것 | 주간 보고서에 **숫자만**. 추세가 나빠지면 그때 본다 |

세 등급이 각각 다른 질문에 대응합니다.

- 차단 = "되돌릴 수 있는가?"
- 경고 = "질의 결과가 틀리는가?" (조용히 빈 결과나 잘못된 합계를 낸다)
- 기록 = "화면이 보기 나쁠 뿐인가?"

---

## 코드로 보는 세 등급 (`shapes.ttl`)

```turtle
# --- 심각도 세 단계. SHACL 은 sh:severity 로 이걸 표준 지원한다. ---
#   sh:Violation — 차단. 되돌릴 수 없는 것.
#   sh:Warning   — 경고. 질의가 틀리는 것.
#   sh:Info      — 기록. 보기 나쁠 뿐인 것.

ex:CompanyShape a sh:NodeShape ;
    sh:targetClass ex:Company ;

    # 차단 — 사업자번호가 없으면 이 노드는 다른 것과 병합될 수 없다
    sh:property [
        sh:path ex:bizNumber ;
        sh:minCount 1 ; sh:maxCount 1 ;
        sh:pattern "^[0-9]{3}-[0-9]{2}-[0-9]{5}$" ;
        sh:severity sh:Violation ;
        sh:message "사업자번호가 없거나 형식이 틀렸다" ] ;

    # 경고 — 등급으로 필터하는 질의가 조용히 빈 결과를 낸다
    sh:property [
        sh:path ex:grade ;
        sh:minCount 1 ;
        sh:in ("A" "B" "C") ;
        sh:severity sh:Warning ;
        sh:message "등급이 없거나 A/B/C 밖이다" ] ;

    # 기록 — 화면에 빈칸이 보일 뿐
    sh:property [
        sh:path rdfs:label ;
        sh:minCount 1 ;
        sh:severity sh:Info ;
        sh:message "표시 이름이 없다" ] .

ex:ContractShape a sh:NodeShape ;
    sh:targetClass ex:Contract ;

    # 차단 — 계약인데 회사가 없으면 고아 노드다
    sh:property [
        sh:path [ sh:inversePath ex:signed ] ;
        sh:minCount 1 ;
        sh:severity sh:Violation ;
        sh:message "이 계약을 체결한 회사가 없다 (고아 노드)" ] ;

    # 경고 — 금액이 음수면 집계가 틀린다
    sh:property [
        sh:path ex:amount ;
        sh:datatype xsd:integer ;
        sh:minInclusive 0 ;
        sh:severity sh:Warning ;
        sh:message "금액이 없거나 음수다" ] .
```

주석 하나하나가 「되돌릴 수 없는가」 판정의 근거입니다.

- 사업자번호 → 차단. **"이 노드는 다른 것과 병합될 수 없다."** 병합 열쇠를 잃으면 복구 불가.
- 역경로(`sh:inversePath ex:signed`) 없음 → 차단. **고아 노드.**
- 등급이 A/B/C 밖 → 경고. 질의가 **조용히 빈 결과**를 내지만, 값은 나중에 고칠 수 있다.
- 금액 음수 → 경고. 집계가 틀리지만 정정 가능.
- `rdfs:label` 없음 → 기록. 화면에 빈칸이 보일 뿐.

## 핵심 함정: `ok` 불리언 하나로 판단하지 마라

`ex1_shacl_severity.py`가 짚는 지점입니다.

```python
ok, report, _ = validate(data, shacl_graph=shapes, inference="none", advanced=True)
```

```
«전체 통과 여부»가 False 인 게 함정이다.
기록 등급 하나만 걸려도 False 가 나온다. 그래서 이 값만 보고
적재를 막으면 «표시 이름이 없다» 때문에 파이프라인이 선다.
```

SHACL 검증 보고서의 `sh:conforms`(pySHACL의 `ok`)는 **`sh:Info` 하나만 걸려도 `False`**입니다. 이 불리언을 그대로 게이트로 쓰면 "표시 이름이 없다"라는 사소한 이유로 적재 전체가 멈춥니다. 그게 앞서 나온 실패담의 정체입니다.

그래서 코드는 `ok`를 버리고 **보고서를 심각도별로 갈라서 센 다음** 처리합니다.

```python
LEVEL = {"Violation": "차단", "Warning": "경고", "Info": "기록"}
...
sev = str(report.value(r, SH.resultSeverity)).rsplit("#", 1)[-1]
...
cnt = Counter(r[0] for r in rows)
print(f"\n차단 {cnt['차단']}건 · 경고 {cnt['경고']}건 · 기록 {cnt['기록']}건")
```

**실무 게이트 조건은 `ok == True`가 아니라 `차단 건수 == 0`입니다.**

## 한 줄로 외우기

> 심각도는 셋(차단/경고/기록), **차단 기준은 「되돌릴 수 없는가」 하나**.
> 게이트는 `ok`가 아니라 **차단 건수 0**.

## 연결되는 이야기

- 이 기준의 반대편에 있는 게 **품질을 한 숫자로 합치지 마라**(13.5)입니다. 심각도를 셋으로 나눠 놓고 다시 하나의 점수로 뭉개면 아무 의미가 없습니다. 차단·경고·기록은 각각 따로 세고, 비율과 절대 개수를 둘 다 적어야 합니다.
- **SHACL로 못 잡는 것들**(13.3 — 슈퍼 노드, 사이클, 중복 의심, 다중 소속)은 애초에 심각도 체계 밖입니다. 세어서 목록만 뽑고 사람이 보게 하지, 자동으로 고치거나 차단하면 안 됩니다.
- 「사업자번호가 없으면 병합될 수 없다」가 왜 되돌릴 수 없는 문제인지는 **14장(같은 사람이 노드 네 개로 앉아 있다)**에서 본편으로 다룹니다.
