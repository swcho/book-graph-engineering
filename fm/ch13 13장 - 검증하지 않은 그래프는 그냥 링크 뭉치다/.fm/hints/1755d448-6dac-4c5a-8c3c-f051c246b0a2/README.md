# 그 마이그레이션은 어떤 검사를 통과하고 어떤 검사에서 걸렸는가?

**정답**: 형태 검사(카테고리 누락 0건)와 노드·타입 분포 검사는 통과했지만, 역량 질의 「카테고리 없는 부품」이 빈 답을 내며 실패했다.

출처: 13장 「검증하지 않은 그래프는 그냥 링크 뭉치다」, 13.4절 *모양은 맞는데 뜻이 달라졌다* / 예제 `code/ex4_regression.py`

---

## 한 줄로

`ex4_regression.py`는 **검사 세 개를 순서대로 돌린다. 앞의 둘은 통과하고 세 번째에서 1건이 걸린다.** 걸린 이유가 「데이터가 더러워져서」가 아니라 **「데이터가 더 깨끗해져서」**라는 게 이 예제의 전부다.

```
=== 1. SHACL 류 형태 검사 ===
  카테고리 누락: 0건  → 통과

=== 2. 노드·엣지 수 검사 ===
  전:  {"노드 수": 5, "타입 분포": {"부품": 3, "제품": 2}}
  후:  {"노드 수": 5, "타입 분포": {"부품": 3, "제품": 2}}
  통과

=== 3. 역량 질의 검사 ===
  [통과] P2 를 쓴 리콜 제품
  [통과] 가온테크 납품 부품
  [실패] 카테고리 없는 부품
        전: ['P3']
        후: []
```

## 무대 설치 — 골든 데이터셋과 고정된 기대값

먼저 사람이 답을 확인해 둔 작은 표본이 있다.

```python
# 골든 데이터셋 — 손으로 만든 작은 표본. 답을 사람이 확인해 뒀다.
GOLDEN = [
    {"id": "P1", "type": "부품", "category": "체결", "supplier": "가온테크"},
    {"id": "P2", "type": "부품", "category": "전자", "supplier": "나루소프트"},
    {"id": "P3", "type": "부품", "category": None,   "supplier": "가온테크"},
    {"id": "D1", "type": "제품", "parts": ["P1", "P2"], "recalled": True},
    {"id": "D2", "type": "제품", "parts": ["P2", "P3"], "recalled": False},
]
```

노드 5개. 부품 3개(P1, P2, P3), 제품 2개(D1, D2). **P3만 `category`가 `None`이다.** 이 한 칸이 이 예제의 뇌관이다.

그리고 기대값을 **마이그레이션이 일어나기 전에** 계산해서 얼려 둔다.

```python
# 기대값 — 처음 만들 때 사람이 확인하고 고정한다
EXPECTED = {name: fn(GOLDEN) for name, fn in QUERIES.items()}
```

이 한 줄이 모듈 최상단에서 임포트 시점에 실행되므로, `EXPECTED`는 **변경 전 세계의 정답**을 붙잡고 있다.

| 역량 질의 | 고정된 기대값 |
|---|---|
| P2 를 쓴 리콜 제품 | `['D1']` |
| 가온테크 납품 부품 | `['P1', 'P3']` |
| 카테고리 없는 부품 | `['P3']` |

> 회귀 테스트의 핵심은 「기대값이 언제 찍혔는가」다. 마이그레이션 후에 기대값을 다시 계산하면 그건 회귀 테스트가 아니라 그냥 항등식이다. 이 예제가 `EXPECTED`를 `migrate()` 호출보다 위에 둔 건 우연이 아니다.

## 문제의 변경 — None을 「미분류」로 채우기

```python
# 스키마 변경 — «카테고리 없음»을 None 대신 «미분류»로 채우기로 했다
def migrate(rows):
    out = []
    for r in rows:
        r = dict(r)
        if r.get("type") == "부품" and not r.get("category"):
            r["category"] = "미분류"
        out.append(r)
    return out
```

누가 봐도 착한 변경이다. 널을 없애고, 화면에 빈칸 대신 「미분류」라는 글자가 나오고, 카테고리 필터 드롭다운에 항목 하나가 생긴다. **NULL을 센티널 값(sentinel value)으로 치환하는** 아주 흔한 데이터 정제 패턴이다.

## 검사 1 — 형태 검사: 왜 「개선」으로 보이는가

```python
print("=== 1. SHACL 류 형태 검사 ===")
bad = [r for r in after if r["type"] == "부품" and not r.get("category")]
print(f"  카테고리 누락: {len(bad)}건  → 통과\n")
```

이 검사가 보는 것은 **「필수 속성이 채워져 있는가」** 하나다. SHACL로 치면 `sh:path ex:category ; sh:minCount 1`에 해당한다. 같은 장의 `shapes.ttl`에 있는 이 형태와 완전히 같은 종류다.

```turtle
    # 기록 — 화면에 빈칸이 보일 뿐
    sh:property [
        sh:path rdfs:label ;
        sh:minCount 1 ;
        sh:severity sh:Info ;
        sh:message "표시 이름이 없다" ] .
```

**수치가 어떻게 움직였나:**

| | 카테고리 누락 |
|---|---|
| 마이그레이션 전 | **1건** (P3) |
| 마이그레이션 후 | **0건** |

여기가 이 문제의 핵심이다. 형태 검사 입장에서 이 변경은 **위반이 1건에서 0건으로 줄어든 명백한 개선**이다. 대시보드 그래프가 아래로 예쁘게 꺾인다. 「데이터 품질 개선 완료」라고 스프린트 회고에 적을 만한 그림이다.

왜 그렇게 보이느냐 — **형태 검사는 「값이 있는가」만 묻고 「그 값이 무엇을 뜻하는가」는 묻지 않기 때문**이다. `None`도 값의 부재, `"미분류"`도 값의 부재를 뜻하는 문자열인데, 검사기 눈에는 전자는 위반이고 후자는 멀쩡한 문자열이다. 의미는 그대로인데 **모양만 바뀌어서 위반이 사라졌다.** 문제를 고친 게 아니라 **문제를 검사기가 못 보는 자리로 옮긴 것**이다.

> `migrate()`의 조건절 `if r.get("type") == "부품" and not r.get("category")`가 질의 `q_uncategorized`의 필터와 **글자 그대로 같다**는 점을 보라. 마이그레이션은 정확히 그 질의가 집어내던 행 집합만을 골라 바꿔 놓았다. 그러니 질의 결과가 빈 배열이 되는 건 사고가 아니라 논리적 필연이다.

## 검사 2 — 노드·타입 분포 검사

```python
def shape_stats(rows):
    return {"노드 수": len(rows),
            "타입 분포": dict(Counter(r["type"] for r in rows))}
```

```python
b, a = shape_stats(GOLDEN), shape_stats(after)
print(f"  전:  {json.dumps(b, ensure_ascii=False)}")
print(f"  후:  {json.dumps(a, ensure_ascii=False)}")
print(f"  {'통과' if b == a else '차이 있음'}\n")
```

이 검사가 보는 것은 **덩어리의 크기와 구성비**다. 실무에서는 「어제 대비 노드 수가 30% 이상 빠졌으면 적재를 멈춘다」 같은 형태로 쓰는, 이른바 볼륨/분포 이상 탐지다. 파일이 반쯤 잘려 들어오거나 조인이 터져 행이 폭증하는 사고를 잡는 데는 아주 잘 듣는다.

**수치가 어떻게 움직였나:**

| | 노드 수 | 타입 분포 |
|---|---|---|
| 전 | 5 | `{"부품": 3, "제품": 2}` |
| 후 | 5 | `{"부품": 3, "제품": 2}` |

**완전히 동일하다.** 당연하다. `migrate()`는 노드를 지우지도 만들지도 않았고 `type`도 건드리지 않았다. **속성 값 한 칸만 바꿨다.** 이 검사는 속성 값의 내용을 아예 보지 않으므로 구조적으로 이 변경을 감지할 수 없다.

## 검사 3 — 역량 질의: 여기서 걸린다

```python
def q_uncategorized(rows):
    return sorted(r["id"] for r in rows
                  if r["type"] == "부품" and not r.get("category"))
```

```python
for name, fn in QUERIES.items():
    got, want = fn(after), EXPECTED[name]
    ok = got == want
```

역량 질의(competency question)는 **온톨로지가 답할 수 있어야 하는 질문의 목록**이다. 12장에서 뽑아 둔 그것을 그대로 회귀 테스트의 단언문으로 쓴다. 이 검사가 보는 것은 스키마도 통계도 아니라 **「사용자가 실제로 던지는 질문의 답이 그대로인가」**다.

| 역량 질의 | 전 | 후 | 판정 |
|---|---|---|---|
| P2 를 쓴 리콜 제품 | `['D1']` | `['D1']` | 통과 |
| 가온테크 납품 부품 | `['P1', 'P3']` | `['P1', 'P3']` | 통과 |
| **카테고리 없는 부품** | **`['P3']`** | **`[]`** | **실패** |

세 번째가 걸린다. `failed = 1`.

주목할 점은 앞의 두 질의는 멀쩡히 통과한다는 것이다. **마이그레이션이 그래프 전체를 망가뜨린 게 아니다.** 딱 한 질의만, 조용히 죽었다. 그래서 눈치채기가 더 어렵다.

```
앞의 두 검사는 통과했는데 세 번째에서 1건이 걸렸다.

«카테고리 없음»을 «미분류»로 채웠더니 «카테고리 없는 부품» 질의가 빈 답을 낸다.
데이터는 더 깨끗해졌고, 형태 검사도 통과하고, 노드 수도 그대로다.
그런데 그 질의에 기대던 화면이 조용히 비었다.
```

## 세 검사의 관할 구역

| | 검사 1 형태 | 검사 2 분포 | 검사 3 역량 질의 |
|---|---|---|---|
| **묻는 것** | 값이 규칙에 맞는 모양인가 | 덩어리 크기·구성비가 그대로인가 | 질문의 답이 그대로인가 |
| **보는 단위** | 노드 하나, 속성 하나 | 그래프 전체 통계 | 질의 결과 집합 |
| **잡는 사고** | 형식 오류, 필수 누락, 고아 노드 | 적재 누락, 행 폭증, 타입 오염 | 의미 변경, 센티널 도입, 술어 재정의 |
| **이번 결과** | 1건 → 0건, 통과 (개선으로 보임) | 5/{3,2} → 5/{3,2}, 통과 | `['P3']` → `[]`, **실패** |
| **놓치는 것** | 모양은 맞고 뜻이 달라진 변경 | 속성 값의 내용 전부 | 질의로 안 뽑아 본 영역 |

1층과 2층은 **데이터를 본다.** 3층만 **질문을 본다.** 그리고 사용자는 데이터를 쓰는 게 아니라 질문을 쓴다.

> 13장은 이 층위를 「1층 SHACL — 참/거짓이 분명한 형태 제약 / 2층 스멜 — 세어 보고 이상하면 사람이 본다」로 나눴다(`ex3`). `ex4`의 역량 질의는 그 위에 얹히는 **3층**이라고 보면 된다. 아래 두 층이 모두 초록불인데 3층이 빨간불인 상황이 바로 13.4절의 제목, 「모양은 맞는데 뜻이 달라졌다」다.

## 실제 서비스에서는 이게 어떻게 드러나나

이 사고의 진짜 무서운 점은 **아무 일도 일어나지 않는다는 것**이다.

**1. 빈 화면**

「미분류 처리 대기 큐」 화면이 있다고 하자. 이 화면은 `q_uncategorized`와 같은 질의를 던져 담당자에게 「분류해야 할 부품 목록」을 보여 준다. 마이그레이션 다음 날부터 이 화면은 **0건**이 뜬다. 화면은 깨지지 않았다. 에러 메시지도 없다. 로딩 스피너가 정상적으로 돌고, 정상적으로 「처리할 항목이 없습니다」가 뜬다.

**0건은 두 가지를 뜻하는데 화면은 그 둘을 구별해 주지 않는다.**
- 일이 다 끝났다 (기쁜 0건)
- 질의가 고장 났다 (재앙인 0건)

담당자는 전자로 읽는다. 그리고 몇 주 뒤 「분류 안 된 부품이 창고에 산더미인데 왜 시스템엔 안 뜨죠?」라는 문의가 들어온다. 그 사이 미분류 부품은 계속 쌓이고 있었다.

**2. 알림 없음**

경보 규칙이 대개 이렇게 짜여 있다는 게 두 번째 문제다.

- SHACL 위반 건수가 임계치를 넘으면 알림 → **위반이 0건이 됐으므로 안 울린다.** 오히려 그래프가 좋아진다.
- 적재 노드 수가 급변하면 알림 → **노드 수가 그대로이므로 안 울린다.**
- 질의가 에러를 뱉으면 알림 → **에러가 아니라 빈 배열이므로 안 울린다.** HTTP 200에 `[]`다.
- 배치 잡이 실패하면 알림 → **성공했다.**

파이프라인의 모든 신호등이 초록불이다. `ex1`에서 다룬 심각도 셋(차단·경고·기록) 어디에도 이 사고는 걸리지 않는다. 형태 위반이 아니니까. `ex3`의 그래프 스멜에도 안 걸린다. 슈퍼 노드도 사이클도 중복도 아니니까. **이 사고를 잡을 수 있는 유일한 그물이 역량 질의 회귀 테스트다.**

**3. 파생 피해**

한 걸음 더 나가면 이런 것들이 딸려 온다.

- 「미분류」가 이제 **정식 카테고리처럼 보인다.** 카테고리별 집계 리포트에 「미분류 30건」이 다른 카테고리와 나란히 한 줄로 올라온다. 「전자 15건, 체결 12건, 미분류 30건」 — 최대 카테고리가 미분류가 됐는데 그래프는 그냥 막대 하나일 뿐이다.
- 카테고리 다중 소속이나 카테고리 기준 추천 같은 하위 로직이 **「미분류끼리 같은 카테고리」**로 묶기 시작한다. 서로 아무 관계 없는 부품 30개가 하나의 슈퍼 노드에 매달린다. 공교롭게도 `ex3_graph_smells.py`가 `hub` 노드의 이름을 **「미분류」**로 잡아 둔 게 바로 이 결말이다.
- 하류 팀이 「미분류도 카테고리다」라고 믿고 코드를 짜기 시작하면, 나중에 되돌리려 해도 **되돌릴 수 없다.** 원래 `None`이었던 것과 사람이 진짜로 「미분류」라고 지정한 것을 구별할 방법이 사라졌기 때문이다.

## 그래서 어떻게 하나

**골든 데이터셋은 30~50건이면 충분하고, 크기보다 경계 사례가 중요하다.** 13장이 못 박은 규칙이다. `ex4`의 `GOLDEN`이 5건뿐인데도 사고를 잡아낸 이유는 그 안에 **`category`가 `None`인 P3**이 들어 있었기 때문이다. 정상 데이터를 500건 넣어 봐야 이 사고는 안 잡힌다. 널, 빈 문자열, 0, 경계 날짜, 다중 소속 — 그런 것들이 골든 데이터셋의 값어치다.

이번 실패를 만났을 때 고를 수 있는 길은 대략 셋이고, **셋 중 무엇을 고르든 사람이 결정해야 한다는 게 요점**이다.

1. **마이그레이션을 되돌린다.** `None`은 「값이 없다」는 정보를 담고 있었고 그건 지울 정보가 아니었다.
2. **질의를 함께 마이그레이션한다.** `not r.get("category")` → `r.get("category") in (None, "미분류")`. 단, 기대값을 새로 얼리면서 「의도적 변경」임을 커밋에 남긴다.
3. **분류 상태를 별도 속성으로 뺀다.** `category`는 표시용, `categorized: bool`은 질의용으로 나눈다. 값과 상태를 한 칸에 우겨넣지 않는다.

회귀 테스트가 해 준 일은 답을 고르는 게 아니라 **「이 변경은 답이 달라지는 변경이다」라고 사람 앞에 들이민 것**이다. 자동으로 통과시켰다면 아무도 이 선택지를 마주하지 못했다.

```
이게 회귀 테스트에 «질의»가 들어가야 하는 이유다.
형태만 검사하면 «모양은 맞는데 뜻이 달라진» 변경을 못 잡는다.
```

## 외워 둘 것

- **통과: 형태 검사(카테고리 누락 1건 → 0건), 노드·타입 분포 검사(5 / 부품3·제품2, 전후 동일).**
- **실패: 역량 질의 「카테고리 없는 부품」. `['P3']` → `[]`. 1건.**
- **`None` → `"미분류"`는 형태 검사 눈에 위반 감소이므로 개선처럼 보인다.** 값의 부재를 값으로 바꿨을 뿐, 뜻은 그대로인데 검사기가 못 보는 자리로 옮겼다.
- **서비스에서는 에러 없이 빈 화면과 무알림으로 드러난다.** 0건이 「일이 없다」인지 「질의가 죽었다」인지 구별되지 않는다.
- **역량 질의를 회귀 테스트에 넣어야 잡힌다. 골든 데이터셋은 30~50건, 크기보다 경계 사례.**
