# 형태 검사를 통과하면서 답이 달라지는 변경은 어떻게 잡는가?

> **답**: 역량 질의를 회귀 테스트에 넣어야 잡힌다. 골든 데이터셋은 30~50건이면 충분하고 크기보다 경계 사례가 중요하다.

13장 13.4절 「모양은 맞는데 뜻이 달라졌다」의 핵심입니다.

---

## 1. 문제: 「위반 0건」이 안전을 뜻하지 않는다

SHACL 같은 형태 검사는 **노드가 어떤 모양이어야 하는가**만 봅니다.

- 사업자번호가 정규식에 맞는가
- 필수 속성이 있는가
- 금액이 음수가 아닌가

그런데 스키마나 데이터를 고칠 때 **모양은 그대로인데 뜻이 달라지는** 변경이 있습니다. 이때 형태 검사기는 조용히 통과 도장을 찍어 줍니다. 그리고 그 질의에 기대던 대시보드 화면이 아무 경고 없이 비어 버립니다.

전형적인 「조용한 변경」 유형:

| 유형 | 예 | 형태 검사 결과 |
|---|---|---|
| 빈 값 채우기 | `category: null` → `"미분류"` | 통과 (오히려 더 깨끗해짐) |
| 기본값 주입 | 등급 미기재를 `"C"`로 채움 | 통과 |
| 관계 방향 바꾸기 | `signed` ↔ `signedBy` | 통과 |
| 클래스 재배치 | 하위 클래스를 다른 상위로 이동 | 통과 |
| 코드 값 통합 | `"체결"`/`"체결류"`를 하나로 병합 | 통과 |

전부 형태 제약에는 걸리지 않습니다. 전부 질의 답을 바꿉니다.

## 2. 해법: 역량 질의(competency question)를 회귀 테스트로

12장에서 온톨로지 범위를 정할 때 뽑은 **역량 질의**를 그대로 테스트 케이스로 승격시킵니다.

역량 질의란 「이 그래프는 이런 질문에 답할 수 있어야 한다」를 문장으로 적어 둔 것입니다. 예를 들어

- "P2 부품을 쓴 리콜 제품은 무엇인가"
- "가온테크가 납품한 부품 목록은"
- "카테고리가 없는 부품은"

이 질문들의 **답을 사람이 한 번 확인하고 고정**해 두면, 이후 어떤 변경이 들어와도 답이 바뀌는 순간 CI가 빨간불을 냅니다.

### 3중 검사 구조

책의 `ex4_regression.py`가 보여 주는 순서입니다.

```
1층  형태 검사 (SHACL 류)     → 카테고리 누락 0건. 통과.
2층  노드·엣지 수 검사         → 노드 5개, 타입 분포 동일. 통과.
3층  역량 질의 검사            → 실패!
```

`migrate()`가 한 일은 「카테고리 없음(None)을 '미분류'로 채우기」뿐입니다. 데이터는 더 깨끗해졌고, 형태 검사도 통과하고, 노드 수도 그대로입니다. 그런데

```
[실패] 카테고리 없는 부품
      전: ['P3']
      후: []
```

**1층과 2층은 절대 이걸 못 잡습니다.** 3층이 있어야만 잡힙니다.

핵심 코드 패턴:

```python
# 기대값 — 처음 만들 때 사람이 확인하고 고정한다
EXPECTED = {name: fn(GOLDEN) for name, fn in QUERIES.items()}

# 변경 후, 같은 질의를 돌려서 기대값과 비교
for name, fn in QUERIES.items():
    got, want = fn(after), EXPECTED[name]
    if got != want:
        print(f"[실패] {name}\n  전: {want}\n  후: {got}")
```

실무에서는 `EXPECTED`를 코드에서 계산하지 말고 **JSON/YAML 파일로 커밋**해 두는 게 좋습니다. 그래야 기대값이 바뀔 때 diff가 리뷰에 남습니다. 기대값을 고치는 커밋은 「의도한 변경」이라는 선언이고, 리뷰어가 그 자리에서 확인할 수 있어야 합니다.

## 3. 골든 데이터셋: 30~50건이면 충분하다

역량 질의를 돌리려면 답이 확정된 작은 표본이 필요합니다. 이게 **골든 데이터셋**입니다.

### 왜 크기가 중요하지 않은가

- **손으로 확인 가능해야 한다.** 사람이 눈으로 답을 검증해야 하는데, 1만 건이면 아무도 안 봅니다. 검증되지 않은 기대값은 기대값이 아닙니다.
- **CI에서 몇 초 안에 돌아야 한다.** 매 PR마다 돌지 않으면 회귀 테스트가 아닙니다.
- **실패했을 때 원인을 읽을 수 있어야 한다.** 답이 3건에서 2건으로 줄었을 때 사라진 그 1건을 바로 짚을 수 있어야 합니다.

### 크기 대신 챙길 것: 경계 사례

30~50건을 무작위 샘플링으로 채우면 의미가 없습니다. 흔한 케이스만 잔뜩 들어오고, 정작 깨지는 건 가장자리이기 때문입니다. 다음이 반드시 들어가야 합니다.

| 경계 사례 | 왜 필요한가 |
|---|---|
| 빈 값 / null | 위 예제가 정확히 이걸로 깨졌다 |
| 다중 소속 | 부품이 카테고리 둘에 걸린 경우 |
| 고아 노드 | 아무 데도 연결 안 된 노드 |
| 중복 의심 | 「가온테크」/「가온테크(주)」 |
| 사이클 | `A REPLACES B REPLACES C REPLACES A` |
| 최대·최소값 | 음수 금액, 0, 아주 긴 문자열 |
| 다국어·특수문자 | 정규화 로직이 흔히 깨지는 곳 |
| 답이 「없음」인 질의 | 빈 결과가 정상인 케이스 — 조용한 변경이 가장 잘 숨는 자리 |

책의 `GOLDEN`이 5건뿐인데도 회귀를 잡아낸 건 그 5건 안에 `"category": None`인 P3이 있었기 때문입니다. **경계 사례 한 건이 무작위 1,000건보다 낫습니다.**

### 골든 데이터셋 유지 규칙

1. **원본 데이터에서 복사하지 말고 따로 관리한다.** 원천이 바뀌면 기대값이 같이 흔들려서 테스트 의미가 사라집니다.
2. **버그를 하나 잡을 때마다 그 케이스를 추가한다.** 그러면 데이터셋이 실제 사고 이력을 따라 자란다.
3. **50건을 넘기 시작하면 잘라낸다.** 커지면 아무도 안 봅니다. 새 케이스를 넣을 때 낡은 케이스를 뺄 수 있는지 먼저 봅니다.

## 4. 정리 — 검증의 세 겹

| 층 | 도구 | 잡는 것 | 못 잡는 것 |
|---|---|---|---|
| 1층 | SHACL 형태 제약 | 참/거짓이 분명한 모양 위반 | 상대값, 뜻의 변화 |
| 2층 | 그래프 스멜 (세어 보기) | 슈퍼 노드, 사이클, 중복 의심, 다중 소속 | 질의 답의 변화 |
| 3층 | 역량 질의 회귀 테스트 | 모양은 맞는데 답이 달라진 변경 | — |

한 줄로: **형태만 검사하면 「모양은 맞는데 뜻이 달라진」 변경을 못 잡는다. 질의를 테스트에 넣어라.**
