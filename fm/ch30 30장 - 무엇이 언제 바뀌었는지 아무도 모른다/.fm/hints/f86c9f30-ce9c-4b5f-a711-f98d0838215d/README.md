# 힌트 — `ex1_no_history.py`의 네 질문 중 답할 수 있는 것

**질문**: `ex1_no_history.py`가 던지는 네 질문 중 현재 상태로 답할 수 있는 것은 무엇인가?

**답**: **Q1(지금 결제팀 팀장은?)뿐이다. Q2~Q4는 답할 수 없다.**

---

## 1. 먼저 데이터를 보자

예제는 변경 6건을 두 방식으로 동시에 기록한다.

| # | 시각 | 주어 | 관계 | 목적어 | op | 행위자 |
|---|---|---|---|---|---|---|
| 0 | 2026-03-02 | 박민수 | 이끔 | 결제팀 | 추가 | hr-sync |
| 1 | 2026-04-01 | 박민수 | 이끔 | 결제팀 | 삭제 | hr-sync |
| 2 | 2026-04-01 | 이서연 | 이끔 | 결제팀 | 추가 | hr-sync |
| 3 | 2026-04-14 | 이서연 | 이끔 | 정산팀 | 추가 | **agent-4821** |
| 4 | 2026-04-15 | 이서연 | 이끔 | 정산팀 | 삭제 | **admin:kim** |
| 5 | 2026-05-20 | 이서연 | 삶 | 마포 | 추가 | user-utterance |

두 저장 방식의 스키마 차이가 이 장 전체의 핵심이다.

```python
# 현재 상태만
c.execute("CREATE REL TABLE Cur(FROM N TO N, kind STRING)")
# 이벤트 로그
c.execute("CREATE NODE TABLE Ev(id INT64, at STRING, subj STRING, "
          "kind STRING, obj STRING, op STRING, actor STRING, "
          "PRIMARY KEY(id))")
```

`Cur` 엣지가 가진 속성은 `kind` 하나뿐이다. **시각(`at`)도 없고 행위자(`actor`)도 없다.**
게다가 `op == "삭제"`일 때 코드는 이렇게 한다.

```python
c.execute("MATCH (a:N {name:$s})-[e:Cur {kind:$k}]->"
          "(b:N {name:$o}) DELETE e", ...)
```

`DELETE e` — 그냥 지운다. 지웠다는 사실조차 남지 않는다.

그 결과 6건을 다 넣고 나면 현재 상태에 남는 엣지는 딱 둘이다.

```
  이서연 -삶-> 마포
  이서연 -이끔-> 결제팀
```

박민수의 흔적(#0, #1)도, 정산팀 팀장이었던 사실(#3, #4)도 그래프에서 통째로 사라졌다.

---

## 2. 질문별로 왜 되고 왜 안 되는가

### Q1 — 「지금 결제팀 팀장은?」 → **답할 수 있다**

```python
a1 = rows(c.execute("MATCH (p:N)-[:Cur {kind:'이끔'}]->"
                    "(:N {name:'결제팀'}) RETURN p.name"))
```

현재 상태 그래프에 `이서연 -이끔-> 결제팀` 엣지가 살아 있다. 쿼리 한 방으로 `이서연`이 나온다.
**질문이 「지금」을 묻기 때문에** 답할 수 있는 것이다. 현재 상태 저장소가 답할 수 있는 질문은 이 한 종류뿐이다 — *「지금 뭐죠?」*.

> 참고: Q1조차 「언제부터 팀장인가」로 한 글자만 바꾸면 바로 답 못 하는 질문이 된다. `Cur` 엣지에 시각이 없기 때문이다.

### Q2 — 「3월 15일에는 팀장이 누구였나?」 → **답 못 함**

박민수 엣지는 4월 1일 이벤트(#1)에서 `DELETE e`로 지워졌다. 현재 그래프에는 3월의 상태를 복원할 재료가 **아예 존재하지 않는다.** 덮어쓰기는 답을 「지운다」.

이벤트 로그 쪽은 3/15까지 재생하면 된다.

```python
for ... in rows(c.execute(
        "MATCH (e:Ev) WHERE e.at <= '2026-03-15' "
        "RETURN e.at, e.subj, e.kind, e.obj, e.op ORDER BY e.id")):
    if op == "추가": st.add((s, k, o))
    else:            st.discard((s, k, o))
```

3/15 이전 이벤트는 #0 하나뿐이므로 상태는 `{(박민수, 이끔, 결제팀)}` → **박민수**.
감사·분쟁에서 반드시 나오는 「그때는 어땠나」가 이 유형이다.

### Q3 — 「'이서연 -이끔-> 정산팀'은 누가 넣고 누가 지웠나?」 → **답 못 함**

두 겹으로 막힌다.

1. **엣지 자체가 없다.** #3에서 만들었다가 #4에서 지웠으니 현재 그래프에 정산팀 엣지는 존재하지 않는다.
2. **설령 남아 있었어도 못 답한다.** `Cur` 스키마에 `actor` 컬럼이 없다. 현재 상태는 *무엇이 참인가*만 담고 *누가 그렇게 만들었나*는 담지 않는다.

이벤트 로그에는 그 짝이 그대로 남는다.

```
추가 agent-4821 (2026-04-14) / 삭제 admin:kim (2026-04-15)
```

「누가 넣었나」는 사고 조사의 첫 질문이다.

### Q4 — 「에이전트가 넣은 것 중 사람이 되돌린 게 몇 건인가?」 → **답 못 함**

이건 Q3보다 한 단계 더 어렵다. 답하려면 **행위자 + 시간 순서 + 추가/삭제 쌍**이 전부 필요하다. 현재 상태에는 셋 중 하나도 없다.

이벤트 로그로는 `actor` 접두사로 짝을 맞춘다.

```python
added = {... "WHERE e.op='추가' AND e.actor STARTS WITH 'agent'" ...}
for ... in rows(c.execute("... WHERE e.op='삭제' AND e.actor STARTS WITH 'admin' ...")):
    if (s, k, o) in added:
        reverted += 1
```

`agent-4821`이 추가한 `(이서연, 이끔, 정산팀)`을 `admin:kim`이 지웠으므로 **1건**.
이것이 28장에서 말한 「에이전트가 넣은 것 중 되돌려진 비율」, 즉 품질 지표 그 자체다.

## 3. 출력이 말하는 것

| | 질문 | 현재 상태만 | 이벤트 로그 |
|---|---|---|---|
| Q1 | 지금 결제팀 팀장은? | 이서연 | 이서연 |
| Q2 | 3월 15일에는 팀장이 누구였나? | 답 못 함 | 박민수 |
| Q3 | 정산팀 엣지는 누가 넣고 누가 지웠나? | 답 못 함 | 추가 agent-4821 / 삭제 admin:kim |
| Q4 | 에이전트가 넣은 것 중 사람이 되돌린 건? | 답 못 함 | 1건 |

**4분의 1.** 그런데 운영에서 자주 나오는 건 나머지 4분의 3이다.

## 4. 외울 포인트

- 현재 상태 저장소가 답할 수 있는 질문은 **「지금 뭐죠?」 한 종류**뿐이다.
- 답 못 하는 이유는 두 가지로 갈린다.
  - **시간이 없어서** (Q2) — 삭제가 흔적 없이 지워진다.
  - **행위자가 없어서** (Q3, Q4) — 엣지에 「누가」가 아예 안 들어 있다.
- 그래서 이 장의 결론이 나온다. **이벤트가 원본이고 상태는 파생이다.** 이벤트를 쌓으면 현재 상태는 재생해서 만들 수 있고 과거도 남지만, 반대 방향으로는 복원이 안 된다.
- 대신 값을 치른다 — 저장 공간과 재생 시간. 그건 `ex2_replay_cost.py`에서 잰다.

## 5. 자주 하는 실수

- **「Q1과 Q2를 답할 수 있다」** — 아니다. Q2는 시점을 못 되돌린다.
- **「Q3은 엣지가 남아 있으면 답할 수 있다」** — 아니다. `Cur` 스키마에 `actor`가 없어서, 엣지가 살아 있어도 못 답한다.
- **「이벤트 로그면 다 해결된다」** — 아니다. 이벤트를 쌓는 것만으로는 아무것도 안 정해진다. *어떻게 접느냐*(리듀서)가 답을 정한다 → `ex4_reducer_conflict.py`.
