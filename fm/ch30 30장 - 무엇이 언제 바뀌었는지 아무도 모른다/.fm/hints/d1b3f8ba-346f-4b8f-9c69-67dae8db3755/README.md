# 현재 상태만 저장하면 답할 수 있는 질문은 「지금 뭐죠?」뿐이다

> **Q.** 현재 상태만 저장하면 답할 수 있는 질문은 무엇뿐인가?
>
> **A.** 「지금 뭐죠?」뿐이다. 감사, 사고 조사, 품질 지표는 전부 이력이 있어야 답할 수 있다.

## 한 줄 핵심

덮어쓰기(update/delete)는 새 값을 쓰는 동시에 **옛 답을 지운다**. 지워진 답은 나중에 복원되지 않는다. 그래서 현재 상태만 가진 시스템은 시제가 「현재」인 질문 하나에만 대답할 수 있다.

## 왜 그런가 — 덮어쓰기는 파괴적 연산이다

관계형 테이블이든 그래프 DB든, 기본 쓰기 모델은 «제자리 갱신(in-place update)»이다.

```
UPDATE team SET lead = '이서연' WHERE name = '결제팀'
```

이 한 줄이 끝나면 저장소에는 `이서연` 하나만 남는다. 남지 않는 것이 네 가지다.

| 사라지는 것 | 그래서 못 하는 질문 |
|---|---|
| 이전 값 | 「전에는 누구였나」 |
| 바뀐 시각 | 「언제 바뀌었나」 |
| 바꾼 주체(actor) | 「누가 바꿨나」 |
| 변경 이유·연산 종류 | 「왜, 어떤 조작으로 바뀌었나」 |

현재 상태는 **결과**만 담는 자료구조다. 결과에는 과정이 들어갈 자리가 없다. 30장이 「이거 원래 이랬나요?」라는 한 문장으로 장을 여는 이유가 여기 있다.

## 30.1 예제로 보는 대비 — `ex1_no_history.py`

같은 변경 6건을 **덮어쓰기**와 **이벤트 쌓기** 두 방식으로 기록하고, 네 가지 질문을 던지는 예제다.

변경 이력(actor 포함):

```
2026-03-02  박민수 -이끔-> 결제팀  추가  (hr-sync)
2026-04-01  박민수 -이끔-> 결제팀  삭제  (hr-sync)
2026-04-01  이서연 -이끔-> 결제팀  추가  (hr-sync)
2026-04-14  이서연 -이끔-> 정산팀  추가  (agent-4821)   ← 에이전트가 넣음
2026-04-15  이서연 -이끔-> 정산팀  삭제  (admin:kim)    ← 사람이 되돌림
2026-05-20  이서연 -삶--> 마포     추가  (user-utterance)
```

결과 대비표:

| | 질문 | 현재 상태만 | 이벤트 로그 |
|---|---|---|---|
| **Q1** | 지금 결제팀 팀장은? | **이서연** ✅ | 이서연 |
| Q2 | 3월 15일에는 팀장이 누구였나? | 답 못 함 ❌ | 박민수 |
| Q3 | 「이서연 -이끔-> 정산팀」은 누가 넣고 누가 지웠나? | 답 못 함 ❌ | 추가 agent-4821 / 삭제 admin:kim |
| Q4 | 에이전트가 넣은 것 중 사람이 되돌린 게 몇 건인가? | 답 못 함 ❌ | 1건 |

**답할 수 있는 칸이 Q1 하나뿐**이라는 것이 이 카드의 답 그대로다. 그리고 Q1은 「지금 뭐죠?」라는 한 가지 질문 유형이다.

Q2에서 중요한 건 지금 팀장이 이서연인데 3월에는 박민수였다는 점이다. 현재 상태를 아무리 잘 봐도 3월의 답은 나오지 않는다. 이벤트를 그 시점까지 **재생(replay)** 하면 그때 상태가 그대로 복원된다.

```python
st = set()
for at, s, k, o, op in events_up_to("2026-03-15"):
    if op == "추가":
        st.add((s, k, o))
    else:
        st.discard((s, k, o))
```

## 답할 수 없게 되는 세 부류 — 답에 나오는 「감사·사고 조사·품질 지표」

카드 답의 뒷문장은 장식이 아니라, 운영에서 실제로 자주 나오는 질문 세 부류를 짚은 것이다. 위 표의 Q2·Q3·Q4에 각각 대응한다.

### 1. 감사(audit) — Q2 「그때는 어땠나」

규제·계약·분쟁 대응에서 반드시 나오는 질문이다. "작년 4분기 시점에 이 데이터에 접근 권한을 가진 사람은 누구였나", "정책 변경 전에는 어떤 값이 적용되고 있었나". 시점을 지정한 질문(as-of query)은 정의상 과거 상태를 요구하므로, 과거를 지운 저장소로는 원리적으로 답이 불가능하다. NIST SP 800-53의 감사 추적(audit trail) 통제가 요구하는 것도 바로 이 「시점 재구성 능력」이다.

### 2. 사고 조사(incident forensics) — Q3 「누가 넣었나」

장애나 데이터 오염이 터졌을 때 **첫 질문**은 언제나 "누가, 언제, 무엇을 바꿨나"다. 현재 상태에는 actor 필드가 없다. 있다 해도 `last_modified_by` 같은 «마지막 한 명»뿐이라, 중간에 거쳐 간 사람들은 사라진다. 이벤트 로그는 각 변경마다 actor를 붙여 두므로 「추가 agent-4821 → 삭제 admin:kim」 같은 궤적 전체가 남는다.

### 3. 품질 지표(quality metrics) — Q4 「되돌려진 비율」

이 책 28장의 에이전트 품질 지표가 여기서 다시 나온다. **「에이전트가 넣은 것 중 사람이 되돌린 비율」** 은 에이전트 출력 품질을 사람의 실제 행동으로 재는 강력한 지표다. 그런데 이 지표는 계산하려면 두 가지가 모두 필요하다.

- 추가한 주체가 에이전트였다는 사실 (actor)
- 그 뒤 사람이 같은 항목을 삭제했다는 사실 (순서가 있는 이력)

현재 상태에는 둘 다 없다. 최종 상태에서 "이 엣지가 없다"는 것만 보이고, **애초에 존재한 적이 있었는지조차** 알 수 없다. 지표 자체가 계산 불가능해진다.

## 이 답에서 곧바로 이어지는 것 — 「기록도 남긴다」가 아니라 「기록이 곧 쓰기다」

여기서 흔히 나오는 반사적인 해법이 「로그를 잘 남기자」다. 30장은 이걸 명시적으로 기각한다.

> 로그는 빠뜨려도 아무 일이 안 생기거든요.

로그가 **부차적인 부산물**이면 언젠가 누락된다. 급한 핫픽스에서 로그 코드가 빠지고, 새로 들어온 경로가 로그를 안 부르고, 그래도 시스템은 잘 돌아간다. 그래서 방향을 뒤집어야 한다.

- ❌ 상태를 쓰고 + 로그도 남긴다 → 로그가 빠져도 동작하므로 반드시 갈라진다
- ✅ **이벤트가 원본이고 상태는 파생이다** → 이벤트를 안 쓰면 상태 자체가 안 생기므로 누락이 불가능하다

이것이 이벤트 소싱(event sourcing)의 핵심이고, DB가 30년째 쓰는 쓰기 전 로그(WAL) + 체크포인트 구조와 같은 구조다. 조회용 뷰는 언제든 다시 만들 수 있어야 하고, 진짜 되는지는 **실제로 지우고 재생해 봐야** 안다.

## 시험에 잘 나오는 대비

| | 현재 상태 저장 | 이벤트 로그 저장 |
|---|---|---|
| 쓰기 모델 | 제자리 갱신(덮어쓰기) | 추가 전용(append-only) |
| 답할 수 있는 질문 | 「지금 뭐죠?」 | 지금 + 그때 + 누가 + 왜 |
| 강한 영역 | 상태 조회 | 변화 추적 |
| 값(비용) | 저장 공간 적음, 조회 빠름 | 저장 공간, 재생 시간 |
| 과거 복원 | 불가 (답을 지웠으므로) | 재생으로 가능 |
| 진실의 원본 | 상태 자신 | 이벤트 (상태는 파생 뷰) |

## 자주 하는 오해

- **「감사 로그 테이블을 따로 두면 되지 않나」** — 그건 다시 「로그도 남긴다」다. 상태 쓰기와 로그 쓰기가 별개의 두 연산인 한, 둘은 언젠가 갈라진다. 방향을 뒤집어 이벤트를 원본으로 삼아야 한다.
- **「구간(유효기간) 엣지를 쓰면 이력이 다 남는 것 아닌가」** — 구간 엣지는 「그 시점에 무엇이 참이었나(상태)」에는 강하지만, 「누가 바꿨나」는 못 묻는다. 엣지에 actor 정보가 없기 때문이다. 그래서 실무에서는 이벤트 로그(원본) + 구간 엣지(파생 조회 뷰)를 **둘 다** 둔다.
- **「이벤트를 쌓으면 답이 정해지나」** — 아니다. 쌓는 것만으로는 아무것도 안 정해진다. **어떻게 접느냐(리듀서)** 가 실제 동작을 정하고, 그건 도메인 결정이다. 「마지막이 이긴다」를 기본으로 두면 에이전트가 사람을 덮는다.
- **「이벤트를 다 쌓으면 재생이 느려지지 않나」** — 재생 시간은 데이터 양이 아니라 **스냅숏 주기**로 정해진다. 주기는 복구 목표 시간에서 거꾸로 계산한다.
- **「그럼 다 이벤트에 넣자」** — 개인정보는 넣지 말아야 한다. 추가 전용 로그는 지울 수 없는 곳이고, 개인정보는 지워야 하는 것이다.

## 암기용 압축

> 현재 상태 = 결과만. 결과에는 시제가 하나뿐이다.
> **Q1만 답한다. Q2(감사)·Q3(조사)·Q4(지표)는 전부 이력을 요구한다.**
