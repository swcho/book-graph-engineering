# 저자의 기본 리듀서 — 「사람이 이긴다」

> **질문** — 저자가 기본으로 쓰는 리듀서와 그 이유는 무엇인가?
>
> **답** — 「사람이 이긴다」다. 출처 등급은 시스템이 정하는 값이라 에이전트가 올릴 수 없다.

---

## 한 줄로 잡는 감

리듀서를 고르는 기준은 「어느 게 더 그럴듯한가」가 아니라
**「이 값을 누가 쓸 수 있는가」**입니다.

- 확신도(confidence)는 **에이전트가 스스로 적어 넣는** 값입니다. → 올리면 이깁니다.
- 출처 등급(rank)은 **시스템이 붙이는** 값입니다. → 에이전트가 손댈 수 없습니다.

그래서 저자는 「사람이 이긴다」를 기본으로 씁니다.
정답이라서가 아니라, **조작할 수 없는 값을 판단 근거로 삼기 때문**입니다.

---

## 30장 안에서 이 문장이 놓인 자리

30장은 이렇게 진행됩니다.

| 절 | 주장 |
|---|---|
| 30.1 | 현재 상태만 두면 「지금 뭐죠?」밖에 못 답한다 |
| 30.2 | 이벤트가 원본이고 상태는 파생이다 |
| 30.3 | 그때 그래프를 되살리는 두 가지 길 (재생 / 구간 쿼리) |
| **30.4** | **어떻게 접느냐(리듀서)가 답을 정한다** |
| 30.5 | 로그가 감사 로그가 되려면 (해시 고리) |

30.1~30.3까지는 「이벤트를 쌓아라」였습니다.
30.4는 그 뒤에 붙는 반전입니다.

> 이벤트를 쌓는 것만으로는 아무것도 안 정해진다.
> **«어떻게 접을 것인가»**가 실제 동작을 정하고, 그건 도메인 결정이다.

같은 이벤트 열을 넣어도 리듀서에 따라 답이 넷으로 갈립니다.
그러니 리듀서 선택은 「구현 디테일」이 아니라 **정책 결정**입니다.

---

## 네 리듀서를 한 이벤트 열에 돌려 보기

`ex4_reducer_conflict.py`의 입력은 이렇습니다.

```python
EVENTS = [
    ("2026-04-01T09:00", "hr-sync",    "선호", "채식", "추가", 0.95),
    ("2026-04-03T14:20", "agent-4821", "선호", "육식", "추가", 0.61),
    ("2026-04-03T14:21", "agent-4821", "선호", "채식", "삭제", 0.61),
    ("2026-04-09T10:05", "user",       "선호", "채식", "추가", 1.00),
    ("2026-04-22T16:40", "agent-5102", "선호", "비건", "추가", 0.78),
]
```

핵심 사건은 마지막 두 줄입니다.
**4월 9일에 사람이 「채식」이라고 명시**했는데, **4월 22일에 에이전트가 「비건」으로 바꿨습니다.**

| 리듀서 | 결과 | 무엇을 기준으로 접나 | 문제 |
|---|---|---|---|
| 마지막이 이긴다 | 비건 | 시각(최신) | 에이전트가 마지막에 쓰기만 하면 사람을 덮는다 |
| 확신도가 이긴다 | 채식 | conf 값 | 그 값을 **에이전트가 직접 적는다** |
| **사람이 이긴다** | **채식** | **출처 등급(rank)** | **등급을 시스템이 정한다 → 조작 불가** |
| 전부 모은다 | 비건 / 채식 | 안 접음 | 답이 여럿이라 조회하는 쪽이 곤란 |

「마지막이 이긴다」는 제일 흔하고 제일 위험합니다.
한 장 요약도 같은 말을 합니다.

> 「마지막이 이긴다」를 기본으로 두면 에이전트가 사람을 덮어요.

---

## 왜 확신도가 아니라 등급인가 — **쓰기 경로**로 보기

「확신도가 이긴다」도 이 예제에서는 **정답(채식)을 냅니다.**
사람 발화의 확신도가 1.00이라 자연히 이기니까요.
그런데 저자는 이걸 기본으로 쓰지 않습니다. 이유는 결과가 아니라 **누가 그 값을 쓰느냐**입니다.

```python
def highest_confidence(evs):
    ...
    if k not in best or conf > best[k][3]:   # ← conf 는 이벤트에 실려 온 값
```

`conf`는 **이벤트를 발생시킨 주체가 페이로드에 담아 보낸 숫자**입니다.
`agent-5102`가 0.78 대신 0.99를 적어 보내면, 리듀서는 그대로 믿고 사람을 덮습니다.
즉 **판정 기준을 피판정자가 쓰는 구조**입니다.

책의 문장이 이걸 20장과 연결합니다.

> 확신도는 에이전트가 «스스로 매기는» 값이다.
> 20장에서 본 「모델이 스스로 올릴 수 있는 값은 지표로 못 쓴다」가 여기도 적용된다.

이제 「사람이 이긴다」의 쓰기 경로를 보세요.

```python
def human_wins(evs):
    st = {}
    rank = {"user": 3, "hr-sync": 2}          # ← 리듀서 안에 박힌 표
    for at, who, k, v, op, conf in evs:
        r = rank.get(who, 1)                  # ← who 로 조회. 이벤트가 r 을 못 실어 보낸다
        ...
```

차이가 여기 있습니다.

| | 확신도(conf) | 출처 등급(rank) |
|---|---|---|
| 값의 출처 | **이벤트 페이로드** | **리듀서/시스템 설정** |
| 쓰는 주체 | 이벤트를 만든 에이전트 | 시스템 운영자 |
| 에이전트가 올릴 수 있나 | **있다** (숫자를 크게 적으면 됨) | **없다** |
| 에이전트가 할 수 있는 최선 | conf=1.00 선언 | 자기 `who`를 바꿔치기(= 신원 위조, 별개 문제) |

`conf`는 **이벤트에 실려 들어오는 입력**이고, `rank`는 **이벤트 바깥에서 조회되는 상수표**입니다.
에이전트는 자기 이벤트의 내용은 마음대로 쓸 수 있지만, `rank` 표에는 쓰기 권한이 없습니다.
그래서 등급은 **조작 불가능한 판단 근거**가 됩니다.

한 마디로: **판단 기준은 판단 대상이 쓸 수 없는 곳에 두어야 한다.**

---

## `human_wins`가 실제로 하는 일

```python
    for at, who, k, v, op, conf in evs:
        r = rank.get(who, 1)
        if op == "삭제":
            if k in st and st[k][3] <= r:     # 내 등급이 기존 값 등급 이상일 때만 지운다
                st.pop(k)
            continue
        if k not in st or r >= st[k][3]:      # 같거나 높은 등급만 덮는다
            st[k] = (v, at, who, r)
```

- 등급 기본값은 1(에이전트), `hr-sync`는 2, `user`는 3입니다.
- **낮은 등급은 높은 등급을 덮지도, 지우지도 못합니다.**
- 같은 등급끼리는 `>=`라서 나중 것이 이깁니다 — 즉 **같은 등급 안에서만 「마지막이 이긴다」**로 동작합니다.

그래서 4월 22일 `agent-5102`(등급 1)의 「비건」은 4월 9일 `user`(등급 3)의 「채식」을 못 덮습니다.

---

## 한계 — 이게 정답 리듀서라는 뜻은 아니다

저자는 이걸 **기본값**이라고 했지 **정답**이라고 하지 않았습니다. 실제로 약점이 있습니다.

### 1. 사람도 틀린다

등급이 보장하는 건 「조작되지 않았다」이지 「옳다」가 아닙니다.
사람이 오타를 내거나, 잘못 알고 입력하거나, 예전 사정으로 입력해도 등급 3은 그대로 3입니다.
`human_wins`는 그 값을 최우선으로 지켜 줍니다 — **틀린 값이라도요.**

### 2. 오래된 사람 값이 최신 에이전트 값을 계속 막는다

이게 더 실무적인 문제입니다. 등급 비교에는 **시간이 안 들어갑니다.**

- 2026-04-09, 사람: 「선호 = 채식」 (등급 3)
- 2027-01-01, 에이전트: 「선호 = 비건」 (등급 1) — 사용자가 실제로 바뀌었더라도

리듀서는 **여전히 「채식」을 유지합니다.** 1년이 지나도, 10년이 지나도요.
`hr-sync` 같은 신뢰 가능한 시스템 출처(등급 2)조차 한번 박힌 사람 값을 못 갱신합니다.
`ex1_no_history.py`의 「박민수 → 이서연 팀장 교체」 같은 **정당한 최신 변경이 막히는** 상황이 여기서 나옵니다.

즉 **「사람이 이긴다」는 신선도(freshness)를 등급과 맞바꾼 리듀서**입니다.
사람 값을 신주단지처럼 모시는 대신, 세상이 바뀌어도 안 따라갑니다.

### 3. 그래서 실무에서는 보통 섞는다

- 등급 + **유효기간**: 사람 값에도 만료를 두어, 오래되면 등급을 낮춘다.
- 등급 + **재확인 요청**: 낮은 등급이 높은 등급과 충돌하면 덮지 말고 사람에게 되묻는다.
- 등급 + **「전부 모은다」**: 충돌 사실 자체를 남기고, 조회 쪽에서 어느 걸 쓸지 정한다.
  (책도 「충돌이 있다는 사실 자체가 중요한 도메인에서는 이게 맞다」고 짚습니다.)

## 시험에 나올 문장으로 압축하면

- **기본 리듀서**: 「사람이 이긴다」(`human_wins`) — 출처에 등급을 매겨 접는다.
- **이유**: 확신도는 에이전트가 스스로 올릴 수 있지만, **등급은 시스템이 정하는 값이라 에이전트가 못 올린다.**
- **원리**: 판단 기준은 **판단 대상이 쓸 수 없는 경로**에 두어야 한다. (20장의 재등장)
- **버리는 것**: 「마지막이 이긴다」 — 흔하지만 에이전트가 사람을 덮는다.
- **대가**: 사람도 틀릴 수 있고, 오래된 사람 값이 최신 에이전트 값을 영원히 막는다.
- **큰 그림**: 이벤트를 쌓는 것만으로는 아무것도 안 정해진다. **어떻게 접느냐가 도메인 결정이다.**
