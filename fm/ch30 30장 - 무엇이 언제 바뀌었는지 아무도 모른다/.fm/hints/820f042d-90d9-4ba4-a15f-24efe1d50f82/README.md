# 이벤트를 쌓는 것만으로 부족한 이유

> **Q.** 이벤트를 쌓는 것만으로 부족한 이유는 무엇인가?
>
> **A.** 어떻게 접을 것인가가 실제 동작을 정하고 그건 도메인 결정이다. 「마지막이 이긴다」를 기본으로 두면 에이전트가 사람을 덮는다.

출처: 30장 「무엇이 언제 바뀌었는지 아무도 모른다」 30.4절 / `code/ex4_reducer_conflict.py`

---

## 1. 한 줄로

**이벤트 로그는 「재료」일 뿐, 「답」이 아니다.** 같은 이벤트 열을 놓고도 어떻게 접느냐(reduce)에 따라 시스템이 내놓는 현재 상태가 완전히 달라진다. 그러니 이벤트 저장소를 깔았다고 해서 무엇이 정해진 게 아니다. 정해야 할 것은 아직 하나도 안 정해졌다.

## 2. 왜 「쌓기」만으로는 부족한가

30장의 앞부분(30.1~30.3)은 이벤트 소싱의 **좋은 점**을 쌓아 올린다.

- 현재 상태만 두면 「지금 뭐죠?」밖에 못 답한다 (`ex1`)
- 이벤트를 쌓으면 「3월 15일엔 누가 팀장이었나」, 「누가 넣고 누가 지웠나」, 「에이전트가 넣은 것 중 사람이 되돌린 게 몇 건인가」에 답할 수 있다
- 재생 값은 스냅숏으로 상한을 건다 (`ex2`)
- 이벤트가 원본, 조회용 뷰는 파생이다 (`ex3`)

여기까지만 읽으면 「이벤트 로그를 도입하면 끝」처럼 보인다. 30.4절은 그 착각을 깬다.

이벤트 로그는 **일어난 일의 목록**이다. 그런데 애플리케이션이 실제로 쓰는 건 「지금 이 사람의 선호는 무엇인가」 같은 **단일 값**이다. 목록에서 단일 값으로 가려면 반드시 접는 함수 — 리듀서(reducer) — 를 통과해야 한다. 그리고 그 리듀서는 이벤트 로그 안에 들어 있지 않다. **로그 밖에서, 사람이, 도메인을 보고 정하는 것이다.**

> 19장에서 상태 그래프를 접던 리듀서가, 여기서는 「이력 접기」로 다시 나온다.

## 3. 예제로 보기 — 같은 이벤트, 네 개의 답

`ex4_reducer_conflict.py`는 사람과 에이전트가 번갈아 「선호」를 고친 이벤트 5건을 준비한다.

| 시각 | 행위자 | 내용 | op | 확신도 |
|---|---|---|---|---|
| 2026-04-01T09:00 | `hr-sync` | 선호 = 채식 | 추가 | 0.95 |
| 2026-04-03T14:20 | `agent-4821` | 선호 = 육식 | 추가 | 0.61 |
| 2026-04-03T14:21 | `agent-4821` | 선호 = 채식 | 삭제 | 0.61 |
| 2026-04-09T10:05 | `user` | 선호 = 채식 | 추가 | **1.00** |
| 2026-04-22T16:40 | `agent-5102` | 선호 = 비건 | 추가 | 0.78 |

여기에 리듀서 넷을 각각 적용하면:

| 리듀서 | 결과 | 채택된 출처 | 시각 |
|---|---|---|---|
| 마지막이 이긴다 (last-write-wins) | 선호 = **비건** | `agent-5102` | 04-22T16:40 |
| 확신도가 이긴다 (highest-confidence) | 선호 = **채식** | `user` | 04-09T10:05 |
| 사람이 이긴다 (source-rank) | 선호 = **채식** | `user` | 04-09T10:05 |
| 전부 모은다 (accumulate) | 선호 = **비건 / 육식 / 채식** | — | — |

**같은 이벤트 열인데 답이 넷이다.** 로그는 하나도 안 바뀌었다. 바뀐 건 접는 방법뿐이다. 이 한 장의 표가 카드의 답 그 자체다.

## 4. 「마지막이 이긴다」가 왜 위험한가

`last_write_wins`는 제일 흔한 기본값이다. 코드도 가장 짧다.

```python
def last_write_wins(evs):
    st = {}
    for at, who, k, v, op, conf in evs:
        if op == "추가":
            st[k] = (v, at, who)
        else:
            st.pop(k, None)
    return st
```

이 함수에는 **행위자(`who`)가 결과에 아무 영향을 주지 않는다.** 오직 시간 순서만 본다. 그래서 이런 일이 벌어진다.

- 4월 9일, **사람이 직접** 「나는 채식입니다」라고 말했다 (확신도 1.00)
- 4월 22일, `agent-5102`가 대화 로그를 보고 「비건인 것 같은데」 하고 0.78짜리 추정을 써 넣었다
- 결과: **비건**. 사람의 명시적 발화가 에이전트의 추정에 조용히 덮였다

에이전트는 사람보다 **훨씬 자주, 훨씬 늦게까지** 쓴다. 배치가 밤에 돌고, 크롤러가 새벽에 돌고, 추론 파이프라인이 매시간 돈다. 「마지막이 이긴다」를 기본으로 두는 순간, 시간이 지날수록 사람이 넣은 값은 구조적으로 밀려난다. 사용자 입장에서는 「고쳤는데 왜 자꾸 원래대로 돌아가죠?」가 된다. 심지어 사고 조사도 어렵다. 로그에는 다 남아 있지만, 시스템이 보여 주는 값은 늘 마지막 것이니까.

## 5. 나머지 세 리듀서의 성격

### 확신도가 이긴다 — 그럴듯하지만 함정이 있다

사람 발화(1.00)를 존중하니 이 예제에서는 옳은 답이 나온다. 그런데 **확신도는 에이전트가 스스로 매기는 값**이다. 20장의 「모델이 스스로 올릴 수 있는 값은 지표로 못 쓴다」가 그대로 적용된다. 에이전트가 자기 확신도를 0.99로 적어 내면 그날로 이 리듀서는 무너진다. 조작할 필요도 없고, 프롬프트 한 줄만 바뀌어도 분포가 흔들린다.

### 사람이 이긴다 — 책이 추천하는 기본값

출처에 **등급**을 매긴다. `user` 3점, `hr-sync` 2점, 나머지(에이전트) 1점. 등급이 같거나 높은 쪽만 덮어쓸 수 있고, 삭제도 같은 규칙을 따른다.

```python
rank = {"user": 3, "hr-sync": 2}
...
if k not in st or r >= st[k][3]:
    st[k] = (v, at, who, r)
```

핵심은 **등급을 시스템이 정한다**는 것이다. 확신도와 달리 에이전트가 자기 등급을 올릴 수 없다. 통제권이 로그를 쓰는 쪽이 아니라 로그를 접는 쪽에 있다.

### 전부 모은다 — 충돌을 숨기지 않는다

지우지 않고 집합으로 모아, 답이 여럿이면 여럿으로 남긴다. 조회하는 쪽이 곤란해지는 대신 「충돌이 있다」는 사실 자체가 소실되지 않는다. 의료 기록, 법적 분쟁 자료처럼 **불일치의 존재가 정보인 도메인**에서는 이게 맞다.

## 6. 「그건 도메인 결정이다」의 뜻

리듀서 선택에 **기술적 정답이 없다**는 말이다. 네 리듀서 모두 코드로는 멀쩡하고, 어느 것도 버그가 아니다. 무엇이 맞는지는 도메인이 정한다.

| 도메인 | 어울리는 리듀서 | 이유 |
|---|---|---|
| 센서/텔레메트리 | 마지막이 이긴다 | 최신값이 곧 진실. 덮어써도 잃는 게 없다 |
| 사용자 프로필/선호 | 사람이 이긴다 | 본인 명시가 추론을 이겨야 한다 |
| 지식 그래프 추출 | 확신도 + 출처 등급 | 다만 확신도는 시스템이 보정한 값이어야 |
| 의료·법률 기록 | 전부 모은다 | 불일치 자체를 남겨야 한다 |

그래서 이 결정은 인프라 팀이 「이벤트 스토어 깔았습니다」로 끝낼 수 없다. **도메인을 아는 사람이 명시적으로 정하고 문서로 남겨야 한다.** 정하지 않으면 기본값(대개 last-write-wins)이 자동으로 정책이 되고, 그건 「아무도 안 정했는데 사람이 에이전트에게 지는 시스템」이 된다.

## 7. 함께 묶어 볼 것

- **19장 리듀서** — 상태 그래프를 접던 그 리듀서가 여기서 이력 접기로 재등장
- **20장 확신도** — 모델이 스스로 올릴 수 있는 값은 지표로 못 쓴다
- **28장 품질 지표** — 「에이전트가 넣은 것 중 되돌려진 비율」은 이벤트 로그가 있어야 잴 수 있다
- **31장(다음 장)** — 이 장은 이벤트가 순서대로 온다고 가정했다. 두 에이전트가 **동시에** 고치면 그 순서조차 없어진다

## 8. 자주 하는 오해

- **「이벤트 소싱을 도입했으니 이력 문제는 해결됐다」** → 이력은 남았지만 현재 상태가 무엇인지는 여전히 안 정해졌다.
- **「리듀서는 구현 디테일이라 나중에 바꾸면 된다」** → 리듀서를 바꾸면 과거 전체의 해석이 바뀐다. 재생 결과가 통째로 달라진다는 뜻이다.
- **「타임스탬프가 있으니 순서는 객관적이다」** → 순서는 객관적일지 몰라도 **누가 이겨야 하는가**는 순서가 답해 주지 않는다. 그게 도메인 결정인 이유다.
