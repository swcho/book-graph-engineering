# `ex2_direction.py`는 같은 조직도를 어떻게 두 벌로 저장하는가?

## 정답

**`MANAGES`(상사 → 부하)와, 그것을 그대로 뒤집은 `REPORTS_TO`(부하 → 상사)** 두 벌로 저장한다.
같은 사실을 담고 있지만 화살표 방향만 반대인 두 엣지 목록이다.

## 코드에서 보기

```python
# 같은 조직도를 두 방향으로 저장한다.
MANAGES = [("김부장", "박대리"), ("김부장", "이주임"), ("최이사", "김부장")]
REPORTS_TO = [(b, a) for a, b in MANAGES]
```

- `MANAGES`는 `(상사, 부하)` 순서의 튜플 목록이다. 김부장이 박대리와 이주임을 관리하고, 최이사가 김부장을 관리한다.
- `REPORTS_TO`는 새로 손으로 적은 게 아니라 **리스트 컴프리헨션으로 `MANAGES`의 각 튜플 `(a, b)`를 `(b, a)`로 뒤집어** 만든 것이다. 즉 `[("박대리", "김부장"), ("이주임", "김부장"), ("김부장", "최이사")]`가 된다.
- 그래서 두 자료구조는 **정보량이 완전히 동일**하다. 엣지 개수도 3개로 같다. 달라지는 건 "무엇이 출발점(source)이냐" 하나뿐이다.

이게 이 예제의 핵심 장치다. 정보가 같은 두 저장 방식을 나란히 놓고, 똑같은 질문을 던졌을 때 **조회 비용만 달라지는 것**을 보여주려는 것이다.

## 왜 두 벌로 만들어 비교하는가

예제는 "나가는 엣지(out-edge) 색인"만 만든다.

```python
def out_index(edges):
    idx = defaultdict(list)
    for a, b in edges:
        idx[a].append(b)   # 출발점 → 도착점들
    return idx
```

이 색인은 **출발점으로만 찾을 수 있다.** 그래서 질문과 방향이 맞으면 한 번에 답이 나오고, 어긋나면 전체를 훑어야 한다.

| 질문 | `MANAGES`(상사→부하) | `REPORTS_TO`(부하→상사) |
|---|---|---|
| 박대리의 상사는? | 도착점으로 찾아야 함 → 전체 훑기(비용 3) | 나가는 엣지 1번(비용 1) |
| 김부장의 부하는? | 나가는 엣지 1번(비용 1) | 도착점으로 찾아야 함 → 전체 훑기(비용 3) |

`ask_boss()`와 `ask_reports()`가 하는 일이 정확히 이것이다. `label`을 보고 자기 질문에 유리한 방향이면 `idx.get(name, [])`으로 즉시 답하며 비용 `1`을 반환하고, 불리한 방향이면 `for a, b in edges:` 루프로 전체를 스캔하며 훑은 개수를 비용으로 반환한다.

엣지 3개짜리 장난감이라 3 대 1 차이지만, 엣지가 100만 개면 100만 대 1이 된다.

## 이 예제가 말하려는 교훈

예제 마지막 출력이 결론을 정리한다.

1. **자주 묻는 질문을 「나가는」 방향으로 둔다.** 조직도에서 "내 상사 누구야?"를 훨씬 자주 묻는다면 `REPORTS_TO`가 맞는 방향이다.
2. **카디널리티는 「1 쪽」에서 「N 쪽」으로.** 부하는 여럿이고 상사는 하나이므로 이 기준만 보면 `MANAGES`(1 → N)가 자연스럽다.
3. **둘이 충돌하면 1번을 따른다.** 성능은 모델의 미학이 아니라 실제로 날아오는 질의가 정한다.

그리고 중요한 단서: **엔진이 역방향 색인을 자동으로 만들어 주면 이 차이는 사라진다.** Neo4j는 양방향 탐색 비용이 대칭이므로 방향을 어느 쪽으로 잡아도 성능 차이가 거의 없다. 하지만 모든 엔진이 그렇지는 않다. 이 예제의 `out_index()`처럼 한쪽 색인만 있는 저장소(직접 만든 인접 리스트, 일부 임베디드 그래프, RDB의 단방향 인덱스 등)에서는 방향 선택이 그대로 성능이 된다.

## 헷갈리기 쉬운 점

- **"두 벌로 저장한다"는 게 권장 사항이 아니다.** 실무에서 `MANAGES`와 `REPORTS_TO`를 둘 다 실제로 저장하면 갱신할 때 두 곳을 동시에 맞춰야 하고, 한쪽만 바뀌면 조직도가 자기 자신과 모순된다. 예제가 두 벌을 만든 건 **비교 실험용**이고, 결론은 "한 방향을 골라라, 자주 묻는 쪽으로"다.
- **방향은 사실의 성질이 아니라 질의의 성질이다.** "김부장이 박대리의 상사다"라는 사실 자체에는 방향이 없다. 방향은 우리가 그 사실을 어떻게 찾아 들어갈지에 대한 선택이다.
- 관계 타입 이름을 뒤집을 때 이름도 같이 뒤집어야 읽힌다. `MANAGES`를 뒤집어 놓고 이름을 그대로 두면 `("박대리", "MANAGES", "김부장")`이 되어 반대 뜻이 된다. 그래서 `REPORTS_TO`라는 별개 이름을 쓴다.
