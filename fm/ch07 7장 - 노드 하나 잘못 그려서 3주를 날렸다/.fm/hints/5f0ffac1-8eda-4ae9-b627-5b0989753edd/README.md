# `degree_simple()`은 어떻게 같은 쌍을 하나로 세는가

> **질문** `degree_simple()`이 같은 쌍을 하나로 세는 구현 방법은 무엇인가?
>
> **답** `(min(a,b), max(a,b))` 정규형으로 set을 만들고, 자기 루프(`a == b`)는 아예 제외한 뒤 차수를 센다.

출처: 7장 `code/ex5_multigraph.py` — 「다중 엣지와 자기 루프. 세는 방식이 흔들리는 자리.」

---

## 1. 핵심 코드

```python
def degree_simple(edges):
    """단순 그래프로 보면: 같은 쌍은 하나로 센다."""
    pairs = {(min(a, b), max(a, b)) for a, b, _ in edges if a != b}
    deg = Counter()
    for a, b in pairs:
        deg[a] += 1
        deg[b] += 1
    return deg
```

한 줄에 세 가지 결정이 들어 있습니다.

| 코드 조각 | 하는 일 | 없으면 생기는 일 |
|---|---|---|
| `{ ... }` (set 컴프리헨션) | 중복 엣지를 접는다 | 같은 계약 3건이 차수 3으로 세어진다 |
| `(min(a, b), max(a, b))` | 무방향 쌍을 하나의 표기로 정규화 | `(A,B)`와 `(B,A)`가 서로 다른 원소로 남아 중복 제거 실패 |
| `if a != b` | 자기 루프 제거 | 자기 루프를 1로 셀지 2로 셀지 논쟁이 코드로 흘러든다 |
| `_` (세 번째 항목 무시) | 계약 번호를 버린다 | 계약 번호가 다르면 같은 쌍이 서로 다른 원소가 된다 |

## 2. 왜 `min`/`max`가 필요한가 — 파이썬 튜플은 순서를 기억한다

파이썬에서 튜플은 순서가 의미를 가지는 값입니다. 그래서 무방향 관계를 그대로 튜플에 담으면 같은 사실이 두 모양으로 존재합니다.

```python
>>> {("가온테크", "나루소프트"), ("나루소프트", "가온테크")}
{('가온테크', '나루소프트'), ('나루소프트', '가온테크')}   # 원소 2개! 안 접힌다
```

`min`/`max`를 씌우면 두 표기가 같은 값으로 수렴합니다. 이것이 **정규형(canonical form)** 입니다. 사전순으로 작은 쪽을 항상 앞에 두기로 규칙을 정하는 것이고, 규칙이 무엇이든 일관되기만 하면 됩니다.

```python
>>> (min("나루소프트", "가온테크"), max("나루소프트", "가온테크"))
('가온테크', '나루소프트')
>>> (min("가온테크", "나루소프트"), max("가온테크", "나루소프트"))
('가온테크', '나루소프트')   # 어느 방향으로 들어와도 같은 모양
```

`sorted()`는 리스트를 돌려주는데 리스트는 해시 불가라 set에 넣을 수 없습니다. 그래서 `tuple(sorted((a, b)))`처럼 다시 튜플로 감싸거나, 이 예제처럼 `min`/`max` 두 번을 쓰는 편이 짧습니다.

**대안 — `frozenset`**

```python
pairs = {frozenset((a, b)) for a, b, _ in edges if a != b}
for pair in pairs:
    for node in pair:
        deg[node] += 1
```

`frozenset`은 애초에 순서 개념이 없어서 정규화가 공짜입니다. 대신 「두 개짜리」임이 타입으로 보장되지 않고, 원소를 꺼낼 때 `a, b = pair` 같은 언패킹이 자기 루프에서 깨질 수 있습니다. 노드 ID가 서로 비교 가능한 동종 타입(문자열끼리, 정수끼리)이면 `min`/`max`가 더 안전하고 읽기 쉽습니다. 반대로 노드 ID 타입이 섞여 있어 `min`이 `TypeError`를 내는 상황이면 `frozenset`이 낫습니다.

## 3. 왜 자기 루프를 「아예」 제외하는가

자기 루프 `(라온에너지, 라온에너지)`의 차수를 얼마로 볼지에 정답이 없습니다.

- **2로 센다**: 엣지의 양쪽 끝이 모두 그 노드에 붙어 있으므로. 「모든 차수의 합 = 엣지 수 × 2」라는 악수 정리(handshaking lemma)가 유지됩니다. NetworkX의 `Graph.degree`, 대부분의 그래프 이론 교과서가 이 관례입니다.
- **1로 센다**: 「이어진 이웃의 수」로 세는 구현. 인접 리스트를 순회하며 이웃을 세는 코드가 자연스럽게 이렇게 됩니다.

같은 이름의 함수가 라이브러리마다 다르게 셀 수 있다는 뜻입니다. 예제 마지막 문단이 이 점을 지적합니다.

> 자기 루프도 함정이다. 알고리즘마다 1로 세기도 하고 2로 세기도 한다.
> 라이브러리를 바꾸면 숫자가 조용히 달라진다. 미리 걸러 두는 편이 낫다.

그래서 `degree_simple()`은 논쟁을 회피하는 쪽을 택합니다. 자기 루프는 「거래처」라는 질문에 대한 답이 아니므로 세기 전에 버립니다. 반대로 `degree_multi()`는 엣지 건수를 세는 함수라서 자기 루프를 남기고 관례대로 2를 더합니다.

```python
def degree_multi(edges):
    """다중 그래프로 보면: 엣지마다 센다. 자기 루프는 2로 센다(관례)."""
    deg = Counter()
    for a, b, _ in edges:
        if a == b:
            deg[a] += 2
        else:
            deg[a] += 1
            deg[b] += 1
    return deg
```

## 4. 예제 데이터로 따라가 보기

```python
EDGES = [
    ("가온테크",   "나루소프트", "C-2023-011"),
    ("가온테크",   "나루소프트", "C-2024-088"),
    ("가온테크",   "나루소프트", "C-2025-118"),
    ("가온테크",   "다올물산",   "C-2025-200"),
    ("라온에너지", "라온에너지", "C-2025-301"),   # 자기 루프
]
```

**1단계 — 자기 루프 걸러내기(`if a != b`)**: 마지막 줄 탈락. 4건 남음.

**2단계 — 정규형으로 바꾸기**: `(가온테크, 나루소프트)` × 3, `(가온테크, 다올물산)` × 1.

**3단계 — set이 중복을 접기**:

```python
{('가온테크', '나루소프트'), ('가온테크', '다올물산')}   # 2개
```

**4단계 — 쌍마다 양쪽 노드에 +1**:

| 노드 | 단순 그래프 차수 | 다중 그래프 차수 |
|---|---:|---:|
| 가온테크 | 2 | 4 |
| 나루소프트 | 1 | 3 |
| 다올물산 | 1 | 1 |
| 라온에너지 | (키 없음 → 0) | 2 |

`가온테크`가 2냐 4냐. **둘 다 맞습니다.** 무엇을 세는지가 다를 뿐입니다.

- 거래처 수를 알고 싶으면 → 단순 그래프 (2곳)
- 거래 건수를 알고 싶으면 → 다중 그래프 (4건)

## 5. 놓치기 쉬운 세부 — 사라진 노드

`degree_simple()`이 돌려준 `Counter`에는 `라온에너지` 키가 **아예 없습니다.** 자기 루프가 그 노드가 등장하는 유일한 엣지였기 때문입니다. 그래서 `main()`이 이렇게 씁니다.

```python
for n in sorted(set(ds) | set(dm)):          # 두 결과의 노드 합집합으로 순회
    print(f"{n:<12} {ds.get(n,0):>16} {dm.get(n,0):>16}")   # 없으면 0
```

`Counter[key]`는 없는 키에 0을 돌려주지만 그 순간 키를 만들지는 않고, 반복에서는 여전히 빠집니다. 「차수 0인 노드」를 보고서에 실어야 한다면 노드 목록을 엣지에서 유도하지 말고 별도로 관리해야 합니다. 자기 루프를 거른 대가입니다.

## 6. 이게 왜 사고로 이어지는가

예제가 경고하는 진짜 위험은 두 함수의 존재가 아니라 **섞어 쓰는 것**입니다.

> 사고는 이 둘을 섞을 때 난다. 중심성을 다중 그래프로 계산해 놓고
> 「거래처가 많은 회사」라고 보고하면 틀린다. 계약을 여러 번 한 회사가 1등이 된다.

한 거래처와 계약을 200번 한 회사가, 200개 거래처와 각 1번 계약한 회사와 같은 차수를 갖습니다. 「허브」를 찾는 질문에 다중 그래프 차수를 쓰면 그냥 계약이 잦은 회사가 1등이 됩니다. 이 장의 요약이 말하는 지점이 이것입니다.

> 다중 엣지와 자기 루프는 세는 방식이 흔들리니, **무엇을 세는지 먼저 정하세요.**

함수 이름에 `simple` / `multi`를 박아 넣은 것도 7.3절의 교훈과 같은 처방입니다. `weight` 대신 `cost_minutes`를 쓰는 것처럼, `degree` 대신 세는 방식을 이름에 드러냅니다.

## 7. NetworkX와 대조

| 이 예제 | NetworkX 대응 |
|---|---|
| `degree_simple()` | `nx.Graph` — 같은 쌍을 다시 `add_edge`하면 속성만 갱신되고 엣지는 하나 |
| `degree_multi()` | `nx.MultiGraph` — 같은 쌍마다 key가 붙어 여러 엣지로 남음 |
| `if a != b`로 루프 제거 | `G.remove_edges_from(nx.selfloop_edges(G))` |

다만 NetworkX의 `Graph.degree`는 자기 루프를 **2로** 셉니다. 즉 `nx.Graph`로 옮겨 담기만 하면 `degree_simple()`과 값이 어긋납니다(`라온에너지`가 0이 아니라 2). 「미리 걸러 두는 편이 낫다」는 조언이 그래서 실무적입니다. 계산 파이프라인 입구에서 자기 루프를 명시적으로 제거해 두면, 아래에 어떤 라이브러리를 끼워도 숫자가 조용히 바뀌지 않습니다.

- `nx.MultiGraph`: https://networkx.org/documentation/stable/reference/classes/multigraph.html

## 8. 한 줄 정리

무방향 중복 제거는 **표기를 하나로 정하는 문제**(`min`/`max` 정규형)이고, 자기 루프는 **셈법을 하나로 정하는 문제**(그래서 논쟁 전에 제외)입니다. 둘 다 「무엇을 세는지 먼저 정한다」는 같은 원칙의 두 얼굴입니다.
