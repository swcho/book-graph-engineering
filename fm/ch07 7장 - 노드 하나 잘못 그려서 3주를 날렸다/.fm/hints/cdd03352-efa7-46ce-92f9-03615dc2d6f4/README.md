# 힌트 — 투영을 자르는 기준: 「엣지 수 ≤ 노드 수 × 20」

## 질문

저자가 투영을 자를 때 쓰는 기준은 무엇인가?

## 답

**엣지 수가 노드 수의 20배를 넘지 않게** 임계값을 잡는다.
즉 «함께 산 사람 N명 이상»의 N을 고정값으로 박지 않고, 투영 결과의 밀도를 보고 N을 역산한다.

---

## 1. 원문 위치

7장 예제 4(`code/ex4_bipartite.py`)의 마지막 출력이다.

```
대안 두 가지.
  1. 투영하지 말고 이분 그래프 그대로 2홉을 돈다. 필요할 때만 계산한다.
  2. 투영하되 «함께 산 사람 N명 이상»으로 자른다. 대개 3명이면 충분하다.
저는 2번을 쓰고, 자르는 값은 엣지 수가 노드 수의 20배를 넘지 않게 잡는다.
```

여기서 **두 숫자를 혼동하기 쉽다.**

| 숫자 | 정체 |
|---|---|
| 3명 | 경험적으로 «대개» 통하는 출발점. 기준이 아니다 |
| 20배 | 저자가 실제로 쓰는 **판정 기준**. N을 정하는 근거 |

카드가 묻는 건 뒤쪽이다. 3은 후보값, 20배는 그 후보를 채택할지 결정하는 자(尺)다.

## 2. 왜 자를 필요가 생기는가 — 투영의 두 가지 대가

이분 그래프는 노드가 두 종류이고 엣지가 서로 다른 종류 사이에만 있는 그래프다.
예제의 원본은 사용자 3명 × 상품 3개, 엣지 6개다.

```python
PURCHASES = [
    ("u1", "상품A"), ("u1", "상품B"),
    ("u2", "상품A"), ("u2", "상품B"), ("u2", "상품C"),
    ("u3", "상품C"),
]
```

이걸 상품 쪽으로 «투영»하면 같은 사람을 공유하는 상품끼리 잇는다.

```
원본(이분)                    투영(상품끼리)
u1 ── 상품A                   상품A ── 상품B   (함께 산 사람 2명)
u1 ── 상품B                   상품A ── 상품C   (1명)
u2 ── 상품A                   상품B ── 상품C   (1명)
u2 ── 상품B
u2 ── 상품C
u3 ── 상품C
```

대가가 둘이다.

**(1) 정보가 사라진다.** 투영 그래프에는 `u1, u2, u3`이 없다. «상품A와 B는 가깝다»만 남고
«누가 샀는지»는 버려진다. 되돌릴 수 없다.

**(2) 엣지가 제곱으로 는다.** 상품 $k$개를 산 사용자 한 명은 그 상품들을 전부 서로 이으므로
$\binom{k}{2}$개의 엣지를 만든다. 예제의 `simulate()`가 그 상한이다.

```python
def simulate(n_users, items_per_user):
    return n_users * items_per_user * (items_per_user - 1) // 2
```

$$E_{\max}=n\cdot\binom{k}{2}=\frac{n\,k(k-1)}{2}$$

| 사용자 $n$ | 1인당 구매 $k$ | 투영 엣지(최대) |
|---:|---:|---:|
| 1,000 | 10 | 45,000 |
| 1,000 | 50 | 1,225,000 |
| 100,000 | 50 | 122,500,000 |
| 100,000 | 200 | 1,990,000,000 |

**핵심은 $k$가 제곱으로 들어간다는 것.** 사용자를 100배 늘리면 엣지도 100배지만,
1인당 구매를 4배(50→200) 늘리면 엣지는 약 16배가 된다. 사용자 10만 명이
1인당 200개를 사면 상한이 **20억 엣지**다. 중복이 합쳐지므로 실제로는 이보다 적지만,
«상한이 이렇다»는 게 설계 시점에 알아야 하는 사실이다.

그래서 그냥 투영하면 안 되고, 자르고 나서 써야 한다.

## 3. 자르는 방법 — 가중치 임계값

투영 엣지에는 자연스러운 가중치가 붙는다. **공유한 상대의 수**다. 예제 코드가 그걸 센다.

```python
out = defaultdict(int)
for val, keys in grouped.items():
    for x, y in combinations(sorted(keys), 2):
        out[(x, y)] += 1      # ← 이 카운트가 가중치
```

자르기는 이 가중치에 임계값 $\tau$를 걸어 «$w \ge \tau$인 엣지만 남긴다»는 뜻이다.

$$E_{\text{kept}}(\tau)=\bigl|\{(x,y): w_{xy}\ge \tau\}\bigr|$$

한 명만 공유한 엣지($w=1$)는 대개 우연이다. 베스트셀러를 각자 하나씩 산 사람 때문에
생긴 연결은 «함께 산다»는 신호가 아니다. 그래서 $\tau=2$ 또는 $3$이 출발점이 된다.
동시발생 행렬이 롱테일이라 $\tau$를 1에서 2, 3으로만 올려도 엣지가 한 자릿수 배로 줄어든다.

## 4. 그런데 왜 $\tau$를 고정하지 않는가

«대개 3명이면 충분하다»에 «대개»가 붙은 이유가 있다. $\tau$를 상수로 박으면 데이터에 따라
양쪽으로 다 실패한다.

| 상황 | $\tau=3$의 결과 |
|---|---|
| 인기 상품이 몰린 대형 커머스 | 베스트셀러 조합은 수만 명이 공유한다. 3으로는 거의 안 잘려서 여전히 폭발 |
| 니치 도메인·초기 서비스 | 대부분의 조합이 1~2명이다. 3으로 자르면 그래프가 텅 빈다 |

$\tau$는 **입력 쪽 손잡이**지 목표가 아니다. 목표는 «쓸 수 있는 크기의 그래프»이므로,
저자는 목표를 **출력 쪽 지표**로 정해 놓고 $\tau$를 거기에 맞춘다. 그 지표가 20배다.

$$\frac{E}{V}\le 20$$

## 5. 20배는 무슨 뜻인가 — 평균 차수 40

무향 그래프에서 차수의 합은 엣지 수의 두 배다(핸드셰이크 보조정리).

$$\sum_{v} \deg(v)=2E \quad\Rightarrow\quad \bar{d}=\frac{2E}{V}$$

따라서 $E/V \le 20$은 **평균 차수 40 이하**와 같은 말이다.

| 투영 노드 수 $V$ | 허용 엣지 수 $E$ | 평균 차수 |
|---:|---:|---:|
| 1,000 | 20,000 | 40 |
| 10,000 | 200,000 | 40 |
| 100,000 | 2,000,000 | 40 |
| 1,000,000 | 20,000,000 | 40 |

이 값이 실무적으로 합리적인 이유.

- **희소성 유지.** $E=O(V)$면 인접 리스트 계열 표현의 메모리가 노드 수에 선형이다.
  $E=\Theta(V^2)$로 가면 100만 노드에서 손을 못 댄다. (8장에서 이어지는 이야기다.)
- **알고리즘 비용.** BFS·연결요소는 $O(V+E)$, 다익스트라는 $O(E\log V)$, PageRank는
  반복마다 $O(E)$다. 전부 $E$에 선형이므로 $E/V$를 상수로 묶어 두면 비용이 노드 수에
  비례해서만 자란다.
- **품질.** 평균 차수 40이면 «비슷한 상품 상위 몇 개»를 뽑기에 충분하다. 그보다 촘촘해지면
  대개 잡음이 늘 뿐 추천 품질은 오르지 않는다.
- **경험적 눈금.** 실제 소셜·구매 그래프의 평균 차수도 보통 수십 수준이다. 20배는
  «현실 그래프와 비슷한 밀도»라는 뜻이기도 하다.

숫자 20 자체는 물리 법칙이 아니라 저자의 운영 규칙이다. 카드의 요점은 «20»이라는 값보다
**절대 임계값이 아니라 결과 밀도 비율로 기준을 잡는다**는 발상 쪽이다.

## 6. 실제로 $\tau$를 정하는 절차

$\tau$를 올리면 남는 엣지 수는 단조 감소한다. 그래서 «비율 20 이하가 되는 가장 작은 $\tau$»를
찾으면 된다. 가장 작은 값을 고르는 이유는 필요 이상으로 정보를 버리지 않기 위해서다.

```python
def choose_tau(proj, n_nodes, ratio=20):
    """비율을 만족하는 가장 작은 임계값. 낮은 tau가 정보를 덜 버린다."""
    for tau in range(1, max(proj.values()) + 2):
        kept = {e: w for e, w in proj.items() if w >= tau}
        if len(kept) <= n_nodes * ratio:
            return tau, kept
    return None, {}
```

가중치 히스토그램(누적 분포)을 한 번 만들어 두면 스캔 대신 바로 역산할 수도 있다.
$\tau$의 범위가 크면 단조성 덕분에 이진 탐색이 가능하다.

예제의 작은 데이터로 확인해 보면, 투영 노드는 상품 3개, 엣지는 3개다.

$$\frac{E}{V}=\frac{3}{3}=1.0 \;\le\; 20 \quad\Rightarrow\quad \tau=1,\ \text{자를 필요 없음}$$

기준을 넉넉히 만족하니 아무것도 버리지 않는다. 기준이 «항상 자른다»가 아니라
«넘칠 때만 자른다»는 것도 함께 기억할 부분이다.

### 함정: 분모의 $V$를 무엇으로 셀 것인가

$\tau$를 올리면 엣지가 사라지면서 **고립 노드**가 생긴다. 그러면 분모도 흔들린다.

| $V$의 정의 | 성질 |
|---|---|
| 투영 대상 쪽 노드 전부 (상품 전체) | $\tau$와 무관하게 고정. 계산이 단순하고 재현 가능 |
| 엣지가 남은 노드만 | $\tau$가 오르면 분모도 줄어 비율이 잘 안 내려간다. 수렴이 느릴 수 있음 |

어느 쪽이든 되지만 **팀에서 하나로 정하고 기록해 둬야 한다.** 정의가 사람마다 다르면
같은 데이터에 같은 기준을 걸었는데 다른 $\tau$가 나오고, 그때부터 숫자를 못 믿는다.
7장이 반복해서 말하는 «무엇을 세는지 먼저 정하라»가 여기에도 그대로 적용된다.

## 7. 한 발 더 — 전역 임계값의 약점과 대안

$w \ge \tau$ 하나로 자르는 건 간단하지만 **모든 노드에 같은 자를 대는** 방식이다.

- 인기 상품(허브)은 $\tau$를 넘는 엣지가 수천 개 남아 여전히 촘촘하다.
- 비인기 상품은 전부 잘려 고립된다. 롱테일 추천이 사라진다.

밀도는 평균으로 맞았는데 분포는 더 치우치는 결과가 나온다. 그래서 실무에서는 아래를 섞는다.

| 방법 | 내용 | 성질 |
|---|---|---|
| 전역 임계값 | $w\ge\tau$ | 예제 방식. 가장 간단, 허브 편중 |
| 노드별 top-k | 각 노드에서 가중치 상위 $k$개만 남긴다 | $E\le kV$가 보장된다. 저차수 노드도 살아남음 |
| 정규화 후 임계값 | 코사인·자카드·PMI로 바꾼 뒤 자른다 | 인기도 보정. 원시 카운트의 «베스트셀러 편향»을 줄임 |
| 백본 추출 | 노드별 가중치 분포와 비교해 통계적으로 유의한 엣지만 남긴다 (disparity filter, Serrano et al., PNAS 2009) | 허브와 롱테일을 동시에 배려. 구현 부담 있음 |

노드별 top-k는 특히 **$E/V$ 기준과 궁합이 좋다.** $k=20$으로 두면 방향성 있는 상위 이웃을
남기면서 $E/V$가 자동으로 20 이하에 묶인다. 임계값 튜닝이 필요 없다.

## 8. 그리고 대안 1도 잊지 말기

예제가 먼저 제시한 대안은 «투영하지 않는 것»이다.

> 1. 투영하지 말고 이분 그래프 그대로 2홉을 돈다. 필요할 때만 계산한다.

이분 그래프 원본은 엣지가 구매 건수만큼만 있다(예제에서는 6개). 투영은 이걸 미리
계산해 두는 **캐시**에 가깝다. 질의가 드물거나 데이터가 자주 변하면 캐시를 만드는 비용이
아깝다. 상품A → (산 사람들) → (그 사람들이 산 다른 상품) 2홉을 그때그때 돌면
정보 손실도 없고 저장 폭발도 없다.

| | 투영 + 자르기 | 이분 2홉 |
|---|---|---|
| 저장 | 엣지 폭발(자르기로 억제) | 원본 그대로 |
| 질의 지연 | 빠름 (미리 계산) | 허브를 지나면 느릴 수 있음 |
| «누가 샀는지» | 사라짐 | 보존 |
| 데이터 변경 | 재계산 필요 | 즉시 반영 |

저자는 «2번(투영)을 쓴다»고 밝히면서 그 판단의 안전장치로 20배 기준을 든다.
자르기 없는 투영은 선택지가 아니라는 뜻이다.

## 9. 외우는 요령

- 답의 형태는 «비율»이다. 「$E \le 20V$」, 다르게 말하면 **평균 차수 40**.
- 3명은 **후보**, 20배는 **기준**. 헷갈리면 «3은 손잡이, 20은 눈금»으로 구분한다.
- 왜 상수 $\tau$가 아닌가 → 데이터 분포가 서비스마다 달라서. 목표를 결과 크기로 잡아야
  둘 다(폭발 / 텅 빔)를 피한다.
- 이 카드는 7장 한 장 요약의 «이분 그래프를 투영하면 정보가 사라지고 엣지가 제곱으로
  늡니다»와 짝을 이룬다. 제곱으로 느는 걸 선형($E=O(V)$)으로 되돌리는 장치가 20배 기준이다.
