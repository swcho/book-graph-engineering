# 실무에서 음수 가중치가 생기는 세 가지 자리는 무엇인가?

> **답**: ① 할인이나 환급을 «음수 비용»으로 넣을 때, ② 유사도를 `1 - 거리`로 바꿨는데 유사도가 1을 넘을 때, ③ 로그를 취했는데 값이 1보다 작을 때(`log 0.5 = -0.69`)다.

## 0. 왜 이게 문제인가 — 다익스트라의 «확정» 가정

9장 예제 `code/ex3_dijkstra_negative.py`의 핵심 한 줄은 이거다.

```python
done.add(u)          # 한 번 확정하면 다시 안 본다
```

다익스트라는 **«지금 큐에서 제일 싼 노드는 더 싸질 수 없다»** 는 가정 위에 서 있다. 앞으로 밟을 엣지가 전부 0 이상이면 참이다. 음수 엣지가 하나라도 있으면 이 가정이 깨지는데, **코드는 아무 말도 하지 않는다.**

예제의 그래프는 엣지 네 개짜리다.

```
A→C: 1     A→B: 2     B→C: -5     C→D: 1
```

| 노드 | 다익스트라 | 벨만-포드(정답) | 같나 |
|---|---:|---:|:--:|
| A | 0 | 0 | 예 |
| B | 2 | 2 | 예 |
| C | -3 | -3 | **예** |
| D | **2** | **-2** | 아니오 |

실행 순서를 따라가면 이렇다. `A→C`가 1이라 C를 제일 먼저 꺼내 확정하고, 그 상태에서 `D = 1 + 1 = 2`로 적는다. 그 뒤 B를 처리하며 `A→B→C = 2 - 5 = -3`인 걸 알아내 **거리표에는 적는다**. 그런데 C는 이미 `done`이라 다시 펼치지 않는다. 그래서 **D는 2로 남는다**.

여기서 두 가지가 고약하다.

1. **C는 맞고 D만 틀렸다.** 거리표를 찍어 보면 시작점 근처는 멀쩡하다. 검증을 시작점 반경 1~2홉만 보고 하면 100% 놓친다.
2. **예외가 안 난다.** 답이 그냥 조용히 틀린다. 알림도, 스택 트레이스도, 지연 시간 이상도 없다.

`ex3`처럼 직접 짠 다익스트라만 그런 건 아니지만, 라이브러리를 쓰면 조금 낫다. NetworkX의 `dijkstra_path()`는 **확정된 노드가 나중에 더 짧아지는 순간**을 감지하면 `ValueError("Contradictory paths found:", "negative weights?")`를 던진다. 위 그래프는 마침 그 조건에 걸려서 잡힌다. 다만 **보장은 아니다** — 음수 엣지가 이미 열등한 경로 위에만 있으면 모순이 표면화되지 않아 그대로 통과한다. 라이브러리를 방어책으로 세지 말라는 뜻이다.

## 1. 할인·환급을 «음수 비용»으로 넣을 때

### 어떻게 생기나

비용 그래프를 만들다 보면 «빼 주는 것»을 자연스럽게 마이너스로 적게 된다.

- 물류: 구간 배송비 5,000원인데 제휴 구간이라 3,000원 환급 → `w = -3000`짜리 엣지
- 결제 라우팅: PG 수수료 120원, 특정 조합에 리베이트 200원 → `w = -80`
- 여행 경로: 구간 요금에서 마일리지 적립분을 차감

### 구체적 수치 — 정답이 뒤집히는 최소 예시

배송 그래프. A에서 D까지 최저 비용을 찾는다.

```
A→C: 1,000원      A→B: 2,000원      B→C: -5,000원(제휴 환급)     C→D: 1,000원
```

- 다익스트라 답: `A→C→D`, **2,000원**
- 진짜 답: `A→B→C→D`, `2000 - 5000 + 1000 =` **-2,000원** (즉 2,000원을 돌려받음)

4,000원 차이다. 그런데 노드가 수만 개인 실제 그래프에서는 이 차이가 «원래 그 정도 나오는 값»에 묻힌다.

### 이 자리만의 진짜 위험 — 음수 사이클

할인·환급은 **음수 사이클**을 만들 수 있는 유일한 부류다. 유사도나 로그는 값의 범위가 정해져 있지만 정산 로직은 그렇지 않다.

```
A→B: -3,000원(환급)      B→A: 1,000원(배송비)      → 한 바퀴 -2,000원
```

이 사이클을 무한히 돌면 비용이 `-∞`로 간다. 최단 경로 자체가 **정의되지 않는다.** («같은 노드를 두 번 안 밟는 최단 경로»로 문제를 바꾸면 NP-난해다. 벨만-포드로도 못 푼다.) 비즈니스 언어로 옮기면 **무한 환급 루프**, 즉 사고다.

### 방어책

**(a) 모델링을 고친다 — 할인은 «가중치»가 아니라 «상태»다.**

실무의 할인은 대개 **한 번만 쓸 수 있다.** 한 번만 쓸 수 있는 값은 엣지 가중치가 아니라 상태다. 그래프를 계층으로 펼쳐라.

```
노드를 (원래 노드, 사용한 쿠폰 비트마스크)로 확장
→ 각 층 안에서는 모든 가중치가 양수 → 다익스트라 그대로 사용 가능
→ 층 간 이동(= 할인 소모) 엣지에만 할인가를 반영하되, 여전히 실지불액 ≥ 0
```

쿠폰 종류가 k개면 상태가 `2^k`배로 는다. k가 작을 때(3~5개)만 쓸 수 있는 방법이고, 이건 사실 «자원 제약 최단 경로(RCSP)» 문제다.

**(b) 클램프한다 — 실지불액은 음수가 될 수 없다.**

```python
w = max(0, base_cost - discount)     # 환급 상한을 원가로 제한
```

대부분의 도메인에서 이게 정확히 맞는 규칙이다. 배송비 5,000원짜리 구간에서 8,000원을 돌려받는 건 없다.

**(c) 그래도 음수가 필요하면 벨만-포드 + 사이클 검사.**

`ex3`의 구현이 마지막 한 바퀴를 더 도는 이유가 이거다.

```python
for _ in range(len(nodes) - 1):      # V-1번 완화
    for a, b, w in edges:
        if dist[a] + w < dist[b]:
            dist[b] = dist[a] + w
for a, b, w in edges:                # 한 바퀴 더 — 여기서 또 줄면 음수 사이클
    if dist[a] + w < dist[b]:
        return dist, True
```

`O(V·E)`다. `V=200,000`, 평균 차수 12면 엣지 120만 개, 곱하면 2,400억 번. **실시간 질의로는 불가능하다.** 그래서 (a)나 (b)로 음수를 애초에 안 만드는 쪽이 실무 답이다.

## 2. 유사도를 `1 - 거리`로 바꿨는데 유사도가 1을 넘을 때

### 어떻게 생기나

임베딩 그래프에서 «비슷할수록 가까운» 거리를 만들 때 관용적으로 쓰는 식이다.

```python
weight = 1 - similarity        # 유사도 0.9 → 비용 0.1
```

`similarity ∈ [0, 1]`이면 완벽하다. 문제는 **그 가정이 코드 어디에도 안 적혀 있다**는 것이다. 유사도가 1을 넘는 순간 `weight`가 음수가 된다.

### 유사도가 1을 넘는 네 가지 경로

| 원인 | 구체적 수치 | 나오는 가중치 |
|---|---|---|
| **정규화를 빼먹고 내적을 씀** — 코사인인 줄 알았는데 내적이었다 | `‖u‖=1.4, ‖v‖=1.3, cos=0.95` → `dot = 1.729` | **-0.729** |
| **부스팅/가중합** — 최근성·인기도 보정을 곱하거나 더함 | `0.88 × boost 1.2 = 1.056` | **-0.056** |
| **외부 리랭커 점수** — BM25, 크로스인코더 로짓은 [0,1]이 아니다 | BM25 `12.4` | **-11.4** |
| **부동소수점 오차** — 정규화된 벡터끼리도 딱 1이 안 나온다 | `np.dot(u, u) = 1.0000000000000002` | **-2.22e-16** |

마지막 줄이 특히 악질이다. `-2.22e-16`은 눈으로 봐서는 0이고, 로그에 찍어도 0으로 보인다. 그런데 다익스트라의 `done` 불변식을 깨는 데는 크기가 필요 없다. **부호만 있으면 된다.**

### 방어책

**(a) 적재 시점 가드 — 값이 들어오는 곳에서 딱 한 번 막는다.**

```python
EPS = 1e-9

def edge_weight(sim: float) -> float:
    if sim > 1 + EPS or sim < -EPS:
        raise ValueError(f"유사도 범위 이탈: {sim}")   # 조용히 틀리느니 시끄럽게 죽는다
    return max(0.0, 1.0 - sim)      # 부동소수점 잔여분은 0으로 접는다
```

`max(0.0, ...)`가 부동소수점 케이스를, `raise`가 나머지 세 케이스를 잡는다. 둘 다 필요하다 — `max`만 쓰면 BM25 12.4가 전부 0이 되어 «모든 엣지가 공짜»인 그래프가 되고, `raise`만 쓰면 `1e-16`짜리 오차로 파이프라인이 죽는다.

**(b) 거리를 직접 정의한다 — 뺄셈을 없앤다.**

`1 - sim`은 «유사도가 [0,1]»이라는 암묵 가정을 코드에 숨긴다. 애초에 음수가 될 수 없는 거리를 쓰면 가정 자체가 사라진다.

- 코사인 거리: `1 - cos(u,v)` → `[0, 2]`, 단 **입력 벡터를 반드시 정규화**해야 성립
- 각도 거리: `arccos(cos) / π` → `[0, 1]`, 항상 비음수
- 유클리드 거리: `‖u - v‖` → 항상 비음수, 삼각부등식도 성립해서 A\* 휴리스틱에도 쓸 수 있다

**(c) 정규화 여부를 타입으로 강제한다.** 벡터 저장소에 넣기 전에 `‖v‖ = 1`을 단언하고, 정규화된 벡터임을 이름이나 타입에 박아라(`unit_emb`). 실무에서 이 버그의 90%는 «어딘가에서 정규화를 한 번 빼먹었다»이다.

## 3. 로그를 취했는데 값이 1보다 작을 때 — 제일 자주 보는 자리

> 예제 원문: **«마지막이 제일 자주 봤다. 확률 곱을 최단 경로로 바꾸는 흔한 기법이다.»**

### 왜 로그를 취하나

«가장 그럴듯한 경로»를 찾는 문제는 **확률의 곱**을 최대화하는 문제다.

```
P(경로) = p₁ × p₂ × p₃ × ...
```

최단 경로 알고리즘은 곱이 아니라 **합**을 다룬다. 그래서 로그를 취해 곱을 합으로 바꾼다.

```
log P = log p₁ + log p₂ + log p₃ + ...
```

여기까지는 교과서적으로 옳다. 부수적으로 언더플로(확률 50개를 곱하면 `1e-30` 밑으로 간다)도 막아 준다.

### 어디서 부호가 뒤집히나

**확률은 1 이하다. 따라서 로그는 항상 0 이하다.**

| p | `log p` | 잘못 쓴 가중치 |
|---:|---:|---:|
| 1.0 | 0.0 | 0 |
| 0.9 | -0.105 | 음수 |
| 0.5 | **-0.693** | 음수 |
| 0.1 | -2.303 | 음수 |
| 0.01 | -4.605 | 음수 |

`w = log(p)`로 적재하는 순간 **그래프의 거의 모든 엣지가 음수**가 된다. 앞의 두 자리는 «드물게 하나 섞이는» 사고인데, 이건 전면적이다. 게다가 확률 곱은 «최대화» 문제라 최단 경로에 넣으려면 부호를 뒤집어야 하는데, 그 단계를 빠뜨린 것이다.

### 나타나는 도메인

- 지식 그래프 추론 — 관계별 신뢰도의 곱이 가장 큰 추론 체인
- 개체 연결(entity resolution) — 병합 확신도의 곱
- 음성/번역 디코딩, HMM 비터비 — 전이 확률의 곱
- 사기 탐지 — 계좌 간 연결 확률의 곱

### 방어책 — 부호를 뒤집으면 문제 자체가 사라진다

```python
w = -math.log(p)        # 음의 로그 가능도(negative log-likelihood)
```

`0 < p ≤ 1`이면 `-log p ≥ 0`이다. **구조적으로 음수가 될 수 없다.** 다익스트라를 그대로 쓸 수 있고, `-log p`의 합을 최소화하는 것이 `∏p`를 최대화하는 것과 정확히 같다(로그는 단조증가, 부호 반전으로 최대화가 최소화가 된다).

주의할 점 둘.

**`p = 0` 처리.** `-log(0) = inf`다. 파이썬은 `math.log(0)`에서 `ValueError`를 던진다. 도달 불가 엣지는 아예 넣지 말거나, 하한을 두어라.

```python
w = -math.log(max(p, 1e-12))     # p=0 → 27.6 (사실상 금지되지만 유한)
```

**`p > 1`이 들어오면 다시 음수가 된다.** 정규화되지 않은 점수(로짓, 카운트, 스코어)를 확률로 착각하고 넣으면 `-log(1.5) = -0.405`로 원점 회귀다. 2번 자리의 가드가 여기에도 필요하다.

```python
assert 0 < p <= 1, f"확률이 아님: {p}"
```

## 4. 세 자리 요약과 공통 방어

| 자리 | 전형적 수치 | 음수 사이클 위험 | 1차 방어 |
|---|---|:--:|---|
| 할인·환급을 음수 비용으로 | `-5,000원` | **있음** | 상태 확장 / `max(0, 원가-할인)` |
| `1 - 유사도`, 유사도 > 1 | `-2.2e-16` ~ `-11.4` | 없음 | 적재 가드 + 정규화 강제 |
| `log p`, `p < 1` | `-0.693` | 없음 | 부호 반전 `-log p` |

### 공통 방어 1 — 적재 시점 단언 (제일 값싸고 제일 효과적)

```python
def load_edges(edges):
    for a, b, w in edges:
        if w < 0:
            raise ValueError(f"음수 가중치: {a}→{b} = {w}")
        yield a, b, w
```

질의 시점이 아니라 **적재 시점**이다. 질의마다 전체 엣지를 훑으면 O(E)가 매번 붙는다. 적재 때 한 번 막으면 공짜다.

### 공통 방어 2 — 가중치 시프트: 순진하게 하면 틀린다

«최솟값의 절댓값을 전부 더하면 되지 않나»는 가장 흔한 오답이다. **경로 길이가 다르면 더해지는 상수의 개수가 달라지기 때문에 틀린다.**

앞의 예제로 확인해 보자. 최소 가중치가 -5이므로 모든 엣지에 +5를 더한다.

```
원본:   A→C 1     A→B 2     B→C -5     C→D 1
시프트: A→C 6     A→B 7     B→C  0     C→D 6
```

| 경로 | 홉 수 | 원본 비용 | 시프트 비용 |
|---|:--:|---:|---:|
| `A→C→D` | 2 | 2 | `6+6 =` **12** |
| `A→B→C→D` | 3 | **-2** | `7+0+6 =` 13 |

시프트 그래프에서 다익스트라는 `A→C→D`를 고른다. **정답은 `A→B→C→D`다.** 홉이 하나 더 많은 경로가 +5를 한 번 더 얻어맞았기 때문이다. 순진한 시프트는 **홉 수가 적은 경로에 편향**된다.

### 공통 방어 3 — 존슨 알고리즘: 올바른 시프트

시프트를 정답으로 만들려면 상수가 아니라 **노드별 포텐셜**을 써야 한다.

```
w'(u,v) = w(u,v) + h(u) - h(v)
```

`h`는 **가상 시작점 q를 만들어 모든 노드에 0짜리 엣지를 걸고 벨만-포드를 한 번 돌려** 얻은 최단 거리다. 이렇게 하면 경로를 따라 `h`가 **망원경처럼 소거되어(telescoping)** 경로 비용이 `h(s) - h(t)`만큼만 바뀐다. 시작·끝이 같은 모든 경로에 **같은 상수**가 붙으므로 **순위가 보존된다.** 홉 수와 무관하다는 점이 순진한 시프트와의 결정적 차이다.

같은 예제로 계산해 보자.

```
h(A) = 0,  h(B) = 0,  h(C) = -5,  h(D) = -4      # 가상 q에서 벨만-포드

w'(A,C) = 1 + 0 - (-5) = 6
w'(A,B) = 2 + 0 -   0  = 2
w'(B,C) = -5 + 0 - (-5) = 0
w'(C,D) = 1 + (-5) - (-4) = 0
```

전부 0 이상이다. 이제 A에서 다익스트라를 돌리면 `d'(B)=2, d'(C)=2, d'(D)=2`. 원래 거리로 되돌린다.

```
d(s,v) = d'(s,v) - h(s) + h(v)

d(A,B) = 2 - 0 + 0    =  2   ✔
d(A,C) = 2 - 0 + (-5) = -3   ✔
d(A,D) = 2 - 0 + (-4) = -2   ✔  (다익스트라 단독으로는 2가 나왔던 그 자리)
```

정확히 벨만-포드의 답이다.

**비용**: 벨만-포드 1회 `O(V·E)` + 다익스트라 V회 `O(V·(E + V log V))`. 그래서 존슨이 이기는 상황은 **가중치가 자주 안 바뀌고, 같은 그래프에 최단 경로 질의가 많이 들어올 때**다. 배치로 `h`를 한 번 계산해 두고 질의는 전부 다익스트라로 처리한다. 벨만-포드 단계에서 **음수 사이클도 함께 잡힌다**(사이클이 있으면 `h`가 수렴하지 않는다).

### 공통 방어 4 — 검증은 «먼 노드»에서 한다

`ex3`이 짚은 대로 **C는 맞고 D가 틀렸다**. 시작점 근처는 음수 엣지를 아직 안 지났으니 당연히 맞는다. 그러니 회귀 테스트는 이렇게 짜라.

- 시작점에서 **가장 먼** 노드들의 거리를 단언한다
- 벨만-포드 결과와 다익스트라 결과를 **전 노드 대조**하는 테스트를 CI에 넣는다(작은 그래프면 싸다)
- 거리뿐 아니라 **경로가 실제로 존재하는 엣지들로 이루어져 있는지** 검증한다

### 공통 방어 5 — 도구가 이미 나눠 놨다

| 도구 | 음수 가중치 |
|---|---|
| `networkx.dijkstra_path` | 감지되면 `ValueError`, 단 **보장 아님** |
| `networkx.bellman_ford_path` | 지원, `NetworkXUnbounded`로 음수 사이클 보고 |
| `networkx.johnson` | 지원(전 쌍 최단 경로) |
| Neo4j GDS `shortestPath.dijkstra` | 비음수만 |
| Neo4j GDS `bellmanFord` | 지원, `negativeCycles` 옵션으로 사이클 열거 |
| Cypher `shortestPath()` | **무가중치** — 홉 수만 센다 |

「가중치가 음수일 수 있다」를 아는 순간 알고리즘 선택이 바뀐다. 모르면 다익스트라를 쓰고, **조용히 틀린 답을 배포한다.**

## 5. 한 줄 정리

음수 가중치는 «누가 일부러 음수를 넣어서» 생기지 않는다. **할인을 빼는 자연스러운 모델링**, **[0,1]인 줄 알았던 유사도**, **곱을 합으로 바꾸는 정석적인 로그 변환** — 셋 다 그 자체로는 옳은 일이고, 그래서 리뷰를 통과한다. 방어는 알고리즘을 바꾸는 것(벨만-포드·존슨)보다 **음수가 나올 수 없는 형태로 값을 정의하는 것**(`max(0, ...)`, `-log p`, 상태 확장)이 먼저다.
