# 음수 가중치는 대개 로그에서 온다

## 질문

저자가 가장 자주 본 음수 가중치 발생 원인은 무엇인가?

## 답

**로그를 취한 경우**다. $\log 0.5 = -0.69$처럼, 확률 곱을 최단 경로 문제로 바꾸는 흔한 기법에서 음수가 생긴다.

---

## 1. 책이 꼽은 세 자리

`ex3_dijkstra_negative.py`의 마지막 출력이 실무에서 음수 가중치가 튀어나오는 자리를 정리해 둔다.

| 자리 | 설명 |
|---|---|
| 할인·환급 | 비용 모델에 「음수 비용」을 그대로 넣을 때 |
| 유사도 변환 | 유사도를 $1 - \text{거리}$로 바꿨는데 유사도가 1을 넘을 때 |
| **로그 변환** | 값이 1보다 작은데 로그를 취할 때 ($\log 0.5 = -0.69$) |

그리고 저자의 결론은 이렇다.

> 마지막이 제일 자주 봤다. 확률 곱을 최단 경로로 바꾸는 흔한 기법이다.

앞의 둘은 「누가 봐도 음수를 넣는 중」이라 리뷰에서 걸린다. 로그는 다르다. 코드에는 `math.log(p)`라는 한 줄만 있고, 음수라는 단어가 어디에도 안 나온다. 그래서 제일 자주 통과한다.

## 2. 왜 확률 곱을 로그 합으로 바꾸나

경로 $P = (e_1, e_2, \dots, e_k)$의 각 엣지에 확률 $p_i \in (0, 1]$이 붙어 있고, 엣지들이 독립이라고 하면 그 경로가 성립할 확률은 곱이다.

$$\Pr(P) = \prod_{i=1}^{k} p_i$$

우리가 원하는 건 「가장 그럴듯한 경로」, 즉 $\arg\max_P \prod p_i$다. 그런데 최단 경로 알고리즘(다익스트라, 벨만-포드, A\*)은 전부 **합을 최소화**하는 기계다. 곱을 최대화하는 기계는 없다. 그래서 변환한다.

$\log$는 **순증가 함수**라서 크기 순서를 바꾸지 않는다. 즉 $x < y \iff \log x < \log y$이므로 $\arg\max$가 보존된다.

$$\arg\max_P \prod_{i} p_i \;=\; \arg\max_P \log \prod_{i} p_i \;=\; \arg\max_P \sum_{i} \log p_i$$

여기에 부호를 뒤집으면 최대화가 최소화가 된다.

$$\boxed{\;\max_P \prod_{i} p_i \;\Longleftrightarrow\; \min_P \sum_{i} \bigl(-\log p_i\bigr)\;}$$

**곱 → 합**, **최대 → 최소**. 이 두 번의 변환이 확률 문제를 최단 경로 문제로 정확히 옮긴다. 그러니 최단 경로 엔진 위에 확률 랭킹을 얹는 팀이라면 누구나 이 변환을 쓴다. 흔하다는 게 핵심이다.

덤으로 얻는 이득이 하나 더 있다. 경로가 길어지면 $\prod p_i$는 부동소수점 **언더플로**로 0이 되어 버린다. $p = 0.1$짜리 엣지 400개면 $10^{-400}$이라 `float64`가 표현하지 못한다. 로그로 바꾸면 $-921.03$이라 아무 문제가 없다. 히든 마르코프 모델의 비터비 알고리즘이 로그 공간에서 도는 이유도 같다.

로그의 밑은 아무거나 상관없다. 밑을 바꾸면 모든 가중치에 같은 양수 상수가 곱해질 뿐이라 최소 경로가 안 바뀐다. 자연로그를 쓰면 nat, $\log_2$를 쓰면 bit 단위의 **자기정보량(surprisal)**이 되고, $-\log p$는 그 자체로 「이 엣지를 지날 때 놀라는 정도」라는 물리적 의미를 갖는다.

## 3. 부호를 잘못 잡으면 전부 음수가 된다

사고는 여기서 난다. 변환의 절반만 하는 것이다.

```python
# 틀림 — 마이너스를 빼먹었다
w = math.log(p)
```

$p \in (0, 1)$이면 $\log p < 0$이다. $\log 0.9 = -0.105$, $\log 0.5 = -0.693$, $\log 0.1 = -2.303$. 확률은 정의상 1 이하이므로 **모든 엣지 가중치가 음수**가 된다. 하나만 음수인 게 아니라 전부다.

결과가 왜 틀리는지 보자. 이 그래프에서 최단 경로를 구하면 알고리즘이 푸는 문제는 이렇다.

$$\min_P \sum_i \log p_i \;=\; \min_P \log \prod_i p_i \;=\; \arg\min_P \prod_i p_i$$

즉 **가장 그럴듯한 경로가 아니라 가장 안 그럴듯한 경로**를 고른다. 의도의 정반대다. 게다가 엣지를 더 밟을수록 합이 더 작아지므로, 알고리즘은 자연스럽게 「빙 돌아가는 긴 경로」를 선호한다.

사이클이 있으면 더 나쁘다. 모든 가중치가 음수라는 말은 **모든 사이클이 음수 사이클**이라는 뜻이다. 사이클을 한 바퀴 더 돌 때마다 거리가 계속 줄기 때문에 최단 거리가 $-\infty$로 정의되지 않는다. 벨만-포드를 쓰면 「음수 사이클 있음」을 돌려주지만, 다익스트라를 쓰면 그런 신호조차 없다.

### 다익스트라는 조용히 틀린다

`ex3_dijkstra_negative.py`가 보여 주는 게 정확히 이 조용함이다. 엣지는 넷뿐이다.

```
A→C: 1,  A→B: 2,  B→C: -5,  C→D: 1
```

- `A→C`가 1이라 다익스트라는 C를 제일 먼저 꺼내 **확정**하고, 그 상태에서 D를 $1+1=2$로 계산한다.
- 나중에 B를 처리하며 `A→B→C`가 $2 + (-5) = -3$인 걸 알아내고 거리표에는 적는다.
- 그런데 C는 이미 확정이라 **다시 펼치지 않는다**. 그래서 D는 2로 남는다. 정답은 $-3 + 1 = -2$다.

책의 표현대로 「C는 맞고 D는 틀렸다」. 이게 고약한 이유가 두 가지다.

1. **예외가 안 난다.** 스택 트레이스도, 경고도 없다. 답이 그냥 조용히 틀린다.
2. **시작점 근처는 맞는다.** 검증할 때 A 바로 옆만 찍어 보면 「잘 돌고 있네」 싶다. 틀린 건 두 홉 뒤쪽이다.

다익스트라의 정당성은 「한 번 확정한 노드의 거리는 앞으로 절대 줄지 않는다」는 불변식에 기대는데, 음수 엣지는 이 불변식을 깬다. 그래서 알고리즘이 깨지는 게 아니라 **답이 틀린 채로 완주한다**.

## 4. 올바른 관례: `-log p`

```python
# 맞음 — 음의 로그 우도(negative log-likelihood)
w = -math.log(p)
```

$p \in (0, 1]$에서 $-\log p \in [0, \infty)$다. 항상 0 이상이다.

| $p$ | $\log p$ (틀림) | $-\log p$ (맞음) |
|---:|---:|---:|
| 1.0 | 0.000 | **0.000** |
| 0.9 | $-0.105$ | **0.105** |
| 0.5 | $-0.693$ | **0.693** |
| 0.1 | $-2.303$ | **2.303** |
| 0.01 | $-4.605$ | **4.605** |

의미도 정확히 맞아떨어진다.

- $p = 1$인 확실한 엣지는 비용 0 — 지나도 손해가 없다.
- 확률이 낮을수록 비용이 커진다 — 「비쌀수록 피한다」는 최단 경로의 직관과 일치한다.
- 가중치가 전부 음이 아니므로 **다익스트라를 그대로 써도 된다**. 벨만-포드로 갈아탈 필요가 없다.
- 최종 거리 $d$를 확률로 되돌리려면 $\prod p_i = e^{-d}$로 지수를 씌우면 된다.

이 값이 머신러닝에서 부르는 **음의 로그 우도(NLL)**, 정보이론에서 부르는 **자기정보량**과 같은 물건이다. 「비용 = 놀라움」이라고 외워 두면 부호를 헷갈릴 일이 줄어든다.

## 5. 경계값 처리: $p = 0$과 $p > 1$

### $p = 0$

$-\log 0 = +\infty$다. 파이썬에서 `math.log(0)`은 `ValueError: math domain error`를 던지고, `numpy`에서는 `-inf`에 경고를 준다. 어느 쪽이든 그대로 두면 안 된다. 선택지는 셋이다.

1. **엣지를 아예 뺀다.** 의미상 가장 정직하다. 확률 0인 전이는 「지나갈 수 없는 길」이므로 그래프에 없는 것과 같다. 도달 불가는 최단 경로 알고리즘이 이미 $\infty$로 잘 표현한다.
2. **평활화(smoothing)한다.** $p' = \dfrac{c + \alpha}{n + \alpha k}$ 같은 라플라스/애드-$\alpha$ 보정으로 0을 아주 작은 양수로 밀어낸다. 데이터가 적어서 「관측이 안 됐을 뿐 불가능한 건 아닌」 경우에 맞다.
3. **상한을 씌운다.** $w = -\log(\max(p, \varepsilon))$처럼 $\varepsilon = 10^{-12}$ 정도로 바닥을 깔아 유한한 큰 값으로 만든다. 구현이 제일 간단하지만 $\varepsilon$ 값이 사실상 「불가능의 가격」을 정하는 하이퍼파라미터가 된다는 걸 알고 써야 한다.

무엇을 고르든 **의도적으로 고르는 것**이 중요하다. `inf`가 거리표에 섞이면 `inf - inf = nan`이 나오는 자리가 생기고, 그때부터는 비교 연산이 전부 `False`가 되어 또 조용히 틀린다.

### $p > 1$

로그 변환이 무너지는 반대쪽 경계다. $p > 1$이면 $-\log p < 0$이라 **다시 음수 가중치**가 된다. 정규화되지 않은 점수(logit, 유사도, TF-IDF 코사인 합, 어텐션 가중치 합 등)를 「확률처럼」 로그에 넣으면 여기에 걸린다. 책이 꼽은 두 번째 자리 — 「유사도를 $1 -$ 거리로 바꿨는데 유사도가 1을 넘을 때」 — 와 사실상 같은 버그다.

그래서 로그를 씌우기 전에 입력을 검증한다.

```python
def edge_cost(p, eps=1e-12):
    if not (0.0 <= p <= 1.0):
        raise ValueError(f"확률이 아님: {p}")   # 조용히 틀리느니 여기서 죽는다
    if p == 0.0:
        return math.inf                        # 또는 엣지를 만들지 않는다
    return -math.log(max(p, eps))
```

핵심은 **자료 적재 시점에 죽는 것**이다. 최단 경로가 다 돌고 나서 틀린 답을 받는 것보다, 엣지를 만들 때 `ValueError`로 멈추는 편이 압도적으로 싸다.

## 6. 정리 — 실무 체크리스트

- [ ] 가중치를 넣을 때 `-math.log(p)`인지 `math.log(p)`인지 눈으로 확인했나. 마이너스 하나가 답을 정반대로 뒤집는다.
- [ ] 엣지 적재 시점에 $0 \le p \le 1$을 검증하나. 특히 「점수」를 확률로 쓰는 자리.
- [ ] $p = 0$ 처리 방침(삭제 / 평활화 / $\varepsilon$ 바닥)을 정해 두었나.
- [ ] 최소 가중치를 한 번 찍어 보나. `min(w for _, _, w in edges) < 0`이면 다익스트라를 쓰면 안 된다.
- [ ] 음수가 정말 필요하다면(할인·환급 등) **벨만-포드**로 가고 음수 사이클 검사를 켜라. 음수 사이클이 있으면 최단 경로 자체가 정의되지 않는다.
- [ ] 검증할 때 시작점에서 멀리 떨어진 노드를 본다. 다익스트라의 음수 버그는 근처는 맞고 뒤쪽이 틀린다.

한 줄로 줄이면 이렇다. **확률에 로그를 취하는 코드가 있으면 그 그래프의 가중치 부호를 의심하라.** 저자가 제일 자주 본 사고 자리다.
