# `bfs_path()`는 경로를 어떻게 복원하는가?

## 한 줄 답

`seen` 딕셔너리에 **각 노드의 부모**를 기록해 두고, 목표에 도달하면 부모를 거슬러 올라간 뒤 뒤집는다. 시작점의 부모는 `None`이다.

---

## 근거 코드 — `code/ex2_bidirectional.py`

```python
def bfs_path(adj, s, t, max_hop=8):
    if s == t:
        return [s], 1
    seen = {s: None}                 # (1) 부모 맵 겸 방문 표시. 시작점의 부모는 None
    q = deque([(s, 0)])
    while q:
        u, d = q.popleft()
        if d >= max_hop:             # (2) 홉 상한. 이게 없으면 사실상 전체 스캔
            continue
        for v in adj.get(u, ()):
            if v in seen:            # (3) 이미 본 노드는 부모를 덮어쓰지 않는다
                continue
            seen[v] = u              # (4) v 는 u 를 통해 처음 발견됐다 → 부모 = u
            if v == t:
                path = [v]                                   # (5) 목표에서 시작
                while seen[path[-1]] is not None:            # (6) 부모가 None 이면 = 시작점
                    path.append(seen[path[-1]])
                return list(reversed(path)), len(seen)       # (7) 뒤집어서 s→t 방향으로
            q.append((v, d + 1))
    return None, len(seen)
```

---

## 왜 `seen`이 집합이 아니라 딕셔너리인가

같은 장의 `ex1_bfs_explosion.py`에서는 `seen = {start}`, 즉 **집합**이다. 거기서는 "몇 개나 방문했나"만 세면 되기 때문이다.

`bfs_path()`는 경로 자체를 돌려줘야 하므로 `seen = {s: None}`, 즉 **딕셔너리**다. 이 하나의 자료구조가 두 가지 일을 동시에 한다.

| 용도 | 쓰는 곳 |
|---|---|
| 방문 여부 판정 | `if v in seen: continue` |
| 역방향 부모 포인터 | `seen[v] = u`, 그리고 복원 루프 |

덤으로 `len(seen)`이 그대로 "방문 노드 수"가 되어, `main()`에서 단방향/양방향 비용 비교 지표(75~88배 절감)로 쓰인다.

## 부모 포인터 = 뒤집힌 트리

BFS가 지나간 자취는 **BFS 트리**를 만든다. 그런데 `seen`은 "부모 → 자식들"이 아니라 **"자식 → 부모"** 방향으로만 저장한다. 자식 리스트를 들고 다닐 필요 없이 노드당 딱 한 칸(포인터 하나)이면 되기 때문이다. 대신 이 방향으로는 앞에서 뒤로 못 걷고 **뒤에서 앞으로만** 걸을 수 있다. 그래서 경로가 `t → s` 순으로 나오고, 마지막에 `reversed()`가 필요하다.

```
seen = {0: None, 3: 0, 7: 0, 12: 3, 99: 12}      # 99 가 목표라면

path = [99]
      → seen[99] = 12  → [99, 12]
      → seen[12] = 3   → [99, 12, 3]
      → seen[3]  = 0   → [99, 12, 3, 0]
      → seen[0]  = None → 정지 (시작점 도달)

reversed → [0, 3, 12, 99]
```

## 종료 조건이 `None`인 이유

복원 루프의 조건은 "시작점 `s`에 닿았나"가 아니라 `seen[path[-1]] is not None`이다. 둘은 같은 뜻이지만 후자가 낫다.

- `s` 값을 복원 함수까지 들고 다닐 필요가 없다. 부모 맵 하나만 보면 어디가 뿌리인지 안다.
- `None`은 "부모가 없는 노드", 곧 **탐색의 뿌리**를 뜻하는 감시값(sentinel)이다. `0`이나 `-1` 같은 값을 쓰면 노드 ID가 `0`인 이 그래프에서 곧바로 충돌한다(실제로 `main()`이 `bfs_path(adj, 0, 199_999)`를 호출한다). `None`은 정수 노드 ID와 절대 겹치지 않는다.
- 그래서 루프가 끝난 시점의 `path[-1]`은 반드시 `s`다. 즉 반환 경로는 **시작점과 목표점을 모두 포함**한다. `main()`이 경로 길이를 `len(p1) - 1`로 계산하는 이유가 이것이다. 노드 수에서 1을 빼야 홉(간선) 수가 된다.

## 부모를 덮어쓰지 않는 것이 최단성을 보장한다

`if v in seen: continue`가 핵심이다. 한 노드는 **처음 발견됐을 때의 부모만** 갖는다. 나중에 다른 노드에서 같은 `v`로 가는 간선을 만나도 `seen[v]`는 바뀌지 않는다.

BFS는 큐(FIFO)로 돌기 때문에 노드를 거리 순서대로 발견한다. 따라서 "처음 발견한 부모"는 곧 "가장 짧은 경로상의 부모"다. 가중치 없는 그래프에서 이 부모 포인터를 따라간 경로가 최단 경로인 이유다. (가중치가 붙으면 이 논리가 깨진다. 그래서 `ex3_dijkstra_negative.py`처럼 다익스트라·벨만-포드로 넘어간다.)

한 가지 더. 목표 판정을 큐에서 꺼낼 때가 아니라 **간선을 펼치는 순간**(`seen[v] = u` 직후)에 한다. 가중치 없는 BFS에서는 `t`를 발견한 시점이 이미 최단 거리이므로 큐에 넣었다 다시 꺼내는 한 바퀴를 아낄 수 있다.

## 실패 경로

`while q`가 다 돌도록 `t`를 못 만나면 `return None, len(seen)`이다. 경로가 없어서일 수도 있고, `max_hop=8` 상한에 걸려서일 수도 있다. 이 함수는 둘을 구분하지 않는다. 9장의 주제상 상한 없는 순회는 전체 스캔이므로, "못 찾았다"와 "상한 안에는 없다"를 같은 값으로 뭉갠 것이 오히려 의도된 설계다.

또 `if s == t`를 맨 앞에서 따로 처리하는 이유도 여기 있다. 그냥 두면 `seen[s] = None`이라 복원 루프가 곧바로 멈춰 `[s]`가 나오긴 하지만, 애초에 `t`를 만나는 지점이 `for v in adj[u]` 안이라 자기 자신은 발견되지 않는다. 그래서 특수 처리가 필요하다.

## 양방향 탐색은 이 기법을 두 번 쓴다

같은 파일의 `bidi_path()`는 부모 맵을 **두 개** 만든다.

```python
fwd, bwd = {s: None}, {t: None}
```

그리고 한쪽에서 발견한 노드가 다른 쪽 맵에 이미 있으면(`if v in other`) 그 노드가 **만난 지점(meet)**이다. 이때 `_join()`이 부모 맵 두 개를 이어 붙인다.

```python
def _join(meet, fwd, bwd):
    left = [meet]                         # meet 에서 s 쪽으로 거슬러 올라감
    while fwd[left[-1]] is not None:
        left.append(fwd[left[-1]])
    right = []
    cur = bwd[meet]                       # meet 은 이미 left 에 있으므로 부모부터 시작
    while cur is not None:                # meet 에서 t 쪽으로
        right.append(cur)
        cur = bwd[cur]
    return list(reversed(left)) + right
```

두 가지만 짚으면 된다.

1. `left`는 `bfs_path()`와 완전히 같은 방식(부모 거슬러 오르기 → 뒤집기)이다. 결과는 `s → meet`.
2. `right`는 `bwd[meet]`부터 시작한다. `meet`을 건너뛰는 이유는 이미 `left`의 마지막 원소이기 때문이다. 그대로 넣으면 `meet`이 두 번 나온다. 그리고 `bwd`는 `t`에서 출발해 만든 맵이라 부모를 따라가면 자연히 `t` 방향이므로 **뒤집지 않는다**.

즉 `reversed(left)`는 `s→meet`, `right`는 `meet 다음 → t`. 이어 붙이면 `s → t` 전체 경로다.

---

## 정리

| 요소 | 역할 |
|---|---|
| `seen = {s: None}` | 부모 맵 초기화. `None`이 뿌리 표시 |
| `seen[v] = u` | v를 처음 발견한 순간에만 기록. 덮어쓰지 않음 → 최단성 |
| `while seen[path[-1]] is not None` | 부모가 없는 노드(= 시작점)까지 역추적 |
| `list(reversed(path))` | `t→s`로 모인 것을 `s→t`로 뒤집음 |
| `len(seen)` | 방문 노드 수. 양방향 탐색과의 비용 비교 지표 |

메모리 관점의 한마디: 부모 포인터는 방문한 노드 수에 비례해 쌓인다. 9장이 반복해 말하는 대로 평균 차수 12에서 5홉이면 그래프의 68%에 닿으므로, `seen`은 곧 그래프 전체 크기의 딕셔너리가 된다. `max_hop` 상한이 시간뿐 아니라 메모리 상한이기도 하다는 뜻이다.
