# 「최단 경로 하나」와 「모든 경로」의 복잡도 차이

> **Q.** 「최단 경로 하나」와 「모든 경로」의 복잡도 차이는 무엇인가?
>
> **A.** 앞은 다항 시간, 뒤는 지수 시간이다. "전부 보여 줘"라는 요구는 되물어야 한다.

출처: 9장 「몇 다리 건너인지 세다가 서버가 죽었다」 9.4절 '경로 하나와 경로 전부', 예제 `code/ex4_path_explosion.py`

---

## 한 줄 정리

같은 그래프, 같은 출발점, 같은 도착점인데 **질문 하나만 바꾸면 문제의 종류가 달라진다.**
「제일 짧은 거 하나 줘」는 다항 시간에 끝나고, 「가는 길 전부 줘」는 답 자체가 지수 개라서 끝나지 않는다.

---

## 왜 다른 문제인가

### 1. 최단 경로 하나 — 다항 시간

BFS나 다익스트라는 **노드마다 한 번씩만 확정**한다. 한 번 "여기까지 최단 거리는 얼마"라고 정하면 다시 안 본다.

| 알고리즘 | 조건 | 복잡도 |
|---|---|---|
| BFS | 가중치 없음 | `O(V + E)` |
| 다익스트라 (이진 힙) | 음수 가중치 없음 | `O((V + E) log V)` |
| 벨만-포드 | 음수 가중치 허용 | `O(V · E)` |
| A* | 허용 가능한 휴리스틱 | 최악은 다익스트라와 같으나 실측이 훨씬 빠름 |

핵심은 **출력 크기가 입력 크기에 비례**한다는 점이다. 경로 하나의 길이는 아무리 길어야 `V`를 넘지 못한다.

### 2. 모든 경로 — 지수 시간

여기서 문제는 알고리즘이 굼떠서가 아니라 **답을 다 적는 것만 해도 지수 개**라는 데 있다.
아무리 좋은 알고리즘을 써도 출력이 지수 개면 실행 시간도 지수다. 이걸 **출력 민감 하한(output-sensitive lower bound)** 이라고 부른다.

- 노드 `n`개짜리 완전 그래프에서 두 점 사이 단순 경로 수는 대략 `(n-2)!` 수준으로 는다.
- 단순 경로 개수를 **세는 것**조차 일반 그래프에서는 `#P-완전(#P-complete)` 문제다. 나열은 말할 것도 없다.
- Cypher의 `MATCH (a)-[*]-(b)` 처럼 **상한 없는 가변 길이 패턴**이 바로 이 함정이다.

## 예제 4가 보여 주는 숫자

`ex4_path_explosion.py`는 오른쪽/아래로만 가는 `n x n` 격자를 만든다.
이 격자에서는 모든 경로가 곧 최단 경로다(다 같은 길이). 그런데도 개수는 이렇게 는다.

| 격자 | 최단 경로 길이 | 서로 다른 경로 수 |
|---:|---:|---:|
| 3x3 | 4 | 6 |
| 5x5 | 8 | 70 |
| 8x8 | 14 | 3,432 |
| 11x11 | 20 | 184,756 |
| 15x15 | 28 | 40,116,600 |
| 20x20 | 38 | **35,345,263,800** |

- **길이**는 `2(n-1)`, 즉 **선형**으로 는다.
- **개수**는 `C(2(n-1), n-1)`, 즉 이항계수라 **조합적으로(≈ 4^n / √n) 폭발**한다.

20x20에서 이미 353억 개다. 경로 하나를 1바이트로 적어도 35GB, 실제로는 노드 38개씩 들어가니 TB 단위다.

> 예제의 `count_paths`는 메모이제이션으로 **세기만** 한다. 그래서 20x20도 순식간에 끝난다.
> 하지만 `go(u)`가 반환하는 건 정수 하나일 뿐, 경로를 `list`로 모으는 순간 메모리가 죽는다.
> **"세는 건 되는데 나열은 못 한다"** 가 이 예제의 핵심 문장이다.

## 격자보다 훨씬 나쁜 현실

격자는 그나마 얌전한 경우다. 실제 소셜/의존성 그래프는 9.1절에서 본 대로 **한 홉마다 11배**씩 는다.

- 평균 차수 12 → 홉당 분기 11 → 5홉이면 그래프의 68%, 6홉이면 사실상 전부
- 여기에 슈퍼 노드(차수 수만~수십만)가 하나만 끼어도 경로 수는 한 자릿수 홉에서 천문학적 수치가 된다

저자가 겪은 장애가 정확히 이 조합이었다.

> "「영향 범위를 다 보여 줘」를 모든 경로 열거로 구현했고, 어느 날 노드 하나가 슈퍼 노드가 됐다."

평소엔 잘 돌던 질의다. 데이터 분포가 바뀌는 순간 같은 코드가 서버를 죽인다.
**터지는 시점이 배포 시점이 아니라 데이터가 변한 시점**이라는 게 이 버그의 고약한 성질이다.

## 그래서 "전부 보여 줘"를 되물어야 한다

요구사항으로 「모든 경로」가 들어오면 그대로 구현하지 말고 다음 세 가지를 확인한다.

1. **정말 전부인가, 아니면 「가장 짧은 것 몇 개」인가?**
   → 대개는 후자다. 상위 K개면 Yen's K-shortest paths로 `O(K · V · (E + V log V))`, 다항 시간이다.
2. **길이 상한이 있나?**
   → `[*1..3]` 처럼 홉 상한을 박으면 최악 크기가 `분기^3`으로 묶인다. 상한 없는 순회는 전체 스캔과 같다.
3. **중간에 반드시 지나야 할 노드가 있나?**
   → 경유점이 있으면 문제를 작은 구간 여러 개로 쪼갤 수 있다.

### 실무에서 쓰는 대안

| 원래 요구 | 안전한 치환 |
|---|---|
| 모든 경로를 보여 줘 | 최단 경로 K개 (K=10 같은 상수) |
| 연결된 것 전부 | 홉 상한 2~3, 결과 개수 상한 |
| 영향 범위 전부 | 도달 가능 **노드 집합** (경로가 아니라 노드. BFS 한 번, 다항) |
| 경로가 몇 개나 되나 | DAG면 DP로 세기, 일반 그래프면 근사/샘플링 |

특히 네 번째 줄이 중요하다. **「도달 가능한 노드 집합」과 「도달하는 모든 경로」는 전혀 다른 문제**다.
전자는 `O(V + E)`, 후자는 지수다. 요구사항을 들어 보면 사실 전자를 원하는 경우가 많다.

---

## 한 줄 암기용

> **경로 하나는 다항, 경로 전부는 지수.**
> 출력이 지수면 알고리즘을 아무리 잘 짜도 지수다.
> 「전부」라는 단어가 나오면 상한을 물어라 — 개수 상한, 홉 상한, 아니면 "사실 노드 집합만 필요했다"는 답.
