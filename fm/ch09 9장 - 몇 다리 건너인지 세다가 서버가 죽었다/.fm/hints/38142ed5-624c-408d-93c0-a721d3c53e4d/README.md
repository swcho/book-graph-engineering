# 양방향 탐색을 쓸 수 없는 조건

**질문** — 양방향 탐색을 쓸 수 없는 조건은 무엇인가?

**답** — 도착지를 모를 때다. "이 사람과 3다리 안에 있는 사람 전부" 같은 질의는 양방향으로 풀 수 없다.

---

## 1. 양방향 탐색이 뭘 하는 것인가

9.2절의 주장은 이렇다. 평균 차수 12짜리 그래프에서 단방향 BFS는 한 홉마다 약 11배씩 불어난다. 거리 `d`만큼 걸어가면 방문 노드는 대략 `b^d` (여기서 `b ≈ 11`)이다.

양방향 탐색은 이 공을 쪼갠다.

- 단방향: 출발점 `s`에서 **반지름 d 짜리 공** 하나를 그린다 → `b^d`
- 양방향: `s`에서 반지름 `d/2`, `t`에서 반지름 `d/2` → **작은 공 두 개** → `2 · b^(d/2)`

공의 크기가 지수라서 반지름을 절반으로 줄이면 결과는 **제곱근**이 된다. `b^d`의 제곱근이 `b^(d/2)`이니까. 이 장의 `ex2_bidirectional.py` 실측에서 방문 노드가 75~88배 줄었다.

## 2. 그런데 공을 두 개 그리려면 중심이 두 개 있어야 한다

여기가 핵심이다. 뒤에서 걸어오는 BFS를 시작하려면 **뒤쪽의 시드(seed)가 필요**하다. 그 시드가 바로 도착지 `t`다.

에셋의 `ex2_bidirectional.py` 코드가 이 조건을 시그니처에 그대로 드러낸다.

```python
def bidi_path(adj, s, t, max_hop=8):
    if s == t:
        return [s], 1
    fwd, bwd = {s: None}, {t: None}   # ← 두 개의 시드. t 가 없으면 bwd 를 만들 수 없다
    fq, bq = deque([s]), deque([t])
```

`fwd`는 `s`에서 자라고 `bwd`는 `t`에서 자란다. 매 홉마다 번갈아 한 층씩 넓히다가, 새로 만난 노드가 반대편 집합(`other`)에 이미 있으면 그 지점이 **만남점(meeting point)**이고 거기서 양쪽 경로를 이어 붙인다(`_join`).

`t`를 모르면 `bwd = {t: None}`이라는 줄 자체를 쓸 수 없다. 알고리즘이 "느려지는" 게 아니라 **성립하지 않는다.**

예제의 마지막 출력문이 그대로 이 얘기다.

> 조건이 하나 있다. 도착지를 알아야 한다.
> «이 사람과 3다리 안에 있는 사람 전부»는 양방향으로 못 푼다.

## 3. 왜 "3다리 안 사람 전부"가 하필 반례인가

두 질의는 겉보기엔 비슷하지만 **문제의 종류가 다르다.**

| | 쌍 질의 (pair query) | 근방 질의 (neighborhood query) |
|---|---|---|
| 예시 | "A와 B는 몇 다리 건너인가" | "A와 3다리 안에 있는 사람 전부" |
| 입력 | 출발점 + **도착점** | 출발점 + **홉 상한** |
| 출력 | 경로 하나(또는 거리 하나) | 반지름 3짜리 공 **전체** |
| 양방향 | 쓸 수 있다 | 못 쓴다 |

근방 질의는 도착점이 애초에 존재하지 않는다. 찾으려는 것이 **특정 목표가 아니라 집합 전체**이기 때문이다.

그리고 설령 도착점을 억지로 하나 정해 봐도 소용없다. 양방향 탐색이 이기는 원리는 "**공 전체를 그리지 않고 만나는 순간 멈추기**"인데, 근방 질의의 정답이 곧 그 공 전체다. 출력 크기가 이미 `b^3`이므로 어떤 알고리즘도 그보다 적게 방문할 수 없다. 이걸 **출력 크기 하한(output-size lower bound)**이라고 부른다. 절감할 여지가 원리적으로 없다.

바꿔 말하면 이렇다.

> 양방향 탐색은 **탐색 공간을 줄이는** 기법이지, **결과 집합을 줄이는** 기법이 아니다.

## 4. 그래서 근방 질의는 어떻게 방어하나

양방향이 안 되니 다른 방어선이 필요하다. 9.1절의 결론("상한 없는 순회는 사실상 전체 스캔")과 이어지는 지점이다. 평균 차수 12에서 5홉이면 이미 전체의 68%, 6홉이면 전부에 닿는다.

- **홉 상한을 반드시 건다.** 3홉과 4홉은 11배 차이다. Cypher의 `[:KNOWS*1..3]` 같은 가변 길이 패턴에서 상한 없는 `*`는 금지에 가깝다.
- **결과 개수 상한(LIMIT)을 함께 건다.** 홉 상한만으로는 슈퍼 노드 하나에 걸리면 그대로 터진다.
- **조기 종료 / 스트리밍.** 전부 모아 반환하지 말고 프런티어를 흘려보내며 상한에 닿으면 끊는다.
- **슈퍼 노드 회피.** 차수가 특정 임계치를 넘는 노드는 확장하지 않거나 별도 처리한다.
- **사전 계산.** "2다리 이내 지인" 같은 고정 질의가 반복되면 질의 때 걷지 말고 미리 만들어 둔다.
- **요구사항 되묻기.** 9.4절의 "모든 경로를 보여 줘"와 같은 부류다. 정말 전부인지, 몇 개면 되는지, 상한이 있는지를 확인한다.

## 5. 놓치기 쉬운 부수 조건들

도착지를 아는 것 말고도 양방향 탐색에는 조건이 몇 개 더 붙는다. 카드의 정답은 아니지만 같이 알아 두면 좋다.

- **역방향으로 걸을 수 있어야 한다.** 무방향 그래프면 공짜지만, 방향 그래프에서 `t`부터 거꾸로 오려면 **들어오는 간선(in-edge) 인덱스**가 있어야 한다. 인접 리스트가 나가는 간선만 갖고 있으면 뒤쪽 BFS를 시작할 수 없다.
- **양쪽을 균형 있게 번갈아 넓혀야 한다.** 한쪽만 계속 키우면 결국 단방향과 같아진다. 예제도 `for q, seen, other in ((fq, fwd, bwd), (bq, bwd, fwd))`로 한 층씩 교대한다.
- **가중치 그래프에서는 만나자마자 끝내면 안 된다.** 무가중 BFS는 층 단위로 진행하니 첫 만남이 곧 최단이지만, 양방향 다익스트라는 처음 만난 지점이 최적이 아닐 수 있어 별도의 종료 조건이 필요하다.
- **한 대 한 질의여야 한다.** 도착지 후보가 수천 개면 뒤쪽 공이 그만큼 커져서 이득이 사라진다. 이 경우는 다중 소스 BFS나 사전 계산이 더 맞다.

## 6. 한 줄 정리

양방향 탐색은 **두 점 사이**의 문제를 푸는 도구다. 반지름을 절반으로 나눠 방문 수를 제곱근으로 만드는 대가로, **도착지를 알아야 한다**는 전제를 요구한다. "이 사람과 3다리 안 전부" 같은 근방 질의는 도착지가 없고 정답이 곧 공 전체라서 양방향으로 풀 수 없다. 이런 질의는 홉 상한과 결과 개수 상한으로 막아야 한다.
