# 매개 중심성 계산 비용에 대한 실용적 결론

**질문**: 매개 중심성 계산 비용에 대한 실용적 결론은 무엇인가?

**답**: 비싸지만 구조가 있는 그래프라면 표본 5%로도 상위권을 맞힌다.

---

## 한 줄로 줄이면

매개 중심성은 「전수로 돌리면 못 쓸 만큼 비싸다」와 「그런데 대개 전수로 돌릴 필요가 없다」가
동시에 참인 지표입니다. 단, 뒷문장에는 조건이 붙습니다 — **구조가 있는 그래프여야** 합니다.

---

## 1. 왜 비싼가

매개 중심성(betweenness centrality)은 이렇게 정의됩니다.

> 노드 v의 매개 중심성 = 모든 노드 쌍 (s, t)에 대해, s→t 최단 경로 중 v를 지나는 것의 비율을 다 더한 값

정의를 그대로 구현하면 「모든 쌍의 모든 최단 경로」를 열거해야 합니다. 10장 `ex1_centralities.py`가
바로 그 순진한 구현입니다.

```python
def betweenness_c(adj):
    """모든 쌍의 최단 경로를 세고, 각 노드가 몇 번 «지나가는 길목»이었는지 센다."""
    score = {v: 0.0 for v in adj}
    for s, t in combinations(sorted(adj), 2):
        paths = all_shortest(adj, s, t)
        ...
```

노드 20개짜리 조직도라면 괜찮지만 이건 실무용이 아닙니다. 실무 표준은 **브랜디스 알고리즘
(Brandes, 2001)** 입니다. 핵심 아이디어는 「경로를 열거하지 말고, 각 시작점 s마다 BFS 한 번 돌고
그 결과를 역순으로 되짚으며 기여도를 누적한다」는 것입니다.

```python
def brandes(adj, sources=None):
    """브랜디스 알고리즘. sources 를 주면 그 노드에서만 시작한다(근사)."""
    for s in (sources if sources is not None else adj):
        # 1) s 에서 BFS — 거리 dist, 최단 경로 수 sigma, 선행자 pred 를 채운다
        # 2) 스택을 역순으로 pop 하며 delta 를 누적 — 의존도(dependency) 누적
```

그래도 **시작점마다 BFS를 한 번씩** 돌아야 합니다. 그래서 비용은

| | 가중치 없는 그래프 | 가중치 있는 그래프 |
|---|---|---|
| 시간 | O(V·E) | O(V·E + V²·log V) |
| 공간 | O(V + E) | O(V + E) |

정의대로 구현할 때의 지수적/조합적 폭발에 비하면 극적인 개선이지만, **여전히 V와 E의 곱**입니다.
이게 다른 중심성과 결정적으로 다른 지점입니다.

| 지표 | 비용 감각 |
|---|---|
| 차수 중심성 | O(V + E) — 엣지 한 번 훑으면 끝 |
| 페이지랭크 | O(k·E), k는 반복 횟수(보통 수십 회) |
| 고유벡터 중심성 | O(k·E), 거듭제곱법 반복 |
| **매개 중심성** | **O(V·E)** — 노드 수만큼 그래프 전체를 훑는다 |

「노드가 두 배가 되면 시간이 네 배쯤 된다」는 게 여기서 나옵니다(E도 대략 V에 비례해 늘어나므로
V·E ≈ V²). 100만 노드짜리 그래프에서는 며칠 단위가 됩니다. 다른 지표는 커피 한 잔 사이에 끝나는데
매개만 배치 잡으로 넘어가는 이유입니다.

## 2. 그런데 대개 정확한 값이 필요 없다

여기가 실용적 결론의 핵심입니다.

> 「정확한 값」이 필요한 경우는 드물다. 대개 「누가 위에 있나」만 필요하다.

매개 중심성을 뽑는 실제 목적은 대부분 **급소 찾기**입니다. "누가 휴가 가면 조직이 갈라지나",
"어느 라우터가 죽으면 망이 쪼개지나". 0.0473이라는 숫자 자체가 아니라 상위 20개가 누구냐가 답입니다.

그렇다면 시작점 전부에서 BFS를 돌 필요가 없습니다. **일부만 뽑아서(pivot sampling) 돌리고,
그 결과를 스케일링**하면 됩니다. 브랜디스 구현에서는 `sources` 인자 하나로 끝납니다.

```python
sample = random.Random(3).sample(sorted(adj), max(5, n // 20))   # 노드의 5%
approx = brandes(adj, sample)                                     # 시작점만 5%
```

## 3. 실제 숫자 — `ex3_betweenness_cost.py`

책 예제를 그대로 돌린 결과입니다(커뮤니티 + 다리 구조를 가진 「구조 있는」 그래프).

```
      노드       전수 계산(s)     표본 5%(s)      상위 20 일치
----------------------------------------------------
     300           0.14         0.01           75%
     800           0.83         0.04           85%
    1600           3.52         0.16          100%
```

읽는 법이 두 가지입니다.

- **비용**: 5% 표본이므로 시간도 대략 1/20. 3.52초 → 0.16초.
- **품질**: 그래프가 커질수록 일치율이 **올라갑니다**(75% → 85% → 100%). 큰 그래프일수록
  구조가 뚜렷해지고 급소가 확실해져서, 표본을 어떻게 뽑든 같은 노드가 상위에 올라오기 때문입니다.
  비싸질수록 근사가 잘 듣는다 — 실무에서 반가운 방향의 비대칭입니다.

또 전수 계산 열의 증가폭을 보세요. 300 → 800 (2.7배)에서 시간은 0.14 → 0.83 (5.9배),
800 → 1600 (2배)에서 0.83 → 3.52 (4.2배). O(V²) 감각과 맞습니다.

## 4. 「구조가 있는 그래프라면」이 진짜 조건이다

답의 단서절을 흘려보내면 안 됩니다. 근사가 잘 듣는 건 알고리즘이 똑똑해서가 아니라
**그래프에 진짜 급소가 있어서**입니다.

같은 실험을 완전 무작위 그래프(Erdős–Rényi 류, 평균 차수 6)로 바꿔 돌리면 이렇게 됩니다.

```
     노드    상위 20 일치     1등/중앙값 비율
     300         35%              4.0
     800         50%              4.7
    1600         10%              4.6
```

대비를 위해 구조 있는 그래프의 분포를 같이 보면,

| 그래프 | 매개 중심성 1등 / 중앙값 | 표본 5% 상위 20 일치 |
|---|---|---|
| 구조 있음 (n=300) | **246배** | 75% |
| 구조 있음 (n=1600) | **1277배** | 100% |
| 완전 무작위 (n=300) | 4배 | 35% |
| 완전 무작위 (n=1600) | 5배 | 10% |

무작위 그래프에서는 매개 중심성이 **거의 평평합니다**. 1등이 중앙값의 고작 4~5배죠.
20등과 21등의 차이가 잡음 수준이라, "상위 20개"라는 집합 자체가 사실상 무작위입니다.
근사가 틀린 게 아니라 **애초에 맞힐 정답이 없는** 상황입니다.

반대로 구조 있는 그래프에서는 1등이 중앙값의 1000배대입니다. 다리 노드는 압도적으로 튀어서
어떤 표본으로 봐도 똑같이 튑니다. 그래서 근사가 듣습니다.

> 근사가 잘 듣는 건 「진짜 급소가 있는」 그래프에서다. 그리고 대개 그렇다.

마지막 문장이 실무적 위안입니다. 조직도, 소셜 그래프, 도로망, 서비스 의존성 그래프 —
현실 그래프는 거의 다 커뮤니티와 다리를 가집니다. 무작위 그래프는 교과서에나 있습니다.

## 5. 그래서 실무에서는 이렇게

**표본 근사를 써도 되는 경우**
- 상위 N개 급소 목록만 필요할 때
- 대시보드/모니터링처럼 주기적으로 순위만 갱신할 때
- 그래프가 커뮤니티 구조를 가진다는 걸 아는 경우 (거의 항상)

**전수 계산을 써야 하는 경우**
- **값 자체를 보고**할 때. 근사는 상위권은 잘 맞히지만 **하위권에서 많이 틀립니다.**
  "이 노드의 매개 중심성은 0.031입니다"라고 쓸 거면 전수를 돌려야 합니다.
- 순위 전체(꼬리 포함)를 쓰는 후속 계산에 넣을 때
- 그래프가 작아서 그냥 전수가 싼 경우(수천 노드 이하는 초 단위)

**빠뜨리기 쉬운 함정**
- **시드를 고정하세요.** 표본을 무작위로 뽑는데 시드가 없으면 같은 데이터로 어제와 오늘 다른
  순위가 나옵니다. 10장은 라벨 전파에서도 같은 잔소리를 합니다 — "고정했다는 사실을 문서에 적어야 한다."
- **표본 비율은 상수가 아닙니다.** 5%는 이 예제 그래프의 숫자입니다. 그래프가 아주 커지면
  절대 개수(예: 시작점 1000개)로 잡는 게 낫고, 아주 작으면 5%가 몇 개 안 돼서 의미가 없습니다
  (예제도 `max(5, n // 20)`으로 하한을 둡니다).
- **근사인지 명시하세요.** 리포트에 "매개 중심성 상위 20"이라고만 쓰면 읽는 사람은 전수라고 믿습니다.

## 6. 더 나아가면

표본 크기를 감으로 정하는 대신 **오차 보장**을 주는 계열이 있습니다. 이름만 알아 두면 됩니다.

- Brandes & Pich (2007): 피벗 선택 전략 비교 — 무작위가 의외로 나쁘지 않다
- Geisberger, Sanders, Schultes (2008): 선형 스케일링 편향을 줄인 개선 추정량
- Riondato & Kornaropoulos (2016) — **RK / ABRA**: VC 차원 기반으로 "오차 ε 이내를 확률 1-δ로
  보장하려면 표본이 몇 개 필요한가"를 계산해 준다
- Borassi & Natale (2019) — **KADABRA**: 상위 k개만 뽑는 데 특화한 적응형 표본

그리고 **매개 중심성은 그래프가 바뀔 때마다 다시 계산해야 한다**는 점도 비용의 일부입니다.
차수 중심성은 엣지 하나 추가되면 두 노드만 고치면 되지만, 매개는 다리 하나가 생기면
그래프 전체의 최단 경로 구조가 바뀝니다. 증분 갱신 알고리즘이 연구되어 있지만 구현이 까다로워서,
실무에서는 대개 **배치로 주기 재계산 + 표본 근사** 조합을 씁니다.

## 정리

| | |
|---|---|
| 비용 | 브랜디스로도 O(V·E). 다른 중심성보다 자릿수가 다르게 비싸다 |
| 근사 | 시작점 5%만 써도 상위권은 대부분 맞는다 (예제: 75~100%) |
| 조건 | **구조(커뮤니티+다리)가 있는 그래프**여야. 평평한 그래프에선 10~50%로 무너진다 |
| 한계 | 하위권 값은 많이 틀린다. 값을 보고할 거면 전수 |
| 위생 | 표본 시드 고정 + 근사임을 명시 |
