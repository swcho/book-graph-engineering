# 요약을 반복하면 '이유'와 '제약'이 먼저 죽는다

**Q.** 요약 반복에서 '이유'와 '제약'은 어떻게 되는가?

**A.** 네 번 만에 각각 5%, 6%로 떨어지고 다섯 번이면 0이 된다. 요약이 근거를 군더더기로 보기 때문이다.

---

## 1. 어디서 나온 숫자인가

24장 예제 3 (`code/ex3_summary_drift.py`)의 시뮬레이션 결과입니다. 사실 200개를 다섯 종류로 나눠 심어 놓고, 요약을 한 번 할 때마다 종류별 **생존 확률**을 굴려서 살아남은 비율을 재는 실험이에요.

```python
KINDS = {
    # 종류        가중치  한 번 요약할 때 살아남을 확률
    "숫자":       (0.20, 0.55),   # 금액, 개수 — 요약이 «대략»으로 바꾼다
    "고유명사":   (0.20, 0.80),   # 이름 — 비교적 잘 남는다
    "결정":       (0.20, 0.90),   # «~하기로 했다» — 요약이 제일 잘 지킨다
    "이유":       (0.20, 0.45),   # «왜 그렇게 했나» — 제일 먼저 날아간다
    "제약":       (0.20, 0.50),   # «~는 하면 안 된다» — 이것도 잘 날아간다
}
```

실행 결과:

```
   요약 회차     전체 생존       숫자     고유명사       결정       이유       제약
--------------------------------------------------------------
       0     100%    100%    100%    100%    100%    100%
       1      68%     63%     74%     90%     49%     55%
       2      52%     37%     65%     81%     35%     27%
       3      40%     23%     56%     71%     11%     18%
       4      30%     11%     47%     63%      5%      6%   ← 카드의 5%, 6%
       5      23%      3%     37%     56%      0%      0%   ← 카드의 «다섯 번이면 0»
```

## 2. 왜 그런 모양이 나오는가

핵심은 **회차마다 확률이 곱해진다**는 점입니다. 생존율은 선형이 아니라 지수로 떨어져요.

| 종류 | 1회 생존율 | 4회 이론값 (p⁴) | 표에서 관측 |
|---|---|---|---|
| 결정 | 0.90 | 66% | 63% |
| 고유명사 | 0.80 | 41% | 47% |
| 숫자 | 0.55 | 9% | 11% |
| 제약 | 0.50 | 6% | 6% |
| 이유 | 0.45 | 4% | 5% |

- 한 번 요약하면 전체 68%가 남습니다. 나쁘지 않아 **보입니다**.
- 다섯 번 반복하면 23%. 여기까지가 흔히 보는 관점(총량)이고요.
- 진짜 문제는 **총량이 아니라 구성**입니다. 표를 가로가 아니라 **세로로** 읽어야 보여요. 같은 23% 안에서 '결정'은 56%가 살아 있는데 '이유'와 '제약'은 이미 0입니다.

## 3. 왜 하필 이유와 제약이 먼저 날아가나

요약 모델은 «결론을 뽑는» 일을 하도록 훈련·프롬프팅됩니다. 그래서:

- **결정**(`~하기로 했다`)은 결론 그 자체라 제일 잘 지킵니다 (0.90).
- **이유**(`왜 그렇게 했나`)는 결론에 딸린 부연으로 보입니다. 요약 입장에서는 잘라내야 할 군더더기예요 (0.45).
- **제약**(`~는 하면 안 된다`)도 마찬가지로 배경 설명 취급을 받습니다 (0.50).
- **숫자**는 죽지는 않지만 «약 300만 원» 같은 근사로 뭉개지면서 사실상 값을 잃습니다 (0.55).

## 4. 왜 위험한가

원문 표현 그대로:

> 결정만 남고 이유가 사라진 컨텍스트를 받은 에이전트는 «그 결정을 왜 했는지» 모른 채로 **그 결정을 뒤집는다**. 제약이 사라지면 «하면 안 되는 일»을 **다시 시도한다**.

즉 요약 손실은 «조금 흐릿해지는» 문제가 아니라 **에이전트가 이미 끝난 논쟁을 다시 시작하고, 이미 금지된 행동을 다시 하는** 문제로 나타납니다. 게다가 남아 있는 '결정'들 때문에 컨텍스트는 겉보기에 멀쩡해 보여서, 손실이 눈에 잘 띄지 않습니다.

## 5. 실무 대응

책이 제시하는 처방은 두 갈래입니다.

**(1) 요약 프롬프트에 «반드시 보존할 종류»를 못 박는다**

- 숫자는 원문 그대로 옮긴다 (`약 300만 원` 금지)
- 결정에는 반드시 이유를 붙인다
- 금지 사항은 요약하지 않고 **목록으로 따로 뺀다**

**(2) 요약의 요약을 하지 않는다**

매번 **원문에서 다시** 요약합니다. p⁵가 아니라 언제나 p¹만 겪게 만드는 거예요. 이게 가능하려면 원문을 컨텍스트 밖에 갖고 있어야 하고, 그래서 이 장은 **오프로딩이 먼저**라고 말합니다.

## 6. 장 전체와의 연결

24장 「한 장 요약」의 해당 항목:

> 요약은 이유와 제약을 먼저 버립니다. 결정만 남고 이유가 없으면 에이전트가 그 결정을 뒤집고, 제약이 없으면 금지된 일을 다시 시도합니다. 프롬프트에 보존할 종류를 못 박고, 요약의 요약을 하지 마세요.

또 하나 이어지는 원칙: 무엇을 버릴지는 중요도가 아니라 「몇 번 쓰나」로 정하되, **사용자가 명시한 제약은 사용 횟수와 무관하게 남긴다**. 제약은 자주 참조되지 않지만 한 번 어기면 되돌리기 어렵기 때문입니다.

---

### 외우기 팁

- **결정은 남고 근거는 죽는다.** 요약은 결론을 좋아한다.
- **4회 → 5%/6%, 5회 → 0%.** (이유가 제약보다 살짝 더 잘 죽는다: 0.45 < 0.50)
- 처방 두 개: **보존 목록 못 박기** + **요약의 요약 금지(항상 원문에서)**
