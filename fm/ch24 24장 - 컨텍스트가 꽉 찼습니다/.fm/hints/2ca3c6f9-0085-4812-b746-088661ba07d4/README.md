# '최근 15턴만' 전략의 특성

**질문**: '최근 15턴만' 전략의 특성은 무엇인가?

**답**: 가장 많이 줄이고 가장 많이 잃는다. 대부분의 턴에서는 잘 동작하지만 필요한 사실이 30턴 전에 있던 그 한 번에 무너진다.

---

## 한 줄로

절감률 1등, 사실 보존율 꼴찌. **평소에는 최고, 결정적인 순간에 최악**인 전략입니다.

## 어디서 나온 이야기인가

24장 `code/ex2_strategies.py`는 컨텍스트를 줄이는 네 가지 방법을 나란히 놓고,
**토큰이 얼마나 줄었나**와 **나중에 실제로 참조되는 사실이 몇 % 남았나**를 같이 잽니다.

실험 설정은 이렇습니다.

- 60턴 대화, 두 턴에 한 번씩 「나중에 쓸 사실」을 심는다
- 심은 사실 중 62% 정도만 실제로 뒤에서 참조된다
- 줄이기를 거친 뒤 그 참조되는 사실이 몇 개나 살아남는지 센다

실제 실행 결과입니다.

```
60턴 대화, 원본 19,389 토큰. 나중에 실제로 필요한 사실 18개.

방법                           토큰      절감     남은 사실      사실 보존율
--------------------------------------------------------------
아무것도 안 함                 19,389     0%        18       100%
최근 15턴만                   4,610    76%         5        28%
오래된 것 요약                  6,383    67%        13        72%
밖에 저장 + 색인                4,886    75%        18       100%
```

`최근 15턴만`이 **절감 76%로 1등**입니다. 그리고 **사실 보존율 28%로 꼴찌**입니다.
필요한 사실 18개 중 13개를 그냥 버렸습니다.

구현은 한 줄짜리라 더 유혹적입니다.

```python
def last_n(turns, n=15):
    return turns[-n:]
```

## 왜 「대부분의 턴에서는 잘 동작」하는가

이게 이 전략의 함정입니다. 실제 대화의 대부분은 **국소적**입니다.
"방금 그거 좀 고쳐 줘", "그럼 이건 어때?" 같은 요청은 직전 몇 턴만 있으면 답이 나옵니다.

그래서 슬라이딩 윈도우를 붙이면 처음엔 아무 문제가 안 보입니다.
비용은 4분의 1로 떨어졌는데 품질 저하는 관측되지 않습니다.
테스트를 20턴까지만 돌리면 더더욱 안 보입니다 — 애초에 잘라 낼 게 없으니까요.

24장 도입부의 「20턴을 기준으로 잡은 이유는... 사실 없었습니다. 테스트할 때 그 정도만 해 봤을 뿐이에요」가
바로 이 함정과 같은 뿌리입니다.

## 어디서 무너지는가

문제는 평균이 아니라 **꼬리**에서 터집니다.

> 필요한 사실이 30턴 전에 나온 그 한 번에 무너진다.

- 사용자가 3턴째에 말한 "예산은 500만 원 이하로" → 40턴째에 창 밖으로 밀려남 → 에이전트가 800만 원짜리 안을 제시
- 2턴째에 정한 "이 API는 절대 쓰지 마세요" → 사라짐 → 금지된 API를 다시 시도
- 초반에 확정한 스키마 이름 → 사라짐 → 엉뚱한 컬럼명으로 쿼리 생성

게다가 **조용히** 실패합니다. 에러도 없고 예외도 없습니다.
잘린 것을 아무도 모르고, 에이전트도 자기가 뭘 모르는지 모릅니다.
그냥 자신 있게 틀린 답을 냅니다.

그리고 이 실패는 **재현이 어렵습니다**. 같은 질문을 짧은 대화에서 다시 물으면 잘 됩니다.
"가끔 이상해요"라는 버그 리포트로 들어오고, 원인이 컨텍스트 절단이라는 걸 알아내기까지 오래 걸립니다.

## 다른 방법들과의 자리

| 방법 | 절감 | 사실 보존 | 성격 |
|---|---|---|---|
| 아무것도 안 함 | 0% | 100% | 비용이 제곱으로 자란다 |
| **최근 N턴만** | **76%** | **28%** | 제일 싸고 제일 위험. 실패가 조용하다 |
| 오래된 것 요약 | 67% | 72% | 중간. 보존율은 요약 프롬프트에 달렸다 |
| 밖에 저장 + 색인 | 75% | 100% | 보존 1등. 대신 조회가 한 번 더 든다 |

- **요약**은 중간입니다. 다만 「어느 정도 남는가」가 요약 프롬프트에 달렸고, 재 보기 전에는 모릅니다.
  게다가 요약은 이유·제약을 먼저 버립니다(`ex3_summary_drift.py`).
- **밖에 저장 + 색인(오프로딩)**은 사실 보존에서 이깁니다. 색인만 남기고 본문은 밖에 두니까요.
  공짜는 아닙니다 — 꺼내 오는 조회가 한 번 더 들고, 그 조회가 엉뚱한 걸 꺼내 오면 요약보다 나쁠 수도 있습니다.

## 이 카드가 진짜로 말하는 것

원문의 결론은 개별 전략 평가가 아니라 **측정 방법**입니다.

> 표를 만들 때 「절감」만 보지 마시라. 오른쪽 두 칸이 없으면 절반만 잰 것이다.

`최근 15턴만`은 절감 칸만 보면 챔피언입니다.
사실 보존 칸을 붙이는 순간 순위가 뒤집힙니다.
같은 76% 절감을 오프로딩은 사실 보존율 100%로 해냅니다 — 같은 값에 훨씬 좋은 물건이 있었던 겁니다.

## 그래도 쓴다면

`최근 N턴만`을 완전히 버릴 필요는 없습니다. 다만 **단독으로** 쓰지 마세요.

- **고정 헤더를 판다**: 사용자가 명시한 제약, 초반에 확정한 결정은 턴 나이와 무관하게 항상 남긴다.
  24장 요약의 "사용자가 명시한 제약은 횟수와 무관하게 남기세요"가 이것입니다.
- **잘라 낸 부분을 밖에 저장한다**: 최근 N턴 + 오래된 것의 색인. 위 표의 마지막 행이 그 조합입니다.
- **N을 실제 사용 분포로 정한다**: 20턴은 테스트에서 나온 숫자였고, 실제 사용자는 평균 47턴이었습니다.
- **길게 테스트한다**: N턴을 넘기지 않는 테스트는 이 전략의 유일한 실패 모드를 절대 못 잡습니다.
