# '요약의 요약'을 하지 말라는 이유와 그 전제 조건

**Q.** '요약의 요약'을 하지 말라는 이유와 그 전제 조건은 무엇인가?

**A.** 회차마다 손실이 곱해지므로 매번 원문에서 다시 요약해야 한다. 그러려면 원문을 밖에 갖고 있어야 하므로 오프로딩이 먼저다.

---

## 1. 왜 안 되나 — 손실이 더해지는 게 아니라 곱해진다

요약은 무손실 압축이 아닙니다. 한 번 요약할 때마다 사실의 일부가 떨어져 나갑니다.
문제는 그 손실이 **더해지는 게 아니라 곱해진다**는 점입니다.

이미 요약된 결과물을 다시 요약하면, 남은 사실에 다시 생존율이 곱해집니다.

```
생존율(n회차) = 생존율(1회) ^ n
```

24장 `ex3_summary_drift.py`는 사실 200개를 심어 두고 요약을 반복합니다.

| 요약 회차 | 전체 생존 |
|---|---|
| 0 | 100% |
| 1 | 약 68% |
| 5 | 약 23% |

> "한 번 요약하면 68%가 남는다. 나쁘지 않아 보인다.
> 다섯 번 반복하면 23%다. 회차마다 곱해지니까 그렇게 된다."

한 회차만 보면 "68%면 괜찮네" 싶습니다. 이 착시가 위험합니다.
긴 세션에서는 요약이 한 번으로 끝나지 않고, 압축이 트리거될 때마다
직전 요약본을 입력으로 삼아 반복되기 때문입니다.

## 2. 더 중요한 건 "몇 %"가 아니라 "무엇이" 사라지느냐

예제는 사실을 다섯 종류로 나누고, 종류마다 한 번 요약할 때의 생존 확률을 다르게 줬습니다.

| 종류 | 1회 생존 확률 | 성격 |
|---|---|---|
| 결정 (`~하기로 했다`) | 0.90 | 요약이 제일 잘 지킨다 |
| 고유명사 | 0.80 | 비교적 잘 남는다 |
| 숫자 (금액·개수) | 0.55 | 요약이 "대략"으로 뭉갠다 |
| 제약 (`~하면 안 된다`) | 0.50 | 잘 날아간다 |
| 이유 (`왜 그렇게 했나`) | 0.45 | 제일 먼저 날아간다 |

요약은 결론을 좋아하고 근거를 군더더기로 봅니다. 그래서 **결정은 남고 이유와 제약은 사라집니다.**
반복하면 이 편향까지 곱해져서, 네 번째 회차쯤 이유·제약은 5~6%만 남고 다섯 번이면 0이 됩니다.

이게 왜 위험한가:

- **결정만 남고 이유가 사라진 컨텍스트**를 받은 에이전트는, 그 결정을 왜 했는지 모른 채 **결정을 뒤집습니다.**
- **제약이 사라지면** "하면 안 되는 일"을 **다시 시도합니다.**

즉 요약의 요약은 단순히 정보를 조금 잃는 게 아니라, 에이전트를 **자신 있게 틀리게** 만듭니다.
남은 23%는 "결정과 이름"이라 겉보기엔 멀쩡한 컨텍스트로 읽히거든요.

## 3. 대응 — 매번 '원문'에서 다시 요약한다

체인을 끊는 방법은 간단합니다. 요약의 입력을 항상 **직전 요약본이 아니라 원문**으로 고정합니다.

```
나쁨:  원문 → 요약1 → 요약2 → 요약3      (생존율 0.68 → 0.46 → 0.31)
좋음:  원문 → 요약1
       원문 → 요약2                      (매번 0.68, 곱해지지 않는다)
       원문 → 요약3
```

이러면 손실은 **매 회차 1회분으로 고정**됩니다. 누적되지 않습니다.

## 4. 전제 조건 — 그래서 오프로딩이 먼저다

여기에 함정이 있습니다. "매번 원문에서 다시 요약한다"는 건
**원문이 아직 어딘가에 남아 있어야** 성립합니다.

그런데 컨텍스트가 꽉 차서 요약을 한 것이고, 요약을 하고 나면 보통 원문은 컨텍스트에서 밀려납니다.
컨텍스트 안에만 원문이 있었다면 그 순간 원문은 사라지고, 다음 요약은 어쩔 수 없이
남아 있는 요약본을 입력으로 쓰게 됩니다. 즉 **요약의 요약이 강제됩니다.**

그래서 순서가 정해집니다.

> "그리고 요약의 요약을 하지 않는다. 매번 «원문»에서 다시 요약한다.
> 원문을 밖에 갖고 있어야 그게 가능하다. 그래서 오프로딩이 먼저다."

**오프로딩(offloading)** — 원문(대화 전체, 도구 결과, 문서 본문)을 컨텍스트 밖의 외부 저장소에 두고,
컨텍스트에는 색인이나 참조만 남기는 것 — 이 선행되어야 원문 재요약이 가능해집니다.

의존 관계로 쓰면 이렇습니다.

```
오프로딩(원문 보존)  →  매번 원문에서 재요약  →  손실이 곱해지지 않음
```

오프로딩 없이 "요약의 요약을 하지 마라"만 지키려 하면 지킬 수가 없습니다. **능력이 아니라 순서의 문제**입니다.

## 5. 함께 쓰는 실무 대응 (24.3절)

원문 재요약 외에, 요약 프롬프트에 "반드시 보존할 종류"를 못 박아 1회 손실 자체를 줄입니다.

- 숫자는 원문 그대로 옮긴다 ("약 300만 원" 같은 뭉개기 금지)
- 결정에는 반드시 이유를 붙인다
- 금지 사항(제약)은 요약하지 않고 목록으로 따로 뺀다

## 6. 한 줄 정리

| 항목 | 내용 |
|---|---|
| 하지 말 것 | 요약본을 다시 요약하기 |
| 이유 | 회차마다 생존율이 **곱해진다** (68% → 5회 반복 시 23%), 그리고 이유·제약이 먼저 날아가 에이전트가 결정을 뒤집고 금지 사항을 재시도한다 |
| 대신 할 것 | 매번 **원문에서 다시** 요약 (손실을 1회분으로 고정) |
| 전제 조건 | 원문이 컨텍스트 밖에 살아 있어야 한다 → **오프로딩이 먼저** |
