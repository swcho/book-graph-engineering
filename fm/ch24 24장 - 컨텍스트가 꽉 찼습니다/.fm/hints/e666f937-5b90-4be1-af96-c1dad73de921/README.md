# `ex3_summary_drift.py` — 다섯 종류의 사실과 생존 확률

## 한 줄 답

| 종류 | 생존 확률 | 코드 주석 |
|---|---|---|
| **결정** | **0.90** | 「~하기로 했다」 — 요약이 제일 잘 지킨다 |
| **고유명사** | **0.80** | 이름 — 비교적 잘 남는다 |
| **숫자** | **0.55** | 금액, 개수 — 요약이 「대략」으로 바꾼다 |
| **제약** | **0.50** | 「~는 하면 안 된다」 — 이것도 잘 날아간다 |
| **이유** | **0.45** | 「왜 그렇게 했나」 — 제일 먼저 날아간다 |

핵심은 이 숫자가 **한 번 요약할 때의** 생존 확률이라는 점입니다. 회차마다 곱해지기 때문에 요약을 반복하면 낮은 쪽이 급격히 무너집니다.

## 원본 코드

```python
KINDS = {
    # 종류        가중치  한 번 요약할 때 살아남을 확률
    "숫자":       (0.20, 0.55),   # 금액, 개수 — 요약이 «대략»으로 바꾼다
    "고유명사":   (0.20, 0.80),   # 이름 — 비교적 잘 남는다
    "결정":       (0.20, 0.90),   # «~하기로 했다» — 요약이 제일 잘 지킨다
    "이유":       (0.20, 0.45),   # «왜 그렇게 했나» — 제일 먼저 날아간다
    "제약":       (0.20, 0.50),   # «~는 하면 안 된다» — 이것도 잘 날아간다
}
N = 200
```

압축(요약) 한 번은 살아 있는 사실마다 주사위를 한 번 굴리는 것입니다.

```python
def compress(facts, rng):
    for f in facts:
        if f["alive"] and rng.random() > KINDS[f["kind"]][1]:
            f["alive"] = False
    return facts
```

`f["alive"]` 조건이 붙어 있으므로 **한 번 죽은 사실은 되살아나지 않습니다**. 그래서 회차별 생존율은 `p`, `p²`, `p³` … 로 곱해집니다. 이게 이 예제 전체의 논지입니다.

## 반복하면 어떻게 되나 (기댓값)

| 회차 | 결정 0.90 | 고유명사 0.80 | 숫자 0.55 | 제약 0.50 | 이유 0.45 | 평균 |
|---|---|---|---|---|---|---|
| 1 | 90% | 80% | 55% | 50% | 45% | 64% |
| 2 | 81% | 64% | 30% | 25% | 20% | 44% |
| 3 | 73% | 51% | 17% | 13% | 9% | 32% |
| 4 | 66% | 41% | 9% | 6% | 4% | 25% |
| 5 | 59% | 33% | 5% | 3% | 2% | 20% |

실제 실행은 시드 고정 난수(`random.Random(99)`, 사실 배치는 `random.Random(5)`)라 표본 오차가 있어 본문 해설은 「1회 68%, 5회 23%」로 적혀 있습니다. 종류마다 결과가 정확히 이 표와 일치하지는 않지만 순서와 격차는 그대로 나옵니다.

읽는 요령은 **가로로 읽는 것**입니다. 세로(전체 생존율)만 보면 「5번 요약해도 20% 남네」로 끝나지만, 가로로 보면 **살아남은 20%가 거의 전부 「결정」과 「고유명사」**라는 게 보입니다.

## 왜 이 배치가 위험한가

이 예제가 말하려는 건 「사실이 준다」가 아니라 **「사실이 편향되게 준다」**입니다.

- 결정 0.90은 높고, 이유 0.45는 낮습니다. → 결정만 남고 근거가 사라진 컨텍스트가 만들어집니다. 그 컨텍스트를 받은 에이전트는 **왜 그렇게 정했는지 모른 채로 그 결정을 뒤집습니다.**
- 제약 0.50도 낮습니다. → 「하면 안 되는 일」이 사라지면 에이전트가 금지된 일을 다시 시도합니다.
- 숫자 0.55는 요약이 정확한 값을 「대략 300만 원」 같은 표현으로 바꿔 버리기 때문입니다. 값이 남은 것처럼 보이지만 정밀도가 죽습니다.

요약 알고리즘의 버그가 아니라 **요약의 본성**입니다. 요약은 결론을 좋아하고 근거를 군더더기로 봅니다. 사람이 회의록을 줄일 때 하는 행동과 같습니다.

## 실무 대응 (본문 결론)

1. 요약 프롬프트에 **반드시 보존할 종류를 못 박습니다.**
   - 숫자는 원문 그대로 옮긴다 (「약 300만 원」 금지)
   - 결정에는 반드시 이유를 붙인다
   - 금지 사항은 요약하지 않고 목록으로 따로 뺀다
2. **요약의 요약을 하지 않습니다.** 매번 원문에서 다시 요약합니다. 그러면 손실이 곱해지지 않고 항상 1회분에 머뭅니다.
3. 그러려면 원문을 밖에 갖고 있어야 하므로 **오프로딩(24.4절, `ex4_offload.py`)이 요약보다 먼저**입니다.

## 앞뒤 예제와의 연결

- `ex2_strategies.py`는 「요약」을 하나의 전략으로 놓고 토큰 절감과 사실 보존율을 같이 쟀습니다(`fact_survival=0.6`이라는 단일 확률).
- `ex3_summary_drift.py`는 그 단일 확률을 **종류별로 쪼갠 것**이고, 나아가 **반복 적용**을 넣었습니다. 「평균 60% 남는다」가 실제로는 어떤 편향을 숨기고 있었는지 드러내는 게 목적입니다.

## 외우기

높은 쪽부터 **결정(0.90) → 고유명사(0.80) → 숫자(0.55) → 제약(0.50) → 이유(0.45)**.
「결정과 이름은 남고, 숫자·제약·이유는 반쯤 날아간다」로 묶어 두면 순서가 안 흔들립니다. 위험한 셋(숫자·제약·이유)이 모두 0.5 언저리에 몰려 있다는 것도 같이 기억하세요.
