# '결정'이 요약에서 잘 살아남는 이유

> **Q.** '결정'이 요약에서 잘 살아남는 이유는 무엇인가?
>
> **A.** 요약이 결론을 좋아하기 때문이다. 그래서 결정만 남고 이유가 사라지는 위험한 컨텍스트가 만들어진다.

---

## 1. 한 줄로

요약은 **"그래서 결론이 뭐냐"를 남기는 작업**이다. `~하기로 했다`는 문장은 요약이 지키려는 바로 그 형태이고, `왜 그렇게 했나`는 요약이 **군더더기로 분류하는** 형태다. 그래서 압축을 반복하면 결정만 살아남고 근거가 빠진, 겉보기에는 멀쩡한데 실제로는 위험한 컨텍스트가 남는다.

## 2. 어디서 나온 얘기인가 — 24.3절 「요약이 먼저 버리는 것」

24장 `ex3_summary_drift.py`는 사실 200개를 다섯 종류로 나눠 심어 두고, 요약을 반복하면서 종류별 생존율을 잰다. 핵심은 **종류마다 한 번 요약할 때 살아남을 확률이 다르게 설정되어 있다**는 점이다.

```python
KINDS = {
    # 종류        가중치  한 번 요약할 때 살아남을 확률
    "숫자":       (0.20, 0.55),   # 금액, 개수 — 요약이 «대략»으로 바꾼다
    "고유명사":   (0.20, 0.80),   # 이름 — 비교적 잘 남는다
    "결정":       (0.20, 0.90),   # «~하기로 했다» — 요약이 제일 잘 지킨다
    "이유":       (0.20, 0.45),   # «왜 그렇게 했나» — 제일 먼저 날아간다
    "제약":       (0.20, 0.50),   # «~는 하면 안 된다» — 이것도 잘 날아간다
}
```

**결정 0.90 vs 이유 0.45.** 이 두 숫자의 차이가 카드가 묻는 전부다. 그리고 이 값은 임의로 정한 게 아니라, 요약이라는 작업의 성격에서 나온다.

## 3. 왜 결정은 잘 남고 이유는 날아가나

| 종류 | 요약이 보는 방식 | 결과 |
|---|---|---|
| 결정 | 요약의 **목적물**. "결론만 말해 줘"가 요약 요청의 기본형 | 0.90, 거의 안 사라짐 |
| 고유명사 | 문장을 성립시키는 **주어/목적어**라 빼기 어려움 | 0.80 |
| 숫자 | 「약 300만 원」처럼 **뭉개도 문장이 성립**함 | 0.55, 정밀도부터 잃음 |
| 제약 | 「~는 하면 안 된다」는 결론에 딸린 **부가 조건**으로 취급 | 0.50 |
| 이유 | 근거·배경은 **분량 대비 기여가 낮은 군더더기**로 취급 | 0.45, 제일 먼저 |

요약은 본질적으로 **"짧게, 그러나 말이 되게"** 만드는 작업이다. 이유를 빼도 문장은 말이 된다. 결정을 빼면 요약할 이유 자체가 사라진다. 그래서 압축 압력은 항상 근거 쪽으로 먼저 간다.

## 4. 반복하면 격차가 벌어진다 — 곱셈이라서

한 회차 확률이 회차마다 곱해진다.

| 요약 회차 | 결정 (0.90ⁿ) | 이유 (0.45ⁿ) | 제약 (0.50ⁿ) |
|---:|---:|---:|---:|
| 1 | 90% | 45% | 50% |
| 2 | 81% | 20% | 25% |
| 3 | 73% | 9% | 13% |
| 4 | 66% | **5%** | **6%** |
| 5 | 59% | ~0% | ~0% |

예제 출력의 서술 그대로다.

```
«결정»은 잘 남는다. 요약이 결론을 좋아하기 때문이다.
«이유»와 «제약»은 빨리 사라진다. 네 번 만에 5%, 6%다. 다섯 번이면 0이다.
요약이 근거를 군더더기로 보기 때문이다.
```

전체 생존율은 1회에 68%로 "나쁘지 않아 보이고", 5회에 23%가 된다. **그런데 진짜 문제는 총량이 아니라 구성비다.** 남은 23% 안에서 결정의 비중은 올라가고 이유의 비중은 0에 수렴한다. 즉 **요약을 반복할수록 컨텍스트는 "근거 없는 결정 목록"에 가까워진다.**

## 5. 그게 왜 위험한가 — 답의 뒷부분

카드 답의 뒤 절반("위험한 컨텍스트가 만들어진다")이 실무적 핵심이다.

- **이유가 사라진 결정 → 에이전트가 그 결정을 뒤집는다.** 왜 그렇게 정했는지 모르는 상태에서 결정만 보면, 에이전트는 그 결정을 "지금 상황에서 최선이 아닌 선택"으로 판단하고 다시 고른다. 그리고 대체로 처음에 배제했던 안으로 돌아간다.
- **제약이 사라지면 → 금지된 일을 다시 시도한다.** 「이 API는 쓰면 안 된다」가 날아가면, 그 API가 문제 해결에 가장 편해 보이므로 다시 손을 뻗는다.

살아남은 결정은 **틀린 게 아니라서 더 위험하다.** 컨텍스트는 자신만만해 보이는데 그 결정을 지탱하던 조건이 전부 빠져 있다. 5절(기억 계층)의 "틀린 채로 빠르다"와 같은 종류의 실패다.

## 6. 대응 — 예제가 제시하는 세 가지

```
실무의 대응은 요약 프롬프트에 «반드시 보존할 종류»를 못 박는 것이다.
  - 숫자는 원문 그대로 옮긴다 («약 300만 원» 금지)
  - 결정에는 반드시 이유를 붙인다
  - 금지 사항은 요약하지 않고 목록으로 따로 뺀다

그리고 요약의 요약을 하지 않는다. 매번 «원문»에서 다시 요약한다.
원문을 밖에 갖고 있어야 그게 가능하다. 그래서 오프로딩이 먼저다.
```

1. **결정과 이유를 한 덩어리로 묶는다.** 「A를 쓰기로 했다(B가 타임아웃 나서)」처럼 이유를 결정 문장 안에 붙여 두면, 결정의 높은 생존율에 이유가 얹혀 간다. 별도 문장으로 두면 따로 잘린다.
2. **제약은 요약 대상에서 뺀다.** 금지 사항은 압축하지 않고 별도 목록으로 유지한다. 24장 「한 장 요약」의 "사용자가 명시한 제약은 횟수와 무관하게 남기세요"와 같은 규칙이다.
3. **요약의 요약을 하지 않는다.** 곱셈이 격차를 벌리는 원인이므로, 회차를 늘리지 않고 **매번 원문에서 1회 요약**하면 결정 0.90 / 이유 0.45가 유지된다. 이게 가능하려면 원문이 컨텍스트 밖에 남아 있어야 하고, 그래서 24.4절 오프로딩(참조만 상태에 싣기)이 요약보다 먼저 온다.

## 7. 시험에 나오는 포인트

- **"왜 잘 남나"의 답은 "중요해서"가 아니다.** 요약이라는 작업의 편향(결론 선호) 때문이다. 중요도로 답하면 절반만 맞다 — 이유와 제약도 똑같이 중요한데 날아간다.
- **결정이 살아남는 것 자체가 좋은 소식이 아니다.** 이유·제약과 **비대칭적으로** 살아남기 때문에 위험이 생긴다. 전부 균등하게 68% 남았다면 오히려 덜 위험했다.
- 관련 예제: `content/ch24/code/ex3_summary_drift.py`

## 관련 카드

- 요약을 반복할 때 가장 먼저 사라지는 사실 종류는? → 이유(0.45), 그다음 제약(0.50)
- 요약의 요약을 하지 말라는 이유는? → 생존 확률이 회차마다 곱해지므로
- 오프로딩이 요약보다 먼저인 이유는? → 원문이 밖에 있어야 매번 원문에서 1회 요약할 수 있으므로
