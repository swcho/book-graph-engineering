# 캐시 히트율을 확률 문제로 풀어 보기

> **질문** 캐시 한 줄과 정수 크기로 볼 때 지역성의 임계값은 얼마인가?
>
> **답** 캐시 한 줄 64바이트에 4바이트 정수 16개가 들어오므로, 이웃 번호 차이가 평균 16 미만이면 같은 줄에 들어올 확률이 생긴다.

이 답의 「확률이 생긴다」를 진짜 확률로 계산해 봅시다. 필요한 건 **균등분포**와 **기댓값**, 그리고 마지막에 **미분** 한 번입니다. 전부 확률과 통계, 미적분 교과 범위입니다.

## 1. 사물함 비유로 상황 정리하기

학교 복도에 사물함이 일렬로 있고, 번호는 0번부터입니다. 그런데 사물함 문이 개별로 안 열립니다. **16개가 한 묶음으로 묶여서, 묶음 단위로만 열립니다.**

- 0~15번이 한 묶음
- 16~31번이 다음 묶음
- 32~47번이 그다음 묶음

이게 컴퓨터 메모리의 **캐시 줄**입니다. 왜 16개씩인지는 나눗셈 한 번입니다.

$$\frac{\text{캐시 한 줄}\ 64\ \text{바이트}}{\text{정수 하나}\ 4\ \text{바이트}} = 16$$

CPU가 메모리에서 값 하나를 가져올 때, 실제로는 그 값이 속한 묶음 64바이트를 통째로 가져옵니다. 그러니까 정수 16개가 한꺼번에 옵니다.

이제 그래프 이야기와 연결합니다. 8장에서 이웃 노드의 번호를 배열의 첨자로 씁니다. 노드 $u$를 방문한 다음 이웃 $v$를 방문하면, 배열의 첨자 $u$번 칸과 $v$번 칸을 차례로 여는 셈입니다.

- 두 칸이 **같은 묶음**에 있으면 → 묶음을 이미 열어 놨으니 공짜입니다 (캐시 히트)
- 두 칸이 **다른 묶음**이면 → 새 묶음을 열러 창고까지 다녀와야 합니다 (캐시 미스)

「지역성」이란 결국 **이웃끼리 같은 묶음에 들어갈 확률**입니다.

## 2. 확률 계산을 위한 가정 세우기

번호 차이를 $d = |u - v|$라 하겠습니다. 이때 「같은 묶음일 확률」을 구하려면 조건이 하나 더 필요합니다. **차이만으로는 결정되지 않기 때문입니다.**

예를 들어 $d = 1$인 두 경우를 봅시다.

- 3번과 4번 → 둘 다 0~15 묶음. **같은 묶음** ✅
- 15번과 16번 → 15는 첫 묶음, 16은 두 번째 묶음. **다른 묶음** ❌

차이가 똑같이 1인데 결과가 다릅니다. 묶음 경계를 넘었는지가 갈랐습니다. 그래서 **첫 번째 칸이 묶음 안에서 몇 번째 자리인가**가 중요합니다.

칸 번호 $u$가 묶음 안에서 몇 번째 자리인지는 나머지로 구합니다.

$$r = u \bmod 16, \qquad r \in \{0, 1, 2, \dots, 15\}$$

여기서 핵심 가정을 세웁니다.

> **가정** 그래프 순회 중에 만나는 노드 번호의 나머지 $r$은 $\{0, 1, \dots, 15\}$ 위에서 **균등분포**를 따른다.

$$P(r = k) = \frac{1}{16} \quad (k = 0, 1, \dots, 15)$$

타당한 가정입니다. 노드 번호가 특별히 16의 배수 쪽으로 몰릴 이유가 없으니까요. 주사위를 16면체로 바꾼 것과 같은 상황입니다.

## 3. 확률 $p(d) = \max\!\left(0,\ \dfrac{16-d}{16}\right)$ 유도

이제 계산합니다. 시작 칸이 묶음의 $r$번째 자리에 있고, 거기서 $d$칸 뒤로 가면 도착 자리는 $r + d$입니다.

**같은 묶음에 머무는 조건**은 간단합니다. 묶음의 자리 번호는 0부터 15까지니까,

$$r + d \leq 15 \quad \Longleftrightarrow \quad r \leq 15 - d$$

이 조건을 만족하는 $r$이 몇 개인지 세면 끝입니다. $r$은 $0, 1, \dots, 15-d$이므로

$$(\text{경우의 수}) = (15 - d) - 0 + 1 = 16 - d$$

전체 경우가 16개이고 각각 확률이 $\frac{1}{16}$이므로

$$p(d) = \frac{16 - d}{16} = 1 - \frac{d}{16}$$

단, $d \geq 16$이면 $16 - d \leq 0$이 되어 경우의 수가 음수가 되는 모순이 생깁니다. 실제로는 **$d$가 16 이상이면 어떤 자리에서 출발해도 반드시 묶음을 넘어갑니다.** 확률 0입니다. 그래서 두 경우를 합쳐 씁니다.

$$\boxed{\ p(d) = \max\left(0,\ \frac{16 - d}{16}\right)\ }$$

### 검산

| $d$ | $p(d)$ | 소수 | 확인 |
|---|---|---|---|
| $0$ | $16/16$ | $1.0$ | 같은 칸이니 당연히 같은 묶음 ✅ |
| $1$ | $15/16$ | $0.9375$ | 바로 옆 칸도 1/16 확률로 경계를 넘음 |
| $4$ | $12/16$ | $0.75$ | |
| $8$ | $8/16$ | $0.5$ | 절반 |
| $15$ | $1/16$ | $0.0625$ | 거의 항상 넘어감 |
| $16$ | $0$ | $0$ | **여기가 절벽** |
| $100$ | $0$ | $0$ | 16 넘으면 다 똑같이 0 |

$d = 0$에서 1, $d = 16$에서 0. 그 사이는 기울기 $-\frac{1}{16}$인 직선입니다. 그래프로 그리면 왼쪽 위에서 내려오다가 $d = 16$에서 $x$축에 닿고, 그 뒤로는 쭉 0인 **꺾인 직선**입니다.

여기서 카드의 답이 왜 「같은 줄에 들어온다」가 아니라 **「들어올 확률이 생긴다」**인지 보입니다. 16은 좋고 나쁨의 경계가 아니라, **이득이 0으로 사라지는 지점**입니다. 이득은 $d$가 1에서 16으로 가는 동안 조금씩 깎여 나갑니다.

## 4. 기댓값으로 평균 접근 시간 구하기

확률을 구했으니 시간으로 바꿉니다. 확률변수의 기댓값 계산입니다.

메모리 계층의 지연 시간을 대략 이렇게 잡습니다(기계마다 다르니 자릿수만 봅니다).

- 캐시에 있으면 (히트): $T_{\text{hit}} \approx 1\ \text{ns}$
- 캐시에 없으면 (미스, DRAM까지): $T_{\text{miss}} \approx 80\ \text{ns}$

접근 시간을 확률변수 $T$로 보면, $T$는 확률 $p$로 $T_{\text{hit}}$, 확률 $1-p$로 $T_{\text{miss}}$를 갖습니다. 기댓값의 정의대로

$$\mathbb{E}[T] = p \cdot T_{\text{hit}} + (1 - p) \cdot T_{\text{miss}}$$

$p = p(d)$를 대입하면 번호 차이의 함수가 됩니다. $d < 16$인 구간에서

$$\mathbb{E}[T(d)] = \left(1 - \frac{d}{16}\right)\cdot 1 + \frac{d}{16}\cdot 80$$

계산해 보면 이렇습니다.

| $d$ | $p(d)$ | $\mathbb{E}[T]$ (ns) | $d \geq 16$ 대비 |
|---|---|---|---|
| $1$ | $0.9375$ | $0.94 + 5.0 = 5.94$ | **13.5배 빠름** |
| $4$ | $0.75$ | $0.75 + 20.0 = 20.75$ | 3.9배 빠름 |
| $8$ | $0.5$ | $0.5 + 40.0 = 40.5$ | 2.0배 빠름 |
| $15$ | $0.0625$ | $0.06 + 75.0 = 75.06$ | 1.07배 |
| $\geq 16$ | $0$ | $80.0$ | 기준 |

번호 차이를 100에서 1로 줄이면 접근 시간이 13.5배 줄어듭니다. **알고리즘을 한 글자도 안 바꾸고요.** 8장 `ex4_relabel.py`가 노드 번호를 다시 매기는 이유가 이 표입니다.

### 미분 한 번: 번호 차이를 1 줄이면 얼마를 버나

$\mathbb{E}[T]$를 $d$에 대한 함수로 보고 미분해 봅시다. $0 \leq d < 16$에서

$$\mathbb{E}[T(d)] = 1 + \frac{d}{16}(80 - 1) = 1 + \frac{79}{16}d$$

$$\frac{\mathrm{d}}{\mathrm{d}d}\,\mathbb{E}[T] = \frac{79}{16} \approx 4.94\ \text{ns}$$

**기울기가 상수입니다.** 해석하면 이렇습니다.

> 번호 차이를 1만큼 줄일 때마다 접근 하나당 약 4.94ns를 번다. 단, $d < 16$인 구간에서만.

$d \geq 16$ 구간에서는 도함수가 0입니다. 차이를 1000에서 500으로 줄여도 **아무 이득이 없습니다.** 100에서 20으로 줄여도 0입니다. 이득은 오직 16 아래로 들어왔을 때부터 발생합니다.

이게 재배치 최적화의 성격을 정확히 말해 줍니다. **어중간하게 하면 공짜로 얻는 게 없습니다.** 임계값 아래로 밀어 넣어야 비로소 이득이 시작됩니다. 그래서 「지역성의 임계값」이라는 표현을 쓰는 겁니다.

## 5. 그래프 전체로 확장하기 — 그리고 평균의 함정

지금까지는 엣지 하나였습니다. 그래프 전체의 히트율은 모든 엣지에 대한 평균입니다. 엣지가 $M$개이고 $i$번째 엣지의 번호 차이가 $d_i$라면

$$(\text{전체 히트율}) = \mathbb{E}[p(d)] = \frac{1}{M}\sum_{i=1}^{M} p(d_i)$$

그런데 8장 코드는 이렇게 계산하지 않습니다. **차이의 평균을 먼저 구하고, 그걸 16과 비교합니다.**

```python
def locality(edges):
    """엣지 양 끝 번호 차이의 평균. 작을수록 좋다."""
    return sum(abs(a - b) for a, b in edges) / len(edges)
```

즉 $\mathbb{E}[p(d)]$ 대신 $p(\mathbb{E}[d])$를 봅니다. **이 둘은 다릅니다.** 그리고 어느 쪽이 큰지도 정해져 있습니다.

### 구체적인 예로 확인

엣지 절반은 $d = 2$, 절반은 $d = 30$인 그래프를 상상합시다.

**방법 A — 코드처럼 평균부터:**
$$\mathbb{E}[d] = \frac{2 + 30}{2} = 16 \quad\Longrightarrow\quad p(16) = 0$$
히트율 0%. 「거의 매번 새 줄을 가져온다」고 판정합니다.

**방법 B — 제대로 각 엣지마다:**
$$\mathbb{E}[p(d)] = \frac{1}{2}\,p(2) + \frac{1}{2}\,p(30) = \frac{1}{2}\cdot\frac{14}{16} + \frac{1}{2}\cdot 0 = 0.4375$$
히트율 43.75%입니다. 절반의 엣지가 실제로 캐시 히트를 내고 있습니다.

접근 시간으로 바꾸면 차이가 더 뚜렷합니다.

- 방법 A 추정: $80\ \text{ns}$
- 방법 B 실제: $0.4375 \cdot 1 + 0.5625 \cdot 80 = 45.4\ \text{ns}$

**1.76배나 틀렸습니다.** 그것도 실제보다 나쁘게 본 방향으로요.

### 왜 항상 이 방향으로만 틀리는가

우연이 아닙니다. $p(d)$의 그래프 모양 때문입니다.

$p(d)$는 아래로 볼록한(convex) 꺾인 직선입니다. 볼록 함수의 성질을 고교식으로 말하면 이렇습니다.

> 그래프 위의 두 점을 잇는 선분은 항상 그래프보다 **위**(또는 같은 높이)에 있다.

$d = 2$일 때 점 $(2, 0.875)$, $d = 30$일 때 점 $(30, 0)$을 잡고 선분을 그으면, 그 선분의 중점은 $\left(16,\ 0.4375\right)$입니다. 한편 그래프 위의 $d = 16$인 점은 $(16, 0)$입니다. 선분의 중점 높이 $0.4375$가 그래프 높이 $0$보다 **위**에 있습니다. 방금 계산한 그 숫자입니다.

이걸 일반화한 게 **옌센 부등식(Jensen's inequality)**입니다. 볼록 함수 $f$에 대해

$$\mathbb{E}[f(X)] \geq f(\mathbb{E}[X])$$

우리 경우에 대입하면

$$\mathbb{E}[p(d)] \geq p(\mathbb{E}[d])$$

**결론: 평균 차이로 계산한 히트율은 실제 히트율의 하한(최소 보장값)입니다.**

실무에서 유용한 결론이 세 개 나옵니다.

1. 평균 차이가 16을 넘어도 히트율이 0은 아닙니다. `ex4_relabel.py`의 「거의 매번 새 줄」은 보수적인 표현입니다. 무작위 그래프처럼 평균 차이가 10,000이어도, 우연히 $d = 3$인 엣지들은 여전히 히트합니다.
2. 재배치 효과를 제대로 재려면 평균 대신 **분포**를 봐야 합니다. 예를 들어 「$d < 16$인 엣지의 비율」이 훨씬 정직한 지표입니다.
3. 커뮤니티 구조가 있는 그래프에서 재배치가 특히 잘 먹히는 이유도 이것입니다. 같은 커뮤니티 안의 엣지들이 한꺼번에 아주 작은 $d$로 몰리기 때문에, 평균은 별로 안 줄어도 분포의 왼쪽 꼬리가 두꺼워집니다.

## 6. 상수를 일반화하기 — 16은 계산 결과일 뿐

16이라는 숫자는 하드웨어 상수 두 개의 나눗셈이었습니다. 문자로 두면 어디에나 쓸 수 있습니다.

- $L$ = 캐시 한 줄의 바이트 수
- $s$ = 정수 하나의 바이트 수
- $K = L / s$ = 한 줄에 들어오는 정수 개수 = **임계값**

$$p(d) = \max\left(0,\ 1 - \frac{d}{K}\right), \qquad K = \frac{L}{s}$$

이제 상황별로 $K$를 계산해 봅시다.

| 상황 | $L$ | $s$ | $K$ |
|---|---|---|---|
| 표준 (x86-64, 일반 ARM) + 4바이트 정수 | 64 | 4 | **16** |
| 표준 + **8바이트** 정수 | 64 | 8 | **8** |
| **Apple Silicon (M1~M4)** + 4바이트 정수 | 128 | 4 | **32** |
| Apple Silicon + 8바이트 정수 | 128 | 8 | **16** |

두 가지가 읽힙니다.

- **노드 번호를 64비트로 잡으면 임계값이 절반으로 줄어듭니다.** 지역성 요구가 두 배로 까다로워집니다. 같은 그래프, 같은 재배치, 같은 CPU인데 히트율만 떨어집니다. 그래서 8장 코드가 `array("i", ...)`로 4바이트를 고집합니다.
- **Apple Silicon에서는 임계값이 32입니다.** 이 문서를 만든 기계(Apple M1 Pro)에서 확인한 값입니다.

```
$ sysctl hw.cachelinesize
hw.cachelinesize: 128
```

그러니까 M1에서 `ex4_relabel.py`를 돌리면, 평균 차이가 20으로 나와서 코드가 「거의 매번 새 줄」이라고 출력해도 실제로는

$$p(20) = 1 - \frac{20}{32} = 0.375$$

37.5% 확률로 같은 줄에 들어옵니다. 코드의 `after < 16` 판정이 이 기계에서는 지나치게 엄격한 겁니다. 임계값을 상수로 박아 두면 안 되는 이유입니다.

## 7. 마지막으로: 이 모델이 놓치는 것

정직하게 짚고 갑니다. 우리 모델은 실제 CPU보다 단순합니다.

CPU에는 **프리페처(prefetcher)**가 있습니다. 다음에 읽을 주소를 예측해서 미리 가져오는 장치입니다. 그래서 배열을 처음부터 끝까지 순서대로 훑는 접근은 미스가 나도 지연이 감춰집니다. 필요해지기 전에 도착하니까요.

그럼 우리 계산이 헛수고인가요? 아닙니다. 프리페처가 **못** 감추는 접근이 정확히 그래프 순회입니다.

```python
for i in range(offset[u], offset[u + 1]):   # ← 순차. 프리페처가 감춘다
    v = nbr[i]
    if not seen[v]:                          # ← v가 데이터에 의존. 못 감춘다
```

다음에 읽을 주소를 알려면 지금 값 `v`를 먼저 읽어야 합니다. 미리 가져올 방법이 없습니다. 이런 접근을 **포인터 체이싱**이라 부르고, 우리가 계산한 확률 모델이 지배하는 영역이 바로 여기입니다.

그리고 파이썬에서는 이 효과가 잘 안 보입니다. 8장 `ex2_csr_walk.py`가 관측한 대로입니다.

```
파이썬에서는 차이가 크지 않다. 인터프리터 오버헤드가 지배하기 때문이다.
같은 코드를 C 나 Rust 로 옮기면 CSR 쪽이 보통 3~10배 빨라진다.
```

파이썬은 배열 접근 한 번에도 수십~수백 ns의 자체 오버헤드가 붙습니다. 80ns짜리 메모리 미스가 그 안에 묻혀 버립니다. 우리가 계산한 5.94ns 대 80ns의 차이는, **메모리 지연이 지배하는 언어에서만 눈에 보입니다.**

## 정리

$$\text{임계값 } K = \frac{\text{캐시 줄 크기}}{\text{노드 ID 크기}} = \frac{64}{4} = 16$$

$$\text{히트 확률 } p(d) = \max\left(0,\ 1 - \frac{d}{K}\right) \quad (\text{나머지 } r \text{의 균등분포에서 유도})$$

$$\text{평균 접근 시간 } \mathbb{E}[T] = p\,T_{\text{hit}} + (1-p)\,T_{\text{miss}}, \qquad \frac{\mathrm{d}\mathbb{E}[T]}{\mathrm{d}d} = \frac{T_{\text{miss}} - T_{\text{hit}}}{K}$$

$$\text{그리고 } \mathbb{E}[p(d)] \geq p(\mathbb{E}[d]) \quad (\text{평균으로 재면 과소평가})$$
