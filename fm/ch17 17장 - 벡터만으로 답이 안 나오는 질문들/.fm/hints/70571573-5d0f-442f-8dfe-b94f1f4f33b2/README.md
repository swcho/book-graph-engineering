# 순위 융합이 항상 이기지 않는 이유

**Q. 순위 융합이 항상 이기지 않는 이유는 무엇인가?**

**A. 융합은 «둘 다 상위에 올린 것»을 밀어 올리는 방식이라, 한쪽만 아는 정답은 순위가 내려간다.**

## 1. RRF는 구조적으로 «합의»에 베팅한다

순위 융합의 사실상 표준은 RRF(reciprocal rank fusion)다. 각 엔진의 순위 목록에서 문서가 `pos`위에 있으면 `1 / (k + pos)` 점수를 주고(관례상 `k = 60`), 여러 엔진의 점수를 **더해서** 다시 정렬한다.

```python
def rrf(*rankings, k=60):
    score = defaultdict(float)
    for r in rankings:
        for pos, item in enumerate(r, 1):
            score[item] += 1 / (k + pos)
    return sorted(score, key=lambda x: -score[x])
```

점수를 더하는 구조이므로:

- **두 엔진 모두**가 적당히 상위에 올린 문서 → 점수가 두 번 쌓여서 크게 올라간다.
- **한쪽 엔진만** 아는 문서 → 아무리 그 엔진에서 상위(예: 2위)여도 점수를 한 번만 받는다.

즉 RRF는 「양쪽이 동의한 것이 정답일 가능성이 높다」는 **합의 편향(consensus bias)** 을 내장한 알고리즘이다. 이 편향이 맞아떨어지면 각 엔진 단독보다 좋아지고, 어긋나면(정답을 한쪽만 알 때) 오히려 나빠진다.

## 2. 수치 예시 — 책 예제(ex4_hybrid_fusion.py) 그대로

두 엔진이 같은 질문에 낸 순위와 정답 집합:

```
벡터   : [d11, d01, d09, d05, d02]
그래프 : [d12, d02, d06, d09, d03]
정답   : {d01, d02, d06, d09},  k = 60
```

RRF 점수 계산:

| 문서 | 벡터 기여 | 그래프 기여 | 합계 | 융합 순위 | 정답? |
|---|---|---|---|---|---|
| d02 | 1/65 = .01538 | 1/62 = .01613 | **.03151** | 1위 | O |
| d09 | 1/63 = .01587 | 1/64 = .01563 | **.03150** | 2위 | O |
| d11 | 1/61 = .01639 | — | .01639 | 3위 | X |
| d12 | — | 1/61 = .01639 | .01639 | 4위 | X |
| d01 | 1/62 = .01613 | — | .01613 | **5위** | O |
| d06 | — | 1/63 = .01587 | .01587 | 6위 | O |

### 융합이 이기는 쪽

두 엔진 모두 1위가 오답(d11, d12)이었는데, 각자 «두 번째로 확신하던 것»(d02, d09)이 겹쳐서 융합 1·2위가 모두 정답이 된다. P@1이 벡터 0.00, 그래프 0.00 → 융합 1.00.

### 융합이 지는 쪽 — 카드의 핵심

정답 **d01**을 보라. 벡터 엔진 단독으로는 **2위**였다. 그런데 그래프 엔진이 전혀 모르는 문서라 점수를 한 번만 받았고, 융합 결과에서는 **5위**로 밀렸다. 심지어 오답인 d11, d12(각 엔진의 단독 1위)보다도 아래다. 한쪽 엔진이 이미 잘 찾아 놓은 정답이, 다른 엔진이 몰랐다는 이유만으로 순위가 내려간 것이다. 이런 질문 유형이 많은 워크로드라면 융합이 단독 엔진보다 못할 수 있다 — 그래서 «융합이 항상 이기지는 않는다».

## 3. 그럼 언제 융합을 쓰나 — 두 기준

책의 기준은 둘이다.

1. **라우터의 정확도가 낮을 때** — 질문을 엉뚱한 엔진으로 잘못 보내는 것보다, 둘 다 돌리고 합치는 편이 안전하다.
2. **질문이 여러 유형에 걸칠 때** — «김하늘 담당 장애의 원인과 그 문서»처럼 그래프(관계)와 벡터(문서 내용)가 모두 필요한 질문.

대가도 명확하다. **매번 두 번 검색**하므로 비용이 두 배이고 지연도 는다. 그래서 저자가 실제로 쓰는 구조는 절충형이다:

> 라우터가 확신하면(임계값 위) 한쪽만 돌리고, 애매하면 둘 다 돌려 융합한다.
> 이러면 애매한 20%만 두 배 비용을 낸다.

## 한 줄 요약

RRF는 점수를 **더하는** 합의 기반 알고리즘이라 양쪽이 겹치는 문서를 밀어 올린다. 그 대칭적 결과로, 한쪽 엔진만 아는 정답은 (그 엔진 단독일 때보다) 순위가 내려간다. 융합은 라우터가 못 미덥거나 질문이 여러 유형에 걸칠 때 쓰되, 검색 두 번의 비용을 감수하는 선택이다.
