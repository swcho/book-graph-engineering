# ex4_hybrid_fusion.py에서 융합이 이긴 이유

## 카드

- **질문**: `ex4_hybrid_fusion.py`에서 융합이 이긴 이유는 무엇인가?
- **답**: 두 엔진 모두 1위가 오답이었지만 각자 두 번째로 확신한 것이 겹쳐서, 융합하면 그것이 1위로 올라온다.

## 무엇을 하는 예제인가

17장의 예제 4는 「라우팅 대신 둘 다 돌리고 합치기」, 즉 하이브리드 검색을 다룬다. 같은 질문에 대해 벡터 엔진과 그래프 엔진이 각각 낸 순위 목록을 **순위 융합(reciprocal rank fusion, RRF)** 으로 합친 뒤, 정답 문서 집합(GOLD) 기준으로 P@n(상위 n개 중 정답 비율)을 비교한다.

```python
VECTOR_RANK = ["d11", "d01", "d09", "d05", "d02"]   # 벡터 엔진의 순위
GRAPH_RANK  = ["d12", "d02", "d06", "d09", "d03"]   # 그래프 엔진의 순위

GOLD = {"d01", "d02", "d06", "d09"}   # 사람이 확인한 정답 문서
K = 60                                 # RRF 상수. 60이 관례다.

def rrf(*rankings, k=K):
    score = defaultdict(float)
    for r in rankings:
        for pos, item in enumerate(r, 1):
            score[item] += 1 / (k + pos)
    return sorted(score, key=lambda x: -score[x])
```

RRF는 점수(유사도, 그래프 거리 등)를 직접 비교하지 않고 **순위만** 본다. 각 목록에서 pos위에 오른 문서에 `1/(k+pos)`를 더해 합산하므로, 서로 스케일이 다른 두 엔진의 결과도 그대로 합칠 수 있다.

## 왜 융합이 이겼는가 — 순위표로 보기

두 엔진의 1위를 보자.

| 순위 | 벡터 | 그래프 |
|---|---|---|
| 1위 | **d11 (오답)** | **d12 (오답)** |
| 2위 | d01 (정답) | **d02 (정답)** |
| 3위 | **d09 (정답)** | d06 (정답) |
| 4위 | d05 (오답) | **d09 (정답)** |
| 5위 | **d02 (정답)** | d03 (오답) |

- **두 엔진 모두 1위가 오답**이다(d11, d12). 각 엔진 단독으로는 P@1 = 0.00.
- 그런데 **d02와 d09는 양쪽 목록 모두에 등장**한다. d02는 벡터 5위 + 그래프 2위, d09는 벡터 3위 + 그래프 4위.
- 반면 오답 1위 d11, d12는 **한쪽 목록에만** 있어서 점수를 한 번밖에 못 받는다.

RRF 점수를 실제로 계산하면 (k=60):

| 문서 | 계산 | RRF 점수 | 정답? |
|---|---|---|---|
| d02 | 1/65 + 1/62 | **0.031514** | 정답 |
| d09 | 1/63 + 1/64 | **0.031498** | 정답 |
| d11 | 1/61 | 0.016393 | 오답 |
| d12 | 1/61 | 0.016393 | 오답 |
| d01 | 1/62 | 0.016129 | 정답 |
| d06 | 1/63 | 0.015873 | 정답 |
| d05 | 1/64 | 0.015625 | 오답 |
| d03 | 1/65 | 0.015385 | 오답 |

두 목록에 모두 등장한 d02, d09는 점수를 **두 번** 받아, 한 번만 받은 단독 1위들(1/61 ≈ 0.0164)을 훌쩍 넘는다. 융합 순위는 `[d02, d09, d11, d12, d01, d06, d05, d03]` — **1위가 정답 d02로 바뀐다.**

핵심 메커니즘을 책의 표현으로 요약하면:

> 두 엔진 모두 1위가 오답인데, 융합하면 1위가 정답이 된다.
> 각자 «두 번째로 확신하는 것»이 겹쳤기 때문이다.

즉 각 엔진이 최상위로 밀지는 않았지만 상위권에 함께 올린 문서(둘 다 어느 정도 확신하는 문서)가, 한쪽만 확신한 오답 1위를 밀어내고 올라온 것이다. 서로 다른 방식으로 틀리는 두 엔진의 **오류가 상관되어 있지 않을 때**, 겹치는 신호(합의)가 정답일 가능성이 높다는 것이 순위 융합이 작동하는 근본 이유다.

## P@n으로 확인

| 방식 | P@1 | P@2 | P@3 | P@4 |
|---|---|---|---|---|
| 벡터 | 0.00 | 0.50 | 0.67 | 0.50 |
| 그래프 | 0.00 | 0.50 | 0.67 | **0.75** |
| 융합 | **1.00** | **1.00** | 0.67 | 0.50 |

## 단서 — 융합이 항상 이기지는 않는다

P@4를 보면 융합(0.50)이 그래프 단독(0.75)에 진다. 정답 d06은 그래프만 알고 있는데(그래프 3위, 벡터 목록에 없음), 점수를 한 번밖에 못 받아 융합 순위에서 6위로 밀렸다. 책의 표현대로:

> 다만 융합이 항상 이기지는 않는다. 한쪽만 아는 정답은 순위가 내려간다.
> 융합은 «둘 다 상위에 올린 것»을 밀어 올리는 방식이라 그렇다.

## 그럼 언제 융합을 쓰나

책이 제시하는 기준은 둘이다.

1. **라우터의 정확도가 낮을 때** — 잘못 보내는 것보다 둘 다 돌리는 게 낫다.
2. **질문이 여러 유형에 걸칠 때** — 「김하늘 담당 장애의 원인과 그 문서」처럼 사실 조회와 관계 추적이 섞인 질문.

대가는 비용이다. 매번 두 번 검색하고 지연도 는다. 저자가 실제로 쓰는 구조는 절충안: **라우터가 확신하면(임계값 위) 한쪽만, 애매하면 둘 다** — 이러면 애매한 20%만 두 배 비용을 낸다.
