# 우리는 사내 용어로 쓰고, 사용자는 자기 말로 묻는다

**Q.** 사용자 어휘 불일치에 대한 대응은 무엇인가?

**A.** 동의어를 설명에 넣는다(상사·상급자·윗사람·결재선). 실제 질문 로그에서 뽑아 넣으면 더 좋다.

---

## 1. 카드 문장의 출처

25.5절 「도구 설명이 곧 엣지 선택 함수다」와 예제 5(`code/ex5_tool_selection.py`)입니다. 예제 5는 도구 코드를 한 줄도 고치지 않고 **설명만** 바꿔서 선택 정확도를 잽니다.

```python
BAD = {
    "find_person":      "사람 조회",
    "chain_of_command": "체인 조회",
    "team_members":     "팀 조회",
}
```

설명이 좋아진 뒤에도 **딱 한 건**이 계속 틀렸고, 그게 이 카드의 소재입니다.

> 남은 하나 «박민수 상급자 알려줘»가 재미있다.
> 설명에는 «상사»가 있는데 사용자는 «상급자»라고 했다. 단어가 안 겹친다.
> 이게 도구 설명을 쓸 때 제일 자주 놓치는 지점이다.
> 우리는 사내 용어로 쓰고, 사용자는 자기 말로 묻는다.
>
> 대응은 «동의어를 설명에 넣는 것»이다. 상사·상급자·윗사람·결재선.
> 촌스러워 보여도 이게 듣는다. 실제 질문 로그에서 뽑아 넣으면 더 좋다.

## 2. 「어휘 불일치」가 정확히 무엇인가

도구 설명은 사람이 읽는 문서가 아니라 **엣지 선택 함수**입니다(25.5절). 모델은 질문과 설명 사이의 의미 거리를 재서 엣지를 고릅니다. 그러니 설명에 없는 말로 물으면 그 엣지의 점수가 낮아집니다.

예제 5의 선택기는 이걸 극단적으로 단순화해서 보여 줍니다.

```python
def tokenize(s):
    return set(re.findall(r"[가-힣A-Za-z]+", s))

def choose(query, descriptions):
    q = tokenize(query)
    best, score = None, -1
    for name, desc in descriptions.items():
        overlap = len(q & tokenize(desc))     # «겹치는 단어 수»가 전부다
        if overlap > score:
            best, score = name, overlap
    return best
```

`{"박민수", "상급자", "알려줘"}` 와 `chain_of_command` 설명의 `{…, "상사", "보고", "라인", "결재선", …}` 은 교집합이 **0**입니다. 그래서 엉뚱한 도구가 뽑힙니다.

책이 스스로 밝히듯 이 선택기는 모델보다 훨씬 멍청합니다. 실제 모델은 임베딩·문맥으로 「상급자 ≈ 상사」를 상당 부분 메꿔 줍니다. 그런데도 이 예제가 유효한 이유는 이렇습니다.

> 여기 쓴 선택기는 단어가 겹치는 걸 세는 게 전부다. 모델보다 훨씬 멍청하다.
> 그런데 «설명이 나쁘면 못 고른다»는 성질은 모델도 같다.

모델은 실패의 **문턱을 낮춰 줄 뿐** 성질을 없애지 못합니다. 특히 사내 은어·약어·시스템 고유명사(「결재선」, 「TF장」, 「셀 리드」, 「N차 승인」)는 학습 데이터에 일반적 의미가 없어서, 모델도 그냥 못 맞힙니다.

## 3. 동의어 주입이 왜 통하는가

동의어를 설명에 넣는 건 촌스럽지만, 통하는 이유가 세 가지 있습니다.

1. **경로가 제일 짧다.** 프롬프트를 안 고치고, 라우터를 안 만들고, 모델을 안 바꿉니다. 도구 정의 문자열 한 줄이 바뀝니다. 배포 단위가 작으니 롤백도 한 줄입니다.
2. **선택 함수의 정의역을 넓히는 일이다.** 「이 도구가 무엇을 하는가」는 그대로 두고, 「어떤 말로 물었을 때 이 도구인가」를 넓힙니다. 도구의 능력이 아니라 **입구**를 늘리는 것이라 부작용의 종류가 예측 가능합니다(4절).
3. **불일치가 시스템 쪽 결함이기 때문이다.** 사용자가 「자기 말」을 고쳐 주기를 기다릴 수는 없습니다. 어휘를 맞추는 책임은 도구를 쓴 쪽에 있습니다.

책이 정리한 좋은 설명의 3요소에서 동의어는 2번 자리입니다.

> 1. 무엇을 «주는지» (반환값을 말한다)
> 2. 어떤 «말»로 물었을 때 이것인지 (사용자 어휘를 넣는다)
> 3. 언제 «안» 쓰는지 (경계를 긋는다)

`GOOD` 설명이 이미 2번을 부분적으로 하고 있었다는 점을 보세요. `team_members` 에는 「명단, 누구누구, 구성원, 몇 명을 물으면 이것이다」가 들어 있고, 그 질문들은 다 맞혔습니다. 실패한 건 2번이 **덜 채워진** 도구 하나였습니다. 즉 동의어 주입은 새 기법이 아니라 이미 하던 것을 끝까지 하는 일입니다.

카드의 처방을 그대로 적용하면 이렇게 됩니다.

```python
"chain_of_command":
    "한 사람의 «위로 올라가는» 보고 체계를 뿌리까지 준다. "
    "상사, 상급자, 윗사람, 팀장, 보고 라인, 결재선, 결재 라인, "
    "«누구한테 보고하나», «위로 누가 있나»를 물으면 이것이다. "
    "아래 부하 목록에는 쓰지 않는다.",
```

## 4. 질문 로그에서 어휘를 뽑는 절차

「실제 질문 로그에서 뽑아 넣으면 더 좋다」가 핵심입니다. 동의어를 **상상해서** 넣으면 그것도 결국 우리 어휘입니다. 우리가 못 떠올리는 말을 사용자가 쓰기 때문에 불일치가 생긴 것이니까요. 순서는 이렇습니다.

1. **원문 질문을 남긴다.** 도구 호출 로그에 `질문 원문 / 고른 도구 / 인자 / 성공 여부 / 사용자가 재질문했는지` 를 같이 적습니다. 정규화·요약된 질문만 남기면 어휘가 지워져서 이 작업 자체가 불가능해집니다.
2. **실패 사례를 먼저 본다.** 도구가 안 불린 질문, 틀린 도구가 불린 질문, 같은 걸 말만 바꿔 다시 물은 질문(재질문 = 라벨이 붙은 실패입니다), 폴백/사과 응답으로 끝난 질문.
3. **질문을 도구로 라벨링한다.** 「이 질문에 맞는 도구는 무엇이었나」를 사람이 붙입니다. 25.3절이 라우터에 대해 말한 것과 같은 얘기입니다. 「제일 먼저 만들 것은 라우터가 아니라 채점하는 데이터셋」이고, **100건이면 시작할 수 있습니다.** 예제 5의 `QUERIES` 는 이 데이터셋의 8건짜리 축소판입니다.
4. **설명에 없는 단어를 뽑는다.** 라벨된 정답 도구의 설명 토큰과 질문 토큰의 **차집합**을 셉니다. 예제 5의 `tokenize` 를 그대로 돌려도 됩니다. 빈도순으로 세우면 「상급자」처럼 자주 나오는데 설명에 없는 말이 위로 올라옵니다.
5. **후보를 골라 넣는다.** 빈도 높고, **한 도구에만 쏠린** 말을 먼저 넣습니다. 여러 도구의 질문에 두루 나오는 말(「알려줘」, 「정보」, 「좀」)은 넣지 않습니다. 그건 동의어가 아니라 잡음이고, 넣으면 4절이 아니라 5절의 부작용을 부릅니다.
6. **넣고 다시 잰다.** 3번에서 만든 데이터셋으로 정확도를 재고, **떨어진 항목이 없는지** 확인합니다. 새 어휘가 다른 도구의 정답을 뺏어 갔을 수 있습니다. 예제 5의 `run()` 이 하는 일이 정확히 이 회귀 측정입니다.
7. **반복 주기를 둔다.** 조직 어휘는 변합니다(조직 개편, 새 시스템 이름). 도구가 추가될 때와 분기마다 4~6을 다시 돕니다.

즉 「로그에서 뽑는다」는 감이 아니라 **채점 데이터셋 + 차집합 + 회귀 측정**의 짧은 루프입니다.

## 5. 무한정 넣으면 무엇이 무너지는가

동의어 주입이 공짜라면 모든 도구 설명에 사전을 다 밀어 넣으면 됩니다. 안 되는 이유가 이 카드의 균형점입니다.

- **도구 간 경계가 흐려진다.** 동의어를 넣는 건 그 도구의 입구를 넓히는 일이고, 입구가 넓어지면 **옆 도구의 입구와 겹칩니다.** 예를 들어 `chain_of_command` 에 「팀」, 「명단」, 「누구누구」까지 넣으면 「결제팀에 누구누구 있어」가 `team_members` 대신 이쪽으로 옵니다. 하나를 고치려고 넣은 말이 **멀쩡했던 두 건을 깨뜨립니다.**
- **점수가 어휘 길이에 오염된다.** 예제 5의 선택기는 겹치는 단어 수를 세니, 설명을 길게 쓴 도구가 그냥 유리해집니다. 정규화되지 않은 점수 함수에서는 **설명이 긴 도구가 만능 도구처럼 행동합니다.** 실제 모델도 정도만 다를 뿐 「많은 말이 걸리는 도구」로 기우는 편향이 있습니다.
- **선택이 애매해질수록 오선택이 늘어난다.** 후보 둘의 점수가 붙으면 선택은 사실상 동전 던지기가 됩니다. 정확도가 낮은 라우터를 스스로 만든 셈이고, 25.3절의 계산에 따르면 **정확도 낮은 라우팅은 대개 손해**입니다.
- **컨텍스트를 먹는다.** 도구 설명은 매 호출마다 프롬프트에 들어갑니다. 도구 20개에 사전을 붙이면 24장에서 다룬 컨텍스트 예산을 도구 목록이 잠식하고, 정작 필요한 대화 이력이 밀려납니다.
- **경계선이 노이즈에 묻힌다.** 3요소 중 제일 크게 듣는 건 3번 「언제 안 쓰는지」입니다. 동의어 나열이 길어지면 그 한 문장의 상대적 비중이 줄어듭니다. **동의어를 늘릴 때는 경계 문장도 같이 세게 써야 합니다.**

그래서 규칙은 이렇게 정리됩니다.

| 넣어야 하는 동의어 | 넣지 말아야 하는 것 |
|---|---|
| 로그에 실제로 나온 말 | 우리가 상상한 말 |
| 한 도구에만 쏠린 말 | 여러 도구 질문에 두루 나오는 말 |
| 도메인 고유명사·사내 은어 | 「알려줘」, 「좀」 같은 기능어 |
| 넣고 회귀 측정에서 순증한 것 | 측정 없이 「그럴 것 같아서」 넣은 것 |

동의어를 넣을 때마다 **반대편에 경계 한 줄을 같이 넣는 것**이 실무 균형점입니다. 「상급자·윗사람·결재선을 물으면 이것이다」와 「아래 부하 목록에는 쓰지 않는다」는 한 쌍입니다. 입구를 넓히면서 벽도 같이 세우는 것이죠.

## 6. 한 줄로 접는 방식

- **문제**: 우리는 사내 용어(「상사」)로 쓰고 사용자는 자기 말(「상급자」)로 묻는다. 설명이 곧 엣지 선택 함수라서, 겹치는 말이 없으면 엣지가 안 골라진다.
- **처방**: 동의어를 설명에 넣는다. 상사·상급자·윗사람·결재선.
- **더 좋게**: 상상하지 말고 **실제 질문 로그**에서 뽑는다. 라벨된 100건 + 차집합 + 회귀 측정의 루프.
- **한계**: 무한정 넣으면 도구 간 경계가 흐려져 오선택이 늘고, 컨텍스트도 먹는다. 동의어 한 줄에 **경계 한 줄**을 짝지어라.

### 외우기 팁

- 카드 문장은 두 겹이다. **「동의어를 넣어라」**(무엇) + **「로그에서 뽑아라」**(어디서). 뒤쪽을 빼먹으면 결국 또 우리 어휘를 넣게 된다.
- 「촌스러워 보여도 이게 듣는다」가 이 처방의 정체다. 우아한 해법이 아니라 **값이 싼 해법**이다.
- 부작용은 한 단어로 **경계 침식**이다. 입구를 넓히면 옆 도구 입구와 겹친다. 그래서 3요소의 3번(「언제 안 쓰는지」)이 동의어와 항상 세트다.
- 예제 5의 8건은 25.3절의 「채점 데이터셋 100건」의 축소판이다. 설명을 고칠 때마다 이걸 다시 돌려서 **떨어진 항목이 없는지** 보는 것이 절차의 마지막 칸이다.
