# 경로와 이분·합류의 토큰이 같은 이유

> **Q.** `ex1_topologies.py`에서 경로와 이분·합류의 토큰이 같은 이유는 무엇인가?
>
> **A.** 나눠 읽는다고 읽는 양이 줄지 않는다. 병렬화는 지연만 줄인다.

---

## 1. 코드에서 확인하기

`ex1_topologies.py`의 두 함수를 나란히 놓으면 답이 그냥 눈에 보입니다.

```python
DOCS = 8
READ_MS,  READ_TOK  = 900, 2_400      # 문서 한 편 읽기
WRITE_MS, WRITE_TOK = 1_800, 3_200    # 보고서 한 장 쓰기
PAR = 4                               # 동시에 돌릴 수 있는 수


def 경로():
    """파이프라인. 한 줄로 죽 이어진다."""
    ms  = DOCS * READ_MS + WRITE_MS
    tok = DOCS * READ_TOK + WRITE_TOK
    return ms, tok, 0.71, "단순. 느리다."


def 이분합류():
    """팬아웃-팬인. 문서를 나눠 읽고 합친다."""
    waves = -(-DOCS // PAR)               # ← 여기만 다르다
    ms  = waves * READ_MS + WRITE_MS      # ← 여기만 다르다
    tok = DOCS * READ_TOK + WRITE_TOK     # ← 완전히 똑같은 식
    return ms, tok, 0.71, "빠르다. 토큰은 같다."
```

**`tok` 을 계산하는 줄이 두 함수에서 글자 하나 다르지 않습니다.** 반면 `ms` 를 계산하는 줄에는
`waves` 라는 나눗셈이 끼어듭니다. 즉 병렬화가 건드리는 변수는 시간뿐이고, 토큰 쪽 식에는
`PAR` 이 아예 등장하지 않습니다.

숫자로 펼치면 이렇습니다.

| 위상 | 지연 계산 | 지연(ms) | 토큰 계산 | 토큰 |
|---|---|---|---|---|
| 경로 | `8 × 900 + 1,800` | **9,000** | `8 × 2,400 + 3,200` | **22,400** |
| 이분·합류 | `2 × 900 + 1,800` | **3,600** | `8 × 2,400 + 3,200` | **22,400** |

지연은 9,000 → 3,600 으로 **2.5배 빨라졌는데 토큰은 22,400 에서 1토큰도 안 줄었습니다.**
예제의 출력문이 이걸 한 줄로 못 박아 둡니다.

```
(경로와 이분·합류는 토큰이 같다. 나눠 읽는다고 읽는 양이 주는 게 아니라서.)
```

```
경로는 8번을 차례로 읽어서 8,  이분·합류는 나눠 읽어서 2 물결이다.
토큰은 똑같다. 나눠 읽는다고 읽는 양이 줄지는 않으니까.
```

`waves = -(-DOCS // PAR)` 는 파이썬에서 올림 나눗셈(`ceil(8/4) = 2`)을 쓰는 관용구입니다.
`-(-8 // 4)` 는 `-(-2)` 이라서 2 가 되고, 문서가 9편이면 `-(-9 // 4)` 는 `-(-3)` 이라서 3 이 됩니다.
「4개씩 묶어 돌릴 때 몇 번의 물결이 필요한가」를 세는 값이에요.

## 2. 왜 그런가 — 일의 양과 일의 시간은 다른 축이다

핵심은 **작업량(work)과 벽시계 시간(latency)이 서로 다른 축**이라는 것입니다.

- 문서 8편은 병렬로 돌리든 직렬로 돌리든 **누군가는 8편 전부를 읽어야 합니다.**
  읽는 주체를 4명으로 늘리면 한 명이 2편씩 읽지만, 8편이라는 총량은 그대로예요.
- 토큰은 「읽은 글자의 총량」에 붙는 값입니다. 그러니 총량이 안 변하면 토큰도 안 변합니다.
- 시간은 「가장 오래 걸리는 경로의 길이」에 붙는 값입니다. 일을 나눠 동시에 하면
  가장 긴 경로가 짧아지므로 시간은 줄어듭니다.

비유하면 이렇습니다. 300쪽짜리 책을 혼자 읽으면 5시간이 걸리고, 친구 넷과 75쪽씩 나눠 읽으면
1시간 15분이 걸립니다. 하지만 **읽힌 쪽수는 여전히 300쪽입니다.** 페이지당 요금을 받는
복사집이 있다면 청구서는 두 경우가 똑같습니다. 줄어든 것은 「당신이 기다린 시간」뿐이죠.

이게 이 장의 요약이 말하는 문장입니다.

> 병렬은 시간을 사는 것이지 돈을 아끼는 게 아닙니다. 토큰은 그대로예요.

암달의 법칙(Amdahl's law)이 말하는 것과 같은 구조입니다. 병렬화는 **총 연산량을 줄이는 기법이
아니라, 연산량을 시간축 위에서 재배치하는 기법**입니다. 재배치는 시계에만 영향을 주고
계산서에는 영향을 주지 않습니다.

## 3. 토큰을 실제로 줄이는 것은 무엇인가

「병렬화가 토큰을 줄인다」는 오해가 흔하니, 진짜로 토큰을 줄이는 방법과 대비해 두면 좋습니다.
토큰이 줄어들려면 **읽거나 쓰는 양 자체가 줄어야** 합니다.

| 방법 | 토큰이 줄어드는가 | 이유 |
|---|---|---|
| 병렬 실행(이분·합류, 폭 늘리기) | ❌ 안 줄어든다 | 총량 그대로, 시간만 재배치 |
| 문서를 8편 → 3편으로 선별(검색·필터) | ⭕ 줄어든다 | 읽을 양 자체가 줄어든다 |
| 요약을 먼저 만들고 요약만 넘김(압축) | ⭕ 줄어든다 | 입력 길이가 줄어든다 |
| 값싼 모델로 라우팅(동적 엣지) | ⭕ 비용이 줄어든다 | 토큰당 단가가 내려간다 |
| 프롬프트 캐싱 | ⭕ 비용이 줄어든다 | 토큰 수는 같지만 단가가 내려간다 |
| 재시도·순환 횟수 줄이기 | ⭕ 줄어든다 | 반복 호출이 줄어든다 |

같은 예제에서 `순환()` 이 이 대비를 잘 보여 줍니다.

```python
def 순환():
    rounds = 3
    tok = DOCS * READ_TOK + rounds * (WRITE_TOK + CHECK_TOK)   # 32,100
    return ms, tok, 0.89, "품질이 오른다. 값이 비싸다."
```

순환은 쓰기·검토를 3번 반복하니 **일의 양이 실제로 늘어나서** 토큰이 22,400 → 32,100 으로
올라갑니다. 위상이 토큰을 움직이는 것은 「호출 횟수·읽는 분량이 변할 때」뿐이고, 이분·합류처럼
호출 횟수가 그대로면 토큰도 그대로입니다.

여섯 위상의 토큰을 나란히 놓아 보면 규칙이 선명해집니다.

| 위상 | 토큰 | 경로 대비 | 늘어난 이유 |
|---|---|---|---|
| 경로 | 22,400 | 기준 | — |
| 이분·합류 | **22,400** | **±0** | **호출 횟수가 안 변했다** |
| 동적 엣지 | 22,800 | +400 | 라우팅 판단 1회가 붙었다 |
| 성형 | 23,600 | +1,200 | 감독자 판단이 물결마다 붙었다 |
| 트리 | 29,600 | +7,200 | 중간 관리자의 부분 보고서 |
| 순환 | 32,100 | +9,700 | 쓰기·검토를 3번 돌렸다 |

**이분·합류만 유일하게 경로와 정확히 같습니다.** 나머지는 모두 「추가 판단」이나 「추가 생성」이
끼어들어서 늘어난 것이지, 병렬이냐 직렬이냐 때문에 변한 게 아닙니다.

## 4. 실무에서의 단서 — 실제로는 오히려 늘어난다

예제는 교육용이라 이분·합류의 토큰을 경로와 **정확히 같게** 모델링했습니다. 실제 시스템에서는
보통 **조금 늘어납니다.** 방향이 「줄어든다」가 아니라 「같거나 늘어난다」라는 게 요점이에요.

- **컨텍스트 복제.** 갈래마다 시스템 프롬프트·작업 지시·공용 배경 정보를 다시 실어야 합니다.
  갈래 4개면 그 서두가 4번 청구됩니다.
- **합류 비용.** 합치는 노드가 부분 결과 전부를 다시 읽어야 합니다. 부분 결과가 길면
  이 읽기가 새 입력 토큰입니다.
- **재시도.** 갈래 하나가 실패하면 그 갈래를 다시 돌립니다. 폭이 넓을수록 하나라도 실패할
  확률이 올라갑니다(`ex2_fanout.py` 의 `FAIL = 0.06`, `p_any_fail = 1 - (1 - FAIL) ** width`).
- **중복 작업.** 갈래들이 같은 배경을 각자 조회하면 그만큼 중복 청구됩니다.

그래서 실무 규칙은 이렇게 정리됩니다.

> **비용(토큰) 제약이 걸린 문제를 병렬화로 풀려고 하면 안 됩니다.**
> 병렬화는 지연 제약을 푸는 도구입니다. 비용은 읽는 양을 줄여서 푸세요.

`ex1_topologies.py` 마지막의 고르는 순서도 정확히 이 분류를 따릅니다.

```
  1. 품질 하한이 있나 → 있으면 순환을 넣는다
  2. 지연 상한이 있나 → 있으면 이분·합류로 편다      ← 지연 문제의 답
  3. 입력 종류가 갈리나 → 갈리면 동적 엣지            ← 비용 문제의 답
  4. 다 아니면 경로. 제일 단순한 게 제일 오래 산다.
```

이분·합류는 2번, 즉 **지연 상한이 있을 때만** 등장합니다. 비용을 아끼려는 3번 자리에는
동적 엣지(라우팅)가 앉아 있습니다.

## 5. 덤 — 「제일 싼 것」이 경로로 나오는 이유

예제를 실행하면 「제일 싼 것」은 경로로 출력됩니다.

```python
cheap = min(rows, key=lambda r: r[2])
```

경로와 이분·합류의 토큰이 22,400 으로 **동점**인데, 파이썬 `min()` 은 동점일 때 **먼저 나온
항목**을 돌려줍니다. 리스트에 경로가 먼저 들어가니 경로가 뽑히는 것이죠. 「경로가 이분·합류보다
싸다」가 아니라 「둘이 같아서 앞의 것이 뽑혔다」입니다.

그리고 두 위상의 품질도 둘 다 `0.71` 로 같습니다. 즉 **경로와 이분·합류는 토큰도 같고 품질도
같고, 지연만 다릅니다.** 지연 제약이 없다면 굳이 이분·합류를 쓸 이유가 없다는 뜻이에요.
합류 코드와 부분 실패 처리라는 복잡도를 공짜로 사들이는 셈이니까요.

## 6. 한 줄 요약

**병렬화는 일을 시간축 위에서 재배치하는 것일 뿐, 일의 총량을 줄이지 않습니다.
토큰은 총량에 붙는 값이라 그대로고, 지연은 가장 긴 경로에 붙는 값이라 줄어듭니다.
그래서 `tok` 계산식이 두 함수에서 글자 하나 다르지 않습니다.**
