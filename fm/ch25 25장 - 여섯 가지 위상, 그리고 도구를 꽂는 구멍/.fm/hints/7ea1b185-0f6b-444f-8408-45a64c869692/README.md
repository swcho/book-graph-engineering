# 트리(계층적 위임) 위상의 득실

> **Q.** 트리(계층적 위임) 위상의 득실은 무엇인가?
>
> **A.** 부분 보고서가 남아 재사용할 수 있지만 중간 요약 과정에서 손실이 생긴다.

## 한 줄로

트리는 **중간 관리자를 끼워 넣는 위상**입니다. 얻는 것은 *중간 산출물*(부분 보고서)이고, 치르는 값은 *중간 요약에서 깎여 나가는 정보*입니다. 원문을 본 사람과 최종 보고서를 쓰는 사람이 달라지기 때문입니다.

## 1. 어떤 모양인가

25장은 위상을 여섯 가지로 셉니다. 경로, 이분·합류, 성형(감독자-작업자), 순환, 동적 엣지, 트리. 트리는 이분·합류를 **한 단 더 쌓은** 것으로 보면 쉽습니다.

```
                    [최상위 종합자]        ← 부분 보고서 2장만 본다
                    /            \
        [중간 관리자 A]            [중간 관리자 B]   ← 각각 부분 보고서 1장을 쓴다
        /  |  |  \                /  |  |  \
      d1 d2 d3 d4              d5 d6 d7 d8      ← 문서 8편
```

`ex1_topologies.py`의 트리 함수가 그대로 이 모양입니다.

```python
def 트리():
    """계층적 위임. 중간 관리자가 부분 보고서를 만든다."""
    groups = 2
    per = DOCS // groups
    ms = (ROUTE_MS + (-(-per // PAR)) * READ_MS + WRITE_MS) + WRITE_MS
    tok = groups * (ROUTE_TOK + per * READ_TOK + WRITE_TOK) + WRITE_TOK
    return ms, tok, 0.84, "부분 요약이 남는다. 중간 손실도."
```

읽는 법:

- `ms` — 그룹 둘은 **동시에** 돌기 때문에 벽시계 시간에는 그룹 *하나*만 들어갑니다(`300 + 900 + 1800`). 거기에 최상위 종합 `WRITE_MS`가 한 번 더 붙어 `3,000 + 1,800 = 4,800ms`.
- `tok` — 토큰은 동시에 돌아도 **깎이지 않습니다**. 그룹마다 라우팅 + 읽기 + 부분 보고서 작성이 전부 들고(`groups *`), 마지막에 종합 보고서 작성 `WRITE_TOK`가 또 붙습니다. `2 × (400 + 9,600 + 3,200) + 3,200 = 29,600`.

핵심은 **보고서를 세 번 쓴다**는 점입니다. 부분 2장 + 종합 1장. `WRITE_TOK`가 3번 계산되고, 이게 트리가 비싼 이유입니다.

## 2. 여섯 위상 나란히 놓고 본 트리의 자리

`ex1_topologies.py`를 실제로 돌리면 나오는 값입니다.

| 위상 | 지연(ms) | 토큰 | 품질 | 토큰당 품질(×10⁴) | 성격 |
|---|---:|---:|---:|---:|---|
| 경로 | 9,000 | 22,400 | 0.71 | 0.317 | 단순. 느리다. |
| 이분·합류 | **3,600** | **22,400** | 0.71 | 0.317 | 빠르다. 토큰은 같다. |
| 성형 | 4,500 | 23,600 | 0.78 | 0.331 | 판단이 붙는다. 감독자가 병목. |
| 순환 | 9,300 | 32,100 | **0.89** | 0.277 | 품질이 오른다. 값이 비싸다. |
| 동적 엣지 | 3,900 | 22,800 | 0.81 | **0.355** | 쉬운 건 싸게, 어려운 건 비싸게. |
| **트리** | 4,800 | 29,600 | 0.84 | 0.284 | **부분 요약이 남는다. 중간 손실도.** |

트리의 위치를 정리하면:

- **품질 2위** (0.84). 순환(0.89) 다음입니다. 중간 관리자가 한 번 정리해 주니 최종 종합자가 편해집니다.
- **비용 2위로 비쌈** (29,600). 순환(32,100) 다음입니다. 보고서를 3번 쓰기 때문.
- **토큰당 품질은 아래쪽** (0.284). 순환(0.277) 바로 위, 즉 밑에서 둘째입니다. → 트리도 **품질을 돈으로 산 위상**입니다.
- 지연은 중간(4,800). 그룹을 병렬로 돌려서 이분·합류에 가깝지만, 종합 단계가 한 층 더 있어 그만큼 늘어납니다.

## 3. 득 — 부분 보고서가 «남는다»

트리에서만 생기는 산출물이 **중간 계층의 부분 보고서**입니다. 다른 위상에는 이게 없습니다. 이분·합류는 갈래별 원문 조각이 곧바로 합류 지점으로 흘러 들어가 사라지고, 경로는 애초에 중간 산물이 없습니다.

부분 보고서가 남으면 이런 게 됩니다.

- **재사용** — 「A 그룹 문서만 다시 요약해 줘」 같은 후속 질문에서 A 그룹 부분 보고서를 그대로 씁니다. 문서를 다시 읽지 않아도 됩니다.
- **부분 무효화** — d3 하나만 바뀌었으면 A 그룹만 다시 돌리고 B 그룹 부분 보고서는 캐시에서 꺼냅니다. 전체 재실행이 아니라 **부분 재실행**이 가능해집니다.
- **컨텍스트 압박 완화** — 최상위 종합자는 문서 8편이 아니라 부분 보고서 2장만 봅니다. 24장(컨텍스트가 꽉 찼습니다)에서 다룬 문제를 구조로 눌러 주는 셈입니다. 문서 수가 늘어도 최상위가 보는 양은 그룹 수만큼만 늡니다.
- **디버깅과 감사** — 「어디서 틀렸나」를 층별로 좁힐 수 있습니다. 중간 관리자 B의 부분 보고서가 이미 틀렸는지, 최상위 종합에서 틀렸는지 나눠서 볼 수 있습니다.

## 4. 실 — 중간 요약에서 «손실»이 생긴다

동시에, 최상위 종합자는 **원문을 한 줄도 보지 않습니다**. 부분 보고서만 봅니다. 그래서 중간 관리자가 요약할 때 버린 것은 최종 보고서에 다시 살아날 방법이 없습니다.

구체적으로 잃는 것들:

- **요약 과정에서 버려진 세부** — 중간 관리자가 「중요하지 않다」고 판단해 뺀 수치·단서가 최종 단계에서는 복구 불가입니다. 원문으로 되돌아가는 엣지가 없습니다.
- **그룹을 가로지르는 관계** — d2와 d7이 서로 모순되는데 둘이 다른 그룹에 있으면, 어느 중간 관리자도 그 모순을 못 봅니다. 최상위는 이미 요약된 두 문장을 받으므로 원문 수준의 대조가 불가능합니다. **문서를 어떻게 그룹으로 갈랐는지가 품질을 좌우**합니다.
- **손실의 누적** — 층을 더 쌓으면(3단, 4단) 요약이 요약을 요약합니다. 손실이 층마다 곱해집니다. 트리를 깊게 만들 때는 이걸 계산해야 합니다.
- **중간 관리자의 오류가 통째로 전파** — 중간 관리자가 잘못 요약하면 최상위는 그걸 사실로 받습니다. 검증할 원본이 손에 없기 때문입니다.

그래서 품질이 0.84로 그치고 순환(0.89)을 못 넘습니다. 순환은 결과를 원본과 다시 맞춰 보는 검증 엣지가 있는데, 트리는 정보가 **한 방향으로만** 흐르기 때문입니다.

## 5. 왜 하필 «부분 보고서 대 중간 손실»이 짝인가

같은 원인의 앞뒷면입니다.

> 중간 관리자가 **원문을 압축해서** 부분 보고서를 만든다.

압축한 결과물이 남으니까 **재사용**이 되고, 압축이니까 **손실**입니다. 손실 없는 요약은 요약이 아니라 원문 전달이고, 원문을 그대로 올려 보내면 그건 트리가 아니라 그냥 이분·합류입니다(그리고 최상위 컨텍스트가 터집니다). 트리를 고른다는 것은 **정보를 얼마나 버릴지 정하는 결정**을 중간 계층에 위임한다는 뜻입니다.

## 6. 언제 고르나

25장 후반 「고르는 순서」는 트리를 명시적으로 넣지 않습니다. 품질 하한 → 순환, 지연 상한 → 이분·합류, 입력 종류가 갈림 → 동적 엣지, 다 아니면 경로. 즉 트리는 **1차 후보가 아닙니다**.

트리가 실제로 남는 장사가 되는 조건:

1. **원문 양이 최상위 컨텍스트를 넘는다.** 문서 8편이 아니라 800편이면 중간 계층 없이는 방법이 없습니다.
2. **후속 질문이 그룹 단위로 온다.** 부분 보고서 재사용이 실제로 일어나야 3번 쓰는 보고서 값을 회수합니다.
3. **문서가 자연스럽게 그룹으로 갈린다.** 그룹 경계를 가로지르는 추론이 별로 없어야 손실이 싸게 먹힙니다.
4. **부분 재실행이 잦다.** 일부만 바뀌는 파이프라인이면 캐시 이득이 큽니다.

반대로 이 셋 중 하나라도 어긋나면 트리는 「이분·합류보다 30% 비싸고 순환보다 품질 낮은」 위상이 됩니다.

## 7. 자주 하는 착각

- **「층을 쌓으면 품질이 오른다」** — 아닙니다. 트리의 품질 이득은 중간 정리 덕이고, 층을 더 쌓으면 요약 손실이 누적돼 어느 지점부터 **내려갑니다**.
- **「트리는 병렬이니 싸다」** — 병렬은 **시간을 사는 것이고 토큰을 아끼는 게 아닙니다**(25장 요약). 트리는 오히려 보고서를 여러 번 써서 이분·합류보다 7,200토큰 비쌉니다.
- **「부분 보고서는 공짜 부산물이다」** — 부분 보고서 2장 작성비 `2 × 3,200 = 6,400`토큰이 트리 비용의 대부분입니다. 재사용하지 않으면 순수한 낭비입니다.
- **「트리는 성형(감독자-작업자)과 같다」** — 다릅니다. 성형은 감독자 **한 명**이 매 물결 다음 일을 정하고 스스로 병목이 됩니다(품질 0.78, 4,500ms). 트리는 감독 계층이 **여러 명이고 병렬**이며, 각자 부분 산출물을 남깁니다.

## 8. 외울 문장

> **트리 = 이분·합류에 중간 요약 계층을 한 단 얹은 것.**
> **득: 부분 보고서가 남아 재사용·부분 재실행·컨텍스트 절약이 된다.**
> **실: 최상위가 원문을 못 보므로 중간 요약에서 버린 것은 복구 불가.**
> 숫자로: 지연 4,800ms / 토큰 29,600 / 품질 0.84 — 품질 2위, 비용 2위, 토큰당 품질은 밑에서 둘째.
