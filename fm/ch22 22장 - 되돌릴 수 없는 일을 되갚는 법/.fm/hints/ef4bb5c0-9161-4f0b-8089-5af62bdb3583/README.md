# 각 층 타임아웃의 합이 바깥 타임아웃보다 크면 무엇을 뜻하는가?

**답: 그 설정은 거짓말이다. 아무도 지킬 수 없는 약속이므로 층이 아니라 예산으로 다뤄야 한다.**

(출처: 22장 22.2절 「타임아웃은 층이 아니라 예산이다」, 예제 `ex2_timeout_budget.py`)

## 왜 "거짓말"인가

바깥 타임아웃은 사용자에게 한 약속이다. 예를 들어 "15초 안에 응답한다"고 약속했다고 하자. 그런데 내부 단계 네 개(검색·요약·초안·검토)에 각각 10초 타임아웃을 걸었다면, 합계는 40초다. 이 설정은 다음 두 문장을 동시에 주장하는 셈이다.

- "전체는 15초 안에 끝난다."
- "각 단계는 최대 10초씩, 총 40초까지 쓸 수 있다."

두 문장은 양립할 수 없다. 각 단계가 자기 타임아웃을 **완벽히 지켜도** 전체 약속은 깨질 수 있다. 그래서 이 설정은 아무도 지킬 수 없는 약속, 즉 거짓말이다.

## 층별 타임아웃의 실패 양상 (예제 ex2의 위쪽 시나리오)

각 단계의 실제 소요: 검색 4초, 요약 3초, 초안 9초, 검토 2초. 단계별 타임아웃 10초, 바깥 15초.

| 단계 | 실제 필요 | 단계 타임아웃 | 결과 |
|---|---|---|---|
| 검색 | 4.0 | 10.0 | 완료 (누적 4초) |
| 요약 | 3.0 | 10.0 | 완료 (누적 7초) |
| 초안 | 9.0 | 10.0 | 완료 (누적 16초) |
| (바깥) | - | 15.0 | **전체 타임아웃 — 여기서 끊긴다** |

- 초안이 9초를 다 써도 자기 타임아웃(10초) 안이므로 아무 단계도 "잘못"하지 않았다.
- 그런데 누적 16초가 되어 바깥 약속(15초)이 먼저 깨지고, **검토 단계에는 아예 도달하지 못한다.**
- 각 층이 자기 타임아웃만 보기 때문에, 전체 실패의 책임을 어느 층에도 물을 수 없다. 이것이 층별 타임아웃 방식의 구조적 문제다.

## 예산 방식 (deadline propagation, 예제 ex2의 아래쪽 시나리오)

타임아웃을 층마다 고정으로 거는 대신, **전체 마감(deadline) 하나를 예산으로 보고 남은 만큼을 각 단계에 그때그때 배분**한다.

핵심 규칙 두 가지:

1. **남은 예산을 본다.** 각 단계에 들어갈 때 `남은 시간 = 바깥 타임아웃 - 지금까지 쓴 시간`을 계산해 그 안에서만 허용한다.
2. **뒤 단계의 최소 필요분을 먼저 떼어 둔다.** 단계마다 "이 단계가 쓸모 있으려면 최소한 필요한 시간"(검색 1, 요약 1, 초안 3, 검토 2초)을 미리 선언해 두고, 현재 단계에는 `남은 시간 - 뒤 단계들의 최소 필요분 합`만 허용한다.

같은 시나리오를 예산 방식으로 돌리면:

- 초안 차례에 남은 예산은 8초, 뒤의 검토 최소분 2초를 떼면 허용은 6초. 초안은 9초가 필요하지만 6초에서 **잘리고 부분 결과를 반환**한다.
- 대신 검토가 필요한 2초를 온전히 받아, 네 단계 모두 실행되고 전체는 15초 약속 안에 끝난다.

「완성 안 된 초안을 검토한 결과」와 「초안만 있고 검토 못 한 결과」 중 어느 쪽이 나은지는 도메인이 정한다. 중요한 건 예산 방식에서는 **고를 수 있게 된다**는 점이다. 층별 방식에서는 선택지 자체가 없다.

## 두 방식 대비 정리

| | 층별 타임아웃 | 예산(deadline propagation) |
|---|---|---|
| 타임아웃 결정 | 층마다 고정값을 미리 박는다 | 남은 예산을 보고 그때그때 정한다 |
| 합계와 바깥의 관계 | 합이 바깥보다 커질 수 있다 (거짓말) | 정의상 바깥 예산을 넘지 않는다 |
| 실패 양상 | 각 층은 무죄인데 전체가 실패, 뒷단계 미도달 | 앞 단계를 잘라서라도 뒷단계 최소분 보장 |
| 부분 결과 | 선택 불가 | 부분 결과 반환 여부를 도메인이 선택 가능 |

## 실무 연결

이 아이디어는 분산 시스템에서 **deadline propagation**이라는 이름으로 널리 쓰인다. gRPC는 호출 체인을 따라 deadline을 전파하고(각 홉이 "남은 시간"을 물려받음), Go의 `context.WithDeadline`/`WithTimeout`도 같은 모델이다. 요점은 항상 하나다: 타임아웃은 층마다 독립적으로 소유하는 값이 아니라, **바깥 약속에서 출발해 아래로 물려주며 깎아 쓰는 하나의 예산**이다.

## 기억할 한 줄

> 각 층의 타임아웃 합이 바깥 타임아웃보다 크면 그 설정은 «거짓말»이다. 아무도 지킬 수 없는 약속이다. — 층이 아니라 예산으로 다루고, 뒤 단계의 최소 필요분을 먼저 떼어 두라.
