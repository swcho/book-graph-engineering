# 만료 vs 정정 — "3월 1일 등급(지금 아는 대로)"의 답이 갈리는 이유

## 질문

만료 시나리오와 정정 시나리오에서 **"3월 1일 등급(지금 아는 대로)"** 은 각각 무엇인가?

## 답

- **만료 시나리오 → A** : 3월 1일에는 진짜 A였다. 5월에 값이 바뀌었을 뿐이다.
- **정정 시나리오 → B** : 3월 1일에도 사실은 B였다. 처음부터 B였는데 A로 잘못 적었던 것이다.

## 두 시나리오의 설정 (16장 예제 2, `ex2_correction.py`)

두 시나리오 모두 겉보기 사건은 같다. "1월 1일에 가온테크 등급을 A로 기록했고, 5월 1일에 B가 되었다." 하지만 5월 1일에 일어난 일의 **의미**가 다르다.

### 만료(expire) — 그때는 맞았고 지금은 아니다

```python
st.assert_fact("가온테크", "등급", "A", valid_from=D(2026, 1, 1), tx_at=D(2026, 1, 1))
st.assert_fact("가온테크", "등급", "B", valid_from=D(2026, 5, 1), tx_at=D(2026, 5, 1))
```

`assert_fact`는 기존 A 기록의 **유효 시간(valid time)** 을 5월 1일에서 잘라 준다. A는 "1월 1일~5월 1일에 참이었던 사실"로 남는다. 현실이 바뀐 것이지 기록이 틀렸던 게 아니다.

### 정정(correct) — 그때도 틀렸다

```python
st.assert_fact("가온테크", "등급", "A", valid_from=D(2026, 1, 1), tx_at=D(2026, 1, 1))
st.correct("가온테크", "등급", "B", valid_from=D(2026, 1, 1), tx_at=D(2026, 5, 1))
```

`correct`는 기존 A 기록을 **기록 시간(transaction time)** 축으로 닫는다(`tx_to = 5월 1일`). "A라고 알고 있던 기간"이 끝났다는 뜻이다. 그리고 같은 유효 기간(1월 1일부터)에 대해 B를 새로 적는다. 현실은 처음부터 B였고, 우리 기록이 틀렸던 것이다.

## 질의 결과가 갈리는 지점

| 질의 | 만료 시나리오 | 정정 시나리오 |
|---|---|---|
| 3월 1일 등급 (지금 아는 대로, `tx_at=None`) | **A** | **B** |
| 3월 1일 등급 (4월 시점 지식으로, `tx_at=4/1`) | A | A |
| 6월 1일 등급 (지금 아는 대로) | B | B |

- **첫 줄이 이 카드의 요점.** "지금 아는 대로"는 아직 안 닫힌(`tx_to == FOREVER`) 기록만 본다. 만료 시나리오에서는 A 기록이 유효 시간만 잘렸을 뿐 여전히 살아 있으니 3월 1일 값은 A. 정정 시나리오에서는 A 기록이 기록 시간으로 닫혔고, 살아 있는 기록은 "1월 1일부터 B"뿐이라 3월 1일 값도 B.
- **둘째 줄은 둘 다 A.** 4월 시점에는 두 시나리오 모두 "A라고 알고" 있었으니까. 정정은 5월에야 일어났다.

## 왜 이 구분이 중요한가

- **만료를 정정으로 처리하면** 과거 보고서가 소급해서 바뀐다. "3월에 A였다"가 갑자기 "3월에 B였다"가 되어 버려, 감사에서 "그때 왜 그렇게 처리했나"에 답할 수 없다.
- **정정을 만료로 처리하면** 틀린 값(A)이 과거에 영원히 참으로 남는다. 실제로는 그때도 B였는데.
- 실무에서는 사람이 둘을 자주 헷갈리므로, 입력 화면에서 **"값이 바뀐 건가요, 잘못 적은 건가요?"** 를 물어보는 게 낫다. 질문 하나가 나중에 며칠을 아낀다.

## 기억법

- 만료 = "현실이 바뀜" → 유효 시간을 자름 → 과거는 그대로(그때는 진짜 A).
- 정정 = "기록이 틀림" → 기록 시간을 닫음 → 과거가 지금 지식으로 다시 보임(그때도 B).
