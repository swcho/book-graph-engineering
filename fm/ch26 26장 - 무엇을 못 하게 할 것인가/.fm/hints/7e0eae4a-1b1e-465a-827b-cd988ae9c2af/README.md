# 예제의 허용 목록이 `cat /etc/passwd`를 통과시킨 이유

## 핵심 답

허용 목록 규칙을 **"cat은 허용"이라고 명령 이름 수준에서만** 적어 두고, **인자(어떤 파일을 읽는지)를 보지 않았기 때문**입니다. 올바른 방법은 cat이 읽을 수 있는 **경로를 작업 디렉터리 아래로 제한**하는 것이었습니다.

## 예제 코드에서 무슨 일이 있었나 (ex2_deny_vs_allow.py)

26장 예제 2는 같은 위험 명령들을 금지 목록(denylist)과 허용 목록(allowlist) 두 방식으로 걸러 봅니다. 허용 목록은 이렇게 정의되어 있었습니다.

```python
ALLOW = {
    "ls":  r"^ls(\s+-[a-zA-Z]+)?(\s+[\w./-]+)?$",
    "cat": r"^cat\s+[\w./-]+$",
    "git": r"^git\s+(status|diff|log)(\s+[\w./-]+)?$",
}
```

`cat`의 패턴 `^cat\s+[\w./-]+$`을 보면, 인자가 "단어 문자·점·슬래시·하이픈으로 된 경로"이기만 하면 무엇이든 통과합니다. 그런데 `/etc/passwd`도 정확히 이 문자들로만 이루어진 경로입니다. 그래서:

- `cat report.md` → 통과 (의도한 대로)
- `cat /etc/passwd` → **통과 (막았어야 하는데!)**

패턴이 검사한 것은 "cat이라는 명령인가, 인자가 경로처럼 생겼는가"뿐이고, **그 경로가 어디를 가리키는지**는 전혀 검사하지 않았습니다.

## 왜 이게 중요한 교훈인가

이 예제에서 허용 목록은 금지 목록보다 훨씬 좋은 성적(오답 4 대 1)을 냈지만, 유일하게 틀린 한 건이 바로 `cat /etc/passwd`입니다. 책은 이것을 **"허용 목록의 진짜 난이도"**라고 부릅니다.

1. **명령 이름 허용만으로는 부족하다.** "cat은 안전한 명령"이라는 판단 자체가 틀렸습니다. cat은 인자에 따라 무해한 파일 읽기가 되기도 하고, 시스템 계정 정보(`/etc/passwd`)나 비밀 파일 유출의 시작점이 되기도 합니다. 도구의 위험은 이름이 아니라 **이름 + 인자의 조합**에서 나옵니다.
2. **"어떤 인자까지 허용하나"를 같이 적어야 한다.** 이 예제의 올바른 수정은 cat의 인자를 작업 디렉터리 아래 경로로 제한하는 것입니다. 예를 들어 절대 경로(`/`로 시작)와 상위 이동(`..`)을 금지하고, 상대 경로를 정규화(canonicalize)한 뒤 작업 디렉터리 안인지 확인하는 식입니다.
3. **문자열이 아니라 정규화한 결과를 비교하라.** 장 요약에도 나오는 원칙입니다. `./secret/../../etc/passwd` 같은 경로는 문자열만 보면 상대 경로처럼 보이지만, 정규화하면 `/etc/passwd`입니다. 경로 검사도 문자열 패턴이 아니라 정규화된 실제 경로를 기준으로 해야 우회를 막을 수 있습니다.

## 참고: `/etc/passwd`가 왜 대표 예인가

`/etc/passwd`는 유닉스 시스템의 사용자 계정 목록 파일로, 모든 사용자가 읽을 수 있어 "임의 파일 읽기(arbitrary file read)" 취약점을 확인하는 고전적 표적입니다. 여기가 읽히면 같은 방법으로 설정 파일, API 키, `~/.ssh` 등 어떤 파일이든 읽힐 수 있다는 신호입니다.

## 큰 그림과의 연결

- 금지 목록은 "셀 수 있는 것만 막아서" 반드시 새고, 허용 목록은 "이해한 것만 통과시켜서" 안 샙니다. 그러나 허용 목록도 **허용의 단위를 너무 크게 잡으면**(명령 이름 단위) 구멍이 생깁니다.
- 허용 목록의 오답은 촘촘하게 쓸수록 "통과했어야 하는데 차단" 쪽으로 옮겨 가고, 이는 사용자가 바로 알려 줍니다. 반면 금지 목록의 오답("막았어야 하는데 통과")은 사고가 나야 압니다. 권한 경계에서 허용 목록을 고르는 이유입니다.
- 이 교훈은 실제 에이전트 도구 권한 설계에도 그대로 적용됩니다. "이 도구 허용"이 아니라 "이 도구를 **이 인자 범위**에서 허용"이 최소 권한의 실제 모양입니다.

## 기억 포인트

> 허용 목록이 뚫린 이유: **이름만 보고 인자를 안 봤다.**
> 고치는 방법: **인자(경로)를 작업 디렉터리 아래로 제한하고, 문자열이 아니라 정규화한 경로로 비교한다.**
