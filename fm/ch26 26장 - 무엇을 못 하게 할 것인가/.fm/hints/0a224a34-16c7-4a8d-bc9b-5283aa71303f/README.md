# 힌트: `ex2_deny_vs_allow.py`에서 금지 목록이 놓친 세 가지 우회

## 질문

`ex2_deny_vs_allow.py`에서 금지 목록(deny list)이 놓친 세 가지 우회는 무엇인가?

## 답

세 가지 모두 결국 «파일을 지우는» 같은 목적을 이루지만, 금지 목록의 패턴을 비껴간다.

1. **`rm -fr`** — 플래그 순서만 바꿨다
2. **`python3 -c`로 `shutil.rmtree` 호출** — 다른 프로그램으로 지웠다
3. **`find ... -delete`** — `rm`을 아예 안 썼다

---

## 왜 이렇게 되는가

예제의 금지 목록은 다음 네 개의 정규식 패턴으로 되어 있다.

```python
DENY = [
    r"\brm\s+-rf\b",   # rm 다음에 -rf 가 오는 경우
    r"\bmkfs\b",
    r"\bdd\s+if=",
    r"/etc/shadow",
]
```

즉 「`rm`이라는 글자 뒤에 공백들, 그리고 정확히 `-rf`」라는 **아주 좁고 구체적인 문자열 모양**만 잡는다. 그래서 같은 파괴 행위라도 이 모양을 조금만 벗어나면 그물을 빠져나간다.

### 1. `rm -fr /var/data` — 플래그 순서 (flag order)

- `-rf`와 `-fr`은 리눅스 `rm` 입장에서 **완전히 동일한 의미**다. `-r`(재귀)과 `-f`(강제)를 묶은 것이라 순서는 상관없다.
- 그런데 정규식 `\brm\s+-rf\b`는 문자 그대로 `-rf`만 찾는다. `-fr`은 매칭되지 않으므로 **통과(차단 실패)**한다.
- 참고로 예제의 `rm  -rf  /var/data`(공백 두 개)는 `\s+`(공백 하나 이상)로 잡히기 때문에 이건 막힌다. 놓치는 건 어디까지나 «순서를 바꾼» 경우다.

### 2. `python3 -c "import shutil,os; shutil.rmtree('/var/data')"` — 다른 프로그램 (different program)

- 파일을 지우는 데 `rm` 명령이 꼭 필요한 게 아니다. 파이썬 표준 라이브러리 `shutil.rmtree()`는 디렉터리 트리를 통째로 지운다.
- 명령줄에 `rm`이라는 글자 자체가 없으므로 어떤 `rm` 패턴에도 걸리지 않는다.
- 핵심: 금지 목록은 «`rm`이라는 도구»를 막으려 했지만, 진짜 막고 싶은 건 «지우는 능력»이다. 능력은 수많은 다른 도구(python, perl, ruby, node ...)로 실현할 수 있다.

### 3. `find /var/data -delete` — rm을 아예 안 씀 (doesn't use rm at all)

- `find`의 `-delete` 옵션은 찾은 파일을 그 자리에서 삭제한다. `rm`을 전혀 호출하지 않는다.
- 역시 `rm` 패턴에 걸리지 않아 통과한다.
- 2번과 같은 맥락: 같은 목적(삭제)을 다른 문법·다른 명령으로 달성하는 우회다.

---

## 이 예제가 말하려는 핵심

> 「지우는 방법」은 셀 수 없이 많고, 금지 목록은 셀 수 있는 것만 막는다.

- 패턴을 세 개 더 추가하면? 곧바로 «네 번째 우회»가 나온다. 우회의 공간이 무한하기 때문에 금지 목록은 **원리적으로 반드시 샌다(leak)**.
- 반대로 허용 목록(allow list)은 «내가 이해하고 명시적으로 허용한 것»만 통과시키고 나머지는 전부 막는다. 새 공격 방식이 나와도 «허용 목록에 없으니까» 막힌다.
- 다만 허용 목록도 이름만 허용하면 부족하다. 예제에서 `cat`을 허용했더니 `cat /etc/passwd`가 통과해 버린다. 명령 이름뿐 아니라 **인자(경로 등)까지** 검사해야 하고, 문자열이 아니라 정규화한 결과를 비교해야 한다.

### 오답의 «방향»도 다르다

- **금지 목록**: 「막았어야 하는데 통과」가 늘어난다 → 사고가 나야 안다.
- **허용 목록**: 촘촘하게 쓸수록 「통과했어야 하는데 차단」으로 오답이 옮겨 간다 → 사용자가 바로 알려 준다.

권한 경계에서는 허용 목록을 고른다. «반드시 샌다»는 성질이 권한 경계에서는 받아들일 수 없기 때문이다.

| 방식 | 손이 가는 정도 | 새는가 |
|---|---|---|
| 금지 목록(deny) | 덜 간다 | **반드시 샌다** |
| 허용 목록(allow) | 계속 간다 | 안 샌다 |

---

## 한 줄 정리

금지 목록이 놓친 셋 — `rm -fr`(플래그 순서), `python3 -c`로 `shutil.rmtree`(다른 프로그램), `find -delete`(rm을 안 씀) — 는 모두 «같은 목적, 다른 모양»이며, 이것이 금지 목록이 원리적으로 새고 권한 경계에서는 허용 목록을 써야 하는 이유다.
