# 금지 목록과 허용 목록의 오류 방향은 어떻게 다른가?

## 핵심 답

- **금지 목록(denylist)**: 오류가 **거짓 음성(false negative)** 쪽으로 쌓인다. 즉 「**막았어야 하는데 통과**」가 늘어난다.
- **허용 목록(allowlist)**: 촘촘하게 쓸수록 오류가 **거짓 양성(false positive)** 쪽으로 옮겨 간다. 즉 「**통과했어야 하는데 차단**」이 늘어난다.

그리고 두 오류는 **발견되는 방식**이 결정적으로 다르다.

> 후자(과잉 차단)는 **사용자가 바로 알려 준다**. 전자(과소 차단)는 **사고가 나야 안다**.

## 왜 금지 목록은 반드시 새는가

금지 목록은 「셀 수 있는 것」만 막는데, 우회 방법은 셀 수 없이 많기 때문이다. 26장 예제 2(`ex2_deny_vs_allow.py`)에서 `rm -rf` 패턴 하나를 막아도 이런 것들이 전부 빠져나간다.

| 우회 시도 | 왜 통과하는가 |
|---|---|
| `rm -fr /var/data` | 플래그 순서만 바꿨다 |
| `rm  -rf` (공백 두 개) | 문자열 패턴이 어긋난다 |
| `/bin/rm -rf ...` | 절대 경로로 이름을 바꿨다 |
| `sh -c 'rm -rf ...'` | 껍데기를 한 겹 씌웠다 |
| `python3 -c "shutil.rmtree(...)"` | 다른 프로그램으로 지웠다 |
| `find /var/data -delete` | `rm`을 아예 안 썼다 |

패턴을 세 개 더 추가하면 네 번째 우회가 나온다. 「지우는 방법」의 집합은 열려 있고(open set), 금지 목록은 닫힌 목록(closed list)이다. 이 비대칭 때문에 금지 목록은 구조적으로 **반드시 샌다**.

## 왜 허용 목록의 오류는 차단 쪽으로 가는가

허용 목록은 「내가 이해한 것」만 통과시킨다. 이해 못 한 것은 — 새로운 공격 방식이든, 정당하지만 미처 등록 안 한 명령이든 — **전부 막힌다**. 그래서:

- 새 공격이 나와도 막힌다. 허용 목록에 없으니까. (안전 쪽 실패, fail-safe)
- 대신 정당한 요청도 목록에 없으면 막힌다. 이게 「통과했어야 하는데 차단」이다.

단, 허용 목록도 허술하게 쓰면 샌다. 예제에서 `cat`을 이름만 허용했더니 `cat /etc/passwd`가 통과했다. 명령 **이름**만이 아니라 **인자까지**(예: 경로를 작업 디렉터리 아래로 제한) 적어야 하고, 문자열이 아니라 **정규화한 결과**를 비교해야 한다.

## 발견 비용의 비대칭 — 이게 결론을 정한다

| | 금지 목록 | 허용 목록 |
|---|---|---|
| 오류 방향 | 막았어야 하는데 통과 (과소 차단) | 통과했어야 하는데 차단 (과잉 차단) |
| 오류를 누가 알려 주나 | **아무도 안 알려 준다** — 유출·삭제 같은 사고가 터져야 안다 | **사용자가 즉시 항의한다** — "왜 안 되죠?" |
| 발견 시점 | 사후 (피해 발생 후) | 즉시 (피해 발생 전) |
| 고치는 비용 | 사고 수습 + 패턴 추가(그래도 또 샌다) | 목록에 한 줄 추가 |
| 운영 비용 | 손이 덜 간다 | 손이 계속 간다 |

과잉 차단은 **시끄러운 오류**라서 피드백 루프가 저절로 돈다. 과소 차단은 **조용한 오류**라서 감사 로그를 뒤지거나 사고가 나기 전까지는 존재조차 모른다.

## 그래서 선택은

- 금지 목록 — 손이 덜 가고, **반드시 샌다**
- 허용 목록 — 손이 계속 가고, **안 샌다**

권한 경계(security boundary)에서는 허용 목록을 고른다. 「반드시 샌다」는 권한 경계에서 받아들일 수 없는 성질이기 때문이다. OWASP 입력 검증 가이드도 같은 이유로 allowlist를 기본으로 권한다.

덧붙여 26장 예제 5(`ex5_audit_trail.py`)가 보여 주듯, 허용 목록의 약점인 과잉 차단은 **차단 로그 + 「사람이 뒤집은 비율」 지표**로 관리할 수 있다. 100% 뒤집히는 규칙은 틀린 규칙이니 고치면 된다 — 이 개선 루프가 돌아간다는 것 자체가, 오류가 「보이는 쪽」에 있다는 허용 목록의 장점이다.
