# `gate:approval` 규칙이 잘못된 근거

## 질문
`ex5_audit_trail.py`의 `gate:approval` 규칙이 잘못된 근거는 무엇인가?

## 핵심 답
**네 번 발동해서 네 번 다 사람이 뒤집었다(overridden).** 뒤집힌 비율 100%는 "규칙이 틀렸다"는 신호다. 외부 도메인 전부를 일괄 차단할 게 아니라, **허용 도메인 목록(allowlist)** 을 뒀어야 했다.

## 예제가 보여주는 구조

`ex5_audit_trail.py`(26장, "막은 것도 로그로 남긴다")는 차단 기록을 SQLite `gate_log` 테이블에 쌓고, "어느 규칙이 실제로 일하고 있나"를 센다. 로그 스키마의 핵심 컬럼은 셋이다.

- `rule` — 어느 규칙이 막았나
- `reason` — 왜 막았나 (사람이 읽을 수 있는 이유)
- `overridden` — 나중에 사람이 뒤집었나 (**정책 품질 지표**)

이벤트 데이터에서 `gate:approval` 관련 행은 네 줄이며, 전부 같은 패턴이다.

```python
("보고서", "send_mail", "gate:approval", "차단", "수신자가 외부 도메인", 1),
("보고서", "send_mail", "gate:approval", "차단", "수신자가 외부 도메인", 1),
("보고서", "send_mail", "gate:approval", "차단", "수신자가 외부 도메인", 1),
("보고서", "send_mail", "gate:approval", "차단", "수신자가 외부 도메인", 1),
```

마지막 컬럼 `overridden=1` — 네 번 모두 사람이 나중에 "이건 보내도 되는 메일"이라며 뒤집었다는 뜻이다. 코드에서 뒤집힌 비율이 80% 이상이면 `← 규칙이 틀렸다` 표시를 붙인다.

```python
rate = over / blocked if blocked else 0
mark = "  ← 규칙이 틀렸다" if rate >= 0.8 else ""
```

## 왜 100% 뒤집힘 = 규칙이 틀렸다는 뜻인가

- 규칙이 막은 결정이 매번 사람 손에서 번복된다면, 그 규칙은 위험을 걸러내지 못하고 **사람 시간만 소모**하고 있다. 승인 게이트가 사실상 "무조건 승인해 주는 요식 절차"가 된 것이다.
- 문제의 원인은 규칙의 조건이 너무 거칠다는 것: "수신자가 외부 도메인이면 전부 차단"은 정상적인 외부 발송(예: 거래처, 고객사 도메인)까지 전부 걸린다.
- 올바른 수정은 규칙을 없애는 게 아니라 **정밀하게 만드는 것** — 신뢰할 수 있는 허용 도메인 목록을 두고, 목록 밖 도메인만 승인 게이트에 태우는 방식이다.

## 대비되는 사례: 잘 일하는 규칙

같은 표에서 `deny:net-out`은 세 번 막았고 한 번도 뒤집히지 않았다(뒤집힘 0%). 권한 없는 에이전트의 외부 전송을 정확히 걸러내는, "잘 일하는 규칙"의 예다.

## 더 큰 교훈

- 차단 로그에 반드시 넣을 셋: **어느 규칙이 막았나 / 왜 막았나 / 사람이 뒤집었나.** 세 번째가 대부분 빠지는데, 그게 없으면 "과하게 막고 있는 규칙"을 영원히 못 찾는다.
- 과하게 막는 규칙은 결국 **다들 우회하는 규칙**이 된다. 로그는 단순 기록이 아니라 정책을 고치는 피드백 루프의 입력이다.
