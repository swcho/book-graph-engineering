# 요약이 시간 문제를 악화시키는 이유

**질문**: 요약이 시간 문제를 악화시키는 이유는 무엇인가?

**답**: 요약은 시간 칸을 갖고 다니지 않는다(24장). 2024년 대화를 요약해 넣으면 박민수가 여전히 팀장으로 남는다.

---

## 한 줄로

요약은 **문장만 남기고 시각을 버리는 압축**이다. 원본 대화에는 최소한 「2024년에 나눈 말」이라는 위치가 붙어 있었는데, 요약본은 그 위치를 떼고 「박민수 팀장」이라는 **시제 없는 단언**만 컨텍스트에 밀어 넣는다. 그래서 요약은 낡은 사실을 지우기는커녕, 낡은 사실을 *영원한 사실처럼* 보이게 만든다.

## 왜 이게 문제인가 — 27.3절의 상황

사용자가 이렇게 말한다.

> 「팀장님께 보고서 보내 줘.」

에이전트는 **지금** 팀장에게 보내야 한다. 그런데 기억이 이렇게 생겼다면?

| 사실 | 유효 시작 | 유효 끝 |
|---|---|---|
| 박민수 -이끔-> 결제팀 | 2024-01-01 | 2026-03-31 |
| 이서연 -이끔-> 결제팀 | 2026-04-01 | (지금도) |

시간 칸을 보고 물으면 답이 갈린다. `ex3_temporal_memory.py`가 그대로 보여 주는 부분이다.

```python
def ask(c, when):
    r = c.execute(
        "MATCH (a:N)-[e:R]->(b:N) WHERE e.vfrom <= $t AND e.vto >= $t "
        "RETURN a.name, e.kind, b.name ORDER BY a.name", {"t": when})
```

- 2025-01-15 시점에 물으면 → 박민수
- 2026-05-20 시점에 물으면 → 이서연

같은 그래프인데 답이 다르다. **그게 맞는 것이다.**

그런데 2024년 대화 기록을 **요약해서** 컨텍스트에 넣으면 이렇게 들어간다.

```
사용자 요약: 결제팀 소속. 팀장은 박민수. 매운 음식 못 먹는 팀장 배려 필요.
```

`vfrom`도 `vto`도 없다. 「2026-03-31에 끝났다」는 정보가 압축 과정에서 통째로 증발했다. 모델 입장에서 이 문장은 **현재형 사실**이다. 그래서 2026년 5월에도 박민수에게 보고서를 보낸다.

## 「악화」인 이유 — 그냥 틀린 게 아니라 더 나쁘다

요약이 없었으면 원본 대화 로그에는 최소한 날짜가 붙어 있었다. 모델이 「이건 2년 전 대화네」라고 판단할 여지가 있었다. 요약은 그 판단 재료를 **없애면서** 문장의 확신은 그대로 유지한다. 즉,

1. **시각 소실** — 요약문에는 유효 시각을 적을 자리가 없다. 24장에서 컨텍스트를 줄이려고 도입한 압축이, 27장에서는 시간 정보를 버리는 통로가 된다.
2. **모순의 은폐** — 원본에는 「박민수 팀장」과 「이서연 팀장」이 각각 다른 날짜에 나온다. 요약본 두 개가 나란히 들어오면 날짜 없이 **둘 다 현재형 단언**으로 보인다. `ex3`의 `ask_no_time()`이 보여 주는 그 화면이다.

```
박민수 -이끔-> 결제팀
이서연 -이끔-> 결제팀
나 -선호-> 채식
나 -선호-> 육식
```

> 박민수와 이서연이 둘 다 팀장이고, 채식과 육식을 둘 다 선호한다. 서로 모순되는 사실이 같이 산다. 시간 칸을 안 봤기 때문이다.

3. **빈도가 최신성을 이긴다** — 이게 결정타다. 모순된 기억을 받은 모델은 「최근 것」이 아니라 **「자주 나온 것」**을 고른다. 박민수가 2년간 팀장이었고 이서연이 두 달이면, 요약본 속 「박민수 팀장」이 압도적으로 많이 등장한다. 요약을 반복할수록(요약의 요약, 세션 간 이월) 옛 사실이 더 자주 재기입되어 **더 굳어진다**. 시간이 지날수록 틀린 답이 강해지는 구조다.

## 그럼 오래된 걸 지우면 되나 — 아니다

> 그래서 «오래된 것을 지운다»가 답이 아니다. 지우면 과거를 못 묻는다. «2025년 3월에 팀장이 누구였지»는 정당한 질문이다.

## 답: 지우지 말고 끝나는 시각을 적어라

- 새 사실이 들어오면 **옛 사실의 `vto`를 채운다**. 옛 사실은 그대로 남는다.
- 단일 값 관계(팀장, 소속, 현재 거주지처럼 한 시점에 하나만 참인 관계) 목록을 코드에 두고, 그 목록에 해당하면 자동으로 이전 엣지를 닫는다.
- 이러면 「지금 팀장」과 「2025년 3월 팀장」을 **같은 그래프에서 다른 질문으로** 답할 수 있다.

이게 요약이 못 하는 일이다. 요약은 문자열이라 시간 칸을 붙일 데가 없지만, 그래프의 엣지에는 `vfrom` / `vto` / `recorded` 속성을 얹을 수 있다(15장의 이시간, bitemporal 모델).

## 오해하기 쉬운 지점

| 오해 | 실제 |
|---|---|
| 요약이 부정확해서 문제다 | 요약이 **정확해도** 문제다. 2024년 시점 기준으로 「팀장은 박민수」는 참이었다. 틀린 건 사실이 아니라 시각의 부재다. |
| 요약할 때 날짜를 같이 적으면 해결 | 완화는 되지만, 「언제 끝났는지」는 요약 시점에 아직 모른다. 끝 시각은 **나중에 새 사실이 들어올 때** 적히는 값이다. 그래서 저장 구조에 갱신 가능한 칸이 있어야 한다. |
| 최근 요약만 남기면 된다 | 과거 질의를 못 하게 된다. 그리고 5절의 결론대로, 나이는 중요도와 별 관계가 없다. |
