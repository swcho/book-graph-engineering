# 「비슷한 것 찾기」는 왜 벡터가 이기는가

**질문**: `ex2_graph_vs_vector.py`에서 '비슷한 것 찾기'는 왜 벡터가 이기는가?

**답**: 정확히는 그래프가 답할 수 없다. "회식 장소 관련"에는 따라갈 엣지가 없고, 유사도 문제이지 경로 문제가 아니다.

---

## 1. 핵심을 한 줄로

「벡터가 더 잘한다」가 아니라 **「그래프는 아예 출발조차 못 한다」**가 정확한 표현입니다.

그래프 순회는 *어디서 출발해서 어떤 엣지를 따라갈지*가 정해져야 시작됩니다. 그런데 "회식 장소 관련해서 뭐가 있었지"라는 질문에는 출발 노드도, 따라갈 엣지 이름도 없습니다. `회식장소관련`이라는 관계는 그래프에 존재하지 않습니다. 그건 **의미가 가까운 정도(유사도)**를 묻는 질문이지, **연결을 따라가는(경로)** 질문이 아니기 때문입니다.

예제 코드가 이 질문에 대해서만 아래처럼 출력하는 이유가 그것입니다.

```python
else:
    print("  그래프: (이 질문에는 순회할 경로가 없다)")
```

## 2. 예제가 어떻게 짜여 있나

기억 일곱 줄에 손으로 적은 3차원 「임베딩」이 붙어 있습니다. 축은 `[사람관계, 장소, 취향]`입니다.

```python
MEMO = [
    ("이서연 님이 결제팀에 새로 왔다",     [0.9, 0.1, 0.0]),
    ("이서연 님은 마포에 산다",           [0.6, 0.8, 0.0]),
    ("박민수 팀장은 매운 음식을 못 먹는다", [0.5, 0.0, 0.9]),
    ("나는 채식을 한다",                 [0.2, 0.0, 0.9]),
    ("회식은 보통 강남에서 한다",         [0.1, 0.9, 0.3]),
    ("결제팀 팀장은 박민수다",            [0.9, 0.0, 0.1]),
    ("나는 강남에서 일한다",              [0.3, 0.9, 0.0]),
]
```

질문 세 개를 같은 기억에 던집니다.

| 종류 | 질문 | 질의 벡터 | 승자 |
|---|---|---|---|
| 비슷한 것 찾기 | 회식 장소 관련해서 뭐가 있었지 | `[0.1, 0.9, 0.3]` | 벡터 (그래프는 답 불가) |
| 여러 홉 잇기 | 우리 팀에서 마포에 사는 사람 | `[0.7, 0.7, 0.0]` | 그래프 |
| 전부 세기 | 결제팀 사람이 몇 명이지 | `[0.9, 0.1, 0.0]` | 그래프만 가능 |

그래프 쪽에는 노드 `나 / 박민수 / 이서연 / 결제팀 / 마포 / 강남`과 엣지 `속함 / 이끔 / 삶 / 일함`만 있습니다. 「회식」이라는 노드도, 「관련」이라는 엣지도 없습니다. 순회할 대상이 애초에 없는 것입니다.

## 3. 왜 벡터는 답할 수 있나

코사인 유사도는 **아무 두 벡터 사이에서나 항상 계산됩니다.** 관계가 미리 정의되어 있을 필요가 없습니다.

```python
def cos(a, b):
    d = sum(x * y for x, y in zip(a, b))
    na = math.sqrt(sum(x * x for x in a))
    nb = math.sqrt(sum(y * y for y in b))
    return d / (na * nb + 1e-9)
```

질의 벡터 `[0.1, 0.9, 0.3]`은 「회식은 보통 강남에서 한다」의 벡터와 정확히 같으므로 유사도 1.00으로 1등이고, 장소 축이 큰 「나는 강남에서 일한다」, 「이서연 님은 마포에 산다」가 뒤를 잇습니다. **명시된 관계가 없어도 「비슷함」은 언제나 정의된다** — 이게 벡터의 성질입니다.

## 4. 여기서 뒤집히는 지점 (같은 예제의 나머지 결론)

이 카드의 답만 외우면 「벡터가 더 좋구나」로 오해하기 쉽습니다. 예제는 곧바로 반대편을 보여 줍니다.

- **여러 홉 잇기**: 벡터도 1등에 「이서연 님은 마포에 산다」를 올려서 맞은 것처럼 보입니다. 하지만 벡터가 준 건 「마포에 사는 사람」이지 「우리 팀에서」가 아닙니다. 2등이 「나는 강남에서 일한다」인 게 증거로, 두 조건 중 하나만 맞춘 것입니다. 마포 사는 사람이 열 명이고 그중 팀원이 한 명이면 벡터는 못 고릅니다. **그래프는 두 조건을 동시에 만족하는 것을 구조로 찾고, 벡터는 두 조건과 비슷한 것을 찾습니다. 다른 일입니다.**
- **전부 세기**: 상위 3에 팀원 셋이 다 나오지 않습니다(「나」가 빠짐). k를 늘리면 나오겠지만 **k를 얼마로 해야 전부 나오는지 미리 알 방법이 없습니다.** 상위 k개를 주는 물건에는 「전부」가 없습니다.
- **없음 확인**: 「마포에 사는 팀원이 없다」를 벡터로는 확인할 수 없습니다. 유사도가 낮아도 뭔가는 돌려주기 때문입니다.

## 5. 정리 — 질문의 종류가 도구를 정한다

| 질문의 종류 | 도구 | 이유 |
|---|---|---|
| 비슷한 것 | 벡터 | 유사도는 관계 정의 없이도 항상 계산된다 |
| 이어진 것 (여러 홉) | 그래프 | 조건 여러 개를 **구조로** 동시에 만족시킨다 |
| 전부 / 세기 / 없음 | 그래프 | top-k에는 「전부」도 「없음」도 담기지 않는다 |

실무 결론은 「하나를 고르라」가 아닙니다. **벡터로 시작점을 찾고 그래프로 넓힙니다.** 질문에서 사람 이름이나 개념을 벡터로 찾아 노드를 잡고, 거기서 엣지를 따라가는 두 단계입니다. 이게 하이브리드 검색(hybrid retrieval)이고, 27장 요약에도 같은 문장으로 실려 있습니다.

## 6. 함정 주의

- `ex2`의 임베딩은 **손으로 적은 3차원 좌표**입니다. 진짜 임베딩 모델을 쓰면 숫자는 달라지지만, **「벡터가 못 하는 것」(전부 세기, 없음 확인)은 그대로**입니다. 그건 모델 품질 문제가 아니라 top-k라는 인터페이스의 성질이기 때문입니다.
- 반대로 이 카드의 결론(그래프가 유사도 질문에 답 못 함)도 모델을 바꾼다고 달라지지 않습니다. 그래프에 「관련」 엣지를 새로 만들어 넣지 않는 한 순회할 길이 생기지 않습니다.
