# 벡터와 그래프가 두 조건을 다루는 방식

> **Q.** 벡터와 그래프가 두 조건을 다루는 방식은 어떻게 다른가?
>
> **A.** 그래프는 두 조건을 **동시에 만족하는 것**을 구조로 찾고, 벡터는 두 조건과 **비슷한 것**을 찾는다. 다른 일이다.

---

## 한 줄로

- **그래프**: 조건 A를 만족하는 집합 ∩ 조건 B를 만족하는 집합 → **교집합(AND)**
- **벡터**: 조건 A와 B를 하나의 좌표로 뭉갠 뒤 그 좌표와 **가까운 순서**로 나열 → **평균(MIX)**

두 조건이 하나의 질의 벡터로 합쳐지는 순간, "둘 다"와 "둘의 중간쯤"의 구분이 사라집니다. 벡터에게 AND를 요구할 방법이 없습니다.

## 27장 예제(`ex2_graph_vs_vector.py`)로 보기

기억에 이런 사실들이 들어 있습니다. 괄호 안은 축이 세 개인 손으로 적은 «임베딩» — `[사람관계, 장소, 취향]`.

| 사실 | 벡터 |
|---|---|
| 이서연 님이 결제팀에 새로 왔다 | `[0.9, 0.1, 0.0]` |
| 이서연 님은 마포에 산다 | `[0.6, 0.8, 0.0]` |
| 박민수 팀장은 매운 음식을 못 먹는다 | `[0.5, 0.0, 0.9]` |
| 나는 채식을 한다 | `[0.2, 0.0, 0.9]` |
| 회식은 보통 강남에서 한다 | `[0.1, 0.9, 0.3]` |
| 결제팀 팀장은 박민수다 | `[0.9, 0.0, 0.1]` |
| 나는 강남에서 일한다 | `[0.3, 0.9, 0.0]` |

여기에 **조건이 둘인 질문**을 던집니다.

> **「우리 팀에서 마포에 사는 사람」** — 조건 ① 우리 팀 소속, 조건 ② 마포 거주. 질의 벡터 `[0.7, 0.7, 0.0]`.

### 벡터가 내놓는 것

유사도 상위 결과는 이렇습니다.

1. 이서연 님은 마포에 산다 `[0.6, 0.8, 0.0]`
2. **나는 강남에서 일한다** `[0.3, 0.9, 0.0]`

1등만 보면 벡터가 맞춘 것처럼 보입니다. 그런데 **2등이 결정적인 증거**입니다. 「나는 강남에서 일한다」는 조건 ②(마포)를 정면으로 위반합니다. 그런데도 상위에 올라옵니다. 왜냐하면 질의 벡터의 «장소 축이 높다»는 성질만 맞으면 되기 때문입니다.

즉 벡터가 실제로 답한 질문은 **「우리 팀에서 마포에 사는 사람」이 아니라 「사람관계·장소 축이 둘 다 좀 높은 문장」**이었습니다. 조건 두 개 중 하나만 맞춘 결과가 자연스럽게 섞여 들어옵니다.

### 왜 1등은 맞았나 — 우연입니다

이 예제에서 마포에 사는 사람은 **한 명뿐**이었습니다. 후보가 하나라서 우연히 정답이 1등이 된 것입니다.

> 마포 사는 사람이 열 명이고 그중 우리 팀이 한 명이면 **벡터는 못 고릅니다.**

마포 관련 문장 열 개가 「장소 축이 높다」는 이유로 상위를 도배하고, 그중 어느 것이 «우리 팀»인지 가려낼 장치가 벡터에는 없습니다. 데이터가 커질수록 이 우연은 사라집니다. 즉 벡터가 두 조건 질문에서 맞는 답을 주는 것은 **후보가 희소할 때 나타나는 착시**입니다.

### 그래프가 내놓는 것

```cypher
MATCH (t:N {name:'결제팀'})<-[:R]-(p:N)-[e:R {kind:'삶'}]->(l:N {name:'마포'})
RETURN p.name
```

패턴을 읽어 보면 `p`는 **결제팀으로 가는 엣지**와 **마포로 가는 «삶» 엣지**를 **둘 다** 가져야 합니다. 하나만 만족하는 노드는 패턴 매칭 단계에서 아예 탈락합니다. 「나」는 결제팀 소속이지만 마포 엣지가 없으므로 후보에조차 오르지 않습니다.

결과는 `['이서연']`. 유사도 점수도, k도, 임계값도 없습니다. **구조가 곧 필터**입니다.

## 핵심 차이 정리

| | 벡터 | 그래프 |
|---|---|---|
| 두 조건 처리 | 하나의 질의 벡터로 합쳐 «비슷한 정도» 계산 | 두 패턴을 동시에 만족하는 경로만 통과 |
| 논리 연산 | AND가 없음(사실상 가중 평균) | AND/OR/NOT을 구조로 표현 |
| 조건 하나만 맞는 것 | 상위에 섞여 들어옴 | 아예 제외됨 |
| 결과 형태 | 순위가 매겨진 상위 k개 | 조건을 만족하는 집합(전부) |
| 틀렸을 때 | 조용히 그럴듯한 답을 줌 | 빈 결과를 줌 |

마지막 줄이 실무에서 특히 중요합니다. 벡터는 **답이 없을 때도 무언가를 돌려줍니다.** 유사도가 낮아도 상위 k개는 채워지니까요. 그래서 「마포에 사는 팀원이 **없다**」를 벡터로는 확인할 수 없습니다. 그래프는 빈 결과가 곧 「없음」의 증명입니다.

## 같은 뿌리에서 나오는 다른 한계 — 「전부」

두 조건 문제와 「전부 세기」 문제는 같은 성질에서 나옵니다.

「결제팀 사람이 몇 명이지」에 대해 벡터 상위 3에는 이서연·박민수는 나왔지만 **「나」가 빠지고 엉뚱한 줄이 3등**에 들어옵니다. k를 늘리면 나오겠지만, **「k를 얼마로 해야 다 나오나」를 미리 알 방법이 없습니다.**

> 상위 k개를 주는 물건에는 «전부»가 없습니다.

「두 조건 동시 만족」도, 「전부」도, 「없음」도 결국 **집합을 확정하는 연산**입니다. 벡터는 집합이 아니라 순위를 다루는 도구이므로 원리적으로 이 셋을 못 합니다.

## 그래서 결론은 「하나를 고르라」가 아니다

| 질문 종류 | 강한 쪽 |
|---|---|
| 비슷한 것 찾기 | **벡터** (그래프는 따라갈 엣지가 아예 없음) |
| 이어진 것 / 여러 홉 잇기 | **그래프** |
| 전부 / 세기 / 없음 확인 | **그래프** |

「회식 장소 관련해서 뭐가 있었지」 같은 질문에는 순회할 경로가 없습니다. 유사도 문제지 경로 문제가 아닙니다. 그래프가 «지는» 게 아니라 **답할 수가 없습니다.**

### 실무 패턴: 벡터로 시작점, 그래프로 확장

이 장이 권하는 하이브리드 검색은 두 단계입니다.

1. 질문에서 사람 이름이나 개념을 **벡터로 찾아 노드를 잡는다** — 표현이 흔들려도(「이서연 씨」/「서연 님」/「결제팀 신입」) 붙잡을 수 있는 건 벡터의 강점.
2. 거기서 **엣지를 따라 넓힌다** — 두 조건 교집합, 전부 세기, 없음 확인은 그래프가 맡는다.

벡터는 «어디서 출발할지»를 정하고, 그래프는 «거기서 무엇이 참인지»를 정합니다. 이 역할 분담을 흐리면 위의 「2등이 강남」 같은 오답이 조용히 섞여 들어옵니다.

## 시험에 나올 한 문장

> 그래프는 **두 조건을 동시에 만족하는 것**을 구조로 찾고, 벡터는 **두 조건과 비슷한 것**을 찾는다. 그게 다른 일이다.
