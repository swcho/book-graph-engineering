# 시간 칸을 안 보면 모순되는 사실이 같이 산다

**질문**: `ex3_temporal_memory.py`에서 시간 칸을 안 보면 어떤 일이 생기는가?

**답**: 박민수와 이서연이 둘 다 팀장이고 채식과 육식을 둘 다 선호하는 등, 서로 모순되는 사실이 같이 산다.

---

## 1. 예제가 담고 있는 사실들

`ex3_temporal_memory.py`는 27장 27.3절(「기억에는 시각이 붙어야 한다」)의 실행 예제입니다. 그래프에 넣는 사실은 다섯 개인데, 각 사실마다 **유효 시작(vfrom) / 유효 끝(vto) / 기록 시각(recorded)** 세 개의 시간 칸이 붙습니다.

```python
# (주어, 관계, 목적어, 유효 시작, 유효 끝(None=지금도), 기록 시각)
FACTS = [
    ("박민수", "이끔",  "결제팀", "2024-01-01", "2026-03-31", "2024-01-05"),
    ("이서연", "이끔",  "결제팀", "2026-04-01", None,         "2026-04-02"),
    ("나",     "속함",  "결제팀", "2023-06-01", None,         "2023-06-01"),
    ("나",     "선호",  "채식",   "2025-09-01", None,         "2025-09-10"),
    ("나",     "선호",  "육식",   "2023-01-01", "2025-08-31", "2023-01-15"),
]
```

읽어 보면 사실 자체에는 아무 모순이 없습니다.

- 박민수는 2024-01-01 ~ 2026-03-31 동안 결제팀을 이끌었고, **그 뒤로** 이서연이 이끕니다.
- 「나」는 2023-01-01 ~ 2025-08-31 동안 육식을 선호했고, **그 뒤로** 채식을 선호합니다.

모순이 아니라 **교대**입니다. 다만 그 교대가 시간 칸 안에만 적혀 있습니다.

## 2. 시간 칸을 안 보는 질의

예제에는 두 종류의 질의가 나란히 있습니다. 차이는 `WHERE` 절 하나뿐입니다.

```python
def ask(c, when):                      # 시간을 보는 질의
    r = c.execute(
        "MATCH (a:N)-[e:R]->(b:N) WHERE e.vfrom <= $t AND e.vto >= $t "
        "RETURN a.name, e.kind, b.name ORDER BY a.name", {"t": when})
    ...

def ask_no_time(c):                    # 시간을 안 보는 질의
    r = c.execute("MATCH (a:N)-[e:R]->(b:N) RETURN a.name, e.kind, b.name "
                  "ORDER BY a.name")
    ...
```

`ask_no_time()`은 엣지에 `vfrom`, `vto`가 **저장되어 있는데도 읽지 않습니다.** 그래서 다섯 사실이 전부 동등한 자격으로 한꺼번에 나옵니다.

```
시간을 안 보면 이렇게 나온다.

  나     -선호-> 채식
  나     -선호-> 육식
  나     -속함-> 결제팀
  박민수 -이끔-> 결제팀
  이서연 -이끔-> 결제팀
```

예제가 곧바로 붙이는 해설이 답 그대로입니다.

> 박민수와 이서연이 둘 다 팀장이고, 채식과 육식을 둘 다 선호한다.
> 서로 모순되는 사실이 같이 산다. 시간 칸을 안 봤기 때문이다.

핵심은 **데이터가 틀린 게 아니라 질의가 시간 칸을 빼먹었다**는 점입니다. 그래프에는 답이 들어 있는데, 물어보는 쪽이 「지금」이라는 좌표를 대지 않아서 과거와 현재가 한 화면에 겹쳐 나온 것입니다.

## 3. 시간 칸을 보면 답이 갈린다

같은 그래프에 시점을 대고 물으면 결과가 깔끔하게 하나씩 떨어집니다.

```
[2025-01-15 시점에 물으면]
  나     -선호-> 육식
  나     -속함-> 결제팀
  박민수 -이끔-> 결제팀

[2026-05-20 시점에 물으면]
  나     -선호-> 채식
  나     -속함-> 결제팀
  이서연 -이끔-> 결제팀
```

예제의 표현대로 *「같은 그래프인데 답이 다르다. 그게 맞는 것이다.」* 시점이 다르면 답이 달라지는 게 정상이고, 시점을 안 대면 모순 덩어리가 나오는 것도 정상입니다.

구현상 요령 하나: `vto`가 `None`(아직 진행 중)인 사실은 저장할 때 `"9999-12-31"`로 채워 넣습니다.

```python
{"vf": vf, "vt": vt or "9999-12-31", ...}
```

이렇게 하면 `e.vto >= $t` 비교 하나로 「끝난 사실」과 「지금도 참인 사실」을 함께 걸러낼 수 있어, 질의에 `IS NULL` 분기를 넣지 않아도 됩니다.

## 4. 에이전트 기억에서 왜 치명적인가

이게 단순한 SQL 실수 이야기가 아닌 이유가 예제 후반부에 나옵니다.

1. **잘못된 행동으로 이어진다.** 사용자가 「팀장님께 보고서 보내 줘」라고 하면 *지금* 팀장에게 보내야 합니다. 그런데 2024년 대화 기록을 요약해서 컨텍스트에 넣으면 박민수가 여전히 팀장으로 남아 있습니다. **요약은 시간 칸을 갖고 다니지 않기 때문**입니다(24장).
2. **모순이 시간에 비례해 늘어난다.** 시간 칸을 안 보는 기억은 사실이 쌓일수록 모순 쌍이 늘어납니다. 기억이 커질수록 나빠지는 구조입니다.
3. **모델은 「최근 것」이 아니라 「자주 나온 것」을 고른다.** 이게 가장 위험한 부분입니다. 모순된 기억을 그대로 컨텍스트에 넣으면 모델은 최신성이 아니라 빈도로 판단합니다. 박민수가 2년간 팀장이었고 이서연이 두 달이면, 관련 문장 수에서 박민수가 압도합니다. **오래된 사실이 이깁니다.**

## 5. 그럼 해법은 「지우기」인가

아닙니다. 예제가 명시적으로 반박합니다.

- 오래된 것을 **지우면 과거를 못 묻습니다.** 「2025년 3월에 팀장이 누구였지」는 정당한 질문이고, 삭제하면 이 질문에 답할 수 없습니다.
- 답은 지우는 게 아니라 **끝나는 시각을 적는 것**입니다. 새 사실이 들어오면 옛 사실의 `vto`를 채워 **닫고**, 옛 사실은 행 그대로 남깁니다.

이것이 15장의 **이시간(bitemporal) 모델**을 에이전트 기억에 적용한 형태입니다.

| 시간 축 | 칸 | 뜻 |
|---|---|---|
| 유효 시간(valid time) | `vfrom`, `vto` | 그 사실이 **현실에서** 참이었던 기간 |
| 기록 시간(transaction time) | `recorded` | 그 사실을 **시스템이 알게 된** 시각 |

두 축이 따로 있어야 「2025년 3월 기준 팀장은 누구였나」와 「2025년 3월에 우리 시스템이 팀장이라고 믿고 있던 사람은 누구였나」를 구분해서 답할 수 있습니다. 뒤늦게 정정된 사실을 추적할 때 이 구분이 필요합니다.

관련 1차 출처는 27장 키워드 표에 정리되어 있습니다.

- 유효 시간 [표준] — <https://www.iso.org/standard/76583.html>
- 시간 인식 지식 그래프 [실험] — <https://arxiv.org/abs/2501.13956>

## 6. 한 줄 정리

`ex3_temporal_memory.py`에서 `ask_no_time()`처럼 `vfrom`/`vto`를 보지 않고 질의하면, **박민수와 이서연이 동시에 팀장이고 채식과 육식을 동시에 선호하는** 상태로 과거 사실과 현재 사실이 한데 섞여 나옵니다. 그래프가 틀린 게 아니라 시점 좌표를 안 준 것이고, 이 상태의 기억을 받은 모델은 최신 사실이 아니라 오래 반복된 사실을 고릅니다.
