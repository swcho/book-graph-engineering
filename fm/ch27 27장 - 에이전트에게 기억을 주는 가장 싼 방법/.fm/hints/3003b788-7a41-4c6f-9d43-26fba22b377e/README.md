# 모순된 기억을 받은 모델은 어떻게 행동하는가?

> **답**: 「최근 것」이 아니라 「자주 나온 것」을 고른다.
> 박민수가 2년, 이서연이 두 달이면 박민수가 이긴다.

---

## 1. 이 카드가 나온 자리

27장 **27.3 「기억에는 시각이 붙어야 한다」**, 예제 `ex3_temporal_memory.py`의 마지막 문단입니다.

이 예제는 15장에서 본 **이시간(bitemporal) 모델**을 에이전트 기억에 적용합니다. 사실 하나를 저장할 때 「주어-관계-목적어」만 적는 게 아니라 **유효 시작(vfrom)**, **유효 끝(vto)**, **기록 시각(recorded)** 을 같이 적습니다.

```python
# (주어, 관계, 목적어, 유효 시작, 유효 끝(None=지금도), 기록 시각)
FACTS = [
    ("박민수", "이끔",  "결제팀", "2024-01-01", "2026-03-31", "2024-01-05"),
    ("이서연", "이끔",  "결제팀", "2026-04-01", None,         "2026-04-02"),
    ("나",     "속함",  "결제팀", "2023-06-01", None,         "2023-06-01"),
    ("나",     "선호",  "채식",   "2025-09-01", None,         "2025-09-10"),
    ("나",     "선호",  "육식",   "2023-01-01", "2025-08-31", "2023-01-15"),
]
```

시간 칸을 **안 보고** 전부 꺼내면 이렇게 됩니다.

```
박민수 -이끔-> 결제팀
이서연 -이끔-> 결제팀
나     -선호-> 채식
나     -선호-> 육식
```

> 박민수와 이서연이 둘 다 팀장이고, 채식과 육식을 둘 다 선호한다.
> 서로 모순되는 사실이 같이 산다. 시간 칸을 안 봤기 때문이다.

시간 칸을 **보고** 물으면 같은 그래프인데 답이 달라집니다.

| 물은 시점 | 팀장 | 선호 |
|---|---|---|
| 2025-01-15 | 박민수 | 육식 |
| 2026-05-20 | 이서연 | 채식 |

```python
"MATCH (a:N)-[e:R]->(b:N) WHERE e.vfrom <= $t AND e.vto >= $t ..."
```

「같은 그래프인데 답이 다르다. 그게 맞는 것이다.」

---

## 2. 그런데 왜 이 카드가 무서운 이야기인가

시간 칸을 안 붙이면 모순된 사실 두 개가 **동시에 프롬프트에 들어갑니다.** 이때 사람들은 은근히 이렇게 기대합니다.

> 「모델이 알아서 최신 걸 고르겠지.」

**아닙니다.** 27장이 못 박는 문장이 이겁니다.

> 모순된 기억을 받은 모델은 「최근 것」이 아니라 **「자주 나온 것」** 을 고른다.
> 박민수가 2년간 팀장이었고 이서연이 두 달이면, **박민수가 이긴다.**

이유는 단순합니다. 대화 로그를 요약해서 기억에 넣으면, 사실의 **분량은 그 사실이 참이었던 기간에 비례**합니다. 박민수가 팀장이던 2년치 대화에는 「박민수 팀장님」이 수백 번 나오고, 이서연이 팀장이 된 두 달치 대화에는 몇 번 안 나옵니다. 모델 입장에서는 **한쪽 증거가 압도적으로 많은 상태**입니다.

그래서 이런 사고가 납니다.

> 사용자가 「팀장님께 보고서 보내 줘」라고 하면 **지금** 팀장에게 보내야 한다.
> 그런데 2024년 대화 기록을 요약해 넣으면 박민수가 팀장으로 남아 있다.
> **요약은 시간 칸을 안 갖고 다니기 때문이다(24장).**

이게 「기억이 쌓일수록 좋아진다」는 직관이 깨지는 지점입니다. 시간 칸 없이 쌓으면 **오래된 사실일수록 강해집니다.** 기억이 쌓일수록 모순이 늘고, 모순이 늘수록 옛날 답이 이깁니다.

## 3. 연구가 뒷받침하는 것 (프롬프트 안의 빈도 편향)

이건 이 책만의 주장이 아니라 LLM 지식 충돌(knowledge conflict) 연구가 반복해서 재현한 현상입니다.

- **지식 충돌의 세 종류**: `context-memory conflict`(프롬프트 vs 학습된 지식), `inter-context conflict`(프롬프트 안의 여러 조각끼리 충돌), `intra-memory conflict`(학습 지식 내부의 충돌). 여기서 문제가 되는 건 **inter-context conflict** — 우리가 기억에서 꺼내 넣은 조각끼리 싸우는 경우입니다. ([Knowledge Conflicts for LLMs: A Survey](https://arxiv.org/html/2403.08319v2), EMNLP 2024)
- **증거 인기도(evidence popularity) 편향**: 상충하는 증거가 함께 주어지면 모델은 **더 많은 문서가 지지하는 답**으로 기울어집니다. 이른바 다수결 편향(majority bias).
- **반복만으로도 뒤집힌다**: 새로운 출처가 하나도 추가되지 않고 **같은 내용을 여러 번 반복하기만 해도** 모델의 선호가 그쪽으로 넘어갑니다. 낮은 신뢰도 출처를 반복하면 정부 문서 같은 고신뢰 출처 선호마저 뒤집힙니다. ([Whose Facts Win? LLM Source Preferences under Knowledge Conflicts](https://arxiv.org/html/2601.03746))
- **시간성은 약한 신호**: 모델은 「어느 쪽이 더 최신인가」를 판단할 안정적 장치가 없습니다. 프롬프트에 날짜가 적혀 있어도 빈도 휴리스틱을 이깁니다. ([ECon: On the Detection and Resolution of Evidence Conflicts](https://arxiv.org/pdf/2410.04068))

정리하면 모델의 실제 결정 규칙은 **「최신성 판단」이 아니라 「양 세기」에 가깝습니다.** 그래서 모순 해소를 모델에게 맡기면 안 되고, **꺼내기 전에(retrieval 단계에서) 해소해야** 합니다.

## 4. 그래서 무엇을 해야 하나

### 「오래된 것을 지운다」는 답이 아니다

지우면 과거를 못 묻습니다. 「2025년 3월에 팀장이 누구였지」는 **정당한 질문**입니다.

### 답은 「끝나는 시각을 적는」 것이다

> 새 사실이 들어오면 옛 사실의 `vto`를 채운다. 옛 사실은 그대로 남는다.

즉 **삭제(delete)가 아니라 마감(close)** 입니다.

| 방식 | 과거 질의 | 모순 | 평가 |
|---|---|---|---|
| 옛 사실을 지운다 | 불가 | 없음 | 과거를 잃음 |
| 그냥 다 쌓는다 | 가능 | **폭증** | 빈도 편향으로 옛 답이 이김 |
| **vto를 채운다** | 가능 | 없음(시점 질의) | 27장이 권하는 방식 |

### 실무 체크리스트

1. **단일 값 관계 목록을 코드에 둔다.** 「팀장이다」, 「거주지」, 「식성」처럼 **동시에 하나만 참일 수 있는** 관계를 명시해 두고, 새 사실이 들어오면 같은 (주어, 관계) 쌍의 옛 엣지 `vto`를 자동으로 닫습니다.
2. **꺼낼 때 시점 필터를 건다.** `WHERE e.vfrom <= $t AND e.vto >= $t`. 기본값 `$t = now`.
3. **요약을 그대로 기억에 넣지 않는다.** 요약은 시간 칸을 안 갖고 다닙니다(24장). 요약에서 사실을 뽑을 때 유효 구간을 같이 붙이거나, 못 붙이면 「원문·추론」 영역으로 격리합니다.
4. **한 시점당 한 답만 컨텍스트에 넣는다.** 모순된 두 줄을 같이 넣어 놓고 모델이 고르길 기대하지 마세요. 빈도가 이깁니다.

---

## 5. 한 줄 암기

> **모델은 최신 걸 안 고른다. 많이 본 걸 고른다.**
> 그래서 모순은 프롬프트가 아니라 **`vto`** 에서 끝내야 한다.
