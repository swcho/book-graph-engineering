# 자동 거절 정책의 문제는 무엇인가?

**답:** 안전해 보이지만 420만 원짜리 요청을 거절하고, 고객은 이유도 모른 채 거절 통보를 받는다.

출처: 23장 「사람이 끼어드는 지점」 23.4절 · `code/ex4_no_answer.py`

---

## 1. 질문의 무대: 사람이 답을 안 할 때

23장은 사람을 그래프 밖의 예외가 아니라 **안의 노드**로 넣는 이야기입니다. 중단점(`interrupt`)으로 멈추고, 체크포인터에 자리를 남기고, 사람이 사흘 뒤에 답해도 이어 갑니다.

그런데 여기에 빈칸이 하나 남습니다. **사람이 아예 답을 안 하면?**

무응답 정책을 정하지 않으면 기본값은 「영원히 기다림」입니다. 그건 정책이 아니라 정책을 안 정한 것입니다. 그래서 23.4절은 무응답 처리 정책 네 가지를 같은 상황에 나란히 붙여 봅니다.

| 정책 | 24시간(SLA) 넘으면 |
|---|---|
| 기다리기 | 계속 기다린다 (영원히) |
| **자동 거절** | **거절 처리 — 안전하지만 고객이 화난다** |
| 자동 승인 | 승인 처리 — 위험 그대로 통과 |
| 등급 올리기 | 시간·금액·위험도에 따라 다르게 |

## 2. 같은 대기 큐, 네 가지 결말

`ex4_no_answer.py`의 대기 목록(SLA 24시간)에 네 정책을 적용하면 이렇게 갈립니다.

| 주문 | 금액 | 대기 | 위험 | 기다리기 | **자동 거절** | 자동 승인 | 등급 올리기 |
|---|---:|---:|---|---|---|---|---|
| A-1024 | 120,000 | 2h | 보통 | 계속 기다린다 | 대기 | 대기 | 대기 |
| A-1031 | 890,000 | 26h | 높음 | 계속 기다린다 | **자동 거절** | 자동 승인 | 담당자 재알림 |
| A-1044 | 150,000 | 73h | 보통 | 계속 기다린다 | **자동 거절** | 자동 승인 | 상급자 호출 |
| **A-1050** | **4,200,000** | **121h** | **높음** | 계속 기다린다 | **자동 거절** | 자동 승인 | 상급자 호출 |
| A-1066 | 110,000 | 200h | 낮음 | 계속 기다린다 | **자동 거절** | 자동 승인 | 자동 승인 |

정책 코드는 세 줄이 전부입니다.

```python
def p_reject(_o, _a, h, _r):
    return ("자동 거절", "안전하지만 고객이 화난다") if h > SLA else ("대기", "-")
```

이 함수의 시그니처가 이미 문제를 말하고 있습니다. **금액(`_a`)도 위험도(`_r`)도 밑줄로 버려집니다.** 자동 거절은 오직 시계만 봅니다. 420만 원짜리 A-1050과 11만 원짜리 A-1066을 완전히 똑같이 취급합니다. 「대기 시간이 SLA를 넘었다」는 사실 하나로 모든 결정을 내리기 때문입니다.

비교해 보면 `p_escalate`는 같은 자리에서 세 신호를 다 씁니다.

```python
def p_escalate(_o, amount, h, risk):
    if h <= SLA:                                  return "대기", "-"
    if risk == "낮음" and amount < 200_000:       return "자동 승인", "소액·저위험만 통과"
    if h > 72:                                    return "상급자 호출", "책임을 위로 올린다"
    return "담당자 재알림", "한 번 더 찌른다"
```

## 3. 핵심: 「안전한 기본값」은 **누구에게** 안전한가

`p_reject`의 사유 문자열이 이 절의 요약입니다. **"안전하지만 고객이 화난다."** 앞뒤 절의 주어가 다릅니다.

- **"안전하다"의 주어 = 시스템/회사.** 거절은 돈이 나가지 않습니다. 잘못 승인해서 420만 원이 빠져나가는 사고가 안 납니다. 장부에 손실이 안 찍히고, 사후 감사에서 「우리는 아무것도 내주지 않았다」고 말할 수 있습니다.
- **"화난다"의 주어 = 고객.** 정당한 환불 요청이 **담당자가 바빴다는 이유로** 거절됩니다. 판단이 있어서 거절된 게 아니라, 판단이 없어서 거절된 것입니다.

즉 자동 거절이 하는 일은 리스크를 **없애는 것이 아니라 옮기는 것**입니다.

```
[자동 승인]  리스크 → 회사가 진다 (위험 노출, 눈에 보임)
[자동 거절]  리스크 → 고객이 진다 (신뢰 손실, 눈에 안 보임)
```

여기가 함정입니다. 자동 승인의 비용은 **계량됩니다.** 23.3절의 `ex3_gate_policy.py`가 계산하던 「자동 처리 위험액」이 바로 그것입니다. 반면 자동 거절의 비용은 **아무 장부에도 안 찍힙니다.** 이탈한 고객, 깎인 신뢰, 콜센터로 들어오는 항의, 소셜 미디어에 올라가는 캡처는 어느 대시보드에도 숫자로 안 나옵니다.

그래서 「안전한 기본값(fail-safe)」이라는 말이 위험합니다. fail-safe는 **어느 방향으로 안전한지**를 반드시 함께 물어야 하는 개념입니다. 원래 이 말은 「고장 나면 피해가 없는 쪽으로 떨어진다」는 뜻인데(엘리베이터가 전원이 끊기면 브레이크가 잡히는 식), 자동 거절은 **피해를 없애는 게 아니라 측정되지 않는 쪽으로 밀어 넣습니다.** 지표상으로는 안전해 보이는데, 실제로는 안전한 게 아니라 **비용이 안 보이는 쪽으로 이동한** 것뿐입니다.

23장 본문이 「안전해 보이지만」이라고 쓴 이유가 이겁니다. 보이는 것과 실제가 다릅니다.

## 4. 왜 하필 420만 원인가

카드의 답에 「420만 원」이라는 구체적인 숫자가 들어간 것은 우연이 아닙니다. 자동 거절이 가장 크게 틀리는 지점을 골라 놓은 것입니다.

- **금액이 클수록 손해가 큽니다.** 11만 원 거절과 420만 원 거절은 고객이 겪는 일이 다릅니다. 그런데 `p_reject`는 둘을 구분하지 않습니다.
- **금액이 클수록 사람이 답을 안 했을 가능성이 큽니다.** 121시간(5일) 묶여 있었다는 건 담당자가 판단하기 어려웠거나, 화면에 정보가 부족했거나, 위로 올릴 사람을 못 찾았다는 뜻입니다. `ex5_audit.py`의 감사 기록에도 A-1050은 `answered_at`이 `None`이고 보여 준 내용은 **"금액 4,200,000 / 확인 불가"** 입니다. **정보가 없어서 못 정한 건**을 시스템이 「거절」로 확정 짓는 셈입니다.
- **즉 자동 거절은 어려운 건일수록 더 세게 틀립니다.** 쉬운 건은 사람이 이미 처리했으니 SLA를 안 넘습니다. SLA를 넘어 자동 거절로 떨어지는 건은 **정의상 판단이 필요했던 건**들입니다. 판단이 필요한 것만 골라 판단 없이 처리하는 정책입니다.

## 5. 두 번째 문제: 고객이 이유를 모른다

답의 뒷부분 — **"고객은 이유도 모른 채 거절 통보를 받는다"** — 은 별개의 결함입니다.

23장 `ex1_interrupt.py`의 거절 경로는 이렇게 되어 있습니다.

```python
return {"결과": "환불 거절 — 사유를 고객에게 안내"}
```

거절에는 **사유가 붙는 게 정상**입니다. 「개봉 상태라서」, 「3회차 반복 환불이라서」처럼 사람의 판단이 담깁니다. 그런데 타임아웃 자동 거절에는 붙일 사유가 없습니다. 진짜 이유는 「담당자가 5일 동안 이 건을 안 봤다」이고, 그건 고객에게 보낼 수 없는 문장입니다. 그래서 안내문은 「정책상 승인되지 않았습니다」 같은 빈 문장이 됩니다.

여파는 세 갈래입니다.

1. **고객이 대응할 수 없습니다.** 이유를 알면 서류를 보완하거나 이의를 제기할 수 있는데, 이유가 없으면 다시 처음부터 요청하는 수밖에 없습니다.
2. **큐가 다시 늘어납니다.** 억울한 고객은 재요청하거나 콜센터에 전화합니다. 자동 거절로 줄인 것처럼 보였던 부하가 다른 창구로 되돌아옵니다. **처리한 게 아니라 옮긴 것**입니다.
3. **감사 추적이 오염됩니다.** 기록에는 「거절」이 남지만 그 결정을 내린 사람도, 그때 화면에 뜬 내용도 없습니다. 나중에 「왜 거절했느냐」에 답할 수 없습니다. 23.5절이 승인 기록에 「보여 준 내용」과 「상태 지문」을 넣으라고 한 이유와 정확히 같은 자리에서, 자동 거절은 빈칸을 남깁니다.

## 6. 그래서 무엇을 쓰나 — 시간이 지날수록 다르게

23.4절의 결론은 자동 거절의 반대편(자동 승인)이 아닙니다. 자동 승인은 대칭적으로 나쁩니다. 위험을 그대로 통과시키고, 420만 원 고위험 건을 그냥 내보냅니다.

실무의 답에 가까운 것은 **네 번째, 등급 올리기**입니다. 핵심은 「시간이 지날수록 다르게 처리한다」입니다.

```
 24시간 — 소액·저위험만 자동 통과, 나머지는 담당자 재알림
 72시간 — 상급자를 부른다
```

이 구조가 자동 거절과 다른 점은 두 가지입니다.

- **결정을 시간에 위임하지 않습니다.** 시간이 하는 일은 「누구에게 물을지」를 바꾸는 것이지 「무엇으로 처리할지」를 정하는 게 아닙니다. 등급 올리기는 **판단을 올리는 장치가 아니라 주의를 끄는 장치**입니다. 420만 원짜리는 여전히 사람이 봅니다. 다만 **다른 사람**이 봅니다.
- **자동 처리 범위를 위험도로 좁힙니다.** A-1066(11만 원·저위험)만 자동 승인으로 빠지고, 나머지는 사람에게 남습니다. 「소액·저위험만 통과」라는 조건이 fail-safe의 방향을 명시적으로 선언합니다.

그리고 23.4절이 마지막에 남기는 문장이 이 카드의 진짜 교훈입니다.

> 중요한 건 «무엇을 고르느냐»가 아니라 «골랐느냐»다.
> 안 고르면 기본값은 언제나 «영원히 기다림»이고, 그건 아무도 원하지 않는다.

자동 거절도 아무것도 안 정한 것보다는 낫습니다. 문제는 그것을 **「안전한 선택」이라고 부르며 검토를 끝내 버리는 것**입니다. 안전 비용이 고객 쪽으로 넘어갔을 뿐인데, 넘어간 자리를 아무도 안 보고 있습니다.

## 한 줄 정리

자동 거절은 **시계 하나만 보고** 금액·위험도를 버린 채 420만 원짜리를 거절합니다. 「안전하다」는 회사 장부 기준일 뿐이고, 실제로는 리스크를 **계량되지 않는 고객 피해와 신뢰 비용으로 전가**한 것입니다. 게다가 진짜 사유가 「담당자가 안 봤다」이므로 고객에게 설명할 말도, 감사에 남길 근거도 없습니다.
