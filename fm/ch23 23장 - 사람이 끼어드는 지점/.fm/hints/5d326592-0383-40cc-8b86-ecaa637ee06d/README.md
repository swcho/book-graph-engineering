# '좋은노드'는 어떻게 구성되어 있는가?

**답:** `interrupt()`를 먼저 호출하고 그 뒤에 기록 같은 부작용을 둔다. 그러면 부작용이 한 번만 실행된다.

---

## 코드로 보면

23장 `ex2_node_reruns.py`에는 같은 일을 하는 노드가 둘 나옵니다. 순서만 다릅니다.

```python
호출수 = {"메일": 0, "조회": 0}


def 나쁜노드(s: S) -> S:
    호출수["메일"] += 1
    print(f"    → 담당자에게 «검토 요청» 메일 발송 (누적 {호출수['메일']}회)")
    답 = interrupt("승인하시겠습니까?")      # 부작용이 «앞»에 있다
    return {"승인": 답}


def 좋은노드(s: S) -> S:
    답 = interrupt("승인하시겠습니까?")      # 부작용 «앞»에 둔다
    호출수["조회"] += 1
    print(f"    → 결과 기록 (누적 {호출수['조회']}회)")
    return {"승인": 답}
```

`좋은노드`의 구성은 딱 세 줄로 요약됩니다.

1. **`interrupt()` 호출** — 그래프가 여기서 멈추고, 사람에게 물음을 던집니다.
2. **부작용** — 기록, 메일, 외부 API 호출처럼 밖으로 나가는 일은 전부 `interrupt()` **뒤에** 둡니다.
3. **상태 반환** — 사람이 준 답(`답`)을 상태에 담아 돌려줍니다.

실행하면 메일은 2회, 결과 기록은 1회로 갈립니다. 같은 「한 번의 승인」인데 횟수가 다릅니다.

## 왜 앞에 두면 두 번 실행되는가

체크포인트는 **노드 경계**에 찍힙니다 (21장의 슈퍼스텝 경계 이야기가 그대로 돌아옵니다).

- `interrupt()`는 노드 *중간*에서 멈춥니다.
- 하지만 저장된 체크포인트는 「이 노드를 실행하기 직전」 지점입니다.
- `Command(resume=...)`으로 재개하면 그 노드를 **처음부터** 다시 돕니다.

```
[첫 실행]   노드 시작 ─ 부작용(1회) ─ interrupt ✋ 멈춤
                        ↑
                   체크포인트는 여기(노드 시작)에 있다

[재개]      노드 시작 ─ 부작용(2회) ─ interrupt (이번엔 답을 갖고 통과) ─ 끝
                        ↑
                   앞에 있던 코드가 또 실행된다
```

즉 `interrupt()` 앞의 코드는 **최소 두 번** 실행됩니다. 뒤의 코드는 재개 후 한 번만 지나갑니다. `좋은노드`는 이 구조를 그대로 이용한 배치입니다.

## 규칙

> **interrupt 앞에는 부작용을 두지 않는다.**

- 읽기만 하는 코드(조회, 계산, 포맷팅)는 앞에 있어도 괜찮습니다. 두 번 돌아도 밖에 흔적이 안 남으니까요.
- 밖으로 나가는 것 — 메일 발송, 결제, DB 쓰기, 외부 API 호출, 로그 기록 — 은 전부 뒤로 밉니다.

## 부작용이 꼭 앞에 있어야 하면?

노드를 둘로 쪼갭니다.

```
«부작용 노드»  →  «interrupt 노드»
                ↑
          여기에 노드 경계 = 체크포인트가 생긴다
```

경계가 사이에 끼면 재개할 때 부작용 노드는 이미 완료된 것으로 처리되고, `interrupt` 노드만 다시 돕니다. 노드를 쪼개는 것이 곧 「여기까지는 다시 하지 않는다」는 선을 긋는 일입니다.

## 함께 기억할 것

- 이 문제의 대안이 **멱등성**입니다. 부작용을 앞에 둬야 하는데 쪼갤 수도 없다면, 그 부작용 자체를 여러 번 호출해도 한 번과 같은 효과가 나도록 만듭니다(22장의 되갚기·멱등 키 이야기).
- 멈춘 자리는 체크포인터에 남으므로 프로세스를 붙잡고 있을 필요가 없습니다. 다만 예제는 `InMemorySaver`라 프로세스가 죽으면 사라집니다. 운영에서는 디스크 체크포인터를 써야 사람이 사흘 뒤에 답해도 이어집니다.
