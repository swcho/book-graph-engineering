# `interrupt()`는 무엇을 반환하는가

**Q.** `ex1_interrupt.py`에서 `interrupt()`는 무엇을 반환하는가?

**A.** 사람이 나중에 `Command(resume=답)`으로 넘긴 값을 반환한다. 호출 시점에는 그래프가 그 자리에서 멈춘다.

---

## 한 줄로 먼저

`interrupt()`는 **「지금」이 아니라 「나중에」 값을 돌려주는 함수**다.
호출하는 순간에는 아무것도 반환하지 않고 그래프를 멈춘다. 사람이 답을 주고 `Command(resume=답)`으로 재개하면, 그때 그 `답`이 `interrupt()`의 반환값이 되어 노드가 이어진다.

즉 반환값의 출처는 그래프 안이 아니라 **그래프 밖의 사람**이다.

---

## 코드에서 짚기

`ex1_interrupt.py`의 `사람확인` 노드:

```python
def 사람확인(s: S) -> S:
    if s["금액"] < 100_000:
        print("  [확인]  10만 원 미만이라 사람에게 안 묻는다")
        return {"승인": "자동"}

    # 여기서 그래프가 «멈춘다». 예외가 아니라 정상적인 중단이다.
    답 = interrupt({
        "물음": "이 환불을 승인하시겠습니까?",
        "금액": s["금액"],
        "근거": "고객 요청 · 상품 미개봉",
    })
    print(f"  [확인]  사람이 «{답}» 라고 했다")
    return {"승인": 답}
```

여기서 **인자와 반환값의 방향이 정반대**라는 게 핵심이다.

| | 방향 | 내용 |
|---|---|---|
| `interrupt(...)`의 **인자** | 그래프 → 사람 | 「무엇을 물을지」. 여기서는 물음·금액·근거가 담긴 dict |
| `interrupt(...)`의 **반환값** | 사람 → 그래프 | 「사람이 뭐라고 답했는지」. 여기서는 `"승인"` 또는 `"거절"` 문자열 |

그리고 호출 쪽(`run` 함수):

```python
out = app.invoke({"금액": 금액, "승인": "", "결과": ""}, cfg)

if "__interrupt__" in out:
    물음 = out["__interrupt__"][0].value      # ← interrupt()에 «넣은» 값이 여기로 나온다
    ...
    out = app.invoke(Command(resume=사람답변), cfg)   # ← 이 사람답변이 interrupt()의 «반환값»이 된다
```

`run(300_000, 사람답변="승인")`을 부르면 `사람확인` 노드 안의 `답` 변수에 결국 `"승인"`이 들어오고, `run(900_000, 사람답변="거절")`이면 `"거절"`이 들어온다. 노드 코드는 한 글자도 다르지 않은데 반환값이 달라진다.

## 멈춤과 재개, 실제로 일어나는 일

```
1차 invoke
  START → 초안 → 사람확인
                    │
                    ├─ interrupt({...}) 호출
                    │     └─ 특수 예외(GraphInterrupt)를 던져 실행을 여기서 끊는다
                    │        · 상태를 체크포인터에 저장
                    │        · interrupt에 넘긴 dict를 밖으로 올려보냄
                    ▼
  invoke 반환 → out["__interrupt__"][0].value == {"물음": ..., "금액": ..., "근거": ...}
                app.get_state(cfg).next == ('사람확인',)   ← 아직 안 끝난 노드가 남아 있다

  ... 여기서 프로세스를 붙잡고 있을 필요가 없다. 사흘 뒤여도 된다 ...

2차 invoke(Command(resume="승인"), cfg)   ← 같은 thread_id 필수
  체크포인터에서 상태 복원
  사람확인 노드를 «처음부터» 다시 실행
                    │
                    ├─ interrupt({...}) 재도달 → 이번엔 멈추지 않고 "승인"을 «반환»
                    ▼
              → 실행 → END
```

포인트 세 가지.

1. **멈춤은 예외가 아니라 정상 흐름이다.** 구현은 내부적으로 예외(`GraphInterrupt`)를 쓰지만, 그건 실행 스택을 되감기 위한 수단일 뿐 「에러」가 아니다. 그래서 `try/except`로 잡으면 안 된다. 잡아 버리면 그래프가 멈추질 못한다.
2. **멈춘 자리는 프로세스가 아니라 체크포인터에 있다.** 그래서 `compile(checkpointer=InMemorySaver())`가 필수다. 체크포인터 없이 `interrupt()`를 쓰면 재개할 자리를 저장할 데가 없어서 동작하지 않는다. (예제는 메모리 세이버라 프로세스가 죽으면 같이 죽는다. 운영에서는 21장에서 본 디스크/DB 체크포인터를 써야 사람이 사흘 뒤에 답해도 이어진다.)
3. **재개는 같은 `thread_id`로 해야 한다.** `cfg = {"configurable": {"thread_id": f"환불-{금액}"}}` — 1차와 2차 invoke가 같은 `cfg`를 쓰는 이유다. 스레드 ID가 다르면 「그 멈춤」을 찾지 못한다.

## 자주 나오는 오해

**「`interrupt()`가 사람 입력을 기다렸다가 받아 온다」 — 아니다.**
`input()` 같은 블로킹 호출이 아니다. `interrupt()`는 기다리지 않고 **즉시 실행을 끊고 빠져나온다**. 기다리는 주체는 프로세스가 아니라 「체크포인터에 저장된 상태」다. 챕터 마지막 문장이 정확히 이걸 짚는다 — *「이게 «사람을 기다리는 while 루프»와 결정적으로 다른 부분이다.」*

**「첫 호출에서도 뭔가 반환한다」 — 아니다.**
첫 호출에서는 `답 =` 대입문 자체가 실행되지 않는다. 그 아래 `print`도, `return {"승인": 답}`도 실행되지 않는다.

**「값을 못 받으면 `None`이 온다」 — 아니다.**
답이 없으면 반환 자체가 없다. 그래프는 무기한 멈춰 있는다. 무응답 처리는 `interrupt()`가 해 주는 게 아니라 별도 정책으로 만들어야 한다 — 23.4절(`ex4_no_answer.py`)이 그 얘기다. 정책을 안 정하면 기본값은 「영원히 기다림」이다.

## 반환값이 「나중」이라서 생기는 부작용 문제 (23.2절과 이어짐)

재개할 때 노드가 **처음부터 다시 실행된다**는 점이 중요하다. 체크포인트는 노드 「경계」에 찍히지 노드 중간에 찍히지 않기 때문이다. 그래서 `interrupt()` **앞**에 있던 코드는 두 번 실행된다.

```python
def 나쁜노드(s: S) -> S:
    호출수["메일"] += 1
    print("→ 담당자에게 «검토 요청» 메일 발송")   # 재개할 때 또 나간다
    답 = interrupt("승인하시겠습니까?")
    return {"승인": 답}

def 좋은노드(s: S) -> S:
    답 = interrupt("승인하시겠습니까?")            # 부작용을 «뒤»로 민다
    호출수["조회"] += 1
    print("→ 결과 기록")
    return {"승인": 답}
```

규칙 하나. **`interrupt` 앞에는 부작용을 두지 않는다.** 읽기만 하는 코드는 괜찮고, 밖으로 나가는 것(메일·결제·API 호출)은 전부 뒤로 민다. 꼭 앞에 있어야 하면 노드를 「부작용 노드 → interrupt 노드」로 쪼개서 사이에 경계를 만든다.

같은 이유로, **한 노드 안에 `interrupt()`를 여러 번 두면 재개 값이 호출 순서(인덱스) 기준으로 매칭된다.** 조건에 따라 어떤 `interrupt`를 건너뛰거나 순서를 바꾸면 짝이 어긋난다. 한 노드에 하나가 안전하다.

---

## 요약

| 시점 | `interrupt()`의 거동 |
|---|---|
| 처음 도달 | 반환하지 않는다. 인자를 밖으로 올려보내고 그 자리에서 그래프를 멈춘다 (`out["__interrupt__"][0].value`) |
| 재개 후 도달 | `Command(resume=답)`으로 넘어온 `답`을 반환한다. 노드는 처음부터 다시 돌아 여기까지 온 상태 |
| 필요 조건 | 체크포인터 + 재개 시 동일한 `thread_id` |
