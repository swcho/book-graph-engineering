# 부작용이 꼭 중단점 앞에 있어야 하면 어떻게 하는가?

**답:** 노드를 둘로 쪼개 「부작용 노드 → interrupt 노드」로 만든다. 그러면 사이에 체크포인트 경계가 생긴다.

---

## 왜 이런 질문이 생기나

23.2절의 규칙은 하나입니다. **「interrupt 앞에는 부작용을 두지 않는다.」**

이유는 21장의 슈퍼스텝 얘기와 같습니다.

- 체크포인트는 **노드 경계**에 찍힌다.
- `interrupt()` 는 노드 **중간**에서 멈춘다.
- 그런데 재개할 때는 그 노드의 **처음부터** 다시 돈다.

즉 노드 안에서 `interrupt()` 앞에 있던 코드는 **두 번 실행**됩니다. 읽기만 하는 코드는 괜찮지만, 밖으로 나가는 것(메일, 결제, API 호출, 파일 쓰기)은 두 번 나갑니다.

```
[노드 시작] ── 메일 발송 ── interrupt() ──╳ 멈춤
                                            ↑ 체크포인트는 여기가 아니라
                                              노드 «경계»에 찍혀 있다

재개 ──▶ [노드 시작] ── 메일 발송(2회차!) ── interrupt() 통과 ── 계속
```

책의 `ex2_node_reruns.py` 가 이걸 그대로 보여 줍니다.

```python
def 나쁜노드(s: S) -> S:
    호출수["메일"] += 1
    print(f"    → 담당자에게 «검토 요청» 메일 발송 (누적 {호출수['메일']}회)")
    답 = interrupt("승인하시겠습니까?")
    return {"승인": 답}

def 좋은노드(s: S) -> S:
    답 = interrupt("승인하시겠습니까?")      # 부작용 «앞»에 둔다
    호출수["조회"] += 1
    print(f"    → 결과 기록 (누적 {호출수['조회']}회)")
    return {"승인": 답}
```

실행하면 담당자가 검토 요청 메일을 **두 번** 받습니다. 승인을 *하고 나서* 한 번 더요.

## 기본 처방: 부작용을 뒤로 민다

대부분의 경우는 순서만 바꾸면 끝납니다. 밖으로 나가는 것은 전부 `interrupt()` **뒤**로 밉니다. 재개 후 딱 한 번만 실행되니까요.

## 그런데 뒤로 못 미는 경우

문제는 **부작용의 결과가 사람에게 보여 줄 내용에 들어가야** 할 때입니다.

- 담당자에게 「검토해 주세요」 알림 메일/슬랙을 *먼저* 보내야 사람이 와서 답한다
- 외부 신용조회 API를 *먼저* 호출해야 그 점수를 승인 화면에 띄울 수 있다
- 티켓 시스템에 이슈를 *먼저* 만들어야 그 번호를 물음에 담을 수 있다

이건 순서를 못 바꿉니다. 부작용이 논리적으로 앞에 있어야 해요.

## 답: 노드를 둘로 쪼갠다

```
[부작용 노드]  ──경계(체크포인트)──  [interrupt 노드]
  메일 발송                            interrupt()
  API 호출                             답 받기
  결과를 상태에 저장
```

쪼개면 **노드 사이에 체크포인트 경계가 생깁니다.** 부작용 노드는 정상적으로 끝나서 체크포인트가 찍히고, 재개는 `interrupt` 노드의 처음으로만 돌아갑니다. 부작용 노드는 다시 안 돕니다.

```python
def 알림발송(s: S) -> S:
    """부작용만 하는 노드. 여기서 끝나면 체크포인트가 찍힌다."""
    티켓 = 티켓시스템.생성(s["주문"])          # 밖으로 나가는 호출
    메일발송(담당자, f"검토 요청: {s['주문']}")  # 밖으로 나가는 호출
    return {"티켓번호": 티켓.id}               # 결과는 «상태»에 남긴다

def 사람확인(s: S) -> S:
    """interrupt 만 하는 노드. 재개하면 여기 처음부터 다시 돈다."""
    답 = interrupt({
        "물음": "이 환불을 승인하시겠습니까?",
        "티켓": s["티켓번호"],                  # 앞 노드가 남긴 값을 읽는다
        "금액": s["금액"],
    })
    return {"승인": 답}

g.add_edge("알림발송", "사람확인")
```

재개 시 `사람확인` 노드가 처음부터 다시 돌아도, `s["티켓번호"]` 는 **상태에서 읽는 것**이라 부작용이 아닙니다. 읽기는 몇 번을 반복해도 안전합니다.

## 핵심 정리

| | |
|---|---|
| 왜 두 번 도나 | 체크포인트는 노드 **경계**에 찍히는데 interrupt 는 노드 **중간**에서 멈추기 때문 |
| 1차 처방 | 부작용을 전부 `interrupt()` **뒤**로 민다 |
| 못 밀 때 | 노드를 **둘로 쪼갠다**: 부작용 노드 → interrupt 노드 |
| 왜 되나 | 노드 사이에 **체크포인트 경계**가 생겨서, 재개가 interrupt 노드 처음으로만 돌아간다 |
| 앞 노드 결과 전달 | 상태(state)에 저장해 두고 interrupt 노드에서 **읽기**만 한다 |

> 「노드를 잘게 쪼갠다」는 곧 「경계를 만든다」이고, 경계는 곧 「여기까지는 다시 안 한다」는 약속입니다. 재실행 안전성(idempotency)을 코드로 지키기 어려울 때는 그래프 구조로 지키면 됩니다.

## 함께 보면 좋은 것

- 21장 — 체크포인트가 슈퍼스텝 경계에 찍힌다는 원리. 이 장의 규칙이 여기서 나옵니다.
- 22장 — 부작용을 되돌리는 보상(compensation). 두 번 나간 걸 되돌리는 것보다 애초에 안 나가게 하는 게 낫습니다.
- `ex2_node_reruns.py` — 직접 돌려 보면 메일 발송 누적 횟수로 확인됩니다.
