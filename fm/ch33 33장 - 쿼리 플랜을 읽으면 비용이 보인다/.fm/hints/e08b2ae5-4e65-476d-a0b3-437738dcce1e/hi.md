# 왜 성능 작업 전에 구간별로 쪼개 보아야 하는가 — 암달의 법칙

## 0. 한 줄 요약

전체가 100인데 한 구간이 95를 차지하면, **나머지 5를 0으로 만들어도 전체는 5%밖에 안 준다.**
이 당연해 보이는 산수를 1967년에 진 암달(Gene Amdahl)이 식으로 정리한 것이 암달의 법칙이고,
60년이 지난 지금 에이전트 시스템의 성능 튜닝에도 그대로 적용된다.

---

## 1. 문제를 고교 수학 언어로 바꾸기

한 요청을 처리하는 데 걸리는 총 시간을 $T$라고 하자.
이 시간을 서로 겹치지 않는 구간들로 쪼갠다 (입력 검증, 그래프 조회, 모델 호출, …).

이 중 **우리가 손댈 수 있는 구간**의 시간을 $T_{\text{개선}}$, 손댈 수 없는 구간을 $T_{\text{고정}}$이라 하면

$$T = T_{\text{고정}} + T_{\text{개선}}$$

여기서 개선 가능한 구간이 전체에서 차지하는 **비율**을

$$p = \frac{T_{\text{개선}}}{T}, \qquad 0 \le p \le 1$$

로 두자. 그러면 자연히 $T_{\text{고정}} = (1-p)T$, $T_{\text{개선}} = pT$이다.

$p$는 「내가 건드릴 수 있는 몫」이라는 뜻의 확률이 아닌 **비율**이다.
비율이라는 점이 핵심이다. 이 뒤의 모든 결론은 $p$가 1을 넘을 수 없다는 사실에서 나온다.

---

## 2. 암달의 법칙 유도

개선 가능한 구간을 **$s$배 빠르게** 만들었다고 하자 ($s \ge 1$).
$s=2$면 그 구간이 절반 시간에 끝난다는 뜻이다.

개선 후의 총 시간 $T'$은:

$$T' = \underbrace{(1-p)T}_{\text{그대로}} + \underbrace{\frac{pT}{s}}_{s\text{배 빨라짐}} = T\left[(1-p) + \frac{p}{s}\right]$$

전체 속도 향상 배수(speedup)는 정의상 $S(s) = T / T'$이므로

$$\boxed{\;S(s) = \frac{1}{(1-p) + \dfrac{p}{s}}\;}$$

이것이 **암달의 법칙**이다. 유도에 쓴 것은 「시간을 더한다」와 「나눗셈」뿐이다.

절감률(시간이 몇 % 줄었나)로 보고 싶으면

$$\text{절감률} = 1 - \frac{T'}{T} = 1 - \frac{1}{S(s)} = p\left(1 - \frac{1}{s}\right)$$

이 형태가 실무에서는 더 쓸모 있다. **절감률은 $p$에 정비례한다.**

---

## 3. $s \to \infty$ 극한: 아무리 잘해도 여기까지

$s$를 무한대로 보내는 것은 「그 구간을 **공짜로**, 즉 0ms로 만들었다」는 뜻이다.
고교 미적분의 극한 계산 그대로:

$$\lim_{s \to \infty} S(s) = \lim_{s \to \infty} \frac{1}{(1-p) + \dfrac{p}{s}}$$

$s \to \infty$일 때 $\dfrac{p}{s} \to 0$이므로

$$\lim_{s \to \infty} S(s) = \frac{1}{(1-p) + 0} = \boxed{\frac{1}{1-p}}$$

이 값을 **상한(upper bound)** 이라고 부른다. $S(s)$는 $s$에 대해 단조증가하지만,
$\dfrac{1}{1-p}$라는 수평 점근선을 절대 넘지 못한다.

미분으로 확인해 보자. $u = s^{-1}$로 두면 $S = \dfrac{1}{(1-p) + pu}$이고

$$\frac{dS}{ds} = \frac{p}{s^2\left[(1-p) + \frac{p}{s}\right]^2} > 0 \quad (p > 0)$$

항상 양수이므로 증가함수이고, 3장의 극한값에 위에서부터가 아니라 아래에서 수렴한다.
즉 **투자를 아무리 늘려도 수익은 $\dfrac{1}{1-p}$에서 멈춘다.**

절감률로 다시 쓰면 극한 절감률은 $p$ 그 자체다:

$$\lim_{s\to\infty}\left[1 - \frac{1}{S(s)}\right] = p$$

**「내가 손댈 수 있는 구간의 비중」이 곧 「내가 얻을 수 있는 절감률의 천장」이다.**
이 한 문장이 「성능 작업 전에 구간별로 쪼개 보라」는 조언의 전부다.
쪼개 보지 않으면 $p$를 모르고, $p$를 모르면 천장을 모르는 채로 일하게 된다.

## 4. 33장 ex5 수치를 식에 대입하기

`ex5_where_time_goes.py`의 한 요청 시간 분해다.

| 구간 | 시간(ms) | 비중 | 최대 절감 비율 |
|---|---:|---:|---:|
| 입력 검증 | 3 | 0.16% | 0% |
| 그래프 조회 ×4 | 9 | 0.47% | 50% |
| 벡터 검색 | 11 | 0.57% | 40% |
| 컨텍스트 조립 | 18 | 0.94% | 70% |
| **모델 호출** | **1,820** | **94.84%** | 30% |
| 응답 후처리 | 24 | 1.25% | 60% |
| 체크포인트 쓰기 | 34 | 1.77% | 80% |
| **합계** | **1,919** | 100% | |

$$T = 3+9+11+18+1820+24+34 = 1919\ \text{ms}$$

모델 호출의 비중은

$$\frac{1820}{1919} = 0.9484\ldots \approx 94.8\%$$

### 시나리오 A — 모델 호출 **말고** 나머지를 전부 0ms로 (극한)

여기서 「개선 가능한 부분」은 모델 호출을 뺀 나머지 여섯 구간이다.

$$p_A = \frac{1919 - 1820}{1919} = \frac{99}{1919} = 0.051589\ldots \approx 5.16\%$$

$s \to \infty$ (전부 공짜) 극한을 대입하면

$$S_{\max} = \frac{1}{1 - p_A} = \frac{1}{1 - \frac{99}{1919}} = \frac{1919}{1820} = 1.0544$$

$$\text{절감률} = 1 - \frac{1}{1.0544} = p_A = 5.16\%$$

**나머지 여섯 구간을 전부 0으로 만드는, 물리적으로 불가능한 최선을 다해도 5.2%다.**
1,919ms가 1,820ms가 된다. 사용자는 이 차이를 느끼지 못한다.

### 시나리오 B — 각 구간을 「최대 절감 비율」만큼 실제로 줄이면

표의 세 번째 열이 현실적인 상한이다. 모델 호출을 뺀 여섯 구간의 절감량:

$$9(0.5) + 11(0.4) + 18(0.7) + 24(0.6) + 34(0.8) + 3(0) = 4.5 + 4.4 + 12.6 + 14.4 + 27.2 = 63.1\ \text{ms}$$

이것을 암달의 법칙에 넣으려면 $s$를 구해야 한다. 개선 대상 99ms가 $99 - 63.1 = 35.9$ms가 되므로

$$s_B = \frac{99}{35.9} = 2.758$$

$$S_B = \frac{1}{(1 - 0.051589) + \dfrac{0.051589}{2.758}} = \frac{1}{0.948411 + 0.018712} = \frac{1}{0.967123} = 1.0340$$

$$\text{절감률} = 1 - \frac{1}{1.0340} = 3.29\%$$

책이 말한 **「나머지를 전부 최적화해도 3%」** 가 바로 이 값이다.
1,919ms → 1,855.9ms. 3주를 쓰고 얻는 것이 이것이다.

검산: 절감률 공식 $p(1 - 1/s)$로 직접 계산해도

$$0.051589 \times \left(1 - \frac{1}{2.758}\right) = 0.051589 \times 0.6373 = 0.03288 = 3.29\% \;\checkmark$$

### 시나리오 C — 반대로 모델 호출만 30% 줄이면

$$p_C = 0.9484,\quad s_C = \frac{1}{1 - 0.3} = 1.4286$$

$$\text{절감률} = p_C\left(1 - \frac{1}{s_C}\right) = 0.9484 \times 0.3 = 28.45\%$$

**한 구간만 30% 줄였는데 28.5%가 준다.** 시나리오 B의 8.7배다 (546ms 대 63.1ms).
게다가 시나리오 C의 극한($s \to \infty$, 모델 호출을 아예 없앰)은

$$\frac{1}{1 - 0.9484} = 19.38\ \text{배}$$

즉 이론적으로 19배까지 갈 여지가 남아 있다. 시나리오 A의 천장은 1.05배였다.

## 5. 도표로 본 결론

$p$에 따른 $S(s)$ 곡선의 모양을 머릿속에 그려 두면 된다.

- $p = 0.9484$ (모델 호출) → 점근선 19.4배. $s$를 올린 만큼 계속 보상이 있다.
- $p = 0.0516$ (나머지 전부) → 점근선 1.05배. $s=2$에서 이미 천장의 절반을 먹고, 그 뒤론 아무리 노력해도 평평하다.

$$\frac{dS}{ds}\bigg|_{s=1} = p$$

라는 사실도 기억할 만하다. **초기 투자 대비 수익률조차 $p$에 정비례한다.**
$p$가 작은 구간은 시작부터 기울기가 낮다.

---

## 6. 왜 「쪼개 보기」가 먼저인가

식 $S(s) = \dfrac{1}{(1-p) + p/s}$에는 두 개의 변수가 있다.

- $s$ — 내가 **노력**해서 만드는 값. 기술, 시간, 사람이 든다.
- $p$ — 내가 **측정**해서 아는 값. 프로파일러를 한 번 돌리면 나온다.

그런데 결과를 지배하는 것은 $p$다. $p$가 작으면 $s$를 무한대로 보내도 소용이 없다.
$p$는 공짜로 알 수 있고 $s$는 비싸다. **싼 것부터 알아내는 게 순서다.**

33장 서두의 「3주 동안 쿼리를 튜닝했습니다. 평균 지연이 9ms에서 4ms로 줄었어요」는
$p = 9/1919 = 0.47\%$, $s = 2.25$인 작업이다. 전체 절감률은

$$0.0047 \times \left(1 - \frac{1}{2.25}\right) = 0.0047 \times 0.556 = 0.26\%$$

1,919ms가 1,914ms가 되었다. **3주짜리 작업의 결과를 5ms로 만든 것은 실력 부족이 아니라 $p$를 안 재본 것이다.**

---

## 7. 정리

$$S(s) = \frac{1}{(1-p) + \dfrac{p}{s}}, \qquad \lim_{s\to\infty} S(s) = \frac{1}{1-p}, \qquad \text{절감률} = p\left(1-\frac{1}{s}\right)$$

1. 총 시간을 구간별로 쪼갠다 → 각 구간의 $p$를 얻는다.
2. $p$가 가장 큰 구간을 찾는다 → 거기가 유일하게 의미 있는 작업 대상이다.
3. $\dfrac{1}{1-p}$를 계산한다 → 그 작업의 **천장**이 나온다. 천장이 1.05배면 시작하지 않는다.
4. 그다음에 $s$를 어떻게 올릴지 고민한다.

에이전트 시스템에서 $p$가 큰 구간은 거의 항상 **모델 호출**이다.
그래서 순서는 「모델 호출 횟수 줄이기 → 모델 호출 시간 줄이기 → 그다음에 나머지」가 된다.
