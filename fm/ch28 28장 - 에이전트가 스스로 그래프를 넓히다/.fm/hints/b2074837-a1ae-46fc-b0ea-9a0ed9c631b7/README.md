# 출처를 달지 않으면 어떤 문제가 생기는가

> **Q.** 출처를 달지 않으면 어떤 문제가 생기는가?
>
> **A.** 오보임을 알아도 그것에 기댄 추론은 남고, 어디서 왔는지 아무도 모르는 사실이 된다. 이런 것이 쌓이면 그래프를 통째로 못 믿게 된다.

---

## 1. 한 문장으로

출처(provenance)가 없으면 **틀린 것을 발견해도 되돌릴 수가 없습니다.**

발견은 되는데 회수가 안 됩니다. 이게 핵심입니다. 잘못된 사실을 못 찾는 게 문제가 아니라, 찾고 나서 "그럼 이거 때문에 믿게 된 것들은 뭐지?"라는 질문에 답할 수단이 없다는 게 문제입니다.

---

## 2. 28장 예제 3이 보여 주는 장면

`ex3_provenance.py`의 그래프는 사실 6개로 시작합니다.

| 사실 | 출처 | 신뢰 |
|---|---|---|
| 박민수 -이끔-> 결제팀 | src1 사용자 발화 | 1.00 |
| 이서연 -속함-> 결제팀 | src2 사내 위키 v3 | 0.90 |
| 이서연 -삶-> 마포 | src1 사용자 발화 | 1.00 |
| 박민수 -삶-> 마포 | **src4 외부 기사** | 0.40 |
| 이서연 -동료-> 박민수 | src3 에이전트 추론 | 0.55 |
| 이서연 -이웃-> 박민수 | src3 에이전트 추론 | 0.55 |

여기서 중요한 건 표에 안 보이는 두 번째 기록입니다. `DERIVED_FROM`, 즉 **추론된 사실이 무엇에 기댔는지**입니다.

```
이서연 -동료-> 박민수   ←  (이서연 속함 결제팀) + (박민수 이끔 결제팀)
이서연 -이웃-> 박민수   ←  (이서연 삶 마포)     + (박민수 삶 마포)
```

이제 외부 기사(src4)가 오보로 밝혀집니다. 「박민수가 마포에 산다」가 틀렸습니다.

**출처가 있을 때:** 엣지 하나를 죽였는데 둘이 죽습니다. 직접 철회 하나(박민수-삶-마포), 연쇄 철회 하나(이서연-이웃-박민수). 「이웃이다」는 마포 거주 사실 두 개에만 기대고 있었으니 근거 하나가 무너지면 같이 무너집니다. 반면 「동료다」는 src2/src1에 기대고 있어 그대로 살아남습니다 — 무너질 것만 정확히 무너집니다.

**출처가 없을 때:** 오보인 걸 알고 「박민수 -삶-> 마포」는 지웁니다. 그런데 **「이서연 -이웃-> 박민수」는 그대로 남습니다.** 지울 이유를 찾을 수가 없거든요. 그리고 이제 그건 어디서 왔는지 아무도 모르는 사실이 됩니다.

## 3. 실패 모드를 하나씩

### 3.1 고아 추론 (orphaned inference)

근거가 죽었는데 결론만 살아 있는 상태입니다. 겉보기에 아무 이상이 없어서 더 나쁩니다. 「이웃이다」는 문법도 맞고 타입도 맞고 조회하면 멀쩡히 나옵니다. 28.2절의 관문 넷(확신도·정규화·스키마·단일 값 충돌)을 다시 통과시켜도 하나도 안 걸립니다. **관문은 들어올 때 거르는 장치고, 이건 들어온 뒤에 근거가 썩은 경우**라서 잡히지 않습니다.

### 3.2 회수 불가 (irreversibility)

출처가 없으면 철회의 단위가 「엣지 하나」밖에 없습니다. 있으면 「이 출처에서 온 것 전부」, 「이 문서 버전에서 온 것 전부」, 「이 추출기 버전이 뽑은 것 전부」를 한 번에 걷어 낼 수 있습니다. 위키 페이지 하나가 잘못됐거나 추출 프롬프트에 버그가 있었다는 걸 나중에 알았을 때, 이 차이가 「쿼리 한 줄」과 「손으로 못 함」을 가릅니다.

### 3.3 감사 불가 (unauditable)

사람이 "이거 왜 이렇게 나왔어요?"라고 물었을 때 답할 수 없습니다. 사용자 본인이 말한 건지, 위키에서 긁어온 건지, 에이전트가 혼자 추론한 건지 구분이 안 됩니다. 예제 3의 src3(에이전트 추론, 0.55)와 src1(사용자 발화, 1.00)이 출처 없이 섞이면 **둘 다 그냥 "그래프에 있는 사실"이 됩니다.** 사실과 짐작의 구분이 사라집니다.

### 3.4 신뢰도 계산 불가

28장 요약에 이런 문장이 있습니다.

> 추론 결과의 신뢰도는 근거 중 가장 약한 것보다 강할 수 없습니다.

「이웃이다」는 0.40짜리 외부 기사에 기대고 있으니 아무리 좋게 쳐도 0.40 이상일 수 없습니다. 그런데 근거 연결이 없으면 이 계산 자체가 불가능합니다. 예제에서 추론 사실에 0.55가 붙어 있는 건 「에이전트 추론이라는 출처의 기본 신뢰도」일 뿐, 실제 근거를 반영한 값이 아닙니다. 근거 링크가 있어야 `min(1.00, 0.40) = 0.40`으로 내려 잡을 수 있습니다.

### 3.5 신뢰 붕괴 — 그리고 이게 진짜 대가

고아 추론 하나는 견딜 만합니다. 문제는 이게 **쌓인다**는 겁니다. 출처 없는 사실이 몇 % 섞이면 어떤 사실이 오염됐는지 골라낼 방법이 없으니, 결국 **전부 의심하게 됩니다.** 부분적으로 못 믿는 그래프는 없습니다. 조금 못 믿으면 통째로 못 믿게 됩니다.

그리고 이 지점이 예제 1과 이어집니다. 예제 1의 「반쯤 맞는」 상태 — 명백히 틀린 게 아니라서 조회 결과만 보고는 문제가 있는지 알 수가 없는 상태 — 를 출처가 없으면 영원히 그 상태로 두게 됩니다.

### 3.6 에이전트가 쓰기 시작하면 배로 심해진다

읽기 전용 그래프에서는 추론 사실의 비율이 낮습니다. 사람이 넣은 것뿐이니까요. 그런데 에이전트가 쓰기 시작하면 **추론된 사실의 비율이 빠르게 오릅니다.** 추론 위에 추론이 얹히고, 2차·3차 파생이 생깁니다. 연쇄 철회가 걷어 내야 할 범위가 커지는 만큼, 그 연쇄를 계산할 근거 기록의 가치도 커집니다.

여기에 28.4절의 드리프트가 겹칩니다. 그래프가 스스로 자라면서 「제약」이 20%→9%로 묽어지는 그 루프가, 동시에 「출처가 사람인 사실」의 비율도 묽게 만듭니다. 사람 개입 20%를 넣어도 방향이 안 바뀌는 것처럼요.

## 4. 그래서 무엇을, 어떤 단위로 기록하는가

### 4.1 단위는 「엣지 하나」

노드가 아니라, 문서가 아니라, 배치가 아니라 **주장(assertion) 하나마다**입니다. 예제 3의 스키마가 그렇게 생겼습니다.

```
CREATE REL TABLE R(FROM N TO N, kind STRING, src STRING,
                   conf DOUBLE, alive BOOLEAN)
```

엣지 자체에 `src`, `conf`, `alive`가 붙어 있습니다. 「이 문서에서 온 사실들」처럼 배치 단위로 묶어 두면 철회할 때 무고한 사실까지 같이 날아갑니다. 반대로 노드 단위로 달면 같은 노드에 서로 다른 출처의 엣지가 붙었을 때 구분이 안 됩니다.

RDF 계열이면 named graph / RDF-star / reification으로, 프로퍼티 그래프면 엣지 프로퍼티로 붙입니다. 어느 쪽이든 **엣지 하나가 자기 출처를 스스로 들고 있어야** 합니다.

### 4.2 최소 다섯 칸

| 칸 | 의미 | 왜 필요한가 |
|---|---|---|
| **출처 식별자** (`src`) | 어디서 왔나 — 발화 ID, 문서 URL + 버전, 추론 규칙 ID | 철회의 단위. 「이 출처 전부」를 한 번에 걷어 내려면 필수 |
| **출처 종류** | 사용자 발화 / 문서 / 외부 API / 에이전트 추론 | 사실과 짐작의 구분. 종류별 기본 신뢰도의 근거 |
| **시각** | 언제 관측·기록됐나 | 최신성 판단, 두 사실이 충돌할 때의 우선순위 |
| **신뢰도** (`conf`) | 얼마나 믿나 | 조회 시 임계값 필터, 상충 해소 |
| **생존 플래그** (`alive`) | 철회됐나 | **지우지 말고 죽이세요.** 아래 4.4 참고 |

### 4.3 그리고 반드시 「기댄 것」 (`derived_from`)

추론으로 만든 사실이면 출처만으로 부족합니다. **어떤 사실들 위에 세웠는지**를 같이 적어야 합니다.

```python
DERIVED_FROM = {
    ("이서연", "동료", "박민수"): [("이서연", "속함", "결제팀"),
                                   ("박민수", "이끔", "결제팀")],
    ("이서연", "이웃", "박민수"): [("이서연", "삶", "마포"),
                                   ("박민수", "삶", "마포")],
}
```

이게 있어야 연쇄 철회가 계산됩니다. 「어느 문서에서 왔다」는 1차 사실용 기록이고, 「어느 사실에 기댔다」는 파생 사실용 기록입니다. **둘은 다른 것이고 둘 다 필요합니다.**

같이 남기면 좋은 것: 어떤 규칙/프롬프트로 추론했는지(규칙 버전), 근거들을 어떻게 결합했는지(AND인지 OR인지 — OR이면 근거 하나가 죽어도 살아남습니다).

### 4.4 기록 시점 — 이게 제일 중요합니다

> 실무에서는 추론할 때 그때그때 기록해야 한다. **나중에는 복원 못 한다.**

예제 3은 `DERIVED_FROM`을 손으로 적어 뒀지만, 실무에서 이건 **쓰기 경로에 박아 넣어야** 합니다.

- 추론 함수가 결론만 반환하면 안 됩니다. `(결론, 근거 목록, 규칙 ID)`를 함께 반환해야 합니다.
- 그래프 쓰기 API가 출처 없는 쓰기를 **거부**해야 합니다. 선택 필드로 두면 반드시 빕니다.
- 28.2절 관문에 「0번 관문: 출처 있나」를 붙이는 식입니다.

이유는 단순합니다. 사후에 복원하려면 "이 결론을 왜 냈지?"를 되짚어야 하는데, 그때의 컨텍스트·모델 버전·그래프 스냅샷이 이미 사라졌습니다. LLM 추론은 재현성도 낮습니다. **기록을 놓친 순간 그 사실은 영구히 고아**입니다.

### 4.5 지우지 말고 무효화하세요

예제 3은 `DELETE`를 쓰지 않습니다. `SET e.alive = false`입니다. W3C PROV의 Invalidation과 같은 발상입니다.

- 조회는 `WHERE e.alive`로 살아 있는 것만 봅니다.
- 죽은 엣지는 남아 있으니 **"왜 이게 없어졌지?"에 답할 수 있습니다.**
- 철회가 잘못됐으면 되살릴 수 있습니다. 오보 판정이 뒤집히는 일은 실제로 있습니다.
- "이 출처를 철회했을 때 몇 개가 죽나"를 **미리 계산**해 사람에게 보여 줄 수 있습니다. 파급이 크면 자동 철회 대신 검토로 보냅니다.

### 4.6 철회는 고정점까지 반복

예제 3의 `retract()`는 `while changed:` 루프를 돕니다. 추론 위에 추론이 얹혀 있을 수 있으니, 죽인 것 때문에 또 죽을 게 없어질 때까지 돌려야 합니다. 한 번만 훑으면 2차 파생이 살아남습니다.

주의할 점 둘:
- **순환 근거**를 막아야 합니다. A가 B에 기대고 B가 A에 기대면 무한 루프거나, 근거 없이 서로를 떠받치는 유령이 됩니다. 쓰기 시점에 사이클을 검사하세요.
- **다중 근거**는 AND/OR을 구분해야 합니다. 다른 경로로도 도출되는 사실이면 근거 하나가 죽어도 살려 둬야 합니다. 예제 3은 AND(하나라도 죽으면 죽음)로 구현돼 있습니다.

## 5. 실무 체크리스트

- [ ] 그래프 쓰기 API가 출처 없는 쓰기를 **거부**하는가 (경고가 아니라 거부)
- [ ] 출처가 **엣지 단위**로 붙는가 (배치·노드 단위가 아니라)
- [ ] 추론 사실에 `derived_from`이 **추론하는 그 순간** 기록되는가
- [ ] 철회가 `DELETE`가 아니라 `alive=false`인가
- [ ] 연쇄 철회가 **고정점까지** 도는가
- [ ] "이 출처를 철회하면 몇 개가 죽나"를 미리 볼 수 있는가
- [ ] 추론 사실의 신뢰도가 **근거 중 최솟값**을 넘지 못하게 계산되는가
- [ ] 「출처가 에이전트 추론인 엣지의 비율」을 주기적으로 재는가 (28.4절 드리프트 지표와 같은 자리)

## 6. 관련 표준·개념

| 개념 | 상태 | 출처 |
|---|---|---|
| 출처 기록 (provenance) | [표준] | https://www.w3.org/TR/prov-o/ |
| 철회 (Invalidation) | [사실상 표준] | https://www.w3.org/TR/prov-o/#Invalidation |
| 진리 유지 시스템 (TMS) | [실험] | https://dl.acm.org/doi/10.1145/321978.321979 |

- **PROV-O**의 3요소 — Entity(사실), Activity(그것을 만든 작업), Agent(작업을 수행한 주체) — 가 위 4.2/4.3의 칸들과 대응합니다. `wasDerivedFrom`이 곧 `derived_from`이고, `wasGeneratedBy`가 「어느 추론이 만들었나」, `wasAttributedTo`가 「어느 출처에 귀속되나」입니다.
- **TMS(Doyle, 1979)**는 이 장의 연쇄 철회를 일반화한 고전입니다. 믿음마다 근거(justification)를 달아 두고, 근거가 무너지면 결론을 자동으로 철회하는 구조입니다. `alive` 플래그는 TMS의 IN/OUT 라벨과 같은 것입니다.

## 7. 한 줄 정리

**출처는 「어디서 왔나」를 답하려고 다는 게 아니라, 「틀렸을 때 무엇을 같이 걷어 낼까」를 답하려고 답니다.** 그리고 그 기록은 쓰는 순간이 아니면 영영 만들 수 없습니다.
