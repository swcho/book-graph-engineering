# 추론 결과의 신뢰도에 대한 원칙

**질문**: 추론 결과의 신뢰도에 대한 원칙은 무엇인가?

**답**: 근거 중 가장 약한 것보다 강할 수 없다.

---

## 1. 한 줄로 말하면

에이전트가 A와 B를 근거로 C를 추론했다면, C의 신뢰도는 **A와 B 중 낮은 쪽을 넘을 수 없다**.
사슬은 가장 약한 고리에서 끊어진다(weakest link). 근거가 0.4짜리 하나라도 섞여 있으면
결론은 아무리 잘해야 0.4다. 나머지 근거가 1.00이어도 마찬가지다.

28장 「한 장 요약」의 문장 그대로입니다.

> 모든 엣지에 출처를 달고, 추론할 때 「무엇에 기댔는지」를 같이 적으세요. 나중에는 복원 못 합니다.
> **추론 결과의 신뢰도는 근거 중 가장 약한 것보다 강할 수 없습니다.**

## 2. 왜 이 원칙이 28장에 나오는가

28장은 **에이전트가 그래프에 쓰기 시작하면** 무슨 일이 벌어지는지를 다룹니다.
읽기 전용 그래프에는 사람이 넣은 사실만 있지만, 쓰기를 열면
「사람이 말해 준 사실」과 「에이전트가 추론해 낸 사실」이 한 그래프에 섞입니다.

문제는 이 둘이 저장소에서는 **똑같이 생겼다**는 것입니다.
`(이서연)-[이웃]->(박민수)` 라는 엣지 하나만 보면
이게 사용자가 직접 말한 것인지, 두 사실에서 추론한 것인지 알 수 없습니다.

그래서 28.3절이 두 가지를 요구합니다.

1. **출처(provenance)**: 이 엣지가 어디서 왔는가 — W3C PROV-O가 표준화한 개념
2. **근거(derived-from)와 신뢰도 전파 규칙**: 추론이면 무엇에 기댔는가, 그 결과 얼마나 믿을 만한가

그 신뢰도 전파 규칙의 상한이 바로 **min**, 즉 「가장 약한 근거」입니다.

## 3. 예제 3(`ex3_provenance.py`)로 보기

출처별 신뢰도가 이렇게 정의돼 있습니다.

| 출처 | 종류 | 신뢰도 |
|---|---|---|
| src1 | 사용자 발화 | 1.00 |
| src2 | 사내 위키 v3 | 0.90 |
| src3 | 에이전트 추론 | 0.55 |
| src4 | 외부 기사 | 0.40 |

그리고 추론된 사실 두 개가 무엇에 기댔는지를 `DERIVED_FROM` 에 적어 뒀습니다.

```python
DERIVED_FROM = {
    ("이서연", "동료", "박민수"): [("이서연", "속함", "결제팀"),   # src2, 0.90
                                   ("박민수", "이끔", "결제팀")],  # src1, 1.00
    ("이서연", "이웃", "박민수"): [("이서연", "삶", "마포"),       # src1, 1.00
                                   ("박민수", "삶", "마포")],      # src4, 0.40
}
```

- **「동료다」**의 근거는 0.90과 1.00 → 상한은 $\min(0.90, 1.00) = 0.90$
- **「이웃이다」**의 근거는 1.00과 0.40 → 상한은 $\min(1.00, 0.40) = 0.40$

「이웃이다」는 근거 하나가 사용자가 직접 말한 확실한 사실(1.00)인데도,
나머지 하나가 외부 기사(0.40)라서 결론은 0.40을 넘을 수 없습니다.
**좋은 근거를 아무리 많이 붙여도 나쁜 근거 하나가 천장을 낮춥니다.**

예제에서 추론 결과에 실제로 붙는 값은 `src3` 의 0.55입니다.
「이웃이다」의 경우 0.55는 상한 0.40보다 높으니 원칙 위반입니다.
실무에서는 다음처럼 계산해야 합니다.

```python
conf(결론) = conf(추론 규칙 자체) * min(conf(근거_i) for i in 근거들)
#            0.55                  * 0.40  = 0.22
```

즉 「추론 단계 자체의 신뢰도」가 한 번 더 곱해지므로, 실제 값은 상한보다 **더 낮아집니다**.
원칙은 어디까지나 「이보다 높을 수는 없다」는 천장을 말합니다.

## 4. 연쇄 철회와 같은 뿌리

예제 3의 후반부는 src4(외부 기사)를 오보로 판정하고 철회합니다.

```
죽임: 박민수 -삶-> 마포   (직접)
죽임: 이서연 -이웃-> 박민수   (연쇄)
```

엣지 하나를 지웠는데 둘이 사라졌습니다.
이것은 min 원칙의 **극단(0으로 간 경우)**입니다.
근거 하나의 신뢰도가 0이 되면 $\min(\cdots, 0) = 0$이니 결론도 0이 됩니다.
철회는 「신뢰도 0」이라는 특수 사례이고, min 원칙은 그 사이의 연속적인 값들을 다루는 일반형입니다.

이 구조를 학계에서는 **진리 유지 시스템(Truth Maintenance System, Doyle 1979)** 이라고 부릅니다.
믿음마다 「이 믿음을 지탱하는 근거 목록(justification)」을 붙여 두고,
근거가 무너지면 그 위에 얹힌 믿음을 자동으로 회수하는 구조입니다.

## 5. 왜 「기록」이 원칙의 전제인가

min을 계산하려면 **근거 목록이 남아 있어야** 합니다.
그런데 추론이 끝나고 결론 엣지만 저장하면 근거 목록은 사라집니다.
예제 3의 마지막 경고가 이것입니다.

> 이 예제는 「기댄 관계」를 손으로 적어 뒀다.
> 실무에서는 추론할 때 그때그때 기록해야 한다. **나중에는 복원 못 한다.**

같은 결론에 도달하는 경로가 여러 개일 수 있고, LLM이 어떤 사실을 보고 그 결론을 냈는지는
사후에 재구성할 수 없기 때문입니다. 그래서 쓰기 시점에

- `src`(어느 출처에서 왔나)
- `derived_from`(어느 엣지들에 기댔나)
- `conf`(얼마나 믿나)

세 가지를 엣지 속성으로 같이 써야 합니다.
28장 예제 3의 릴레이션 스키마가 정확히 그 모양입니다.

```sql
CREATE REL TABLE R(FROM N TO N, kind STRING, src STRING, conf DOUBLE, alive BOOLEAN)
```

`alive` 는 철회를 「삭제」가 아니라 「무효화」로 표현합니다(PROV-O의 Invalidation).
지워 버리면 왜 지웠는지도 같이 사라지니까요.

## 6. 이 원칙이 막아 주는 실패

### 6.1 신뢰도 세탁(confidence laundering)

가장 흔한 사고입니다.
0.4짜리 사실 두 개를 근거로 추론했는데 결론에 0.9를 붙이는 것.
그러면 다음 턴에 에이전트가 그 0.9를 「믿을 만한 사실」로 읽고 또 추론합니다.
근거가 약하다는 정보가 한 단계 만에 씻겨 나가고, 그래프 어디에도 흔적이 없습니다.

min 원칙은 **약함이 아래로 흐르게** 만들어 이 세탁을 막습니다.

### 6.2 다중 홉 확장의 폭주

예제 5의 홉별 정확도가 그 결과입니다.

| 홉 | 노드당 새 사실 | 맞을 확률 |
|---|---|---|
| 1 | 3.2 | 86% |
| 2 | 2.1 | 71% |
| 3 | 1.4 | 52% |
| 4 | 0.9 | 38% |

홉이 깊어질수록 「이전 홉의 결론」이 「다음 홉의 근거」가 되므로 신뢰도가 계속 깎입니다.
min만 봐도 절대 올라가지 않고, 실제로는 곱으로 떨어집니다($0.86^2 \approx 0.74$, $0.86^3 \approx 0.64$).
그래서 28장은 「평소에는 2홉, 가끔 4홉까지 가되 결과는 **사람 검토 대기**로」를 권합니다.
정확도 38%짜리를 그래프에 바로 쓰면 예제 1의 참사(엣지 10개 중 3개가 틀린 상태)가 됩니다.

### 6.3 쓰기 관문과의 연결

28.2절의 관문 넷 중 첫째가 **확신도 관문**(`MIN_CONF = 0.65`)입니다.
추론 결과의 신뢰도를 min으로 정직하게 계산해 두면,
0.4짜리 근거에서 나온 결론은 자동으로 0.65 아래가 되어 관문에서 걸립니다.
반대로 신뢰도를 부풀리면 관문이 무력해집니다.
**관문의 성능은 신뢰도 계산의 정직함에 달려 있습니다.**

## 7. 구현할 때의 체크리스트

- [ ] 모든 엣지에 `src`, `conf` 를 단다. 추론된 엣지에는 `derived_from` 도 단다.
- [ ] 추론 결과의 `conf` 는 `규칙_신뢰도 × min(근거들의 conf)` 이하로만 준다.
- [ ] 근거는 추론하는 **그 순간에** 기록한다. 사후 복원은 불가능하다.
- [ ] 철회는 `DELETE` 가 아니라 `alive = false` 로 한다.
- [ ] 철회할 때 그 근거에 기댄 추론을 **연쇄적으로** 무효화한다. 고정점에 도달할 때까지 반복한다.
- [ ] 「사람이 말한 사실」과 「추론된 사실」의 비율을 모니터링한다. 후자가 빠르게 늘면 그래프가 자기 말을 믿기 시작한 것이다(28.4절 드리프트).

## 9. 한 번 더

> **추론 결과의 신뢰도는 근거 중 가장 약한 것보다 강할 수 없다.**

「강할 수 없다」는 상한(ceiling)에 대한 진술입니다.
실제 값은 대개 그보다 **더 낮습니다**. 왜 min이 상한이고 곱이 그 아래인지,
확률의 곱셈정리와 어떻게 이어지는지는 같은 폴더의 `hi.md` 에서 다룹니다.
