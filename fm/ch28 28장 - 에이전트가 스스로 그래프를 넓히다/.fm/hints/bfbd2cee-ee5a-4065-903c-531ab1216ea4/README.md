# 확신도 관문만으로 막을 수 없는 것

## 질문

확신도 관문만으로 막을 수 없는 것은 무엇인가?

## 답

**「확신 있게 틀린 것」(confidently wrong)** 입니다.

28장 예제 2(`ex2_write_gate.py`)의 후보 목록에는 이런 트리플이 들어 있습니다.

```
("결제팀", "속함", "이서연", 0.92)
```

방향이 뒤집혔습니다. 사실은 「이서연 -속함-> 결제팀」인데 추출기가 주어와 목적어를 바꿔 읽었어요.
그런데도 확신도는 **0.92**. 임계값 `MIN_CONF = 0.65`를 한참 넘습니다.
확신도 관문은 이걸 그냥 통과시킵니다.

본문의 정리 문장 그대로입니다.

> 확신도만 두면 «확신 있게 틀린 것»을 못 막는다.
> «결제팀 -속함-> 이서연»이 0.92 로 나왔다. 방향이 뒤집혔는데도 확신이 높다.
> 추출기가 문장을 잘못 읽으면 «자신 있게» 잘못 읽는다. 확신도로는 못 잡는다.

---

## 핵심: 확신도는 무엇을 재는 값인가

여기가 이 카드의 진짜 알맹이입니다. 확신도(confidence)는 **「이게 참인가」를 재는 값이 아닙니다.**
**「내 출력이 참일 것 같다고 내가 믿는 정도」** 를 재는 값입니다.

| | 재는 것 | 기준점 |
|---|---|---|
| **확신도 점수** | 모델이 자기 출력에 매긴 주관 확률 `p̂ = P(내 답이 맞다 \| 내가 읽은 것)` | 모델 자신의 내부 표현 |
| **정확성(correctness)** | 그 트리플이 세상에서 참인가 | 외부 세계 / 그래프의 제약 |

조건부 확률의 조건 자리에 **「내가 읽은 것」** 이 들어가 있는 게 핵심입니다.
읽기 자체가 틀렸으면, 그 틀린 읽기를 기준으로 계산한 확률은 얼마든지 높을 수 있습니다.
「결제팀이 이서연에 속한다」를 문장에서 뽑아냈다고 *잘못* 확신한 모델에게,
그 확신을 스스로 의심하라고 요구할 근거가 점수 안에는 없습니다.

### calibration vs correctness

두 개념을 분명히 갈라 두세요. 자주 섞여 쓰이지만 완전히 다른 성질입니다.

**보정(calibration)** — 점수가 *집단 수준에서* 정직한가.
「확신도 0.9로 뱉은 트리플 1,000개를 모으면 그중 약 900개가 참인가?」를 묻습니다.
보정 오차는 ECE(Expected Calibration Error), 신뢰도 다이어그램(reliability diagram),
브라이어 점수(Brier score) 같은 걸로 잽니다.

**정확성(correctness)** — *이 한 개가* 참인가.
0/1의 사실 문제입니다.

여기서 나오는 결론이 세 가지입니다.

1. **완벽하게 보정된 모델도 0.92에서 8%는 틀립니다.** 보정은 「틀리지 않음」을 약속하지 않고
   「틀리는 빈도가 광고한 값과 맞음」만 약속합니다. 0.92짜리 트리플을 100개 쓰면 8개쯤 오답이
   들어오는 게 *정상 동작*입니다. 문제는 그 8개가 어느 것인지 점수로는 못 고른다는 겁니다.
2. **보정은 집단의 성질이고, 관문은 개별 건에 대한 판정입니다.** 층위가 안 맞아요.
   집단 통계에서 개별 판정을 끌어낼 수 없으니, 임계값 하나로 개별 오답을 골라내는 건 원리적으로 불가능합니다.
3. **오류가 계통적(systematic)이면 보정마저 무너집니다.** 주어-목적어 뒤집기, 부정어 놓치기,
   대명사 오연결 같은 파싱 오류는 무작위 잡음이 아니라 *일관된* 오독입니다.
   모델은 헷갈린 게 아니라 확실하게 다른 걸 읽었습니다. 그래서 확신도가 안 떨어지고,
   0.9 구간의 실제 정답률만 조용히 깎아 먹습니다.

### 확신도가 잡을 수 있는 것 / 없는 것

- **잡는 것**: *스스로 자신 없는* 오답. 근거 문장이 흐릿하거나 여러 해석이 갈리는 경우.
  베이지안 딥러닝 용어로는 **인식적 불확실성(epistemic)** 과 **우연적 불확실성(aleatoric)** 이
  점수에 드러난 부분입니다.
  예제에서 `("이서연", "속함", "정산팀", 0.42)` 하나가 여기 걸립니다.
- **못 잡는 것**: 확신을 동반한 오독. 방향 뒤집힘, 타입 위반, 이미 있는 사실과의 모순, 중복.
  이건 「모델이 얼마나 확신하나」가 아니라 **「그래프의 구조·기존 사실과 어긋나나」** 로만 잡힙니다.
  점수는 그래프를 본 적이 없습니다.

## 예제 2에서 관문별로 무엇이 걸리나

`gate()` 함수는 확신도 → 정규화 → 스키마 → 단일값 → 중복 순서로 돕니다.
후보 11개의 판정을 따라가 보면 확신도 관문의 힘이 얼마나 좁은지 바로 보입니다.

| 후보 | 확신 | 걸린 관문 | 왜 |
|---|---|---|---|
| 박민수 -이끔-> 결제팀 | 0.94 | 통과 | 맞는 사실 |
| 이서연 -속함-> 결제팀 | 0.91 | 통과 | 맞는 사실 |
| 민수 -이끔-> 결제팀 | 0.88 | 5.중복 | 정규화가 「민수→박민수」로 고친 뒤 중복이 됨 |
| 이서연 -속함-> 정산팀 | 0.42 | **1.확신도** | 유일하게 확신도가 잡은 건 |
| 박민수 -이끔-> 정산팀 | 0.87 | 4.단일값충돌 | 타입은 맞음(Person→Team). 이미 결제팀을 이끔 |
| **결제팀 -속함-> 이서연** | **0.92** | **3.스키마** | Team이 Person에 속할 수 없음 |
| 박민수 -관리-> 결제팀 | 0.83 | 5.중복 | 「관리→이끔」 정규화 뒤 중복 |
| 이서연 -속함-> 결제팀 | 0.90 | 5.중복 | 같은 사실 재추출 |
| PM -이끔-> 결제팀 | 0.71 | 5.중복 | 「PM→박민수」 정규화 뒤 중복 |
| 이서연 -선호-> 매운맛 | 0.86 | 통과 | 맞는 사실 |
| 박민수 -선호-> 결제팀 | 0.88 | 3.스키마 | Team은 Pref가 아님 |

**확신도 관문이 잡은 건 11개 중 딱 1개.** 나머지 오류·중복은 전부 0.71~0.92 구간에 있습니다.
임계값을 0.92보다 위로 올려서 뒤집힌 엣지를 막으려 하면 0.91의 정상 사실이 같이 죽습니다.
스칼라 하나에 임계값을 걸어 서로 다른 종류의 오류를 가르려는 시도 자체가 성립하지 않습니다.

## 그래서 관문이 넷인 이유

한 장 요약의 문장이 이 지점입니다.

> 관문은 넷입니다. 확신도, 정규화, 스키마, 단일 값 충돌. 각각 다른 것을 잡으니 하나만 두면 나머지가 샙니다.

네 관문은 **서로 직교하는 서로 다른 정보원**을 봅니다.

| 관문 | 무엇을 보나 | 성격 |
|---|---|---|
| 1. 확신도 | 추출기의 자기 평가 | 막는다 |
| 2. 정규화 | 이름/관계의 표준형 사전 (ALIAS, CANON) | **고친다** |
| 3. 스키마 | 노드 타입과 허용 관계 (ALLOWED) | 막는다 |
| 4. 단일값 충돌 | 그래프에 이미 있는 사실 | 막는다(사람에게 보낸다) |
| 5. 중복 | 그래프에 이미 있는 엣지 | 막는다 |

- 「결제팀 -속함-> 이서연」(0.92)은 **스키마**가 잡습니다. Team은 Person에 속할 수 없으니까요.
  확신도 점수가 아니라 *도메인 지식이 코드로 적혀 있어서* 잡힌 겁니다.
- 반대로 스키마만 두면 「박민수 -이끔-> 정산팀」(0.87)이 샙니다. 타입은 Person→Team으로 멀쩡하거든요.
  이건 **단일값 관문**이 그래프의 기존 상태와 대조해서 잡습니다.
- **정규화는 막는 관문이 아니라 고치는 관문**이고, 반드시 중복 검사보다 **먼저** 돌아야 합니다.
  순서가 거꾸로면 「민수」와 「박민수」가 서로 다른 것으로 보여서 중복이 안 걸리고,
  예제 1처럼 같은 사람 노드가 셋으로 갈라집니다.

일반화하면 이렇습니다. **확신도는 모델 내부에서 온 신호이고, 나머지는 모델 밖에서 온 신호입니다.**
모델의 오류를 모델 자신의 점수로 검증할 수 없으니, 검증 신호는 반드시 모델 바깥
— 스키마, 기존 그래프, 표준형 사전 — 에서 와야 합니다.

## 함께 기억할 것

- 28.3절의 명제와 이어집니다. **「추론 결과의 신뢰도는 근거 중 가장 약한 것보다 강할 수 없다」.**
  확신도는 곱해지며 약해지지 실수를 지워 주지 않습니다.
- 단일값 충돌은 **자동으로 덮어쓰지 마세요**. 높은 확신도의 오답이 낮은 확신도의 정답을 지웁니다.
  둘 다 살려 두고 사람에게 보냅니다.
- 실무에서 확신도를 쓸 거라면 임계값을 감으로 정하지 말고, 보유 데이터로 **신뢰도 다이어그램**을 그려
  구간별 실제 정답률을 재세요. 온도 스케일링(temperature scaling) 같은 사후 보정으로
  점수를 정직하게 만들 수는 있지만, **그래도 「확신 있게 틀린 것」은 그대로 남습니다.**
  보정은 점수를 고치는 일이지 오독을 고치는 일이 아닙니다.

## 한 줄 요약

확신도는 「모델이 얼마나 확신하나」를 재는 값이고 「그게 참인가」를 재는 값이 아니다.
그래서 뒤집힌 엣지 같은 계통적 오독은 0.92를 달고 관문을 통과한다 —
그건 스키마와 기존 그래프처럼 **모델 바깥의 제약**만이 잡을 수 있다.
