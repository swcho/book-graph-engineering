# 단일 값 충돌을 자동으로 덮어쓰면 안 되는 이유

> **Q.** 단일 값 충돌을 자동으로 덮어쓰면 안 되는 이유는 무엇인가?
>
> **A.** 오답이 정답을 지운다. 둘 다 살려 두고 사람에게 보내야 한다.

---

## 1. 단일 값 제약이란

관계 중에는 **대상이 하나뿐이어야 하는 것**이 있습니다. 28장 예제 2에서는 이렇게 선언합니다.

```python
SINGLE = {"이끔"}          # 팀장은 한 명
```

`이끔`은 단일 값(single-valued) 관계입니다. 온톨로지 쪽 용어로는 **함수적 속성(functional property)** 이라고 부릅니다. 생년월일, 주민번호, 소속 회사, 팀장 — 이런 것들이 여기 해당합니다.

그래서 쓰기 관문의 4번은 "이미 다른 값이 있는가"를 봅니다.

```python
    # 4) 단일 값 — 이미 다른 값이 있나
    if k in SINGLE:
        r = c.execute("MATCH (a:N {name:$s})-[e:R {kind:$k}]->(b:N) "
                      "RETURN b.name", {"s": s, "k": k})
        while r.has_next():
            if r.get_next()[0] != o:
                return False, "4.단일값충돌"
```

여기서 중요한 건 **`return False`** 입니다. 새 값으로 갈아 끼우지 않고, 쓰기를 **막습니다**.

---

## 2. 왜 덮어쓰기가 위험한가 — 예제의 실제 숫자

예제 2의 후보 목록을 보시죠.

| 후보 | 확신도 | 실제 |
|---|---:|---|
| 박민수 -이끔-> **결제팀** | 0.94 | 맞음 |
| 박민수 -이끔-> **정산팀** | 0.87 | **틀림** |

`정산팀`은 **스키마 관문을 통과합니다**. 타입이 맞으니까요(Person → Team). 확신도도 0.87이라 확신도 관문(0.65)도 통과합니다. 이걸 잡는 건 오직 단일 값 관문뿐입니다.

> "반대로 스키마만 두면 «박민수 -이끔-> 정산팀»(0.87)을 못 막는다.
> 타입은 맞으니까(Person → Team). 이건 단일 값 관문이 잡는다."

만약 이 관문이 "충돌하면 새 값으로 덮어쓴다"였다면 어떻게 될까요.

```
그래프 상태:  박민수 -이끔-> 결제팀   (0.94, 정답)
새 후보 도착:  박민수 -이끔-> 정산팀   (0.87, 오답)
자동 덮어쓰기 →
그래프 상태:  박민수 -이끔-> 정산팀   (0.87, 오답)     ← 정답이 사라졌다
```

**확신도 0.87짜리 오답이 확신도 0.94짜리 정답을 지웠습니다.** 이게 답에서 말하는 "오답이 정답을 지운다"입니다.

## 3. 덮어쓰기가 기대는, 틀린 가정 세 가지

### 가정 A — "나중에 온 게 더 최신이다"

Last-write-wins는 사람이 시간 순서로 입력하는 시스템에서나 성립합니다. 에이전트 추출 파이프라인에서 도착 순서는 **문서를 훑은 순서**일 뿐, 사실의 시간 순서가 아닙니다. 3년 전 아카이브 문서를 오늘 파싱하면 그게 「나중」이 됩니다.

### 가정 B — "충돌하면 둘 중 하나가 틀린 것이다"

충돌의 원인은 최소 셋인데, 시스템은 이 셋을 구별할 수 없습니다.

| 원인 | 올바른 조치 |
|---|---|
| 새 값이 오답 | 기존 값 유지 |
| **기존 값이 오답** | 새 값으로 교체 |
| **둘 다 맞음 — 제약이 틀렸다** (공동 리드, 겸직) | `SINGLE` 선언 자체를 고침 |

세 번째가 특히 고약합니다. 자동 덮어쓰기는 "제약이 틀렸다"는 신호를 **영원히 삼켜 버립니다**. 실제로는 두 팀을 겸직하는 사람이 있는데, 시스템은 매번 조용히 한쪽을 지우며 값이 A↔B로 진동할 뿐입니다.

### 가정 C — "잘못 지워도 나중에 복구된다"

27~28장의 그래프는 **에이전트가 쓰고 에이전트가 다시 읽습니다**. 지워진 정답은 다음 턴의 조회 결과에서도 사라지고, 그 결과를 근거로 삼은 추론까지 오염됩니다. 예제 3의 `DERIVED_FROM`을 보면 「이서연 -동료-> 박민수」는 「박민수 -이끔-> 결제팀」에 기대고 있습니다. 밑동을 갈아 끼우면 **그 위에 얹힌 추론 전체가 같이 틀립니다**.

게다가 28.4절의 드리프트가 여기에 겹칩니다. 오염은 「지워져서」가 아니라 「묽어져서」 퍼지고, 사람이 20%를 개입해도 방향은 안 바뀝니다.

## 4. 그러면 어떻게 하나 — 둘 다 살려서 사람에게

핵심은 **충돌을 "해소"하지 말고 "기록"하라**는 것입니다.

```
                   ┌─ 통과 ──────────────→ 그래프에 쓴다
후보 트리플 ─ 관문 ─┤
                   └─ 4.단일값충돌 ─→ 충돌 큐 ─→ 사람 검토
                                       (기존 값 + 새 값 + 출처 + 확신도)
```

### 4-1. 기존 값을 건드리지 않는다

예제 코드가 그대로 그렇게 합니다. `return False`니까 그래프는 이전 상태를 유지합니다. **틀릴 수 있는 판단을 자동으로 내리지 않는 것**이 기본값입니다.

### 4-2. 새 값도 버리지 않는다

여기서 한 걸음 더 나가야 합니다. 예제는 단순히 막고 끝내지만, 실무에서는 **거절된 후보를 검토 대기열에 쌓아야** 합니다. 28.5절의 결론과 정확히 같은 패턴입니다.

> "주기적으로(주 1회) 4홉까지 넓히되 «사람 검토 대기»로 넣는다"
> "일단 대기열에 쌓고, 중단 조건에 걸리면 대기열을 통째로 버린다."

그냥 버리면 「기존 값이 오답이었던 경우」와 「제약이 틀렸던 경우」를 영영 못 고칩니다.

### 4-3. 사람이 판단할 재료를 같이 넘긴다

충돌 항목에는 28.3절의 **출처(provenance)** 를 붙여야 사람이 1초 만에 판정할 수 있습니다.

| 필드 | 기존 값 | 새 값 |
|---|---|---|
| 대상 | 결제팀 | 정산팀 |
| 확신도 | 0.94 | 0.87 |
| 출처 | src1 사용자 발화 (신뢰도 1.00) | src4 외부 기사 (신뢰도 0.40) |
| 시점 | 2026-05-01 | 2026-03-11 |

이 표만 보면 답이 명백하죠. **출처를 안 남기면 나중에는 복원 못 합니다.**

### 4-4. 대안 — 시간축으로 재해석

"팀장이 바뀌었다"가 정말 맞는 경우라면, 덮어쓰기 대신 **유효 기간(valid time)** 을 넣는 방법이 있습니다.

```
박민수 -이끔[2025-01-01 ~ 2026-04-30]-> 결제팀
박민수 -이끔[2026-05-01 ~ ]------------> 정산팀
```

이러면 「현재 단일 값」 제약은 지켜지면서 과거 사실도 살아 있습니다. 다만 **어느 시점부터인지를 에이전트가 알아야** 하고, 그걸 모르면 결국 사람에게 물어야 합니다.

## 5. 관문 넷 안에서의 위치

| # | 관문 | 무엇을 잡나 | 성격 |
|---|---|---|---|
| 1 | 확신도 | 애초에 못 미더운 추출 | 막는다 |
| 2 | 정규화 | 「민수」/「PM」→「박민수」 | **고친다** |
| 3 | 스키마 | 타입이 안 맞는 관계 (방향 뒤집힘 등) | 막는다 |
| 4 | **단일 값** | **타입은 맞지만 이미 값이 있는 것** | **막고 → 사람에게** |
| 5 | 중복 | 이미 있는 엣지 | 막는다 |

1·3·5는 "쓰지 않는다"로 끝나도 손해가 없습니다. 4번만 다릅니다. **판단이 필요한 유일한 관문**이고, 그래서 자동으로 결정하면 안 됩니다.

또 하나 — 확신도만으로 자동 판정을 하면 안 되는 이유도 예제가 보여 줍니다. 「결제팀 -속함-> 이서연」은 방향이 뒤집혔는데 **확신도가 0.92**입니다. 추출기는 잘못 읽을 때도 「자신 있게」 잘못 읽습니다. 확신도 비교로 충돌을 자동 해소하는 것 역시 같은 함정입니다.

---

## 6. 한 줄 정리

단일 값 충돌은 **"어느 쪽이 맞는가"라는, 시스템이 답할 수 없는 질문**입니다. 자동 덮어쓰기는 그 질문에 동전 던지기로 답하면서 오답 쪽이 나왔을 때 **정답을 복구 불가능하게 삭제**합니다. 그래서 기존 값은 그대로 두고, 새 값은 출처와 함께 검토 대기열에 넣어, **판단할 수 있는 유일한 주체인 사람에게 넘깁니다.**
