# 에이전트가 그래프에 쓰기 시작하면 무엇이 시스템의 일부가 되는가?

**답: 품질 관리다. 검증 없이 쓰면 10턴이면 망가진다.**

---

## 한 줄로

읽기 전용 그래프에서는 품질이 *입력 단계의 문제*였습니다(사람이 넣었으니까). 에이전트에게 **쓰기 권한**을 주는 순간, 품질 관리는 「가끔 하는 점검」이 아니라 **런타임에 항상 돌아가는 시스템 구성 요소**가 됩니다. 쓰기 경로에 관문(gate)이 없으면 그래프는 열 턴 만에 못 믿을 물건이 됩니다.

## 왜 「10턴」인가 — 28.1의 실험

`ex1_write_loop.py`는 추출기가 뽑은 트리플을 **검증 없이 그대로** 10번 넣습니다. 입력은 이렇게 생겼습니다.

| 턴 | 트리플 | 문제 |
|---|---|---|
| 1 | 박민수 -이끔-> 결제팀 | 정상 |
| 2 | 이서연 -속함-> 결제팀 | 정상 |
| 3 | **민수** -이끔-> 결제팀 | 같은 사람, 다른 이름 |
| 4 | 이서연 -속함-> 정산팀 | 잘못 뽑음 |
| 5 | 박민수 -이끔-> 정산팀 | 잘못 뽑음 |
| 6 | 결제팀 -속함-> 이서연 | **방향 뒤집힘** |
| 7 | 박민수 -**관리**-> 결제팀 | 같은 뜻, 다른 관계 이름 |
| 8 | 이서연 -속함-> 결제팀 | 중복 |
| 9 | **PM** -이끔-> 결제팀 | 또 다른 이름 |
| 10 | 박민수 -이끔-> 결제팀 | 중복 |

10턴 뒤 결과가 이 카드의 핵심입니다.

- 노드 6개(박민수 / 민수 / PM 이 **셋으로 갈라짐**), 엣지 10개, 그중 틀린 사실 3개(**30%**)
- 「결제팀을 이끄는 사람은?」 → `['박민수', '민수', 'PM']` — **세 명이 나오는데 실제로는 한 명**
- 「정산팀은?」 → 틀린 엣지 두 개가 **통째로 답이 됨**

## 여기서 진짜 배울 점 세 가지

### 1) 「반쯤 맞는」 상태가 제일 고약하다

박민수·민수·PM 은 **셋 다 맞는 사실**로 들어왔습니다. 이름만 달랐을 뿐이죠. 그래서 각각을 따로 보면 틀린 게 없습니다. 하지만 「이 팀을 이끄는 사람이 한 명이냐 세 명이냐」를 물으면 셋 다 틀립니다. 명백한 오류가 아니라 **조회 결과만 봐서는 문제가 있는지 알 수 없는** 상태가 됩니다. 이게 자동 확장이 조용히 무너지는 방식입니다.

### 2) 추출 정확도를 올리는 것으로는 안 고쳐진다

노드가 셋으로 갈라진 원인은 추출기가 틀려서가 아닙니다. **개체 해상도(entity resolution)** 문제이고, 27장에서 다룬 주제입니다. 추출 F1을 아무리 올려도 「민수」와 「박민수」를 같은 노드로 묶어 주지는 않습니다. 즉 품질 관리는 모델 성능이 아니라 **파이프라인의 별도 단계**로 존재해야 합니다.

### 3) 넣을 때 안 거른 것은 꺼낼 때도 안 걸러진다

조회는 「있는 것을 전부」 줍니다. 필터링을 읽기 시점으로 미룰 수 없다는 뜻입니다. 그래서 관문은 **쓰기 앞**에 서야 합니다.

## 그래서 시스템의 일부가 되는 것들 (28.2~28.5 미리보기)

이 카드의 「품질 관리」가 구체적으로 무엇을 뜻하는지, 나머지 절이 채웁니다.

**28.2 — 관문 넷.** 확신도 / 정규화 / 스키마 / 단일 값 충돌. 각각 다른 것을 잡으므로 하나만 두면 나머지가 샙니다.
- 확신도만 두면 「결제팀 -속함-> 이서연」(0.92, 방향 뒤집힘)을 못 막습니다. 추출기는 **자신 있게 틀립니다**.
- 스키마가 그걸 잡습니다(Team 이 Person 에 속할 수 없음).
- 스키마만 두면 「박민수 -이끔-> 정산팀」(0.87)을 못 막습니다. 타입은 맞으니까요. 단일 값 관문이 잡습니다.
- 정규화는 **막는** 관문이 아니라 **고치는** 관문입니다(민수·PM → 박민수). 그리고 **정규화가 중복 검사보다 먼저** 돌아야 합니다. 순서를 뒤집으면 「민수」와 「박민수」가 달라 보여 중복이 안 걸립니다.
- 단일 값 충돌은 **자동으로 덮어쓰지 마세요.** 오답이 정답을 지웁니다. 둘 다 살려 두고 사람에게 보냅니다.

**28.3 — 출처(provenance).** 모든 엣지에 출처를 달고, 추론할 때 「무엇에 기댔는지」를 그 자리에서 기록합니다. 나중에는 복원 못 합니다. 출처를 철회하면 **거기 기댄 추론까지 연쇄로** 걷어 냅니다(예제에서 「박민수가 마포에 산다」가 오보로 밝혀지자 「이웃이다」도 같이 무너짐). 추론 결과의 신뢰도는 **근거 중 가장 약한 것보다 강할 수 없습니다.**

**28.4 — 드리프트.** 그래프는 아무도 시키지 않은 방향으로 자랍니다. 제약이 20%→9%로 반토막 나는데, **지워져서가 아니라 비율이 묽어져서** 사라집니다. 사람이 20%를 넣어도 12%에서 멈출 뿐 방향은 안 바뀝니다. 개별 사실이 아니라 **비율에 개입**해야 합니다(종류별 비율 상한 + 경보).

**28.5 — 예산.** 깊이 넓힐수록 수확은 줄고 오답은 늡니다(4홉 정확도 38%). 평소엔 얕게(2홉), 가끔 깊게 가되 결과는 **검토 대기열**에 넣습니다. 그리고 자동 확장의 진짜 위험은 「틀린 사실」이 아니라 **「멈출 줄 모르는 것」**이라 노드 증가율에 상한을 둡니다.

## 외우는 방식

> 쓰기를 열면 = 품질 관리가 켜진다. 안 켜면 10턴, 30% 오염, 한 사람이 세 명.
