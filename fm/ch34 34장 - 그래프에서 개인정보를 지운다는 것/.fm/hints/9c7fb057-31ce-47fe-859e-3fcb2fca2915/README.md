# "이어진 것을 전부 지운다"가 답이 아닌 이유

**답:** 집계와 결정은 개인정보가 아니고, 남의 이력을 깨면 안 된다.

---

## 1. 질문이 겨누는 지점

삭제 요청이 들어오면 엔지니어가 제일 먼저 떠올리는 그림은 관계형 DB의
`ON DELETE CASCADE`입니다. 뿌리를 지우면 매달린 것이 알아서 따라 지워지는 것.
그래프에서 이걸 그대로 하면 어떻게 되는지를 34.4절(`ex4_cascade.py`)이 세어 봅니다.

핵심은 이렇습니다. **연쇄 쿼리는 "영향 범위"를 보여 주는 도구일 뿐이고,
그 범위가 곧 "삭제 목록"은 아니다.** 범위를 세는 것과 무엇을 지울지 정하는 것은
별개의 판단이고, 후자는 자동으로 못 합니다.

> 이 쿼리는 «영향 범위»를 보여 줄 뿐이고, 그중 무엇을 지울지는 따로 정해야 한다.
> — `ex4_cascade.py`

## 2. 자료의 예제 그래프 — 일곱 개가 걸린다

`ex4_cascade.py`가 만드는 그래프입니다. 뿌리는 사람(`p1` 김도현)입니다.

```
p2(이서연) ─속함─┐
                 ↓
p1(김도현) ─속함─→ t1(결제팀)          ← 공유된 대상
    │
    └─작성─→ d1(3분기 보고서)
                  ↑ 집계함
              s1(팀별 문서 수)   [Stat]
                  ↑ 기댐
              f1(결제팀은 문서 생산이 많다)   [Fact]
                  ↑ 기댐
              a1(결제팀에 리소스를 더 배정하자)   [Answer]
                  ↑ 생성함
              r1(분기 분석 #901)   [Run]
```

예제의 두 쿼리가 세는 것:

| 구분 | 쿼리 | 걸린 것 |
|---|---|---|
| 직접 이어진 것 | `(p1)-[:R]->(b)` | `t1`, `d1` — 2개 |
| 그것에 기대고 있는 것 | `(x)-[:R*1..5]->(d)<-[:R]-(p1)` | `p2`, `s1`, `f1`, `a1`, `r1` — 5개 |

**합쳐서 일곱 개.** 사람 하나를 지우려는데 일곱 개가 걸립니다.
그런데 이 일곱 중 실제로 지워야 하는 것은 **하나도 없습니다**(뿌리 `p1` 자신 제외).
연쇄 삭제가 답이 아닌 이유가 이 목록 안에 두 종류로 들어 있습니다.

## 3. 이유 ① — 집계와 결정은 애초에 개인정보가 아니다

경로를 따라가 보면 이렇습니다.

```
김도현 → 3분기 보고서 → 팀별 문서 수 → 결제팀은 문서 생산이 많다
      → 결제팀에 리소스를 더 배정하자
```

김도현이 쓴 문서를 지우면 집계가 바뀌고, 집계가 바뀌면 그 위의 판단이 근거를 잃습니다.
28장의 연쇄 철회와 **구조는 같습니다.** 그런데 성질이 다릅니다.

- `s1` **집계(팀별 문서 수)** — 「결제팀 문서 12건」은 개인을 안 가리킵니다.
  개인정보가 아니니 삭제권의 대상이 아닙니다. 지울 이유가 없습니다.
- `a1` **결정(리소스 배정)** — 회사가 내린 판단의 기록입니다.
  개인이 삭제를 요청했다고 회사의 의사결정 이력이 사라져야 할 근거는 없습니다.
- `f1` **Fact / `r1` Run** — 마찬가지로 개인을 가리키지 않거나, 가리키는 부분이
  「누가 돌렸는지」 한 칸뿐입니다.

**28장 연쇄 철회와의 결정적 차이:**
연쇄 철회는 *근거가 틀렸을 때* 그 위의 결론에서 신뢰를 회수하는 일입니다.
개인정보 삭제는 근거가 틀린 게 아닙니다. 문서는 실제로 존재했고 집계는 실제로 맞았습니다.
바뀌는 것은 「그것을 누가 만들었는지를 우리가 계속 보관해도 되는가」뿐입니다.
사실의 참/거짓이 변하지 않았으니, 위쪽으로 철회를 전파할 이유도 없습니다.

## 4. 이유 ② — 남의 이력을 깨면 안 된다 (공유된 엣지)

일곱 개 중에 **`p2`(이서연)**이 있습니다. 왜 걸렸을까요.

```
p1 ─속함─→ t1 ←─속함─ p2
```

`p1`과 `p2`가 **같은 노드 `t1`을 공유**하기 때문입니다. 연쇄 탐색은 공유 지점을 지나
옆 사람에게로 번집니다. 이건 명백히 지우면 안 되는 것입니다.
`t1`(결제팀)을 지우면 이서연의 소속 이력이 함께 사라집니다.

34.1절(`ex1_delete_scope.py`)은 같은 문제를 **들어오는 엣지**로 다시 보여 줍니다.

```
("p2", "p1", "멘토")   # 남이 나를 가리킨다
("d1", "p1", "언급")   # 문서 본문 안에 이름이 있다
("r1", "p1", "읽음")   # 29장의 Reads
```

> «이서연이 김도현의 멘티였다»는 이서연 쪽 사실이기도 하다.
> 지우면 이서연의 이력이 사라진다.

엣지는 두 사람의 것입니다. 한쪽이 삭제를 요청했다는 이유로 엣지를 통째로 지우면
요청하지 않은 쪽의 기록까지 지우는 것이 됩니다.
GDPR 삭제권도 「타인의 권리와 자유를 침해하지 않는 범위에서」 작동합니다.
연쇄 삭제는 바로 그 선을 넘는 동작입니다.

## 5. `ex2`의 표가 같은 이야기를 숫자로 한다

`ex2_delete_levels.py`의 기준 표에서 **4번(완전 삭제)** 열을 보면
정확히 이 세 칸이 ✗입니다.

| 기준 | 1 숨기기 | 2 식별자 끊기 | 3 가명화 | 4 완전 삭제 |
|---|---|---|---|---|
| 집계·통계가 유지된다 | ○ | ○ | ○ | **✗** |
| 감사 이력이 유지된다 | ○ | ○ | ○ | **✗** |
| 남의 이력이 안 깨진다 | ○ | ○ | ○ | **✗** |
| 만족한 기준 수 | 5 | 5 | 6 | **4** |

「전부 지운다」는 제일 강해 보이는데 만족하는 기준이 제일 적습니다(4개).
강한 삭제가 좋은 삭제가 아니라는 것을, 이 열이 그대로 보여 줍니다.

## 6. 그래서 cascade는 어디서 멈추는가

`ex5_deletion_plan.py`의 `POLICY` 표가 "멈추는 자리"를 노드 종류별로 못 박아 둔 것입니다.
cascade가 **삭제로 계속 번지지 않고 다른 동작으로 갈아타거나 끊기는** 지점을 보세요.

| 종류 | 방침 | cascade가 여기서 무엇을 하나 |
|---|---|---|
| `Person` | 삭제 | 뿌리. 여기까지가 진짜 삭제 |
| `Contact` | 삭제 | 개인 그 자체이므로 따라 삭제 |
| `Msg` | 본문 마스킹 | **삭제 → 부분 치환으로 갈아탄다.** 발화 자체는 남고 이름만 가린다 |
| `Doc` | 작성자 익명화 | **노드는 안 지운다. 엣지의 작성자만 익명 노드로 바꾼다** |
| `Team` | 유지 | **여기서 끊긴다.** 공유 노드이자 개인정보 아님 → 이서연 보호 |
| `Stat` | 재계산 | **삭제 → 갱신으로 갈아탄다.** 집계는 남기되 다시 센다 |
| `Fact` | 유지 | 개인을 안 가리키면 끊긴다 |
| `Answer` | 유지 | 회사의 결정 기록. 끊긴다 |
| `Run` | 행위자 익명화 | 누가 돌렸는지만 가린다 |
| `Event` | 식별자 치환 | 30장 — 추가 전용이라 못 지운다. 가리키는 표에서 지운다 |

정리하면 세 줄입니다.

```
개인을 특정하는 것   → 지운다
그 사람이 만든 산출물 → 대개 남긴다 (작성자만 익명화)
집계와 결정          → 남긴다
```

**경계는 하나의 질문입니다.** 「그것이 개인을 가리키는가?」
「3분기 보고서」는 개인을 안 가리킵니다. 「김도현이 작성」이 가리킵니다.
그러니 **문서는 두고 「누가 작성」 엣지만 바꿉니다.**
즉 그래프에서 삭제의 단위는 흔히 *노드가 아니라 엣지*입니다.

## 7. 이 판정은 자동화할 수 없다

`ex5`가 `Photo`(회식 사진)에서 일부러 막히게 되어 있는 이유입니다.

> 방침이 없으면 자동으로 처리하지 않고 멈춘다.
> «모르는 것을 모른다고» 말해 준다.

회식 사진은 개인을 가리킬까요, 회사의 기록일까요. 얼굴이 나오면? 여러 명이 나오면?
이건 코드가 정할 수 없습니다. 표가 없으면 담당자가 그때그때 판단하고,
다음 요청에서는 다른 담당자가 다르게 판단합니다.
「지난번엔 지웠는데 이번엔 안 지웠다」가 되면 그게 더 큰 문제입니다.

## 8. 반대쪽 함정도 같이 기억할 것

cascade를 멈춘다는 것은 **무언가를 남긴다**는 뜻입니다. 남은 것이 재식별 경로가 될 수
있습니다(34.3절). 이름을 지워도 팀·지역·직군·입사연도 넷을 조합하면 66%가 혼자가 되고,
그래프에서는 속성을 다 지워도 **이웃의 모양 자체가 식별자**입니다.

그러니 결론은 「덜 지워라」가 아닙니다.

- 연쇄로 몰아 지우는 것 → 집계·감사 이력·남의 이력을 깨뜨림 (34.4)
- 이름만 지우고 멈추는 것 → 재식별로 되찾힘 (34.3)

**정답은 노드 종류마다 어느 수준까지 지울지를 사람이 미리 정해 표로 두고,
그 표를 통과시키는 것**입니다. 엔지니어의 일은 어느 수준을 택할지 정하는 것이 아니라,
「그 수준을 선택했을 때 무엇이 깨지는지」를 미리 세어 두는 것입니다.

## 9. 한 줄 암기

> 연쇄 쿼리는 **영향 범위**를 세는 도구지 **삭제 목록**이 아니다.
> 지우면 안 되는 것이 두 종류 섞여 있다 — **개인정보가 아닌 것**(집계·결정)과
> **내 것이 아닌 것**(공유 엣지에 걸린 남의 이력).
