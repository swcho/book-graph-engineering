# `ex3_what_survives.py`에서 가장 오래된 항목은 무엇인가?

**답**: **복식부기**다. 등장 연도가 **1494년**, `NOW = 2026` 기준으로 **532년**이다. 표에서 유일하게 컴퓨터 이전 시대의 항목이고, 종류는 「해법」이다. 그리고 예제의 결론 문단이 곧바로 잇는 문장이 핵심이다 — **30장의 이벤트 소싱이 그것과 같은 구조다.**

    ("진리 유지 시스템",      1979, "다시 필요해짐",   "해법"),
    ("복식부기",           1494, "그대로 씀",      "해법"),
```

```
이름은 사라지고, 문제는 남고, 해법은 이름을 바꿔 가며 재사용된다.

그리고 30장의 이벤트 소싱이 그것과 같은 구조다.
「지우지 말고 반대 기입을 하라」가 「이벤트를 쌓아라」가 됐을 뿐이다.

## 1. 1494년이 무슨 해인가

1494년 11월, 베네치아에서 프란치스코회 수사이자 수학자였던 **루카 파치올리(Luca Pacioli)** 의 『**Summa de arithmetica, geometria, proportioni et proportionalità**』가 인쇄된다. 615쪽짜리 당대 수학 백과사전이었고, 구텐베르크 인쇄기로 찍힌 초기 수학서 중 하나였다.

그 안에 27쪽짜리 절이 하나 들어 있다. 「**Particularis de computis et scripturis**」(계산과 기록에 관하여). 파치올리는 이것을 「베네치아 방식(the Method of Venice)」이라고 불렀고, 이 절이 **복식부기를 최초로 인쇄·체계화한 기록**이다.

여기서 자주 틀리는 대목을 짚어 두는 게 좋다.

- **파치올리가 복식부기를 발명한 것은 아니다.** 그는 이미 베네치아·피렌체 상인들이 쓰고 있던 실무를 정리해 출판했다. 현존하는 가장 오래된 완전한 복식 원장은 님(Nîmes)에서 영업한 피렌체 상인 조반니 파롤피(Giovanni Farolfi) 상회의 **1299~1300년** 장부이고, 제노바 코무네 재무관(Massari)의 **1340년** 회계는 공공 재정에 적용된 완벽한 복식 형태로 남아 있다.
- 그래도 예제가 **1494년**을 택한 것은 타당하다. 표가 세는 것은 「발명 시점」이 아니라 「**이 해법이 이름과 절차를 갖고 전파 가능한 형태로 고정된 시점**」이다. 필사 장부의 관행은 상회 안에서 죽지만, 인쇄된 27쪽은 유럽 전체로 복제된다. 이 표의 다른 항목들도 마찬가지로 「논문/제품이 나온 해」에 걸려 있다 — 낙관적 잠금 1979(Kung–Robinson), 진리 유지 시스템 1979(Doyle), 이벤트 소싱 2005(Fowler).

즉 **1494년은 파치올리가 복식부기를 "명세로 적은" 해**다. 이 책의 어휘로 옮기면, 그때 복식부기는 [사실상 표준]에서 [표준]으로 올라갔다.

## 2. 복식부기는 무엇을 보장하는 기법인가

「돈 계산법」이 아니다. 복식부기는 **기록의 무결성을 표현 형식 자체로 강제하는 기법**이다. 세 개의 장치로 되어 있다.

### (1) 대차 균형이라는 불변식

모든 거래를 반드시 **두 곳**에 적는다. 한쪽은 차변(debit), 다른 쪽은 대변(credit)이고, 금액이 같다. 그래서 장부 전체에 항상 다음이 성립한다.

```
Σ 차변 = Σ 대변
자산 = 부채 + 자본        (회계 항등식)
```

이게 왜 중요한가. **오류 검출이 데이터 구조 안에 들어 있다.** 한 건을 잘못 적으면 합계가 어긋나고, 시산표(trial balance)를 뽑는 순간 드러난다. 기록자의 성실성이나 별도 검증 도구에 의존하지 않는다. 소프트웨어 용어로는 **중복 기입을 체크섬으로 쓰는 것**이고, 이 책의 어휘로는 **불변식(invariant)** 이다.

이 책이 반복해서 말하는 형태와 정확히 같다. 좋은 해법은 「조심해서 잘 하기」가 아니라 「**틀리면 티가 나게 만드는 구조**」다. 28장의 관문, 18장의 체인 검증, 31장의 버전 체크가 모두 같은 계열이다.

### (2) 기록 수정 대신 반대 기입

복식부기의 두 번째 규칙이 이 카드의 핵심이다. **틀린 기록을 지우거나 고치지 않는다.** 대신 반대 방향으로 한 건을 더 적는다.

| 시각 | 분개 | 뜻 |
|---|---|---|
| t1 | 차) 매출채권 500 / 대) 매출 500 | 원래 기입 |
| t2 | 차) 매출 500 / 대) 매출채권 500 | **역분개** — t1을 무효화 |
| t3 | 차) 매출채권 300 / 대) 매출 300 | 올바른 값으로 재기입 |

잔액은 300이 되지만 **장부에는 세 줄이 다 남는다.** 결과는 같은데 왜 이렇게 하는가.

- **원장은 append-only다.** 지우면 「원래 무엇이 적혀 있었는지」와 「누가 언제 왜 고쳤는지」가 사라진다. 지운 흔적이 없는 장부는 검증할 수 없다.
- **과거의 어느 시점 상태를 그대로 재구성할 수 있다.** t2 이전으로 되감으면 잔액 500이 나온다.
- **감사(audit)가 가능하다.** 감사는 「지금 잔액이 맞는가」가 아니라 「이 잔액에 이르는 경로가 정당한가」를 본다. 경로가 남아 있어야 성립한다.

파치올리 시대의 실무 규칙도 이랬다. 잉크로 긁어내지 말 것, 여백을 남기지 말 것, 줄을 비우지 말 것 — 나중에 끼워 넣을 자리를 없애는 것이 목적이다.

### (3) 분개장과 원장의 분리

파치올리는 세 권의 장부를 규정한다. 비망록(memoriale) → **분개장(giornale)** → **원장(quaderno)**. 분개장은 거래를 **일어난 순서대로** 적는 시간축 기록이고, 원장은 그것을 **계정별로 합산**한 조회용 뷰다.

원장은 분개장으로부터 항상 다시 만들 수 있다. 그래서 원장이 망가지면 재구축하면 된다. 진실은 분개장에 있다.

## 3. 왜 532년을 살아남았는가

「좋은 기법이라서」로는 설명이 안 된다. 이 표에 있는 다른 해법들도 좋은 기법이었고, 그중 하나(규칙 기반 추론, 1975)는 「일부만 남음」이다. 복식부기가 살아남은 이유는 **해법의 구조가 그것을 실어 나르는 것들과 독립**이기 때문이다.

| 무엇이 바뀌었나 | 복식부기는 |
|---|---|
| **매체**: 양피지 → 종이 장부 → 천공카드 → 메인프레임 → RDBMS → 클라우드 ERP | 그대로. 「두 곳에 같은 금액」은 매체를 언급하지 않는다 |
| **언어**: 이탈리아어 → 라틴어 → 각국어 → COBOL → SQL → 한국어 계정과목 | 그대로. 계정 이름은 라벨이고 불변식은 라벨과 무관하다 |
| **규제**: 상인 관습 → 회사법 → GAAP → IFRS → 각국 세법 | 그대로. 규제는 「무엇을 어느 계정에 넣나」를 바꾸지만 「차변=대변」은 안 건드린다 |
| **규모**: 상회 한 곳 → 다국적 연결 결산 → 초당 수만 건 결제 | 그대로. 불변식이 국소적(거래 한 건 안에서 성립)이라 분할해도 깨지지 않는다 |
| **주체**: 사람 서기 → 회계사 → 배치 잡 → 에이전트 | 그대로. 「기록자를 신뢰하지 않는다」가 원래 전제였다 |

핵심은 마지막 두 줄이다. 복식부기는 **세계에 대한 가정을 하지 않는다.** 가정하는 것은 오직 「기록은 나중에 검증되어야 하고, 기록자는 틀리거나 속일 수 있다」뿐이다. 이 가정은 500년 동안 한 번도 거짓이 된 적이 없다.

대조 사례가 같은 표 안에 있다. **규칙 기반 추론(1975)** 은 「지식을 규칙으로 다 적을 수 있다」는 세계에 대한 가정 위에 서 있었다. 그 가정이 흔들리자 해법도 「일부만 남음」이 됐다. **진리 유지 시스템(1979)** 은 「추론 근거를 댈 수 있는 시스템」을 전제했고, 근거를 못 대는 신경망 시대에 잊혔다가 에이전트가 그래프에 쓰기 시작하면서 「다시 필요해짐」이 됐다.

정리하면 — **구현에 대한 명세가 아니라 불변식에 대한 명세였기 때문에** 살아남았다. 35장 한 장 요약의 문장이 이 관찰의 압축이다.

> 이름은 몇 년, 문제는 수십 년, 해법은 수백 년 갑니다.

## 4. 30장 이벤트 소싱과의 대응 — 「같은 구조」의 실제 내용

예제가 「같은 구조다」라고만 말하고 넘어가니 한 칸씩 맞춰 보는 게 좋다.

| 복식부기 (1494) | 이벤트 소싱 (2005) | 공통 원리 |
|---|---|---|
| 분개장 (giornale) | 이벤트 로그 / 이벤트 스토어 | 시간 순 append-only 기록 |
| 원장 (quaderno) | 프로젝션 / 읽기 모델 | 로그에서 파생된 조회용 뷰, 언제든 재구축 |
| 분개 한 줄 | 이벤트 한 건 | 불변(immutable) 사실 |
| **역분개(반대 기입)** | **보상 이벤트 / 취소 이벤트** | **수정은 삭제가 아니라 추가로 한다** |
| 시산표 (차변=대변) | 재생 후 상태 검증 / 체크섬 | 표현 자체가 오류를 검출 |
| 「어느 시점 잔액」 조회 | 특정 오프셋까지 재생 | 과거 상태 재구성 |
| 감사 추적(audit trail) | 계보/출처 (PROV-O, 19·30장) | 결과가 아니라 경로를 검증 |
| 결산·마감 잔액 | 스냅숏 | 재생 비용을 끊는 체크포인트 |

**바뀐 것은 어휘뿐이다.** 「지우지 말고 반대 기입을 하라」가 「이벤트를 쌓아라」가 됐다. 그리고 예제가 말하지 않은 대응이 하나 더 있다 — 이 표의 **이시간 모델(1990)** 도 실은 복식부기 안에 이미 있었다. 회계는 처음부터 **발생일(거래가 실제로 일어난 날)** 과 **기표일(장부에 적힌 날)** 을 나눠 적었다. 유효 시간과 시스템 시간, 즉 bitemporality다. 1990년의 이시간 모델은 그것을 형식화한 것이고, 관행은 500년 전부터 있었다.

## 5. 표 안에서 이 항목이 갖는 위치

`ex3_what_survives.py`는 16개 항목을 「이름 5 / 문제 5 / 해법 6」으로 나누고 종류별 평균 나이를 찍는다. 실행하면 이렇게 나온다.

```
[이름]  평균 나이 21년      (4, 12, 16, 25, 46)
[문제]  평균 나이 46년      (36, 41, 46, 51, 56)
[해법]  평균 나이 122년     (21, 36, 47, 47, 51, 532)
```

복식부기가 이 표에서 하는 일이 여기서 드러난다.

- **논지의 유일한 실증 사례다.** 「해법은 수백 년 간다」는 주장은 복식부기 하나에 걸려 있다. 복식부기를 빼면 해법 평균은 **122년 → 40년**으로 내려앉고, 문제 평균 46년과 구별이 안 된다. 「이름 21 / 문제 46 / 해법 40」은 「해법은 수백 년」을 뒷받침하지 못한다. 즉 이 항목은 **표의 결론을 지탱하는 유일한 하중점**이자, 동시에 **표본 1개에 의존한다는 약점**이다 — 반증 가능성을 다루는 35장의 맥락에서 이건 의도된 자기 노출로 읽는 게 맞다.
- **정렬하면 첫 줄에 온다.** `sorted(rows, key=lambda x: x[1])`이라 「해법」 블록의 맨 위가 1494년 복식부기다. ITEMS 리터럴에서는 맨 끝에 적혀 있는데 출력에서는 맨 앞에 오도록 되어 있다.
- **유일한 비(非)컴퓨터 항목이다.** 나머지 15개는 전부 전산 분야에서 태어났다. 복식부기만 상업 실무에서 왔다. 이게 논증의 힘을 만든다 — 컴퓨터 안에서 살아남은 것은 「컴퓨터가 아직 30년밖에 안 됐으니까」로 반박할 수 있지만, 복식부기는 컴퓨터가 없던 460년을 이미 통과했다.
- **가장 새로운 해법과 짝을 이룬다.** 해법 6개 중 최연소는 이벤트 소싱(2005, 21년), 최고령은 복식부기(532년)다. **25배 차이가 나는 두 항목이 같은 구조**라는 게 이 예제의 결정타다. 「최신 해법이 실은 최고(最古) 해법의 재발견」이라는 형태이고, 이게 왜 「이름」에 투자하면 안 되는지를 설명한다.
- **「그대로 씀」 그룹에 속한다.** 해법 6개의 상태는 그대로 씀 4(이시간 모델, 낙관적 잠금, 이벤트 소싱, 복식부기) / 일부만 남음 1(규칙 기반 추론) / 다시 필요해짐 1(진리 유지 시스템)이다. 대조적으로 「이름」 5개 중 지금도 그대로 쓰는 것은 **1개**(마이크로서비스)뿐이다.

## 6. 그래서 이 카드가 실무에 주는 것

예제 결말이 우선순위를 못 박는다.

```
  1. 문제  — 30년 뒤에도 그대로 있을 것
  2. 해법  — 이름이 바뀌어도 구조는 남을 것
  3. 이름  — 내년에 없을 수도 있는 것
```

복식부기는 2번의 증거물이다. 판단 기준으로 바꿔 쓰면 이렇다.

- **새 기법을 볼 때**: 이 기법이 무엇에 의존하는가를 묻는다. 특정 매체·엔진·프레임워크·모델 아키텍처에 의존하면 그것들과 함께 죽는다. **불변식 하나로 서술할 수 있으면** 오래 간다.
- **설계할 때**: 상태를 지우고 고치는 구조가 아니라 **쌓아서 되감을 수 있는 구조**를 택한다. 에이전트가 그래프에 쓰기 시작하면 「누가 언제 무엇을 왜 넣었나」가 반드시 필요해지고(19·28·30장), 그때 append-only가 아니면 답할 방법이 없다.
- **이름에 걸린 것을 알고 있을 때**: 35장이 스스로 인정하듯 「에이전트 그래프 엔지니어링」이라는 용어에 대한 저자 확신은 **20%** 로 다섯 주장 중 최저다. 이름은 20%, 그 안에 든 구조는 532년 — 이 낙차가 35장의 논지 전체다.
