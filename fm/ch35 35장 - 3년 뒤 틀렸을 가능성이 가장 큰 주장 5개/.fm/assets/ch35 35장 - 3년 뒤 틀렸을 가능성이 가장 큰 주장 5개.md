> 이 책을 쓰기 시작할 때 정한 게 하나 있습니다. *마지막 장에서 제가 틀렸을 곳을 직접 지목하기.*

둘째, 이게 더 큰 이유인데 *제가 확신하지 못하는 부분을 스스로 알기 위해서*였습니다. 「어디가 틀렸을까」를 마지막에 써야 한다고 정해 두면, 쓰는 내내 그 질문을 갖고 다니게 됩니다. 그리고 실제로 그랬습니다. 이 장의 목록은 마지막에 만든 게 아니라 *쓰면서 쌓인* 것이에요.

## 이 장의 절

| 절 | 제목 |
|---|---|
| 35.1 | 주장을 반증 가능한 형태로 |

## 한 장 요약

- 이 책의 핵심 주장 다섯 개에 대해 저는 평균 46%만 확신합니다.
- 제일 빨리 틀릴 것 같은 건 「모델 호출이 90%를 차지한다」입니다. 모델이 빨라지고 있어요. 제일 오래 갈 것 같은 건 「자동 확장에는 관문이 필요하다」고, 관문 중 하나가 정확도와 무관하기 때문입니다.
- 반증 조건을 못 쓰는 것은 주장이 아니라 의견입니다. 이 책에서 그리로 빠진 문장은 전부 뺐습니다.
- 트랙 1과 트랙 2는 성숙도가 20년쯤 차이 납니다. [표준] 다섯은 전부 트랙 1이고 [실험] 넷은 전부 트랙 2예요. 그래서 3부와 4부의 문체가 다릅니다.
- 이름은 몇 년, 문제는 수십 년, 해법은 수백 년 갑니다. 이 책의 제목은 첫 번째 층에 걸려 있고, 안에 든 것은 두 번째와 세 번째이기를 바랍니다.
- 이 책의 숫자는 자릿수와 방향으로만 쓰세요. 여러분 환경에서 다시 재는 데 하루면 됩니다. 하나만 고르라면 [33장](../../ch33/code/README.md)의 지배 구간입니다.
- 그리고 이 책을 쓰면서 저는 19번 정정했습니다. 절반쯤은 오래 믿고 있던 것이었어요. 그 정정들을 지우지 않고 남겼습니다.

## 키워드와 1차 출처

| 키워드 | 상태 | 출처 |
|---|---|---|
| 반증 가능성 | [사실상 표준] | [falsifiability](https://plato.stanford.edu/entries/popper/) |
| ISO GQL | [표준] | [ISO/IEC 39075](https://www.iso.org/standard/76120.html) |
| SPARQL 1.2 | [표준] | [SPARQL 1.2](https://www.w3.org/TR/sparql12-query/) |
| 모델 컨텍스트 프로토콜 | [사실상 표준] | [MCP](https://modelcontextprotocol.io/specification/2025-06-18) |

| 세계 모형 | [실험] | [world model](https://openreview.net/forum?id=BZ5a1r-kVsf) |

상태 표시는 **[표준]** 공식 명세, **[사실상 표준]** 명세는 없지만 업계가 널리 쓰는 것, **[실험]** 아직 자리를 잡는 중이라는 뜻입니다.

```python
"""
예제 1 — 이 책의 주장 다섯 개를 「무엇이 참이면 틀리는가」로 적는다.

    python3 ex1_five_claims.py

의존성 없음. 주장을 반증 가능한 형태로 만드는 연습이다.
반증 조건을 못 쓰면 그건 주장이 아니라 의견이다.
"""

CLAIMS = [
    dict(
        n=1,
        claim="모델 호출이 응답 시간의 90% 넘게 차지한다",
        chapter="33장",
        falsifier="같은 작업의 모델 지연이 10분의 1이 되면 60% 아래로 내려간다",
        watch="분기마다 구간별 시간을 다시 잰다",
        confidence=0.35,
        note="지난 2년 추세가 이대로면 3년 안에 뒤집힌다",
    ),
    dict(
        n=2,
        claim="프롬프트 인젝션은 프롬프트 층에서 못 막는다",
        chapter="26장",
        falsifier="지시와 데이터를 «구조적으로» 나눈 모델이 나오면 틀린다",
        watch="모델 아키텍처 논문에서 «채널 분리»를 찾아본다",
        confidence=0.55,
        note="지금 구조에서는 맞는데, 구조가 안 바뀐다는 보장이 없다",
    ),
    dict(
        n=3,
        claim="에이전트가 스스로 넓힌 그래프는 관문 없이 못 쓴다",
        chapter="28장",
        falsifier="추출 정확도가 99.9% 가 되면 관문 넷 중 셋이 필요 없어진다",
        watch="추출 정확도를 분기마다 재고, 관문별 차단 건수를 본다",
        confidence=0.70,
        note="정확도가 올라도 «이름 정규화»는 남는다. 다른 문제라서",
    ),
    dict(
        n=4,
        claim="지식 그래프와 에이전트 상태는 따로 두는 게 옳다",
        chapter="29장",
        falsifier="그래프 DB 의 쓰기 성능이 키-값 저장소 수준이 되면 합쳐도 된다",
        watch="쓰기 지연 비율(그래프/키-값)을 반기마다 잰다",
        confidence=0.50,
        note="성능이 아니라 «수명이 다르다»는 이유는 안 바뀐다",
    ),
    dict(
        n=5,
        claim="「에이전트 그래프 엔지니어링」이라는 용어가 자리를 잡는다",
        chapter="서문",
        falsifier="3년 뒤에 아무도 이 말을 안 쓰면 틀린 것이다",
        watch="이 말을 쓰는 1차 출처가 늘어나는지 센다",
        confidence=0.20,
        note="제일 자신 없는 주장. 이름은 자주 바뀐다",
    ),
]


def bar(p, width=20):
    return "█" * int(p * width) + "░" * (width - int(p * width))


def main():
    print("이 책에서 3년 뒤에 틀렸을 가능성이 큰 주장 다섯 개.\n")
    print("«확신»은 3년 뒤에도 이 주장이 참일 것으로 보는 정도다.\n")

    for c in sorted(CLAIMS, key=lambda x: x["confidence"]):
        print(f"[{c['n']}] {c['claim']}  ({c['chapter']})")
        print(f"     확신     {bar(c['confidence'])} {c['confidence']:.0%}")
        print(f"     반증 조건 {c['falsifier']}")
        print(f"     지켜볼 것 {c['watch']}")
        print(f"     덧붙임   {c['note']}")
        print()

    avg = sum(c["confidence"] for c in CLAIMS) / len(CLAIMS)
    print(f"평균 확신 {avg:.0%}. 절반 아래다.")

    print(
        "\n주장을 이렇게 적으면 두 가지가 생긴다.\n"
        "\n첫째, «무엇을 지켜보면 되는지»가 정해진다.\n"
        "막연히 「나중에 바뀔 수도」가 아니라 「이 값이 이렇게 되면 틀린다」다.\n"
        "\n둘째, 반증 조건을 못 쓰는 주장이 걸러진다.\n"
        "「그래프가 중요하다」 같은 문장은 반증 조건을 못 쓴다.\n"
        "무엇이 참이면 그게 틀리는지 말할 수 없기 때문이다. 그건 주장이 아니라 의견이다.\n"
        "\n이 책을 쓰면서 반증 조건을 못 쓴 문장이 꽤 많이 나왔고, 그건 전부 뺐다.\n"
        "\n다섯 개 중 5번이 제일 자신 없다. 20% 다.\n"
        "그런데 그건 이 책의 부제이기도 하다. 그래서 서문에 미리 밝혀 뒀다."
    )


if __name__ == "__main__":
    main()
```

```python
"""
예제 2 — 표준이 어디까지 왔나. 그리고 무엇을 지켜볼 것인가.

    python3 ex2_standard_watch.py

의존성 없음. 이 책에서 [표준]/[업계 표준]/[실험] 로 표시한 것들이
지금 어느 단계에 있는지 정리한다. 확인 시점 2026년 8월.
"""

STAGES = ["아이디어", "구현이 여럿", "명세 초안", "공식 명세", "널리 채택"]

ITEMS = [
    # 이름                        단계   이 책 표시   지켜볼 신호
    ("RDF · OWL · SHACL",          4, "표준",
     "이미 안정. 큰 변화 없을 것"),
    ("SPARQL 1.1",                 4, "표준",
     "1.2 작업이 진행 중"),
    ("ISO GQL",                    3, "표준",
     "엔진들이 실제로 구현하는지"),
    ("SQL/PGQ",                    3, "표준",
     "DuckDB · 상용 DB 의 지원 범위"),
    ("Cypher 방언",                1, "업계 표준",
     "GQL 로 수렴하는지, 갈라지는지"),
    ("MCP",                        2, "업계 표준",
     "명세 버전이 얼마나 자주 바뀌는지"),
    ("PROV-O",                     4, "표준",
     "에이전트 계보에 실제로 쓰이는지"),
    ("GraphRAG 계열",              1, "업계 표준",
     "공통 평가 기준이 생기는지"),
    ("에이전트 간 프로토콜",         1, "실험",
     "구현이 둘 이상 상호운용되는지"),
    ("에이전트 그래프 위상 이론",     0, "실험",
     "논문에 공통 용어가 생기는지"),
    ("그래프 기반 장기 기억",        1, "실험",
     "벤치마크가 생기는지"),
    ("자기수정 온톨로지",           0, "실험",
     "운영 사례가 공개되는지"),
]


def main():
    print(f"확인 시점 2026년 8월. 단계: {' → '.join(STAGES)}\n")
    print(f"{'항목':<26}{'단계':<12}{'표시':<12}지켜볼 신호")
    print("-" * 88)
    for name, stage, tag, watch in sorted(ITEMS, key=lambda x: -x[1]):
        dots = "●" * (stage + 1) + "○" * (4 - stage)
        print(f"{name:<26}{dots:<12}{tag:<12}{watch}")

    counts = {}
    for _n, _s, tag, _w in ITEMS:
        counts[tag] = counts.get(tag, 0) + 1
    print(f"\n표시별 개수: {counts}")

    exp = [i for i in ITEMS if i[2] == "실험"]
    print(f"\n[실험] {len(exp)}개의 평균 단계: "
          f"{sum(i[1] for i in exp) / len(exp):.1f} / 4")

    print(
        "\n[표준] 과 [실험] 사이가 비어 있는 게 이 표의 요점이다.\n"
        "\n[표준] 다섯은 전부 W3C 나 ISO 것이고, 트랙 1(지식 그래프) 쪽이다.\n"
        "[실험] 넷은 전부 트랙 2(에이전트) 쪽이고, 평균 단계가 0.5 다.\n"
        "\n그러니까 이 책의 두 트랙은 «성숙도가 20년쯤 차이 난다».\n"
        "그래서 3부는 「이렇게 하면 된다」로 쓸 수 있었고\n"
        "4부는 「저는 이렇게 하는데 확신은 없습니다」로 쓸 수밖에 없었다.\n"
        "\n3년 뒤에 이 표를 다시 그리면 아래쪽 넷이 위로 올라와 있을 수도 있다.\n"
        "안 올라와 있을 수도 있고, 아예 다른 이름으로 바뀌어 있을 수도 있다.\n"
        "\n지켜볼 신호를 적어 둔 게 그래서다.\n"
        "「MCP 명세 버전이 얼마나 자주 바뀌는지」 같은 건 링크 하나 열면 5분에 확인된다.\n"
        "그리고 그 5분이 「지금 이걸 도입해도 되나」의 답을 준다."
    )


if __name__ == "__main__":
    main()
```

### `code/ex3_what_survives.py`

```python
"""
예제 3 — 무엇이 살아남나. 지난 30년의 기술을 놓고 세어 본다.

    python3 ex3_what_survives.py

의존성 없음. 「이름」과 「문제」와 「해법」을 나눠서 본다.
셋의 수명이 다르다.
"""

ITEMS = [
    # (이름, 등장, 지금 상태, 종류)
    ("전문가 시스템",       1980, "이름은 사라짐",   "이름"),
    ("시맨틱 웹",          2001, "이름은 흐려짐",   "이름"),
    ("빅데이터",           2010, "이름은 사라짐",   "이름"),
    ("마이크로서비스",       2014, "이름은 남음",     "이름"),
    ("프롬프트 엔지니어링",   2022, "이름이 옮겨감",   "이름"),

    ("지식을 명시적으로 적기", 1970, "지금도 문제",    "문제"),
    ("무엇이 언제 참이었나",   1980, "지금도 문제",    "문제"),
    ("어디서 온 정보인가",    1990, "지금도 문제",    "문제"),
    ("동시 변경 충돌",       1975, "지금도 문제",    "문제"),
    ("무엇을 잊을 것인가",    1985, "지금도 문제",    "문제"),

    ("규칙 기반 추론",       1975, "일부만 남음",    "해법"),
    ("이시간 모델",         1990, "그대로 씀",      "해법"),
    ("낙관적 잠금",         1979, "그대로 씀",      "해법"),
    ("이벤트 소싱",         2005, "그대로 씀",      "해법"),
    ("진리 유지 시스템",      1979, "다시 필요해짐",   "해법"),
    ("복식부기",           1494, "그대로 씀",      "해법"),
]

NOW = 2026


def main():
    print("지난 30년(그리고 500년)의 것들을 세 종류로 나눠 본다.\n")
    for kind in ("이름", "문제", "해법"):
        rows = [i for i in ITEMS if i[3] == kind]
        ages = [NOW - i[1] for i in rows]
        print(f"[{kind}]  평균 나이 {sum(ages) / len(ages):.0f}년")
        for name, year, state, _k in sorted(rows, key=lambda x: x[1]):
            print(f"    {year}  {name:<24}{state}")
        print()
```

```python
    ("종류별 비율 상한·하한을 도메인마다 정하는 원칙",
     "28장", "실무", "낮음"),
    ("여러 마이그레이션이 동시에 돌 때 불일치의 원인 구분",
     "32장", "실무", "낮음"),
```
