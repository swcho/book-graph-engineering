# 전역 질문 문제의 풀이 — 세는 시점을 옮긴다

**Q.** 전역 질문 문제의 풀이는 무엇인가?

**A.** 세는 시점을 옮기는 것이다. 색인 시점에 그래프를 만들고 뭉치마다 요약을 접어 두면 질의 시점에는 펴기만 하면 된다.

---

## 1. 무엇이 문제였나 — 「전역 질문」의 정체

조각 검색(RAG)은 **답이 어느 한 조각 안에 들어 있을 때** 잘 돈다. "d01 장애의 원인이 뭐였나" 같은 질문은 그 문서 한 건만 찾아오면 끝난다.

문제는 이런 질문이다.

> "우리 장애 회고 **전체**에서 반복되는 원인은 무엇인가?"

이 답은 어느 한 조각에도 적혀 있지 않다. **전체를 훑고 세어야만** 나온다. 6장 예제의 정답은 `{"멱등성 없음", "재시도"}`인데, 이건 12건을 모두 세어 빈도를 비교해야 나오는 값이다.

이런 질문을 책에서는 **전역 질문(global question)** 이라고 부른다. 「전부 몇 건인가」, 「가장 흔한 패턴은」, 「이 데이터셋의 주제는」 같은 집계·요약형 질문이 여기 속한다.

### 왜 top-k로는 못 넘나

`ex1_rag_limits.py`가 보여 주는 게 정확히 이 벽이다.

```
질문: 우리 장애 회고 전체에서 반복되는 원인은 무엇인가?
상위 4개 조각
  [0.xxx] d0? ...
  ...
이 4개만 보고 «반복되는 원인»을 셀 수 있나?
전체 12건 중 4건만 봤다. 나머지 8건에 무엇이 있는지 모른다.
```

여기서 흔히 나오는 반박이 "k를 12로 올리면 되잖아"다. 예제에서는 **된다**. 문서가 12건뿐이니까. 그런데 문서가 12만 건이면 못 넣는다.

핵심은 이것이다.

> **「조각을 더 넣기」로는 못 넘는 벽이다.**

k를 키우는 건 벽을 넘는 게 아니라 벽을 조금 뒤로 미는 것뿐이다. 컨텍스트 윈도가 아무리 커져도 코퍼스는 항상 그보다 크게 자란다. 게다가 유사도 상위 k개는 **대표 표본이 아니라 편향 표본**이라, 몇 건을 넣든 전체 분포를 대신하지 못한다.

---

## 2. 풀이 — 시점을 옮긴다

발상의 전환은 "무엇을 검색하나"가 아니라 **"언제 세나"** 를 바꾸는 데 있다.

| | 조각 검색(RAG) | 그래프 기반 RAG(GraphRAG 계열) |
|---|---|---|
| 훑는 시점 | **질의 시점**에 top-k만 | **색인 시점**에 전부 한 번 |
| 질의 시점에 하는 일 | k개 조각을 읽고 답한다 | 접어 둔 요약을 **펴서** 합친다 |
| 전체를 셀 기회 | 없다 | 색인 때 이미 셌다 |
| 비용이 드는 곳 | 질의마다 조금씩 | 색인 때 크게 한 번 |

질의 시점은 사용자를 기다리게 하는 시점이라 예산이 몇 초뿐이다. 색인 시점은 배치라서 몇 시간을 써도 된다. **비싼 전수 조사를 예산이 넉넉한 쪽으로 옮기는 것**, 이게 풀이의 전부다.

### 「접는다 / 편다」는 비유

- **접는다(fold)**: 색인 시점에 원문 뭉치를 훑어, 그 뭉치가 무슨 얘기인지를 요약 한 덩어리로 압축해 저장해 둔다. 12건이든 12만 건이든, 뭉치 수만큼의 요약만 남는다.
- **편다(unfold)**: 질의 시점에는 원문 대신 접어 둔 요약들만 꺼내 합친다. 읽을 양이 원문 전체가 아니라 요약 개수로 줄어든다.

## 3. 실제로 어떻게 접나 — 4단계

`ex2_graphrag_lite.py`가 축소판으로 보여 주는 절차다.

### (1) 트리플 추출 — 문서를 그래프로

각 문서에서 `(문서, 관계, 개념)` 트리플을 뽑는다.

```
("d01", "원인", "재시도"), ("d01", "원인", "멱등성 없음"), ("d01", "영역", "결제"),
("d02", "원인", "중복 요청"), ("d02", "원인", "멱등성 없음"), ...
```

여기서 중요한 일이 일어난다. `d01`과 `d02`는 원문 텍스트로는 서로 다른 장애지만, **"멱등성 없음"이라는 같은 노드를 공유**하게 된다. 벡터 공간에서는 그냥 "좀 비슷한 두 점"이었을 관계가, 그래프에서는 **명시적인 간선**이 된다. (실제 시스템에서는 이 추출을 LLM이 한다. 책에서는 15장에서 다룬다.)

### (2) 커뮤니티 탐지 — 뭉치를 찾는다

노드들을 서로 촘촘히 연결된 덩어리로 나눈다. 예제는 의존성을 없애려고 **라벨 전파(label propagation)** 를 직접 구현했다.

```python
def label_propagation(adj, rounds=12):
    """이웃에서 제일 흔한 라벨을 가져온다. 몇 바퀴 돌면 뭉친다."""
    label = {n: i for i, n in enumerate(sorted(adj))}
    for _ in range(rounds):
        changed = False
        for n in sorted(adj):
            best = Counter(label[m] for m in adj[n]).most_common(1)[0][0]
            if label[n] != best:
                label[n], changed = best, True
        if not changed:
            break
```

각자 자기 번호를 라벨로 갖고 시작해서, 매 바퀴 이웃 중 최빈 라벨을 따라간다. 몇 바퀴면 수렴하면서 같은 라벨끼리 뭉친다. 실제 Microsoft GraphRAG는 여기에 **Leiden 알고리즘**을 써서 계층적 커뮤니티(커뮤니티 안의 커뮤니티)까지 만든다.

### (3) 커뮤니티 요약 — 접어 둔다

뭉치마다 요약을 만들어 저장한다.

```python
def summarize(community, triples):
    causes = Counter(o for s, p, o in triples
                     if p == "원인" and s in members and o in members)
    ...
    return {"문서": docs, "요약": f"문서 {len(docs)}건. 자주 나온 원인: {top}", "원인분포": causes}
```

예제는 **규칙 기반**이라 매번 같은 결과가 나온다. 진짜 GraphRAG는 이 요약문을 모델이 쓴다. 책이 여기서 강조하는 건 명시적이다.

> `ex2`의 요약문은 규칙으로 만듭니다. 진짜 GraphRAG는 모델이 씁니다.
> 여기서 보여 주려는 건 요약 품질이 아니라 **언제 접느냐**입니다.

### (4) 질의 시점 — 편다

```python
total = Counter()
for s in summaries:
    total.update(s["원인분포"])
```

원문 12건을 다시 읽지 않는다. 접어 둔 요약만 합친다. 그리고 정답이 나온다.

```
답: ['멱등성 없음', '재시도']
정답: ['멱등성 없음', '재시도']
맞았나: 예
```

실제 GraphRAG에서는 이 단계가 **map-reduce**로 돈다. 커뮤니티 요약마다 부분 답을 만들고(map), 그걸 다시 하나로 합친다(reduce). 원문 전체를 컨텍스트에 넣는 대신 요약들만 넣으니 12만 건짜리 코퍼스에서도 성립한다.

## 4. 공짜가 아니다 — 대가

예제 출력이 스스로 밝히는 부분이다.

```
대가도 분명하다. 색인이 비싸고, 문서가 바뀌면 다시 접어야 한다.
그래서 자주 바뀌는 데이터에는 안 맞는다.
```

정리하면 세 가지다.

1. **색인이 비싸다.** 트리플 추출과 커뮤니티 요약을 전부 LLM으로 돌리면 문서 수에 비례해 토큰 비용이 든다. 조각 검색의 색인(임베딩 한 번)과는 자릿수가 다르다.
2. **갱신이 어렵다.** 문서 하나가 바뀌면 그 문서가 속한 커뮤니티 구성이 흔들리고, 요약을 다시 접어야 한다. 최악에는 커뮤니티 경계 자체가 재계산된다. **자주 바뀌는 데이터에는 안 맞는다.**
3. **사실 조회에서는 오히려 살짝 진다.** 6장 요약이 정직하게 적고 있는 대목이다.

> 그리고 정직하게 말하면, 사실 조회에서는 그래프를 붙인 쪽이 살짝 집니다.
> **전역 질문 비율이 5%도 안 되면 안 붙이는 게 맞습니다.**

즉 이 풀이는 "RAG의 상위 호환"이 아니라 **질문 분포에 따라 고르는 트레이드오프**다. 판단 기준은 하나다. 우리 질의 로그에서 전역 질문이 몇 %인가.

---

## 5. 한 줄로 다시

> 전역 질문은 조각을 더 넣어서 푸는 문제가 아니다. **세는 시점을 질의 시점에서 색인 시점으로 옮겨서** 푸는 문제다. 색인 때 그래프를 만들고 뭉치마다 요약을 접어 두면, 질의 때는 펴기만 하면 된다.
