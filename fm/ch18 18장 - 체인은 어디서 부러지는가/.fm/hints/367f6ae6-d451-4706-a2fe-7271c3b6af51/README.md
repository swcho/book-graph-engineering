# "if를 쓰지 마라"가 18장의 결론인가?

**아니다.** 18장의 결론은 "if를 버려라"가 아니라 **"조건 수에 따라 유리한 구조가 달라진다"**이다. 조건이 두세 개면 if가 훨씬 읽기 쉽고, 그래프는 오히려 배워야 할 개념이 늘어난다.

## 왜 이런 질문이 나오는가

18.2절(`ex2_if_explosion.py`)은 if 문의 약점을 강하게 보여 준다.

- **경우의 수는 지수로 는다** — 조건이 하나 늘 때마다 두 배. 조건 5개면 32가지.
- **그래프 엣지는 선형으로 는다** — 조건마다 갈림길 노드 하나 + 나가는 엣지 둘.
- 실무에서 무너지는 지점이 대개 **조건 5개**다. 32가지 경우 중 몇 가지는 테스트를 안 해 보게 되고, 안 해 본 경우가 운영에서 터진다.

이 표만 보면 "if는 나쁘다"로 읽기 쉽다. 그래서 책은 예제 끝에 바로 못을 박는다.

> 그런데 이게 «if 를 쓰지 마라»는 뜻은 아니다.
> 조건 두세 개면 if 가 훨씬 읽기 쉽다. 그래프는 개념이 늘어나니까.

## 진짜 결론: 비용 비교

if와 그래프의 차이는 **늘어나는 방식**의 차이다.

| | if 문 | 상태 그래프 |
|---|---|---|
| 경우의 수 표현 | 코드로 **펼친다** → 지수 증가 | 갈림길을 **선언**한다 → 조합은 실행 시점에 만들어짐 |
| 조건 n개일 때 | 경로 2ⁿ개 | 엣지 2n개 |
| 초기 비용 | 거의 없음 | 개념·도구 학습 비용 (책의 가정: 약 2일) |

조건이 적을 때는 if의 "지수 증가"가 아직 작고, 그래프의 "학습 비용"이 상대적으로 크다. 그래서 **작을 때는 if가 싸고, 커지면 그래프가 싸진다.**

## 갈아타는 지점 (18.5절, `ex5_when_to_switch.py`)

책은 손익분기점을 직접 계산해 보인다. 기본 가정(학습 비용 2일, 미검증 경로가 터질 확률 8%, 버그 하나 0.5일)에서는 **조건 6~7개 사이**에서 그래프가 유리해진다. 단, 이 지점은 전제에 따라 움직인다.

- 팀이 이미 상태 그래프를 안다면 학습 비용 0 → 지점이 앞으로 온다.
- **결제·삭제처럼 되돌리기 힘든 작업**이면 버그 비용이 커서 조건 두세 개에서도 그래프가 낫다.
- 반대로 "틀려도 사람이 다시 누르면 그만"인 일이면 조건 여덟 개까지 체인+if로 버틸 만하다.

## 요약

- 18장의 메시지는 도구 금지("if 쓰지 마라")가 아니라 **손익 계산**이다.
- 조건 두세 개 → if가 읽기 쉽고 싸다. 그래프는 개념(노드, 엣지, 상태, 체크포인트)이 늘어난다.
- 조건이 다섯 개를 넘어가며 경우의 수가 사람이 다 못 보는 수준이 되면 → 그래프의 선형 증가가 이긴다.
- 같은 맥락에서 책은 "처음부터 그래프로 가지 말고, **바꿀 준비만 해 두라**"(단계를 함수로 분리, 데이터를 딕셔너리로 통일)고 권한다.
