# 세 가지 부분 실패 전략은 각각 어떤 산출물에 맞는가?

## 한 줄 답

- **전부 아니면 없음(all-or-nothing)** — 결재 서류처럼 **불완전하면 안 되는** 산출물
- **되는 것만(best-effort)** — 대시보드처럼 **있는 만큼 보여 주면 되는** 것
- **빈칸 표시(degrade, 빈칸을 표시하고 진행)** — 보고서처럼 **무엇이 빠졌는지 보여야 하는** 것

## 어떤 상황에서 나온 질문인가

18장 18.3절 "병렬로 돌렸는데 하나만 실패했다"의 핵심이다. 작업 4개를 병렬로 돌렸는데 그중 하나(예제에서는 "법무 검토")만 실패한 상황을 가정한다.

```
재무 자료 조회   성공  → 매출 84.2억
법무 검토       실패
영업 이력 조회   성공  → 계약 12건
리스크 평가     성공  → 중간
```

이때 "결과를 어떻게 낼 것인가"에 대한 답이 세 가지이고, **셋 다 맞는 답이다. 상황(산출물의 성격)이 정한다.**

## 세 전략의 동작 차이

| 전략 | 하나 실패 시 결과 | 맞는 산출물 | 이유 |
|---|---|---|---|
| 전부 아니면 없음 | `실패`, 결과 없음 | 결재 서류 | 일부만 채워진 결재 서류는 서류로서 무효. 불완전한 산출물이 나가면 안 됨 |
| 되는 것만 | `부분 완료`, 성공한 3건만 반환 | 대시보드 | 있는 데이터만큼만 보여 주면 충분. 빠진 항목을 굳이 표시할 필요 없음 |
| 빈칸 표시 | `완료 (미확인 1건)`, 실패 항목은 `"확인 불가"`로 채워 반환 | 보고서 | 읽는 사람이 "무엇이 빠졌는지"를 알아야 판단을 그르치지 않음 |

코드로 보면 (예제 `ex3_partial_failure.py`):

```python
def strategy_all_or_nothing(tasks):
    if all(ok for _, ok, _ in tasks):
        return "완료", {...}
    return "실패", None            # 하나라도 실패 → 전체 실패

def strategy_best_effort(tasks):
    return "부분 완료", {성공한 것만}  # 실패 항목은 조용히 빠짐

def strategy_degrade(tasks):
    # 실패 항목을 "확인 불가"로 채우고, 미확인 건수를 상태에 남김
    return f"완료 (미확인 {n}건)", {전 항목}
```

## 책이 덧붙이는 두 가지 포인트

1. **세 번째(빈칸 표시)가 대개 제일 낫다. 그런데 제일 안 쓰인다.** "확인 불가"를 화면에 그리는 일이 귀찮아서다. 되는 것만 보여 주는 방식은 실패를 조용히 숨기므로, 읽는 사람이 "법무 검토는 원래 없었나?"를 알 수 없다.

2. **체인에는 이 선택을 표현할 자리가 없다.** 체인은 한 단계가 실패하면 예외가 위로 던져지고 끝이다. 상태 그래프에서는 병렬 분기 뒤의 **합류 노드**가 이 결정을 맡는다. 즉 "부분 실패를 어떻게 다룰지"가 노드 하나의 명시적 책임이 된다 — 이것이 18장 제목("체인은 어디서 부러지는가")과 이어지는 지점이다.

## 암기 힌트

산출물의 "독자 계약"으로 기억하면 된다.

- 결재 서류: **완전성이 계약** → 불완전하면 아예 내지 마라 (전부 아니면 없음)
- 대시보드: **최신성이 계약** → 있는 만큼 그려라 (되는 것만)
- 보고서: **정직성이 계약** → 빠진 칸을 "확인 불가"로 드러내라 (빈칸 표시)
