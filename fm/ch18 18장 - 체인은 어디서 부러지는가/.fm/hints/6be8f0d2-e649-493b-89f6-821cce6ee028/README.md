# 상태 그래프로 얻는 세 가지는 무엇인가?

**답: 되돌아갈 수 있고, 몇 번 돌았는지가 프롬프트가 아니라 상태에 있고, 매 단계 체크포인트가 남아 죽어도 이어서 할 수 있다.**

## 어디서 나온 이야기인가

18장 18.4절 「같은 작업, 두 구조」(예제 `ex4_same_task_two_ways.py`)에서 같은 작업 — 「초안 작성 → 검사 → 빠진 절이 있으면 다시 작성」 — 을 체인과 상태 그래프(LangGraph `StateGraph`)로 각각 구현해 비교합니다.

- **체인**은 「작성 → 검사」까지 하고 끝납니다. 검사에서 빠진 절을 *알아도*, 다시 작성으로 돌아갈 자리가 구조에 없습니다.
- **상태 그래프**는 조건 함수(`route`) 하나와 조건부 엣지 한 줄만 추가하면 검사 결과를 보고 작성 노드로 되돌아갑니다.

늘어난 코드는 그 둘뿐인데, 그 대가로 얻는 것이 셋입니다.

## 세 가지를 하나씩

### 1. 되돌아갈 수 있다 (순환, cycle)

체인은 방향이 한쪽뿐인 직선입니다. 뒤 단계가 앞 단계의 결과에 문제를 발견해도 고칠 방법이 없습니다. 상태 그래프는 엣지로 「검사 → 작성」 같은 뒤로 가는 경로를 선언할 수 있어서, 검토-수정 루프(예: ReAct처럼 생각과 행동을 교차하는 패턴)를 구조 자체로 표현합니다.

예제에서는 `add_conditional_edges("검사", route, {"작성": "작성", END: END})` 한 줄이 이 순환을 만듭니다.

### 2. 몇 번 돌았는지가 프롬프트가 아니라 상태에 있다

예제의 상태 정의에 `rounds: Annotated[int, operator.add]` 필드가 있고, 작성 노드가 돌 때마다 1씩 누적됩니다. 라우팅 함수는 `s["rounds"] >= 4`면 END로 보내 무한 루프를 막습니다.

책이 이 항목을 특히 강조합니다:

> «3번까지만 시도해»를 프롬프트에 적으면 그건 **부탁**이고, 상태에 적으면 그건 **보장**이다.

프롬프트에 적은 제한은 모델이 지킬 수도, 안 지킬 수도 있는 자연어 요청입니다. 상태에 적은 제한은 코드가 강제하는 불변식입니다. 반복 횟수·예산·시도 한도 같은 안전장치는 모델의 선의가 아니라 구조에 두어야 합니다.

### 3. 매 단계 체크포인트가 남는다 — 죽어도 이어서 할 수 있다

체크포인터(예제에서는 `compile(checkpointer=InMemorySaver())`)를 붙이면 각 노드 실행이 끝날 때마다 상태 스냅숏이 저장됩니다. 예제도 `app.get_state_history(cfg)`로 체크포인트 개수를 출력해 확인합니다.

이것이 주는 실익:

- **중단 복구** — 프로세스가 죽거나 API 호출이 실패해도, 마지막 체크포인트에서 이어서 실행합니다. 처음부터 다시 하지 않습니다. (18.1절의 핵심 — 체인은 실패하면 앞 단계 결과를 전부 버리지만, 그래프는 실패한 단계만 다시 합니다. 이미 낸 토큰 값을 지킵니다.)
- **디버깅·감사** — 어느 단계에서 어떤 상태였는지 되짚어볼 수 있습니다.
- 이 성질은 Temporal 등이 말하는 **내구성 있는 실행(durable execution)** 개념과 같은 계열입니다.

## 기억 고리

세 가지를 한 단어씩으로 압축하면 **「순환 · 상태 · 체크포인트」**:

1. 순환 — 뒤로 가는 엣지 (되돌아간다)
2. 상태 — 반복 횟수가 프롬프트(부탁)가 아니라 상태(보장)에
3. 체크포인트 — 매 단계 저장, 죽어도 이어서

## 균형 감각

책은 「그러니 무조건 그래프」라고 말하지 않습니다. 단계가 두세 개고 실패가 드물면 체인이 더 쌉니다(개념이 적고 코드가 짧으니까). 다만 갈아탈 준비 — 단계를 함수로 분리하고 데이터를 딕셔너리로 통일 — 를 해 두면 전환이 반나절이라고 조언합니다. 그리고 구조를 바꿔도 실패율 자체는 줄지 않습니다. 줄어드는 것은 **실패의 값(비용)** 입니다.
