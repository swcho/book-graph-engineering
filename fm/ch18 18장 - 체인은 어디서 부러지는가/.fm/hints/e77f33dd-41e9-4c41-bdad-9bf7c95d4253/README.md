# 처음부터 그래프로 가야 하는가?

**답: 아니다.** 단계가 두세 개고 실패가 드물면 체인이 싸다. 대신 단계를 함수로 분리하고 데이터를 딕셔너리로 통일해 두면, 나중에 그래프로 전환하는 데 반나절이면 된다.

## 왜 "아니다"인가

18장은 체인이 부러지는 지점(재시도 시 앞 단계 결과를 버림, if 분기의 지수 폭발, 병렬 부분 실패를 표현할 자리 없음)을 계속 보여 주지만, 결론은 "그러니 처음부터 그래프"가 아니다. 이유는 비용 구조에 있다.

- **체인의 장점**: 개념이 적고 코드가 짧다. `f3(f2(f1(x)))` 수준의 파이프라인은 누구나 읽는다.
- **그래프의 비용**: StateGraph, 노드/엣지, 리듀서, 체크포인터 같은 개념 학습 비용이 처음에 한 번 붙는다 (책의 예제 5는 이걸 약 2일로 잡는다).
- 단계가 두세 개고 실패가 드물면, 그래프가 아껴 주는 "실패의 값"(다시 하지 않아도 되는 앞 단계 비용)이 학습·유지 비용보다 작다. 즉 **체인이 싸다**.

예제 1(`ex1_chain_vs_graph.py`)의 결론도 같다. 체인 대 그래프의 격차는 (1) 뒤쪽 단계가 자주 실패할수록, (2) 단계가 많을수록 벌어진다. 뒤집으면, 단계가 적고 실패가 드물면 격차가 거의 없다는 뜻이다. 그리고 대부분의 시스템은 거기서 시작한다 — "시작은 그게 맞다."

## 언제 갈아타는가 (예제 5의 손익 계산)

`ex5_when_to_switch.py`는 조건 수별로 체인의 예상 손실과 그래프 총비용을 견준다.

- 체인 경로 수는 2^n(지수)으로 늘고, 사람이 실제로 테스트하는 건 여덟 가지쯤. 나머지는 미검증 경로로 남는다.
- 그래프 비용은 학습 2일 + 노드 수(선형)뿐.
- 기본 가정(학습 2일, 미검증 경로 폭발 확률 8%, 버그당 0.5일)으로는 **조건 6~7개 사이**에서 갈아타는 지점이 나온다.

단, 전제 셋을 자기 값으로 바꿔야 한다.

1. 팀이 이미 그래프를 알면 학습 비용 0 → 지점이 앞으로 온다.
2. 미검증 경로가 터질 확률은 도메인마다 다르다.
3. **결제·삭제처럼 되돌리기 힘든 일**이면 버그 비용이 커서 조건 두세 개에서도 그래프가 낫다. 반대로 "틀려도 사람이 다시 누르면 그만"인 일은 조건 여덟 개까지 체인으로 버틸 만하다.

## 핵심: "바꿀 준비"를 해 두는 법

처음부터 그래프로 가지 않되, 전환을 반나절로 만드는 두 가지 규율:

1. **단계를 함수로 분리** — 각 단계가 독립 함수면 나중에 그대로 그래프의 노드가 된다. 한 덩어리 함수 안에 단계가 섞여 있으면 전환 시 먼저 뜯어내야 한다.
2. **데이터를 딕셔너리로 통일** — 단계 사이에 오가는 데이터가 하나의 딕셔너리(예: `TypedDict`) 모양이면 그게 그대로 그래프의 상태(State)가 된다. 예제 4의 `class S(TypedDict)`가 정확히 이 형태다.

이 두 가지만 지키면 전환 작업은 "노드 등록 + 엣지 선언 + 조건 함수 하나"로 줄어든다. 예제 4에서 체인과 그래프의 코드 차이가 "조건 함수 하나와 엣지 한 줄"뿐이었던 이유다.

## 함께 기억할 것

- 구조를 바꿔도 **실패율은 안 줄어든다**. 줄어드는 건 실패의 *값*(버리는 양)이다. 이 구분을 팀에 먼저 설명하라.
- 조건 두세 개면 if 문이 그래프보다 읽기 쉽다(예제 2). "if를 쓰지 마라"가 아니라 "조건 다섯 개 근처에서 사람이 경우의 수를 다 못 본다"가 요점이다.
