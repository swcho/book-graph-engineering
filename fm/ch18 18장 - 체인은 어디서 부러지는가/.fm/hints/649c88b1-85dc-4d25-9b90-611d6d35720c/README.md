# `ex4_same_task_two_ways.py`에서 체인은 왜 문제를 고치지 못하는가?

**한 줄 답:** 체인은 '작성 → 검사'까지 하고 끝나므로, 빠진 절을 알아내도 되돌아가 고칠 자리가 구조에 없다.

## 예제가 만든 상황

`ex4_same_task_two_ways.py`(18장 4절 「같은 작업, 두 구조」)는 같은 작업을 체인과 상태 그래프로 각각 구현해 놓고 **코드 길이가 아니라 「할 수 있는 것」**을 비교한다.

작업 자체는 단순하다. 보고서 초안에 필수 절 세 개(`## 개요`, `## 원인`, `## 조치`)가 다 있는지 확인하는 것이다.

- `draft()` — 모델 자리. 처음 호출하면 **일부러 첫 절 하나만** 쓴다. `hint`(빠진 절 목록)를 주면 그 절을 채운다.
- `check()` — 필수 절 중 빠진 것을 목록으로 돌려준다.

## 체인 쪽 코드가 전부다

```python
def run_chain():
    text = draft("")
    missing = check(text)
    return text, missing, ["작성", "검사"]
```

이게 체인의 전체다. 실행하면:

- 거친 단계: `["작성", "검사"]`
- 빠진 절: `['## 원인', '## 조치']` — **알아냈지만 그걸로 끝**

핵심은 `check()`가 문제를 **발견까지는 한다**는 점이다. `missing`에 빠진 절이 정확히 들어 있다. 그런데 체인은 단계를 한 방향으로 이어 붙인 구조라서, 검사 다음에 「다시 작성으로」라는 **엣지(되돌아갈 경로) 자체가 존재하지 않는다**. 진단 결과를 받아서 다시 작성 단계에 넘겨줄 자리가 코드 구조에 없는 것이다. 그래서 함수는 빠진 절 목록을 그냥 반환하고 종료한다.

책의 표현 그대로: **"체인은 «검사»까지 하고 끝난다. 빠진 걸 알아도 고칠 자리가 없다."**

## 상태 그래프는 무엇이 다른가

그래프 쪽은 같은 `draft`/`check`를 노드로 감싸고, 조건 엣지 하나를 선언한다.

```python
def route(s: S) -> str:
    if not s["missing"]:
        return END
    return END if s["rounds"] >= 4 else "작성"

b.add_conditional_edges("검사", route, {"작성": "작성", END: END})
```

검사 노드가 끝나면 `route`가 상태를 보고 결정한다. 빠진 절이 없으면 끝(`END`), 있으면 **"작성" 노드로 되돌아간다**(단, `rounds >= 4`면 무한 루프 방지로 종료). 되돌아갈 때 `n_draft`가 `s["missing"]`을 `hint`로 넘기므로, 두 번째 작성은 빠진 절을 채운다. 실행 결과 trace는 `['작성1', '검사', '작성2', '검사']`처럼 나오고 빠진 절은 `[]`가 된다.

## 늘어난 코드와 얻은 것

늘어난 코드는 **조건 함수 하나(`route`)와 엣지 한 줄**뿐이다. 그 대신 얻은 것이 셋:

1. **되돌아갈 수 있다** — 사이클(루프)이 구조로 표현된다.
2. **몇 번 돌았는지가 상태에 있다** — `rounds`는 프롬프트가 아니라 상태(`Annotated[int, operator.add]`)에 있다. "3번까지만 시도해"를 프롬프트에 적으면 **부탁**이고, 상태에 적으면 **보장**이다.
3. **매 단계 체크포인트가 남는다** — `InMemorySaver` 덕에 중간에 죽어도 이어서 할 수 있다.

## 정리

| | 체인 | 상태 그래프 |
|---|---|---|
| 검사에서 문제 발견 | 가능 (`missing` 계산) | 가능 |
| 발견한 문제를 고치기 | **불가 — 되돌아갈 엣지가 없다** | 조건 엣지로 「작성」에 복귀 |
| 반복 횟수 제한 | 표현할 자리 없음 | 상태 `rounds`로 보장 |
| 중단 후 재개 | 불가 | 체크포인트로 가능 |

즉 체인이 못 고치는 이유는 검사 능력이 없어서가 아니라, **검사 결과를 받아 되돌아가는 경로를 구조상 표현할 수 없기 때문**이다. 이것이 18장 전체의 주제 — "한 줄로 이어 붙인 파이프라인은 어디서 부러지는가" — 의 구체적인 예다.
