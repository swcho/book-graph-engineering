# '모델 확신도'를 진전 척도로 쓸 수 없는 이유는 무엇인가?

**답:** 계속 오른다. 15장에서 본 것처럼 자기 보고 확신도는 믿을 게 못 된다.

---

## 1. 문제의 자리 — 「진전 없음」이라는 종료 조건

20장은 종료 조건을 넷으로 나눕니다. 횟수 상한, 예산 상한, 시간 상한, 그리고 **진전 없음(정체)**입니다. 앞의 셋은 재기 쉬워요. 회차는 세면 되고, 비용은 더하면 되고, 시간은 시계를 보면 됩니다. 다 **루프 바깥의 사실**이고 모델이 손댈 수 없는 값이에요.

문제는 넷째입니다. 「나아지고 있는가」를 재려면 *점수*가 필요한데, 그 점수를 무엇으로 삼느냐가 20.2절의 주제고, 이 장에서 제일 어려운 부분입니다.

`code/guards.py`의 정체 판정은 이렇게 생겼습니다.

```python
def stalled(self) -> bool:
    """최근 stall_limit+1 개 점수가 나아지지 않았나.
    «같음»도 정체로 본다. 나빠지는 것만 잡으면 늦다."""
    n = self.stall_limit + 1
    if len(self.scores) < n:
        return False
    window = self.scores[-n:]
    best_before = min(window[:-1])
    return window[-1] >= best_before
```

이 함수는 `scores`가 무엇을 뜻하는지 모릅니다. 그냥 「최근 창에서 최고를 못 넘었으면 정체」라고 판단할 뿐이에요. 즉 **정체 감지의 품질은 전적으로 어떤 값을 `scores`에 넣느냐에 달려 있습니다.** 잘못된 값을 넣으면 이 조건은 조용히 무력화됩니다 — 에러도 없이, 그냥 영원히 `False`만 돌려주면서요.

## 2. ex2가 보여 주는 것 — 같은 루프, 세 가지 척도

`code/ex2_stall_detection.py`는 **완전히 같은 루프 하나**를 세 가지 척도로 재 봅니다. 회차별 데이터는 이겁니다.

```python
ROUNDS = [
    # (위반 건수, 산출물 길이, 모델이 매긴 확신도)
    (9, 320, 0.55),
    (6, 480, 0.61),
    (4, 610, 0.68),
    (4, 890, 0.74),      # 위반은 그대로인데 길이와 확신도는 올랐다
    (4, 1240, 0.79),
    (3, 1610, 0.83),
]
```

표로 다시 보면 이렇습니다.

| 회차 | 위반 건수 | 산출물 길이 | 모델 확신도 |
|---:|---:|---:|---:|
| 1 | 9 | 320 | 0.55 |
| 2 | 6 | 480 | 0.61 |
| 3 | 4 | 610 | 0.68 |
| 4 | **4** | 890 | 0.74 |
| 5 | **4** | 1240 | 0.79 |
| 6 | 3 | 1610 | 0.83 |

**확신도 시퀀스는 `0.55 → 0.61 → 0.68 → 0.74 → 0.79 → 0.83`입니다. 한 번도 안 꺾입니다.** 단조 증가예요.

그런데 4·5회차를 보세요. 실제 품질 지표인 위반 건수는 `4 → 4 → 4`로 **세 회차 동안 하나도 안 줄었습니다.** 같은 구간에서 확신도는 `0.68 → 0.74 → 0.79`로 계속 올라갑니다. 즉 **모델은 아무것도 못 고치는 동안에도 자기가 점점 잘하고 있다고 보고했습니다.**

세 척도를 `stalled_at()`에 각각 물리면 결과가 이렇게 갈립니다 (예제를 실제로 돌린 출력).

| 척도 | 멈추는 회차 | 그때 위반 |
|---|---:|---:|
| 위반 건수 (낮을수록 좋다) | **4** | 4 |
| 산출물 길이 (길수록 좋다?) | 안 멈춤 | 3 |
| **모델 확신도 (높을수록 좋다)** | **안 멈춤** | 3 |

「안 멈춤」이 핵심입니다. 예제 데이터가 6회에서 끝나니까 표에는 6회차 값이 찍히지만, **데이터가 60회, 600회로 이어져도 확신도 척도는 계속 안 멈춥니다.** 확신도로 정체를 재는 루프에는 정체 감지가 사실상 **없는** 거예요. 남는 건 횟수·예산·시간 상한뿐이고, 그건 「안 될 일에 예산을 끝까지 쓰고 끝나는」 정확히 그 시나리오입니다(ex1의 «제자리걸음» 항목).

## 3. 왜 루프가 절대 안 멈추는가 — 구조의 문제

값이 우연히 오른 게 아닙니다. **구조적으로 오르게 되어 있습니다.**

### 3.1 척도의 생산자와 소비자가 같다

정체 감지의 논리는 이렇습니다.

> 점수가 안 오른다 → 모델이 못 고치고 있다 → 멈춘다

이 추론이 성립하려면 「점수」가 **모델의 통제 밖**에 있어야 합니다. 그런데 확신도는 모델이 직접 만들어 내는 숫자예요. 그래서 화살표가 뒤집힙니다.

> 멈추기 싫으면(=계속하라는 신호를 주려면) 모델은 그냥 더 높은 숫자를 말하면 된다

루프를 계속 돌릴지 말지를 결정하는 심판이, 루프를 도는 당사자 자신인 겁니다. 20장 한 장 요약이 이걸 한 문장으로 못박습니다.

> 진전 척도는 「모델이 스스로 올릴 수 있는 값」이면 안 됩니다. 길이도 확신도도 모델이 마음대로 올려요. 규칙으로 세는 값을 쓰세요.

ex2의 마지막 출력도 같은 말입니다.

> 진전 척도를 고르는 기준 하나. «모델이 스스로 올릴 수 있는 값이면 안 된다.»
> 길이도 확신도도 모델이 마음대로 올릴 수 있다. 위반 건수는 못 올린다.

### 3.2 왜 하필 「오르는」 방향인가

생성-검증 루프에서 모델은 이전 회차의 산출물과 「고쳤다」는 맥락을 함께 봅니다. 회차가 쌓일수록 문맥에는 「내가 여기를 손봤다」는 증거가 계속 누적돼요. 확신도를 자기 보고하는 시점의 모델 입장에서는, **고칠수록 확신이 오르는 게 자연스러운 서사**입니다. 실제로 뭐가 나아졌는지와 무관하게요.

여기에 확신도의 성질이 겹칩니다. 확률값은 위로 **막혀 있어요**(≤1.0). 0.55에서 시작해 회차마다 조금씩 올리면 1.0 근처에서 포화합니다. 즉 이 척도는 **떨어질 이유가 구조적으로 없고, 오를 여지만 남은** 값입니다. `stalled()`가 잡으려는 「최근 최고를 못 넘음」이라는 사건 자체가 잘 일어나지 않습니다.

### 3.3 정체일수록 오히려 오를 수 있다

가장 고약한 부분입니다. 4·5회차처럼 모델이 **더 못 고치는 국면**에서, 모델은 「이제 다 됐다」고 판단하기 쉽습니다. 남은 위반이 자기 눈에 안 보이니까 못 고치는 거고, 안 보이니까 확신은 오르는 거예요. **진짜 정체 신호와 확신도 상승이 같은 원인에서 나옵니다.** 척도가 잡아야 할 바로 그 순간에 반대 방향을 가리키는 셈입니다.

### 3.4 산출물 길이도 같은 병이다

ex2가 길이를 나란히 놓은 이유가 여기 있습니다. `320 → 480 → 610 → 890 → 1240 → 1610`. 이것도 안 멈춥니다. 모델은 계속 문장을 덧붙일 수 있으니까요.

> «산출물 길이»는 영원히 안 멈춘다. 계속 길어지니까.
> 그런데 길어지는 게 나아지는 건 아니다. 위반은 4에서 안 줄었다.

확신도와 길이는 겉보기엔 다른 지표지만 **같은 결함**을 공유합니다. 둘 다 모델이 일방적으로 만들어 내는 값이고, 둘 다 단조 증가할 수 있고, 둘 다 실제 품질과 끊겨 있습니다.

## 4. 15장과의 연결 — 자기 보고는 참·거짓을 못 가른다

ex2의 문구가 15장을 콕 집어 참조합니다.

> «모델 확신도»도 계속 오른다. 15장에서 봤듯 자기 보고는 믿을 게 못 된다.

15장 `ex4_confidence.py`는 트리플 추출에서 자기 보고 확신도를 실측합니다. 결과가 이래요.

```python
SELF_REPORTED = {
    ("가온테크", "체결", "C-2025-118"): 0.95,
    ("C-2025-118", "담당", "김하늘"): 0.92,
    ("C-2025-118", "상대", "나루소프트"): 0.90,
    ("C-2025-118", "체결일", "2025-06-02"): 0.88,
    ("가온테크", "업종", "IT 서비스"): 0.91,     # 지어낸 건데 확신이 높다
    ("가온테크", "규모", "중견기업"): 0.87,       # 이것도
}
```

> 자기 보고는 거짓에도 0.91, 0.87 을 준다. 참과 구분이 안 된다.

**15장의 결론은 「자기 보고 확신도는 정답과 오답을 못 가른다」, 20장의 결론은 「그러니 진전 척도로도 못 쓴다」입니다.** 한 회차 안에서 참·거짓을 못 가르는 값이, 회차를 가로질러 「나아졌는가」를 갈라 줄 리가 없죠.

15장이 대안으로 쓴 건 **여러 번 돌려 표 세기(self-consistency)**입니다. 지어낸 건 매번 다르게 지어내니까 표가 안 모여요. 그것도 모델 출력이지만 **모델이 한 번의 답변으로 임의 조작할 수 없는** 값이라는 점이 다릅니다. 20장의 기준과 정확히 같은 기준입니다.

### 참고 — 연구계의 같은 결론

LLM의 verbalized confidence(말로 표현한 확신도)가 미보정(miscalibrated)이고 체계적으로 부풀려진다는 건 반복 확인된 관찰입니다.

- 자기 보고 확신도는 정확도가 낮은 사례에도 높은 값을 주며, 신뢰할 만한 답과 아닌 답을 구분하지 못한다. ([Wired for Overconfidence](https://arxiv.org/html/2604.01457))
- 부풀림이 태스크별 우연이 아니라 **모델 내부의 안정된 메커니즘**(중후반 층의 특정 MLP/어텐션 헤드가 확신 팽창 신호를 기록)에서 나온다. ([같은 논문](https://arxiv.org/pdf/2604.01457))
- 표준적인 verbalized confidence는 0.9, 1.0 같은 **거칠고 포화된 값으로 붕괴**해서, 순위 매기기나 임계값 판정 신호로 쓰기 어렵다. ([Calibrating Verbalized Confidence with Self-Generated Distractors](https://openreview.net/forum?id=pZs4hhemXc))
- 이미 어떤 행동을 **저지른 에이전트는 그것을 비판하기보다 정당화할 유인**을 갖는다 — 프롬프트 기반 자기 보고 확신도의 구조적 편향. ([Uncertainty Decomposition for Clarification Seeking in LLM Agents](https://arxiv.org/pdf/2606.19559))
- 컨텍스트 메모리가 계속 늘어나면 verbalized confidence는 점점 더 부풀고 불안정해진다.

마지막 두 항목이 특히 루프와 맞닿습니다. **회차가 쌓일수록 문맥이 길어지고, 모델은 자기가 이미 내놓은 산출물을 정당화할 유인을 갖습니다.** 즉 반복 루프는 자기 보고 확신도의 부풀림을 **완화하는 게 아니라 증폭하는** 환경이에요.

## 5. 그래서 무엇을 쓰나 — 「규칙으로 세는 값」

ex2에서 유일하게 정체를 잡는 건 **위반 건수**입니다. 4회차에서 잡아요.

> «위반 건수»만 4회차에서 정체를 잡는다. 규칙으로 세는 값이라 안 흔들린다.

「규칙으로 세는 값」의 조건은 이렇습니다.

1. **결정적(deterministic)이다** — 같은 산출물이면 항상 같은 점수가 나온다.
2. **코드가 센다** — 모델의 말이 아니라 파서/린터/스키마 검사기/테스트 러너가 센다.
3. **모델이 못 올린다** — 점수를 올리는 유일한 방법이 *실제로 산출물을 고치는 것*이다.

3번이 결정적입니다. 위반 건수를 줄이려면 진짜로 위반을 없애야 해요. 확신도처럼 숫자만 바꿔 쓸 수가 없습니다.

`ex4_generator_critic.py`가 이 원칙을 구현합니다. 모델에게 「끝났나요?」를 묻지 않고, **필수 섹션이 있는지 코드가 직접 셉니다.**

```python
REQUIRED = ["## 개요", "## 원인", "## 조치", "## 재발 방지"]

def critic(s: S) -> dict:
    miss = [x for x in REQUIRED if x not in s["text"]]
    return {"missing": miss, "scores": [len(miss)]}
```

`scores`에 들어가는 건 `len(miss)` — **파이썬 `in` 연산자가 센 개수**입니다. 모델이 여기에 개입할 여지는 「실제로 섹션을 쓰는 것」밖에 없어요. 그 결과 루프는 위반이 `3 → 2 → 2`로 가면서 «정체»로 정확히 끝납니다.

> «정체»로 끝났다. 위반이 3→2→2 로 가면서 마지막에 안 줄었기 때문이다.
> 횟수 상한만 있었다면 6회차까지 돌아 132를 썼을 것이다. 정체 감지가 세 회차를 아꼈다.

한 장 요약의 세 번째 항목이 이 전환을 요약합니다.

> 모델에게 「끝났나요?」를 묻지 마세요. 「무엇이 남았나요」만 묻고, 끝났는지는 코드가 정합니다. 그러면 남은 목록이 진전 척도도 됩니다.

「끝났나요?」는 확신도와 같은 병에 걸립니다 — 모델이 답을 만드는 값이니까요. 「무엇이 남았나요」는 **목록**을 받아서 코드가 세면 되고, 그 개수가 곧 정체 감지의 입력이 됩니다. 종료 판정과 진전 척도가 같은 값 하나에서 나오게 되는 거예요.

### 쓸 만한 규칙 기반 척도 예시

| 도메인 | 척도 | 왜 안 흔들리나 |
|---|---|---|
| 문서 생성 | 누락 필수 섹션 수 | 문자열 검사 |
| 코드 생성 | 실패 테스트 수, 린터 에러 수 | 테스트 러너/린터가 센다 |
| 구조화 추출 | 스키마 위반 수, 근거 검사 탈락 수 | 검증기가 센다 |
| SQL/쿼리 | 파싱 실패, 결과 행 수 0 여부 | 엔진이 판정한다 |
| 트리플 추출 | 여러 번 돌려 얻은 표 수 (15장) | 한 번의 답변으로 조작 불가 |

## 6. 시험에 나올 한 줄

> **확신도는 모델이 스스로 올릴 수 있는 값이다.** 그래서 `0.55 → 0.61 → 0.68 → 0.74 → 0.79 → 0.83`처럼 실제 품질(위반 4건 고정)과 무관하게 계속 오르고, 「최고를 못 넘으면 정체」라는 감지기가 영원히 발동하지 않는다. 15장에서 확인했듯 자기 보고는 거짓에도 0.9대를 주므로, 애초에 참·거짓조차 못 가르는 신호다.

- **자기 보고 vs 외부 검증** — 15장 4절, 20장 2절이 같은 축의 두 사례
- **평가자-최적화 패턴(evaluator-optimizer)** — 평가자를 모델로 두느냐 코드로 두느냐가 이 장의 갈림길 ([Anthropic, Building effective agents](https://www.anthropic.com/engineering/building-effective-agents))
- **조기 종료(early stopping)** — 정체 감지의 원형. 여기서도 검증 지표는 학습 손실이 아니라 **홀드아웃 셋**에서 잽니다. 「최적화 대상이 스스로 못 올리는 값으로 재라」는 같은 아이디어예요 ([Deep Learning Book, Regularization](https://www.deeplearningbook.org/contents/regularization.html))
- **끝난 이유를 상태에 남기기** — 「상한」과 「정체」는 대응이 다릅니다. 상한은 더 돌리면 될 수도 있고, 정체는 더 돌려도 안 됩니다
