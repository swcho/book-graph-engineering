# `Guards`가 불리언 대신 문자열을 반환하는 이유

**질문** — `Guards` 클래스가 불리언 대신 문자열을 반환하는 이유는 무엇인가?

**답** — 어떤 이유로 끝났는지 알려 줘야 호출한 쪽이 다르게 대응할 수 있다.

---

## 1. 원문에 뭐라고 쓰여 있나

`code/guards.py`의 모듈 도크스트링이 이 설계 의도를 그대로 못 박아 둡니다.

```python
"""
20장 공통 — 종료 조건 네 가지를 한곳에. 의존성 없음.

핵심은 «어떤 이유로 끝났는지»를 돌려주는 것이다.
불리언 하나만 돌려주면 호출한 쪽이 다르게 대응할 수 없다.
"""
```

그리고 실제 시그니처와 반환값은 이렇습니다.

```python
    def check(self) -> Optional[str]:
        """멈출 이유가 있으면 «그 이유»를, 없으면 None."""
        if self.rounds >= self.max_rounds:
            return "횟수 상한"
        if self.cost >= self.max_cost:
            return "예산 상한"
        if self.elapsed >= self.max_seconds:
            return "시간 상한"
        if self.stalled():
            return "진전 없음"
        return None
```

반환 타입은 `bool`이 아니라 `Optional[str]`입니다. 값의 의미는 두 갈래예요.

| 반환값 | 뜻 | 호출 측 행동 |
|---|---|---|
| `None` | 멈출 이유 없음 | 루프 계속 |
| `"횟수 상한"` / `"예산 상한"` / `"시간 상한"` / `"진전 없음"` | 멈춰야 함 + **그 이유** | 루프 종료 + 이유별 분기 |

## 2. 왜 불리언이면 안 되나 — 정보 손실

`check()`가 `bool`을 돌려준다고 해 봅시다. 내부적으로 이 함수는 **네 개의 서로 다른 종료 조건**을 판정합니다(20.1 「네 가지가 각각 다른 걸 잡는다」). 그런데 `True` 하나로 압축하는 순간, 네 갈래가 한 갈래로 뭉개집니다.

```
횟수 상한 ─┐
예산 상한 ─┼→ True    (4비트어치 정보 → 1비트)
시간 상한 ─┤
진전 없음 ─┘
```

즉 `bool`은 「멈춰라」는 **명령**만 전달하고, 「왜」라는 **맥락**을 버립니다. 문자열 반환은 이 맥락을 종료 신호와 같은 채널로 함께 실어 보내는 것이고요.

### 이유가 다르면 대응도 다르다

정보 손실이 왜 치명적인지는 `ex4_generator_critic.py`의 마지막 출력이 정확히 설명합니다.

```
  성공 — 그대로 쓴다
  상한 — 사람에게 넘긴다 (더 돌리면 될 수도 있다)
  예산 — 예산을 올릴지 물어본다
  정체 — 사람에게 넘긴다 (더 돌려도 안 된다)

«상한»과 «정체»의 대응이 다르다. 불리언 하나로는 이 구분이 안 된다.
```

특히 **「상한」과 「정체」는 겉보기엔 둘 다 「실패로 끝남」이지만 의미가 정반대**입니다.

- **횟수 상한** — 아직 나아지는 중이었는데 한도가 먼저 왔다. → 한도를 올리거나 재개하면 성공할 가능성이 있다. `ex1`의 «천천히 나아진다» 시나리오가 이 경우고, 주석도 "더 돌리면 될 텐데 못 돌린다"라고 씁니다.
- **진전 없음(정체)** — 점수가 더는 안 줄었다. → 더 돌려도 같은 자리를 맴돈다. 한도를 올리는 건 돈만 태우는 짓이다. `ex1`의 «제자리걸음»이 이 경우입니다.

불리언만 받은 호출자는 이 둘을 구분할 수 없으니, **잘못된 자동 재시도**(정체인데 한도만 올려 재실행)나 **잘못된 포기**(조금만 더 돌리면 됐는데 사람에게 넘김) 중 하나를 저지르게 됩니다. 20장 한 장 요약의 마지막 줄이 이겁니다 — "끝난 이유를 상태에 남기세요. 「상한」과 「정체」는 대응이 다릅니다."

### 「상태를 다시 뒤져 보면 되지 않나」

`Guards`는 `rounds`, `cost`, `elapsed`, `scores`를 전부 공개 필드로 갖고 있으니, 호출자가 `bool`을 받은 뒤 `if g.rounds >= g.max_rounds: ...` 식으로 이유를 **역추적**할 수는 있습니다. 그런데 이건 세 가지가 나쁩니다.

1. **판정 로직 중복** — `check()` 안의 비교식을 호출부마다 다시 씁니다. 임계 조건이 바뀌면 전부 같이 고쳐야 하고, 안 고치면 조용히 어긋납니다.
2. **우선순위 소실** — `check()`는 위에서부터 순서대로 검사하므로, 여러 조건이 동시에 참이어도 **먼저 걸린 하나**를 확정합니다(횟수 → 예산 → 시간 → 정체). 밖에서 역추적하면 「횟수도 넘고 예산도 넘었을 때 무엇으로 끝난 것인가」의 답이 호출부마다 달라집니다.
3. **`stalled()`는 값이 아니라 판정** — 정체 여부는 `scores` 원본만 봐서는 안 나오고 `stall_limit` 윈도를 다시 계산해야 알 수 있습니다. 사실상 `check()`를 통째로 복제하는 셈이에요.

문자열 반환은 이 판정을 **한곳(가드)에 두고, 결과만 밖으로 내보내는** 구조입니다.

## 3. `None` / 문자열 조합이 주는 실용적 이점

Python에서 `None`은 falsy, 비어 있지 않은 문자열은 truthy입니다. 덕분에 호출부는 불리언을 쓸 때와 **똑같은 문법**을 유지하면서 이유까지 받습니다. `ex1_four_guards.py`가 그 예입니다.

```python
def run(steps, **kw):
    g = Guards(**kw)
    for cost, secs, score in steps:
        g.record(cost, secs, score)
        if score == 0:
            return "성공", g
        why = g.check()
        if why:
            return why, g
    return "입력 소진", g
```

`if why:`는 `if g.should_stop():`와 형태가 같은데, 같은 줄에서 `why`가 이유 문자열까지 들고 있습니다. 그래서 아래 출력 코드가 별도 조회 없이 그대로 "끝난 이유" 열을 찍을 수 있습니다.

```python
        print(f"{name:<14} {why:<10} {g.rounds:>4} {g.cost:>7.0f} "
              f"{g.elapsed:>7.0f} {str(last):>10}")
```

`ex1`이 「성공」, 「입력 소진」 같은 값을 `check()`의 반환값과 **같은 자리**에 넣어 돌려주는 것도 눈여겨볼 만합니다. 이유가 문자열이라 가드가 모르는 종료 사유(정상 성공, 입력 고갈)까지 하나의 어휘 집합으로 확장됩니다. 불리언이었다면 「성공한 True」와 「한도에 걸린 True」를 별도 플래그로 또 나눠야 했겠죠.

> 주의할 점 하나 — 이 관용구는 **이유 문자열이 절대 빈 문자열이면 안 된다**는 전제 위에 있습니다. `""`를 이유로 반환하면 falsy라서 루프가 안 멈춥니다. 그래서 열거형(`Enum`)이나 리터럴 유니온으로 좁히면 더 안전하고, 실무에서는 오타(`"예산상한"` vs `"예산 상한"`)로 분기가 조용히 새는 것도 막을 수 있습니다.

## 4. 반환값에서 그치지 않고 「상태」에 남긴다

`ex4_generator_critic.py`는 같은 아이디어를 LangGraph 상태 스키마로 옮깁니다. 종료 이유가 함수 반환값을 넘어 **그래프 상태의 필드**가 됩니다.

```python
class S(TypedDict):
    text:    str
    missing: list
    rounds:  Annotated[int, operator.add]
    cost:    Annotated[float, operator.add]
    scores:  Annotated[list, operator.add]
    ending:  str          # 어떤 이유로 끝났는지. 이게 중요하다.
```

라우터 `route()`가 `check()`와 똑같이 「이유 문자열」을 돌려주고, 이유마다 별도 종료 노드를 두어 `ending`에 도장을 찍습니다.

```python
def route(s: S) -> str:
    if not s["missing"]:
        return "성공"
    if s["rounds"] >= MAX_ROUNDS:
        return "상한"
    if s["cost"] >= MAX_COST:
        return "예산"
    if stalled(s["scores"]):
        return "정체"
    return "생성"
```

이렇게 상태에 남으면 실행이 끝난 뒤(혹은 체크포인트에서 재개한 뒤)에도 `out["ending"]`으로 이유를 읽을 수 있습니다. 반환값은 호출 순간에만 살아 있지만, 상태에 적힌 이유는 감사·재개·운영 알림에서 계속 쓰입니다. 20장이 21장(내구성 있는 실행)으로 넘어가는 연결 고리이기도 하고요.

## 5. 한 줄로 압축하면

> `check()`는 「멈출까?」가 아니라 **「왜 멈추는가?」**에 답한다. 불리언은 네 갈래 종료 조건을 1비트로 뭉개서 호출자가 이유별로 다르게 대응할 길을 없애 버린다. `Optional[str]`은 `if why:`라는 불리언과 같은 사용 편의를 유지하면서 이유를 함께 실어 보내고, 그 이유는 `ending`처럼 상태에 남아 사람에게 넘길지 예산을 올릴지 결정하는 근거가 된다.
