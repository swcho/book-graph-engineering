# '산출물 길이'를 진전 척도로 쓰면 어떻게 되는가?

**답**: 영원히 멈추지 않는다. 계속 길어지지만 위반은 4에서 줄지 않아 실제 개선이 없다.

---

## 1. 질문의 자리

20장의 종료 조건은 넷입니다. **횟수 / 예산 / 시간 / 진전 없음**. 앞의 셋은 세기만 하면 되니 논쟁의 여지가 없습니다. 문제는 넷째입니다. "진전 없음"을 판정하려면 먼저 **진전을 무엇으로 잴지**를 정해야 하는데, 여기서 잘못 고르면 정체 감지 자체가 무력화됩니다.

`ex2_stall_detection.py`는 **같은 루프 하나**를 세 가지 척도로 재 보는 예제입니다. 루프는 하나인데 척도에 따라 멈추는 시점이 완전히 달라진다는 걸 보여주죠.

## 2. 같은 루프, 세 척도

```python
ROUNDS = [
    # (위반 건수, 산출물 길이, 모델이 매긴 확신도)
    (9,  320, 0.55),
    (6,  480, 0.61),
    (4,  610, 0.68),
    (4,  890, 0.74),      # 위반은 그대로인데 길이와 확신도는 올랐다
    (4, 1240, 0.79),
    (3, 1610, 0.83),
]
```

두 시퀀스를 나란히 놓으면 구조가 바로 보입니다.

| 회차 | 산출물 길이 (길수록 좋다?) | 위반 건수 (낮을수록 좋다) | 길이 증가 | 위반 감소 |
|---:|---:|---:|---:|---:|
| 1 | 320 | 9 | — | — |
| 2 | 480 | 6 | +160 | −3 |
| 3 | 610 | 4 | +130 | −2 |
| 4 | **890** | **4** | +280 | **0** ← |
| 5 | **1240** | **4** | +350 | **0** ← |
| 6 | 1610 | 3 | +370 | −1 |

- **길이**: `320 → 480 → 610 → 890 → 1240 → 1610`. 단 한 번도 꺾이지 않고 5배로 늘어납니다.
- **위반**: `9 → 6 → 4 → 4 → 4 → 3`. 3회차에서 4에 도달한 뒤 **4→4→4로 두 번 연속 정지**합니다.

4회차와 5회차가 이 예제의 급소입니다. 길이는 +280, +350으로 가장 크게 뛰는 구간인데, 정작 고쳐야 할 위반은 4에서 한 건도 줄지 않았습니다. **가장 열심히 쓴 구간이 가장 아무것도 개선하지 못한 구간**입니다.

## 3. 정체 판정기가 무엇을 하는가

```python
def stalled_at(values, higher_better, limit=2):
    """limit 번 연속 나아지지 않으면 그 회차를 돌려준다."""
    for i in range(limit + 1, len(values) + 1):
        window = values[i - limit - 1:i]
        best_before = max(window[:-1]) if higher_better else min(window[:-1])
        worse = window[-1] <= best_before if higher_better else window[-1] >= best_before
        if worse:
            return i
    return None
```

`limit=2`이므로 창(window) 크기는 3입니다. **"직전 두 회차의 최선보다 나아졌는가"**를 보고, 못 나아졌으면(같아도 포함) 그 회차를 정체로 신고합니다. 같은 값을 정체로 취급하는 게 핵심인데, `guards.py`의 주석이 이유를 밝힙니다.

> `«같음»도 정체로 본다. 나빠지는 것만 잡으면 늦다.`

이제 두 척도를 이 판정기에 넣어 봅니다.

**길이** (`higher_better=True`):
- i=3: window `[320, 480, 610]`, best_before=480 → 610 ≤ 480? 아니오
- i=4: `[480, 610, 890]`, best_before=610 → 890 ≤ 610? 아니오
- i=5: `[610, 890, 1240]` → 아니오
- i=6: `[890, 1240, 1610]` → 아니오
- **결과: `None` — 안 멈춤**

**위반** (`higher_better=False`):
- i=3: window `[9, 6, 4]`, best_before=min(9,6)=6 → 4 ≥ 6? 아니오
- i=4: `[6, 4, 4]`, best_before=min(6,4)=4 → **4 ≥ 4? 예 → 4회차에서 정체 확정**

실행 결과가 이 표입니다.

| 척도 | 멈추는 회차 | 그때 위반 |
|---|---:|---:|
| 위반 건수 (낮을수록 좋다) | 4 | 4 |
| 산출물 길이 (길수록 좋다?) | **안 멈춤** | 3 |
| 모델 확신도 (높을수록 좋다) | **안 멈춤** | 3 |

길이가 안 멈추는 이유는 단순합니다. **단조 증가하는 값에는 정체가 정의될 수 없습니다.** 판정기는 "나아졌나"만 묻는데, 길이는 회차를 돌 때마다 무조건 나아지는(=커지는) 값이거든요. 6회차에서 데이터가 끊겨서 멈춘 것처럼 보일 뿐, 데이터가 계속됐다면 60회차든 600회차든 계속 돌았을 겁니다. 정체 조건을 코드에 넣어 뒀지만 **영원히 참이 되지 않는 죽은 가드**가 된 셈이고, 결국 횟수/예산/시간 상한에 걸릴 때까지 돈을 다 쓰고 끝납니다. `ex1`의 표현대로 "안 될 일에 예산을 끝까지 쓰고 끝나는" 구조죠.

## 4. 왜 길이는 실패하는가 — 대리 지표의 문제

길이는 **대리 지표(proxy metric)** 입니다. 진짜 목표는 "문서가 요구를 만족하는가"인데, 그건 재기 번거로우니 **대개 좋은 문서가 짧지 않더라**는 상관관계를 빌려 길이를 대신 재는 겁니다. 상관은 실제로 존재합니다 — 1~3회차에서 길이와 위반은 실제로 같이 좋아졌으니까요. 대리 지표가 위험한 이유가 바로 이겁니다. **초반엔 잘 맞아서 신뢰를 얻고, 정작 필요한 순간에 갈라집니다.**

4회차부터 두 곡선이 분기합니다. 이 지점이 바로 **굿하트의 법칙(Goodhart's law)** 이 발동하는 자리입니다.

> "When a measure becomes a target, it ceases to be a good measure."
> (측정값이 목표가 되는 순간, 그것은 좋은 측정값이기를 그만둔다.)
> — Marilyn Strathern의 정식화. 원래 Charles Goodhart의 통화정책 관찰에서 나왔습니다.

루프가 "길이를 늘려라"를 목표로 받으면, 목표를 **가장 싸게** 달성하는 길을 찾습니다. 그건 위반을 고치는 게 아니라 문장을 덧붙이는 것입니다. 미사여구, 중복 설명, 장황한 서론 — 길이는 +350, 위반은 0. 척도가 성공을 보고하는 동안 실제 품질은 제자리인 겁니다.

## 5. 위반 건수는 왜 되는가 — "모델이 못 올리는 값"

본문이 제시하는 선택 기준은 한 줄입니다.

> **«모델이 스스로 올릴 수 있는 값이면 안 된다.»**

세 척도를 이 기준으로 갈라 보면 이렇게 됩니다.

| 척도 | 누가 값을 정하는가 | 모델이 조작 가능한가 | 정체 감지 |
|---|---|---|---|
| 산출물 길이 | 산출물 자체 | **가능** — 아무 말이나 덧붙이면 오름 | 실패 (영원히 안 멈춤) |
| 모델 확신도 | 모델의 자기 보고 | **가능** — 숫자를 그냥 올려 말하면 됨 | 실패 (영원히 안 멈춤) |
| 위반 건수 | **외부 규칙/검증기** | 불가 — 실제로 고쳐야만 줄어듦 | 성공 (4회차 포착) |

`ex4_generator_critic.py`가 이 원칙의 구현입니다.

```python
REQUIRED = ["## 개요", "## 원인", "## 조치", "## 재발 방지"]

def critic(s: S) -> dict:
    miss = [x for x in REQUIRED if x not in s["text"]]
    return {"missing": miss, "scores": [len(miss)]}
```

점수는 모델이 매기지 않습니다. **코드가 `REQUIRED` 목록을 대조해서 셉니다.** 모델이 텍스트를 아무리 길게 써도 `## 재발 방지`가 없으면 `missing`은 줄지 않습니다. 그래서 "위반 건수는 못 올린다"가 성립합니다.

한 장 요약의 다른 항목과도 이어집니다.

> 모델에게 「끝났나요?」를 묻지 마세요. 「무엇이 남았나요」만 묻고, 끝났는지는 코드가 정합니다. 그러면 남은 목록이 진전 척도도 됩니다.

"끝났나요?"는 자기 보고라 확신도와 같은 병에 걸립니다. "무엇이 남았나요"는 **검증 가능한 목록**을 돌려주고, 그 목록의 길이가 곧 조작 불가능한 진전 척도가 됩니다. 종료 판정과 진전 측정이 한 번에 해결되는 셈이죠.

## 6. 일반화 — 이 함정을 알아보는 법

에이전트 루프 밖에서도 같은 형태가 반복됩니다.

| 진짜 목표 | 흔한 대리 지표 | 갈라지는 방식 |
|---|---|---|
| 좋은 문서 | 산출물 길이 | 장황해질 뿐 요건은 그대로 |
| 정답에 근접 | 모델 확신도 | 자신 있게 틀림 |
| 코드 품질 | 커버리지 % / LoC | assert 없는 테스트, 코드 부풀리기 |
| 문제 해결 | 도구 호출 횟수 | 바쁘게 헛돌기 |
| 고객 만족 | 티켓 종료 건수 | 안 고치고 닫기 |

공통 진단 기준 두 가지입니다.

1. **행위자가 직접 밀어 올릴 수 있는 값인가?** 그렇다면 진전 척도가 아니라 **활동량 척도**입니다. 활동은 진전을 보장하지 않습니다.
2. **단조로운 값인가?** 어떤 상황에서도 오르기만 하는 값에는 "정체"가 정의되지 않습니다. 정체 감지가 절대 발화하지 않는 가드가 되면, 코드에 조건은 있는데 실효는 없습니다 — 20장 도입부의 "종료 조건이 세 개나 있었는데 240번을 돌았다"와 같은 종류의 실패입니다.

처방도 같습니다. **척도의 산정 주체를 루프 밖으로 빼세요.** 린터, 스키마 검증기, 테스트 러너, 필수 항목 대조 — 규칙으로 세는 값이라야 안 흔들립니다.

## 7. 한 줄 정리

산출물 길이는 단조 증가하는 자기 조작 가능 지표라, 정체 감지가 **영원히 발화하지 않습니다**. `320→1610`으로 5배 늘어나는 동안 위반은 4회차 근처에서 `4→4→4`로 굳어 있고 — 척도는 오르는데 품질은 그대로인 굿하트 법칙의 교과서적 사례입니다. 진전 척도는 **모델이 스스로 올릴 수 없는, 규칙으로 세는 값**이어야 합니다.
