# `ex2_stall_detection.py`가 비교하는 세 가지 진전 척도

> **Q.** `ex2_stall_detection.py`가 비교하는 세 가지 진전 척도는 무엇인가?
>
> **A.** 위반 건수(낮을수록 좋음), 산출물 길이(길수록 좋음?), 모델이 매긴 확신도(높을수록 좋음)다.

---

## 1. 이 예제가 던지는 질문

20장의 네 가지 종료 조건 중 「진전 없음(정체)」만 유일하게 **무엇을 재는지 직접 정해야** 합니다. 횟수·예산·시간은 셀 값이 이미 정해져 있지만, 진전은 아니에요. 20.2절이 그래서 "진전을 무엇으로 잴 것인가. 이게 제일 어렵다"로 시작합니다.

`ex2_stall_detection.py`는 **완전히 동일한 루프 하나**를 세 가지 척도로 각각 재 보고, 정체 판정 시점이 척도마다 어떻게 달라지는지를 보여 줍니다.

```python
# 같은 루프를 세 가지 척도로 재 본다
ROUNDS = [
    # (위반 건수, 산출물 길이, 모델이 매긴 확신도)
    (9, 320, 0.55),
    (6, 480, 0.61),
    (4, 610, 0.68),
    (4, 890, 0.74),      # 위반은 그대로인데 길이와 확신도는 올랐다
    (4, 1240, 0.79),
    (3, 1610, 0.83),
]
```

## 2. 세 척도 정의 — `METRICS`

```python
METRICS = {
    "위반 건수 (낮을수록 좋다)": (lambda r: r[0], False),
    "산출물 길이 (길수록 좋다?)": (lambda r: r[1], True),
    "모델 확신도 (높을수록 좋다)": (lambda r: r[2], True),
}
```

각 항목의 값은 `(추출 함수, higher_better)` 튜플입니다. 두 번째 원소가 바로 **방향 부호**예요.

| # | 척도 | 튜플 인덱스 | 방향 | `higher_better` | 누가 만드는 값인가 |
|---|---|---|---|---|---|
| 1 | 위반 건수 | `r[0]` | 낮을수록 좋다 | `False` | **코드/규칙**이 센다 |
| 2 | 산출물 길이 | `r[1]` | 길수록 좋다**?** | `True` | 모델이 쓰는 만큼 늘어난다 |
| 3 | 모델이 매긴 확신도 | `r[2]` | 높을수록 좋다 | `True` | 모델의 **자기 보고** |

> 정답의 "길수록 좋음**?**"에 붙은 물음표는 오타가 아니라 **원문 그대로**입니다. 지문 문자열 자체가 `"산출물 길이 (길수록 좋다?)"`로, 이 척도의 전제가 의심스럽다는 걸 이름에 박아 둔 겁니다.

## 3. 회차별 값 — 실행 출력

`python3 ex2_stall_detection.py` 실행 출력의 앞부분입니다.

```
  회차     위반      길이      확신도
------------------------------
   1      9     320     0.55
   2      6     480     0.61
   3      4     610     0.68
   4      4     890     0.74
   5      4    1240     0.79
   6      3    1610     0.83
```

표로 옮기고 회차별 변화량까지 붙이면 이렇습니다.

| 회차 | 위반 건수 | Δ위반 | 산출물 길이 | Δ길이 | 모델 확신도 | Δ확신도 |
|---:|---:|---:|---:|---:|---:|---:|
| 1 | 9 | — | 320 | — | 0.55 | — |
| 2 | 6 | −3 (개선) | 480 | +160 (개선) | 0.61 | +0.06 (개선) |
| 3 | 4 | −2 (개선) | 610 | +130 (개선) | 0.68 | +0.07 (개선) |
| 4 | **4** | **0 (정체)** | 890 | +280 (개선) | 0.74 | +0.06 (개선) |
| 5 | **4** | **0 (정체)** | 1240 | +350 (개선) | 0.79 | +0.05 (개선) |
| 6 | 3 | −1 (개선) | 1610 | +370 (개선) | 0.83 | +0.04 (개선) |

핵심은 **4~5회차 구간**입니다. 소스 코드에도 주석이 달려 있어요 — `# 위반은 그대로인데 길이와 확신도는 올랐다`. 실제로는 아무것도 고쳐지지 않았는데, 길이와 확신도는 태연히 우상향합니다.

## 4. 방향 부호를 어떻게 처리하는가 — `stalled_at()`

```python
def stalled_at(values, higher_better, limit=2):
    """limit 번 연속 나아지지 않으면 그 회차를 돌려준다."""
    for i in range(limit + 1, len(values) + 1):
        window = values[i - limit - 1:i]
        best_before = max(window[:-1]) if higher_better else min(window[:-1])
        worse = window[-1] <= best_before if higher_better else window[-1] >= best_before
        if worse:
            return i
    return None
```

부호 처리는 **두 줄에 국한**되어 있습니다. `higher_better` 하나로 `max`/`min`과 `<=`/`>=`를 동시에 뒤집습니다.

| | `higher_better=True` (높을수록 좋음) | `higher_better=False` (낮을수록 좋음) |
|---|---|---|
| 이전 구간의 「최고 기록」 | `max(window[:-1])` | `min(window[:-1])` |
| 「나아지지 않았다」 판정 | `window[-1] <= best_before` | `window[-1] >= best_before` |
| 등호 포함 | 포함 (**제자리도 정체**) | 포함 (**제자리도 정체**) |

읽을 때 주의할 점 세 가지가 있습니다.

- **창(window) 크기는 `limit`이 아니라 `limit + 1`**입니다. `limit=2`면 3개짜리 창을 봐요. 「직전 2회의 최고 기록을 이번 값이 못 넘겼는가」를 묻는 구조입니다.
- **등호가 포함**되어 있어서, 값이 나빠질 필요가 없습니다. **같기만 해도** 정체로 잡힙니다. 위반 건수가 4 → 4로 유지된 게 그래서 걸립니다.
- **반환값은 bool이 아니라 회차 번호**(1-based)입니다. 정체가 끝까지 없으면 `None`을 돌려주고, `main()`에서 `'안 멈춤'`으로 찍습니다.

### 위반 건수의 창을 손으로 돌려 보기

`values = [9, 6, 4, 4, 4, 3]`, `higher_better=False`, `limit=2`:

| i | window | `best_before` = `min` | `window[-1] >= best_before`? | 결과 |
|---:|---|---:|---|---|
| 3 | `[9, 6, 4]` | `min(9,6)` = 6 | `4 >= 6` → False | 통과 |
| 4 | `[6, 4, 4]` | `min(6,4)` = 4 | `4 >= 4` → **True** | **정체, 4 반환** |

길이(`[320, 480, ..., 1610]`)와 확신도(`[0.55, ..., 0.83]`)는 **단조 증가**라 `higher_better=True` 조건에서 `window[-1] <= best_before`가 한 번도 성립하지 않습니다. 그래서 루프를 다 돌고 `None`이 나옵니다.

## 5. 각 척도가 정체를 언제 잡는가 — 실행 출력

```
척도                             멈추는 회차     그때 위반
--------------------------------------------------
위반 건수 (낮을수록 좋다)                     4         4
산출물 길이 (길수록 좋다?)                 안 멈춤         3
모델 확신도 (높을수록 좋다)                 안 멈춤         3
```

| 척도 | 방향 | 멈추는 회차 | 그때 위반 | 왜 그렇게 되는가 |
|---|---|---|---|---|
| **위반 건수** | 낮을수록 좋음 (`False`) | **4** | 4 | 4회차에 4 → 4로 제자리. 규칙으로 세는 값이라 흔들리지 않고, 정체를 **정확히 그 지점에서** 잡는다 |
| **산출물 길이** | 길수록 좋음? (`True`) | **안 멈춤** (`None`) | 3 | 매 회차 320→1610으로 계속 길어진다. 「길어짐 = 나아짐」이 아닌데도 조건상 영원히 개선으로 읽힌다 |
| **모델 확신도** | 높을수록 좋음 (`True`) | **안 멈춤** (`None`) | 3 | 0.55→0.83으로 계속 오른다. 자기 보고라 모델이 알아서 올려 준다 |

> 「그때 위반」 열 읽는 법: `v = ROUNDS[at - 1][0] if at else ROUNDS[-1][0]` — 멈춘 척도는 **멈춘 회차의** 위반 건수, 안 멈춘 척도는 **마지막(6) 회차의** 위반 건수를 보여 줍니다. 두 `안 멈춤` 행의 `3`은 「끝까지 다 돌렸을 때의 위반」이지 「정체를 잡아서 얻은 값」이 아닙니다.

### 놓치기 쉬운 뒷맛

위반 건수는 4회차에서 위반 4로 멈춥니다. 그런데 끝까지 돌렸으면 6회차에 위반 3까지 내려갔어요. 즉 **정체 감지는 「더 돌리면 나아졌을 수도 있는 여지」를 버리는 대신 헛도는 비용을 막는** 트레이드오프입니다. 20.1절 `ex1_four_guards.py`가 «천천히 나아진다 — 더 돌리면 될 텐데 못 돌린다»로 지적한 것과 같은 성격이고, `stall_limit`를 얼마로 둘지가 그 저울입니다.

## 6. 이 예제의 결론

프로그램이 마지막에 직접 찍는 문장입니다.

```
같은 루프인데 척도에 따라 멈추는 시점이 다르다.

«산출물 길이»는 영원히 안 멈춘다. 계속 길어지니까.
그런데 길어지는 게 나아지는 건 아니다. 위반은 4에서 안 줄었다.

«모델 확신도»도 계속 오른다. 15장에서 봤듯 자기 보고는 믿을 게 못 된다.

«위반 건수»만 4회차에서 정체를 잡는다. 규칙으로 세는 값이라 안 흔들린다.

진전 척도를 고르는 기준 하나. «모델이 스스로 올릴 수 있는 값이면 안 된다.»
길이도 확신도도 모델이 마음대로 올릴 수 있다. 위반 건수는 못 올린다.
```

한 줄 규칙: **모델이 스스로 올릴 수 있는 값은 진전 척도가 될 수 없다.**

- 길이 → 모델이 늘려 쓰면 오른다. ❌
- 확신도 → 모델이 높게 매기면 오른다. ❌
- 위반 건수 → 코드가 규칙으로 세므로 모델이 손댈 수 없다. ✅

20장 「한 장 요약」의 두 번째·세 번째 항목이 정확히 이 얘기입니다. 모델에게 "끝났나요?"를 묻지 말고 "무엇이 남았나요"만 물으면, 그 **남은 목록의 길이**가 곧 위반 건수처럼 조작 불가능한 진전 척도가 됩니다.

## 7. 다음 예제와의 연결

`ex4_generator_critic.py`가 이 결론을 실제 LangGraph 루프에 적용합니다. `critic` 노드가 `missing`(누락된 필수 섹션 목록)을 계산하고 그 **개수**를 `scores`에 쌓아요.

```python
def critic(s: S) -> dict:
    miss = [x for x in REQUIRED if x not in s["text"]]
    return {"missing": miss, "scores": [len(miss)]}


def stalled(scores):
    n = STALL_LIMIT + 1
    if len(scores) < n:
        return False
    w = scores[-n:]
    return w[-1] >= min(w[:-1])
```

`stalled()`는 `stalled_at()`에서 **`higher_better=False` 분기만 남긴** 형태입니다(`min` + `>=`). 진전 척도를 규칙 기반 카운트 하나로 고정했기 때문에 방향 부호를 인자로 받을 필요가 없어진 거예요.

## 8. 암기 포인트

- 세 척도: **위반 건수 / 산출물 길이 / 모델 확신도**. 코드상 튜플 순서 `(위반, 길이, 확신도)`와 같다.
- 방향: 위반만 **낮을수록 좋음**(`higher_better=False`), 나머지 둘은 높을수록 좋음(`True`).
- 결과: **위반만 4회차에서 잡고, 나머지 둘은 "안 멈춤"**.
- 이유: 길이·확신도는 **모델이 스스로 올릴 수 있는 값**이라 정체를 못 잡는다.
