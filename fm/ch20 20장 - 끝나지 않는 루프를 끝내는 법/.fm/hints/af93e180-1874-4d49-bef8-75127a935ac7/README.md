# '위반 건수'가 진전 척도로 적합한 이유

> **Q.** '위반 건수'가 진전 척도로 적합한 이유는 무엇인가?
>
> **A.** 규칙으로 세는 값이라 흔들리지 않고, 모델이 스스로 올릴 수 없다. 4회차에서 정체를 정확히 잡는다.

출처: 20장 「끝나지 않는 루프를 끝내는 법」 20.2절 / `code/ex2_stall_detection.py`, `code/ex4_generator_critic.py`, `code/guards.py`

## 1. 질문의 배경 — 네 번째 종료 조건만 척도를 요구한다

20장의 종료 조건은 넷입니다.

| 조건 | 무엇을 재나 | 척도를 고를 필요가 있나 |
|---|---|---|
| 횟수 상한 | `rounds` | 없음. 세면 끝 |
| 예산 상한 | `cost` | 없음. 더하면 끝 |
| 시간 상한 | `elapsed` | 없음. 시계가 준다 |
| **진전 없음(정체)** | **`scores`** | **있음. 「진전」을 무엇으로 잴지 내가 정해야 한다** |

앞의 셋은 값이 이미 정해져 있습니다. 회차는 세면 되고 비용은 더하면 되고 시간은 시계가 줍니다. 그런데 네 번째만은 **「나아졌다」를 무엇으로 판정할지를 설계자가 골라야** 합니다. 그리고 이 선택을 잘못하면 정체 감지 자체가 무력화됩니다 — 코드는 멀쩡히 돌지만 영영 안 걸립니다.

`ex2_stall_detection.py`는 **같은 루프 하나**를 세 가지 척도로 재서, 척도만 바꿔도 멈추는 시점이 완전히 달라진다는 걸 보여 줍니다.

## 2. ex2의 원본 데이터 — 회차별 세 값

```python
ROUNDS = [
    # (위반 건수, 산출물 길이, 모델이 매긴 확신도)
    (9,  320, 0.55),
    (6,  480, 0.61),
    (4,  610, 0.68),
    (4,  890, 0.74),      # 위반은 그대로인데 길이와 확신도는 올랐다
    (4, 1240, 0.79),
    (3, 1610, 0.83),
]
```

| 회차 | 위반 건수 (↓ 좋음) | 산출물 길이 (↑ 좋음?) | 모델 확신도 (↑ 좋음) |
|---:|---:|---:|---:|
| 1 | 9 | 320 | 0.55 |
| 2 | 6 | 480 | 0.61 |
| 3 | 4 | 610 | 0.68 |
| 4 | **4** | 890 | 0.74 |
| 5 | **4** | 1240 | 0.79 |
| 6 | 3 | 1610 | 0.83 |

핵심은 **3~5회차 구간**입니다. 실제 품질(= 규칙 위반)은 4에서 세 회차 동안 멈춰 있는데, 길이는 610 → 890 → 1240으로 두 배가 되고 확신도는 0.68 → 0.79로 계속 오릅니다. **모델은 「열심히 하고 있는 것처럼 보이는 신호」를 계속 만들어 낼 수 있습니다.** 길이와 확신도를 진전 척도로 쓰면 이 구간을 진전으로 오독합니다.

## 3. 정체 판정 알고리즘 — 정확히 무슨 일이 벌어지나

```python
def stalled_at(values, higher_better, limit=2):
    """limit 번 연속 나아지지 않으면 그 회차를 돌려준다."""
    for i in range(limit + 1, len(values) + 1):
        window = values[i - limit - 1:i]
        best_before = max(window[:-1]) if higher_better else min(window[:-1])
        worse = window[-1] <= best_before if higher_better else window[-1] >= best_before
        if worse:
            return i
    return None
```

읽는 법을 정확히 해 두면 회차 추적이 쉬워집니다.

- **창(window) 크기는 `limit + 1` = 3.** 그래서 판정은 **3회차부터** 가능합니다. 1~2회차는 비교할 이력이 모자라 무조건 통과입니다(`guards.py`의 `if len(self.scores) < n: return False`와 같은 조건).
- **판정식은 「새 값이 직전 `limit`개 중 최선보다 나아졌는가」**입니다. 낮을수록 좋은 값이면 `window[-1] >= min(window[:-1])`이면 정체.
- **동률(=)도 정체로 봅니다.** `guards.py`의 주석이 이유를 답니다 — *「같음도 정체로 본다. 나빠지는 것만 잡으면 늦다.」* 나빠질 때까지 기다리면 이미 예산을 다 쓴 뒤입니다.
- 참고로 docstring의 「limit 번 **연속**」은 느슨한 표현입니다. 실제 구현은 「최근 `limit`개의 최선을 못 넘으면 그 자리에서」이므로, 3회차 이후엔 **한 번만 정체해도 즉시** 걸립니다. `limit`은 「몇 번을 참을까」가 아니라 **「얼마나 뒤까지 돌아보고 최선을 잡을까」**의 창 길이입니다.

### 3-1. 위반 건수 `[9, 6, 4, 4, 4, 3]` — 회차별 추적

| i (회차) | window | best_before = min(앞 2개) | 새 값 | `새 값 >= best_before`? | 판정 |
|---:|---|---:|---:|---|---|
| 3 | `[9, 6, 4]` | min(9, 6) = 6 | 4 | 4 >= 6 → 거짓 | 진전 있음. 계속 |
| **4** | `[6, 4, 4]` | min(6, 4) = **4** | **4** | 4 >= 4 → **참** | **정체. `return 4`** |

→ **`stalled_at` = 4.** 그때의 위반 건수는 `ROUNDS[3][0]` = **4**.

3회차에서 위반이 6 → 4로 떨어지며 최선 기록을 4로 갱신했는데, 4회차가 그 4를 못 넘었습니다. **동률을 정체로 보는 규칙 덕분에** 「나빠지지는 않았으니 좀 더」로 흘러가지 않고 그 자리에서 잡힙니다. 데이터를 보면 실제로 5회차까지 4가 유지되므로, 4회차 판정은 **오탐이 아니라 정확한 조기 감지**입니다.

### 3-2. 산출물 길이 `[320, 480, 610, 890, 1240, 1610]` — 회차별 추적

높을수록 좋으므로 `best_before = max(...)`, 정체 조건은 `새 값 <= best_before`.

| i | window | best_before = max(앞 2개) | 새 값 | `새 값 <= best_before`? | 판정 |
|---:|---|---:|---:|---|---|
| 3 | `[320, 480, 610]` | 480 | 610 | 거짓 | 계속 |
| 4 | `[480, 610, 890]` | 610 | 890 | 거짓 | 계속 |
| 5 | `[610, 890, 1240]` | 890 | 1240 | 거짓 | 계속 |
| 6 | `[890, 1240, 1610]` | 1240 | 1610 | 거짓 | 계속 |

→ **`None` = 「안 멈춤」.** 단조 증가라서 **원리적으로 영원히 안 걸립니다.** 정체 감지를 붙여 놨지만 실질적으로는 없는 것과 같고, 결국 횟수/예산/시간 상한이 다 소진될 때까지 돕니다.

### 3-3. 모델 확신도 `[0.55, 0.61, 0.68, 0.74, 0.79, 0.83]` — 회차별 추적

역시 단조 증가. 3~6회차 모두 `새 값 <= best_before`가 거짓 → **`None` = 「안 멈춤」**.

15장에서 다룬 그대로입니다. **자기 보고(self-report)는 믿을 게 못 됩니다.** 모델은 산출물이 나아지지 않아도 "이제 꽤 확신합니다"를 계속 올려 쓸 수 있습니다.

### 3-4. ex2 출력 요약

| 척도 | 멈추는 회차 | 그때 위반 |
|---|---:|---:|
| 위반 건수 (낮을수록 좋다) | **4** | 4 |
| 산출물 길이 (길수록 좋다?) | 안 멈춤 | 3 |
| 모델 확신도 (높을수록 좋다) | 안 멈춤 | 3 |

「안 멈춤」의 위반 3은 6회차까지 다 돌린 결과입니다. **회차를 50% 더 써서 위반 한 건을 줄인 것**이고, 그마저도 상한이 없었다면 어디서 멈출지 알 수 없습니다. 위반 건수는 두 회차(5, 6회차)를 아끼는 대신 위반 1건을 포기했습니다 — 이게 조기 종료의 정직한 거래입니다.

## 4. '규칙으로 세는 값'의 조건

책 20.2절이 제시하는 선택 기준은 한 줄입니다.

> **「모델이 스스로 올릴 수 있는 값이면 안 된다.」**

이걸 실무에서 쓸 수 있게 세 조건으로 풀면 이렇습니다.

### 조건 1. 결정적(deterministic)이다

같은 산출물을 넣으면 **몇 번을 재도 같은 값**이 나와야 합니다. 회차 간 비교가 판정의 전부이므로, 척도 자체에 노이즈가 있으면 정체인지 측정 흔들림인지 구분할 수 없습니다.

- 통과: 규칙 위반 개수, 필수 섹션 누락 개수, 실패한 테스트 수, 타입 에러 수, 스키마 검증 실패 수, 미해결 TODO 수
- 탈락: LLM 심사 점수(온도 있는 샘플링), 모델 확신도, 사람마다 다른 주관 평점

### 조건 2. 외부 검증기가 매긴다 — 루프 밖에서 온다

값을 만드는 주체가 **루프 안의 모델이 아니어야** 합니다. 린터, 스키마 검증기, 테스트 러너, 정규식, 문자열 포함 검사처럼 **모델과 무관한 코드**가 산출물을 읽고 세야 합니다.

`ex4_generator_critic.py`의 검증자가 정확히 그 모양입니다.

```python
REQUIRED = ["## 개요", "## 원인", "## 조치", "## 재발 방지"]

def critic(s: S) -> dict:
    miss = [x for x in REQUIRED if x not in s["text"]]
    return {"missing": miss, "scores": [len(miss)]}
```

모델 호출이 하나도 없습니다. **순수한 문자열 포함 검사**입니다. 그래서 `len(miss)`는 모델이 무슨 말을 하든 바뀌지 않습니다.

### 조건 3. 모델이 값을 못 올린다 — 유일한 상승 경로가 「실제 개선」이다

가장 중요한 조건입니다. 척도를 좋게 만드는 방법이 **문제를 실제로 고치는 것 하나뿐**이어야 합니다.

| 척도 | 모델이 값을 좋게 만드는 방법 | 실제 개선을 강제하나 |
|---|---|---|
| 산출물 길이 | 문장을 늘려 쓰기. 반복. 사족 | ✗ 공짜로 올라간다 |
| 모델 확신도 | "확신도: 0.9"라고 쓰기 | ✗ 선언 한 줄이면 끝 |
| 위반 건수 | **누락된 섹션을 실제로 채우기** | ✓ 다른 길이 없다 |

「길이」와 「확신도」는 **모델이 자기 출력 안에서 직접 조작 가능한 값**입니다. 반면 「위반 건수」는 모델이 직접 쓸 수 없는 값입니다 — 모델이 만든 텍스트를 **외부 규칙이 읽고 세서** 나오기 때문에, 위반을 줄이려면 위반을 실제로 없애야 합니다.

### 보너스로 따라오는 성질들

이 세 조건을 만족하는 척도는 실무적으로 편한 성질을 덤으로 갖습니다.

- **성공 조건이 공짜로 생긴다.** 위반 0 = 완료. 별도 판정이 필요 없습니다 (`ex1`의 `if score == 0: return "성공"`).
- **하한이 있다.** 0 아래로 못 내려가니 개선 여지가 유한하고, 「끝없이 좋아지는 척」이 불가능합니다.
- **끝난 이유와 남은 일이 한 자료구조에서 나온다.** `missing` 리스트는 정체 판정용 점수(`len(missing)`)이면서 동시에 사람에게 넘길 인수인계 목록입니다.

## 5. 「끝났나요?」를 묻지 말고 「무엇이 남았나요」를 물어라

20장 요약의 이 문장이 지금 조건들과 같은 이야기입니다.

> 모델에게 「끝났나요?」를 묻지 마세요. 「무엇이 남았나요」만 묻고, 끝났는지는 코드가 정합니다. 그러면 남은 목록이 진전 척도도 됩니다.

「끝났나요?」는 **불리언 하나를 모델에게 맡기는 것**입니다. 조건 3을 정면으로 위반합니다 — 모델이 "네, 끝났습니다"라고 쓰면 루프가 그냥 끝나고, "아직요"라고 쓰면 무한히 돕니다. 반면 「무엇이 남았나요」의 답은 **목록**이고, 그 목록의 **길이를 세는 건 코드**입니다. 세는 주체가 코드로 넘어오는 순간 위반 건수와 같은 성질을 갖게 됩니다.

## 6. ex4에서 같은 척도가 실제로 작동하는 모습

`ex4_generator_critic.py`는 위반 건수(= `len(missing)`)로 LangGraph 루프를 세웁니다. `MAX_ROUNDS=6, MAX_COST=90.0, STALL_LIMIT=2`, 회차당 22.0.

| 회차 | 생성 결과 | `missing` | `scores` 누적 | `route()` 판정 |
|---:|---|---|---|---|
| 1 | `## 개요` | 3개 | `[3]` | 창 미달 → **생성** 계속 |
| 2 | `## 개요`, `## 원인` | 2개 | `[3, 2]` | 창 미달 → **생성** 계속 |
| 3 | 더 못 고침 (그대로) | 2개 | `[3, 2, 2]` | `w=[3,2,2]`, `2 >= min(3,2)=2` → **정체** |

```python
def stalled(scores):
    n = STALL_LIMIT + 1          # 3
    if len(scores) < n:
        return False
    w = scores[-n:]
    return w[-1] >= min(w[:-1])  # 동률도 정체
```

결과: `ending="정체"`, `rounds=3`, `cost=66`, `scores=[3,2,2]`, `missing=["## 조치", "## 재발 방지"]`.

**횟수 상한만 있었다면 6회차까지 돌아 132를 썼습니다.** 정체 감지가 세 회차와 66을 아꼈고, 그게 가능했던 건 점수가 「규칙으로 세는 값」이었기 때문입니다. 만약 여기서 점수를 산출물 길이로 잡았다면 3회차 텍스트가 2회차와 동일하니 우연히 걸렸겠지만, 모델이 「내용」 대신 장황한 문단을 채워 넣는 순간 길이는 계속 늘고 정체는 영영 안 걸립니다.

그리고 종료 이유가 상태(`ending`)에 남는 것도 이 척도 덕입니다.

- **상한** — 사람에게 넘긴다 (*더 돌리면 될 수도 있다*)
- **정체** — 사람에게 넘긴다 (*더 돌려도 안 된다*)

이 두 대응이 갈리려면 「정체」 판정이 믿을 만해야 합니다. 확신도로 정체를 판정했다면 「정체」라는 라벨 자체가 무의미해집니다.

## 7. 한계와 주의점 — 정직하게

1. **조기 종료의 대가는 있다.** ex2에서 4회차에 멈추면 6회차까지 갔을 때의 위반 3을 놓칩니다. 그래서 「정체」와 「상한」을 구분해 상태에 남기고, 사람이 「한 번 더 돌릴지」를 정할 수 있게 하는 겁니다.
2. **`stall_limit`은 인내심 손잡이다.** 창이 짧으면(값이 작으면) 일시적 정체를 정체로 오판하고, 길면 헛돌이를 오래 봅니다. 다만 이 구현에서는 창을 늘려도 「최근 창 안의 최선」과 비교하므로 무작정 관대해지지는 않습니다(ex2 데이터는 `limit=3`으로 올려도 여전히 4회차에서 걸립니다).
3. **척도의 굿하트 법칙(Goodhart's law)은 남는다.** 모델이 검증 규칙을 알면 「규칙만 통과시키는 껍데기」를 만들 수 있습니다. ex4의 `## 조치\n내용`이 딱 그 형태죠. 위반 건수는 **모델이 값을 자기 마음대로 「보고」할 수 없게** 막아 주지, **규칙이 곧 품질임을 보장하지는 않습니다.** 규칙의 품질은 별도 문제입니다.
4. **검증기 자체가 모델이면 무효다.** 「LLM 심사자에게 위반 개수를 세게 시키기」는 조건 1(결정적)과 조건 2(외부)를 동시에 깹니다. 겉모습만 위반 건수일 뿐 확신도와 같은 부류가 됩니다.

---

## 8. 한 줄 정리

> **위반 건수는 (a) 규칙 기반이라 결정적이고, (b) 루프 밖 검증기가 매기며, (c) 모델이 값을 직접 올릴 수 없어 개선 외에는 좋아지는 길이 없다. 그래서 ex2의 세 척도 중 유일하게 3~5회차의 실제 정체를 포착해 4회차에서 멈추고, 길이와 확신도는 단조 증가하느라 영영 안 멈춘다.**
