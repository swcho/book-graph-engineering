# 진전 척도를 고르는 핵심 기준

> **Q.** 진전 척도를 고르는 핵심 기준은 무엇인가?
>
> **A.** 모델이 스스로 올릴 수 있는 값이면 안 된다. 길이도 확신도도 모델이 마음대로 올리므로, 규칙으로 세는 값을 써야 한다.

출처: 20장 「끝나지 않는 루프를 끝내는 법」 20.2절 *진전을 무엇으로 잴 것인가*, `code/ex2_stall_detection.py`

---

## 1. 왜 이 질문이 나오는가

20장의 종료 조건은 넷입니다.

| 종료 조건 | 잡는 것 |
|---|---|
| 횟수 상한 | 무한 반복 |
| 예산 상한 | 회차는 적은데 비싼 루프 |
| 시간 상한 | 사용자가 기다리다 떠나는 느린 루프 |
| **진전 없음(정체)** | 계속 돌지만 나아지지 않는 루프 |

앞의 셋은 재는 값이 자명합니다. 회차는 세면 되고, 비용은 토큰을 더하면 되고, 시간은 시계를 보면 됩니다. 셋 다 **루프 바깥에서 객관적으로 결정되는 값**이에요.

문제는 넷째입니다. "진전"은 정의를 우리가 골라야 합니다. 그리고 이 선택이 실무에서 제일 아픕니다. 20장 예제 1이 보여주듯 「제자리걸음」 상황은 횟수 상한만 있으면 안 될 일에 예산을 끝까지 쓰고 끝나거든요.

## 2. 같은 루프, 세 가지 척도

`ex2_stall_detection.py`는 **완전히 동일한 루프 하나**를 세 가지 척도로 재 봅니다.

| 회차 | 위반 건수 | 산출물 길이 | 모델 확신도 |
|---:|---:|---:|---:|
| 1 | 9 | 320 | 0.55 |
| 2 | 6 | 480 | 0.61 |
| 3 | 4 | 610 | 0.68 |
| 4 | **4** | 890 | 0.74 |
| 5 | **4** | 1240 | 0.79 |
| 6 | 3 | 1610 | 0.83 |

4회차를 보세요. **위반은 4에서 안 줄었는데 길이와 확신도는 계속 올라갑니다.** 실제로 나아진 게 없는데 두 척도는 "잘 되고 있다"고 말하고 있어요.

정체 판정은 `stall_limit=2`, 즉 3개 창(window)에서 마지막 값이 앞선 최고치를 못 넘으면 정체로 봅니다(같아도 정체입니다 — 나빠지는 것만 잡으면 늦어요).

| 척도 | 멈추는 회차 | 그때 위반 |
|---|---|---:|
| 위반 건수 (낮을수록 좋다) | **4** | 4 |
| 산출물 길이 (길수록 좋다?) | 안 멈춤 | 3 |
| 모델 확신도 (높을수록 좋다) | 안 멈춤 | 3 |

- **산출물 길이**는 영원히 안 멈춥니다. 텍스트는 계속 길어지니까요. 그런데 길어지는 게 나아지는 건 아닙니다.
- **모델 확신도**도 계속 오릅니다. 15장에서 본 대로 자기 보고는 믿을 게 못 됩니다.
- **위반 건수**만 4회차에서 정체를 잡습니다. *규칙으로 세는 값이라 안 흔들리기* 때문이에요.

"안 멈춤"은 안전한 게 아닙니다. 정체 감지가 아예 작동하지 않았다는 뜻이고, 결국 남은 세 조건(횟수·예산·시간) 중 하나에 걸릴 때까지 돈다는 뜻입니다. 넷째 가드가 사실상 없는 것과 같아요.

## 3. 기준 한 줄

> **모델이 스스로 올릴 수 있는 값이면 안 된다.**

길이도 확신도도 모델이 마음대로 올릴 수 있습니다. 위반 건수는 못 올립니다. 위반은 **모델 바깥의 규칙**(체크리스트, 파서, 린터, 테스트)이 세는 값이기 때문입니다.

이건 사실 굿하트의 법칙(Goodhart's law)의 루프 버전입니다. 척도가 목표가 되는 순간 척도이기를 그만두는데, 여기서는 **척도를 올리는 주체와 최적화되는 주체가 같아지는 것**이 문제의 핵심입니다. 척도의 분자와 분모를 모두 모델이 쥐고 있으면 그건 측정이 아니라 자기 채점이에요.

| 나쁜 척도 (모델이 올릴 수 있음) | 좋은 척도 (규칙이 셈) |
|---|---|
| 산출물 토큰/문자 길이 | 필수 섹션 중 빠진 개수 |
| 모델이 매긴 확신도·자기 점수 | 실패한 테스트 개수 |
| "많이 개선했습니다" 같은 자평 | 린터·타입체커 에러 건수 |
| LLM이 자기 출력에 준 1~10점 | 스키마 검증 실패 필드 수 |
| "완료했나요?" 예/아니오 | 미해결 요구사항 항목 수 |

## 4. 따라오는 규칙 — 「끝났나요?」를 묻지 말 것

20장의 한 장 요약에 같이 붙어 있는 항목입니다.

> 모델에게 「끝났나요?」를 묻지 마세요. 「무엇이 남았나요」만 묻고, 끝났는지는 코드가 정합니다. 그러면 남은 목록이 진전 척도도 됩니다.

"끝났나요?"는 모델이 스스로 올릴 수 있는 값(불리언 확신)입니다. 반면 "무엇이 남았나요"는 목록을 돌려주고, **그 목록의 길이를 코드가 셉니다.** 종료 판단이 모델 손에서 코드 손으로 넘어오고, 동시에 정체 감지용 숫자가 공짜로 생깁니다.

`ex4_generator_critic.py`가 정확히 이 구조입니다.

```python
REQUIRED = ["## 개요", "## 원인", "## 조치", "## 재발 방지"]

def critic(s: S) -> dict:
    miss = [x for x in REQUIRED if x not in s["text"]]
    return {"missing": miss, "scores": [len(miss)]}
```

검증자는 판정을 내리지 않습니다. **빠진 항목 목록만** 돌려주고, `len(miss)`가 그대로 점수 이력이 됩니다. 종료 여부는 `route()`가, 즉 코드가 정합니다.

```python
def route(s: S) -> str:
    if not s["missing"]:      return "성공"
    if s["rounds"]  >= MAX_ROUNDS: return "상한"
    if s["cost"]    >= MAX_COST:   return "예산"
    if stalled(s["scores"]):       return "정체"
    return "생성"
```

이 예제에서 위반이 3→2→2로 가며 마지막에 안 줄어 「정체」로 끝납니다. 횟수 상한만 있었다면 6회차까지 돌아 132를 썼을 텐데, 정체 감지가 세 회차를 아꼈습니다.

## 5. 정체를 어떻게 세는가

`guards.py`의 판정 로직입니다.

```python
def stalled(self) -> bool:
    """최근 stall_limit+1 개 점수가 나아지지 않았나.
    «같음»도 정체로 본다. 나빠지는 것만 잡으면 늦다."""
    n = self.stall_limit + 1
    if len(self.scores) < n:
        return False
    window = self.scores[-n:]
    best_before = min(window[:-1])
    return window[-1] >= best_before
```

포인트 두 개.

1. **한 회차만 보고 판단하지 않습니다.** `stall_limit+1` 크기의 창을 봅니다. 한 번 삐끗한 걸 정체로 오인하면 될 일도 못 끝냅니다.
2. **`>=`로 비교합니다.** 값이 "같아도" 정체입니다. 나빠질 때까지 기다리면 이미 여러 회차를 버린 뒤예요.

그리고 `check()`는 불리언이 아니라 **이유 문자열**을 돌려줍니다.

```python
if self.rounds  >= self.max_rounds:  return "횟수 상한"
if self.cost    >= self.max_cost:    return "예산 상한"
if self.elapsed >= self.max_seconds: return "시간 상한"
if self.stalled():                   return "진전 없음"
return None
```

「상한」과 「정체」는 대응이 다르기 때문입니다. 상한이면 더 돌리면 될 수도 있으니 예산을 올려 볼 만하고, 정체면 더 돌려도 안 되니 사람에게 넘겨야 합니다. 불리언 하나로는 이 구분이 안 됩니다.

## 6. 실무 체크리스트

진전 척도 후보를 하나 떠올렸다면 이렇게 물어보세요.

1. **이 값을 모델이 직접 쓰거나 매기는가?** → 그렇다면 탈락.
2. **모델이 출력을 늘리거나 말투를 바꾸는 것만으로 이 값이 좋아지는가?** → 그렇다면 탈락.
3. **모델을 끄고 사람이 손으로 세도 같은 숫자가 나오는가?** → 그렇다면 합격 후보.
4. **값이 유한하고 0에 수렴할 수 있는가?** (빠진 항목 수, 실패 테스트 수) → 종료 조건으로도 재사용 가능.
5. **정체를 「같음」까지 포함해 세고 있는가?**
6. **끝난 이유를 문자열/열거형으로 상태에 남기는가?**

한 줄로 압축하면 이렇습니다. **진전은 모델이 주장하는 것이 아니라, 코드가 세는 것이어야 합니다.**
