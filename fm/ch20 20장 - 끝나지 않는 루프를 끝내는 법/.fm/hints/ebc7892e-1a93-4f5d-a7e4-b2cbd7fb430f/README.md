# `ending` 필드는 무엇을 담는가

**질문** — `ex4_generator_critic.py`의 상태에서 `ending` 필드는 무엇을 담는가?

**답** — 끝난 이유(성공 / 상한 / 예산 / 정체)를 담는다. 호출한 쪽이 이 값으로 다르게 대응한다.

---

## 1. State TypedDict 전체

`ex4_generator_critic.py`가 선언한 상태는 이렇습니다.

```python
REQUIRED = ["## 개요", "## 원인", "## 조치", "## 재발 방지"]
MAX_ROUNDS, MAX_COST, STALL_LIMIT = 6, 90.0, 2


class S(TypedDict):
    text:    str
    missing: list
    rounds:  Annotated[int, operator.add]
    cost:    Annotated[float, operator.add]
    scores:  Annotated[list, operator.add]
    ending:  str          # 어떤 이유로 끝났는지. 이게 중요하다.
```

여섯 필드가 각각 하는 일이 다릅니다.

| 필드 | 리듀서 | 담는 것 | 누가 쓰나 |
|---|---|---|---|
| `text` | 없음(덮어쓰기) | 지금까지 만들어진 산출물 | `generate` |
| `missing` | 없음(덮어쓰기) | 아직 없는 필수 섹션 목록 | `critic` |
| `rounds` | `operator.add` | 누적 회차 | `generate`가 매번 `1`을 더함 |
| `cost` | `operator.add` | 누적 비용 | `generate`가 매번 `22.0`을 더함 |
| `scores` | `operator.add` | 회차별 위반 건수 이력(리스트 이어붙이기) | `critic`이 `[len(miss)]`를 더함 |
| `ending` | **없음(덮어쓰기)** | **끝난 이유 한 낱말** | `mark(...)` 노드 |

여기서 세 개(`rounds`, `cost`, `scores`)만 `Annotated[..., operator.add]`로 누적 리듀서를 답니다. 루프를 도는 값이니 매 회차 더해져야 하거든요. 반대로 `ending`은 리듀서가 없어서 LangGraph 기본값인 **마지막 쓰기가 이긴다(덮어쓰기)** 로 동작합니다. 어차피 딱 한 번, 루프가 끝날 때만 쓰이니까 그게 맞습니다.

초기값은 `main()`에서 빈 문자열로 넣습니다.

```python
out = app.invoke({"text": "", "missing": [], "rounds": 0,
                  "cost": 0.0, "scores": [], "ending": ""}, cfg)
```

즉 `ending == ""`는 「아직 안 끝났다」는 뜻이고, 값이 채워졌다는 건 곧 「이 이유로 끝났다」는 뜻입니다.

## 2. `ending`은 어디서 채워지나 — `mark` 노드

`ending`을 쓰는 코드는 딱 한 군데, `mark`가 만들어 내는 노드 함수뿐입니다.

```python
def mark(reason):
    def fn(s: S) -> dict:
        return {"ending": reason}
    return fn
```

`mark`는 노드 자체가 아니라 **노드를 찍어내는 클로저 공장**입니다. 종료 사유마다 노드를 하나씩 만들고, 그 노드는 상태에 자기 이름을 남기고 곧장 `END`로 갑니다.

```python
for r in ("성공", "상한", "예산", "정체"):
    b.add_node(r, mark(r))
    b.add_edge(r, END)
```

이 네 줄이 「끝난 이유가 넷이고, 각각이 그래프의 별도 종착 노드」라는 구조를 만듭니다. `성공`, `상한`, `예산`, `정체` — 이 네 낱말이 `ending`에 들어갈 수 있는 값의 전부입니다.

## 3. 값을 정하는 쪽 — `route`

어느 `mark` 노드로 갈지는 `검증` 뒤에 달린 조건부 엣지가 정합니다.

```python
def route(s: S) -> str:
    if not s["missing"]:
        return "성공"
    if s["rounds"] >= MAX_ROUNDS:
        return "상한"
    if s["cost"] >= MAX_COST:
        return "예산"
    if stalled(s["scores"]):
        return "정체"
    return "생성"


b.add_conditional_edges("검증", route,
                        {"생성": "생성", "성공": "성공", "상한": "상한",
                         "예산": "예산", "정체": "정체"})
```

`route`의 반환값이 곧 `ending`에 남을 낱말이 됩니다. 다만 **`route`가 직접 `ending`을 쓰지는 못합니다.** 조건부 엣지 함수는 다음에 갈 노드 이름을 고르는 순수 라우팅 함수라, 반환값이 상태에 저장되지 않아요. 그래서 `mark`라는 얇은 노드를 한 겹 두는 겁니다. 라우팅 결정을 **상태에 물리는** 다리 역할이죠.

읽는 순서도 의미가 있습니다. 성공을 먼저 보고(다 채웠으면 다른 조건은 볼 필요가 없다), 그다음 회차 → 예산 → 정체 순입니다. `"생성"`만 유일하게 종료가 아니라 루프를 한 바퀴 더 도는 경로고요.

`stalled`는 20.2절의 「진전 없음」 판정입니다. 최근 `STALL_LIMIT + 1`개(=3개) 점수를 보고, 마지막 값이 그 앞 최소값보다 나아지지 않았으면 정체로 봅니다. 「같음」도 정체로 칩니다.

```python
def stalled(scores):
    n = STALL_LIMIT + 1
    if len(scores) < n:
        return False
    w = scores[-n:]
    return w[-1] >= min(w[:-1])
```

## 4. 실제로 이 예제는 어떤 값으로 끝나나

`generate`는 「3회차부터는 더 못 고치는 모델」을 흉내 냅니다(`if s["rounds"] < 2`일 때만 섹션을 하나 더 채움). 그래서 진행이 이렇게 됩니다.

| 회차 | 채워진 섹션 | `scores` | 누적 `rounds` / `cost` | `route` 판단 |
|---|---|---|---|---|
| 1 | 개요 | `[3]` | 1 / 22 | 이력 부족 → `생성` |
| 2 | 개요, 원인 | `[3, 2]` | 2 / 44 | 이력 부족 → `생성` |
| 3 | 그대로 | `[3, 2, 2]` | 3 / 66 | `2 >= min(3,2)` → **`정체`** |

그래서 출력은 `끝난 이유  정체`, 회차 3/6, 비용 66/90, 남은 항목 `['## 조치', '## 재발 방지']`입니다.

횟수 상한만 뒀다면 6회차까지 돌아 132를 썼을 겁니다. 정체 감지가 세 회차, 66원을 아낀 셈이죠. 참고로 이 예제에서는 `상한`(회차)과 `예산` 분기가 실제로 타지지는 않습니다. 정체가 먼저 걸리니까요 — 그게 20.1절이 말하는 「하나만 두면 못 잡는 경우가 남는다」의 반대편 증거입니다.

## 5. 그래서 왜 남기나 — 호출부 대응

핵심은 여기입니다. 예제 스스로 이렇게 설명합니다.

```
성공 — 그대로 쓴다
상한 — 사람에게 넘긴다 (더 돌리면 될 수도 있다)
예산 — 예산을 올릴지 물어본다
정체 — 사람에게 넘긴다 (더 돌려도 안 된다)
```

`상한`과 `정체`는 둘 다 「미완성으로 끝났다」지만 대응이 정반대입니다.

- **`상한`** — 회차를 더 주면 완성될 가능성이 있습니다. 재시도가 합리적인 실패예요.
- **`정체`** — 더 돌려도 같은 자리를 맴돕니다. 재시도가 낭비인 실패고, 사람이 개입하거나 프롬프트/도구를 바꿔야 합니다.

`ending`이 없고 `done: bool` 하나만 있었다면 이 둘이 구분되지 않습니다. 그래서 예제 주석이 「이게 중요하다」라고 달려 있고, 마지막 문장이 **「불리언 하나로는 이 구분이 안 된다」** 로 끝나는 겁니다.

같은 원칙이 이 장 공통 모듈 `code/guards.py`에도 그대로 들어 있습니다.

```python
def check(self) -> Optional[str]:
    """멈출 이유가 있으면 «그 이유»를, 없으면 None."""
    if self.rounds >= self.max_rounds:
        return "횟수 상한"
    if self.cost >= self.max_cost:
        return "예산 상한"
    if self.elapsed >= self.max_seconds:
        return "시간 상한"
    if self.stalled():
        return "진전 없음"
    return None
```

모듈 docstring이 아예 이렇게 적어 뒀습니다 — 「핵심은 «어떤 이유로 끝났는지»를 돌려주는 것이다. 불리언 하나만 돌려주면 호출한 쪽이 다르게 대응할 수 없다.」 `ending`은 이 반환값을 **LangGraph 상태에 옮겨 놓은 것**입니다.

## 6. 왜 반환값이 아니라 «상태»여야 하나

`app.invoke(...)`의 리턴만 봐도 되지 않느냐고 할 수 있는데, 상태에 두는 이유가 따로 있습니다.

- 이 그래프는 `b.compile(checkpointer=InMemorySaver())`로 체크포인터를 답니다. 상태에 있는 값은 스레드(`thread_id: "gc"`)에 저장돼서, 나중에 같은 스레드를 조회하거나 재개할 때 그대로 남아 있습니다.
- 20장 한 장 요약이 「그 예산은 전역 변수가 아니라 *상태*에 둡니다. 안 그러면 재개할 때 리셋됩니다」라고 한 것과 같은 이유입니다. 종료 사유도 프로세스 밖에서 살아남아야 하는 정보예요.
- 상태에 있으니 그래프 안의 다른 노드나 상위 그래프도 `s["ending"]`을 읽고 분기할 수 있습니다. 반환값은 최상위 호출자만 봅니다.

## 한 줄 정리

`ending`은 「이 루프가 **왜** 멈췄는가」를 담는 문자열 필드입니다. `route`가 사유를 고르고, `mark(사유)` 노드가 그 값을 상태에 새기고, 호출한 쪽이 그 값을 보고 그대로 쓸지·재시도할지·예산을 올릴지·사람에게 넘길지를 나눕니다. 「멈췄다」만으로는 이 네 갈래가 안 나옵니다.
