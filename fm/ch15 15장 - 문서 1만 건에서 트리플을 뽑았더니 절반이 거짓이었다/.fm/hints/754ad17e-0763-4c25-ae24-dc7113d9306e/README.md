# `ex2_grounding.py`의 세 가지 근거 검사는 각각 무엇을 잡는가?

## 한 줄 답

| 검사 | 함수 | 잡는 실패 유형 |
|---|---|---|
| ① 근거 문장 존재 | `has_evidence()` | 모델이 **근거 문장 자체를 지어낸** 경우 |
| ② 목적어 포함 | `supports()` | 문장은 진짜인데 **값(목적어)을 지어낸** 경우 |
| ③ 단정 여부 | `is_hedged()` | 원문이 단정하지 않았는데 **추측을 사실로 바꾼** 경우 |

## 배경: 왜 근거 검사인가

15장의 사고는 위키 1만 2천 건에서 트리플 47만 개를 뽑았는데, 근거가 안 붙어 있어서 무엇이 거짓인지 알 방법이 없었다는 것이다. 두 번째 시도의 핵심 처방이 「근거 문장을 같이 내놓게 하고 원문과 문자열로 대조하라」다. 모델을 한 번 더 부르지 않으니 밀리초 단위로 싸고, 결과가 매번 같다(결정적이다).

`ex2_grounding.py`는 추출기가 내놓은 `(주어, 술어, 목적어, 근거문장)` 4-튜플을 세 단계 필터에 통과시킨다.

## 검사 ①: 근거 문장 존재 — `has_evidence`

```python
def has_evidence(doc_id, quote):
    """근거 문장이 원문에 실제로 있는가."""
    return normalize(quote) in normalize(TEXT.get(doc_id, ""))
```

공백을 제거해 정규화한 뒤, 모델이 근거라고 내놓은 문장이 해당 문서 원문에 **부분 문자열로 실제 존재하는지** 본다. 근거 문장까지 통째로 지어낸 트리플이 여기서 걸린다. 탈락 사유는 「근거 문장이 원문에 없다」.

## 검사 ②: 목적어 포함 — `supports`

```python
def supports(quote, subj, obj):
    """핵심은 «목적어»다. 주어는 문서 전체에 흔히 나오지만,
    목적어가 근거 문장에 없으면 그 값은 문장에서 나온 게 아니다."""
```

근거 문장이 원문에 있더라도, 그 문장이 트리플을 실제로 **뒷받침**하는지는 별개다. 주어가 아니라 **목적어**를 보는 이유: 주어(예: «가온테크는»)는 문서 어디에나 흔히 나오지만, 목적어(값)가 근거 문장 안에 없으면 그 값은 그 문장에서 나온 게 아니라 모델이 만든 것이다.

책에서 「제일 많이 잡고, 제일 늦게 깨달은」 검사다. 처음에 검사 ①만 돌렸더니 지어낸 트리플 «가온테크, 업종, IT 서비스»가 통과했다. 근거로 낸 문장 «가온테크는…»이 원문에 진짜 있었기 때문이다. **문장은 진짜고 값만 지어낸 것** — 이것이 제일 흔한 실패다. 탈락 사유는 「문장이 트리플을 뒷받침하지 않는다」.

## 검사 ③: 단정 여부 — `is_hedged`

```python
HEDGE = ["알려져", "추정", "듯", "로 보인다", "가능성", "일 수 있"]
```

근거 문장 주변(앞 20자~뒤 40자 창)에 «알려져 있으나», «추정», «가능성» 같은 **유보(hedge) 표현**이 있는지 본다. 원문은 «모회사로 알려져 있으나 공시된 바 없다»라고 단정을 피했는데, 모델이 «마루상사, 모회사, 다올물산»처럼 사실로 굳혀 버린 경우를 잡는다. 탈락 사유는 「원문이 단정하지 않는다」.

## 세 검사가 서로 겹치지 않는 이유

세 검사는 하나의 파이프라인에서 순서대로 적용되며(`①→②→③`), 각각 **다른 종류의 지어내기**를 담당한다.

- ①은 근거의 **존재** — 인용 자체가 가짜인가
- ②는 근거의 **관련성** — 인용은 진짜인데 값이 거기서 나왔는가
- ③은 근거의 **양상(modality)** — 원문의 확신 수준을 왜곡했는가

## 대가와 한계 (같이 기억할 것)

- **재현율 하락**: 근거 검사 뒤 정밀도는 오르지만 재현율이 0.778 → 0.667로 떨어졌다. 맞는 트리플 «가온테크 체결 C-2025-118»이 억울하게 걸렸는데, 근거 문장을 «가온테크는 2025년 6월 2일»처럼 짧게 잘라 계약번호가 그 안에 없었기 때문. 고치는 법은 프롬프트에서 **근거를 문장 단위(마침표까지)로 내놓게** 하는 것이다.
- **관계 방향은 못 잡는다**: 검사 ②는 목적어가 문장에 «있기만» 하면 통과시키므로, «A가 B를 인수»를 «B가 A를 인수»로 뒤집은 오류는 못 잡는다. 그건 모델을 한 번 더 불러야 하고, 비용이 두 배가 되는 대신 정밀도가 오른다.

이 접근은 RAG의 grounded generation(근거 기반 생성) 아이디어를 추출 파이프라인의 검증에 적용한 것으로, 장의 키워드 표에서도 [사실상 표준]으로 분류된다.
