# `careful_merge()`는 어떻게 사람 입력을 보호하는가?

## 한 줄 답

사람이 손댄 **(주어, 술어) 쌍을 키로 모아 두고**, 새로 추출된 트리플 중 그 키에 해당하는 것은 그래프에 **반영하지 않고 충돌(conflicts)로 따로 보고**한다.

## 문제 상황 (ex5_incremental.py)

문서 `d01`이 수정되어 다시 추출했다. 그런데 그래프에는 문서에서 뽑은 것 말고 **사람이 손으로 넣은 트리플**도 섞여 있다.

- 재추출 결과 V2: 담당이 `박서준`으로 바뀌고 `금액 5000000`이 추가됨
- 사람 입력 MANUAL: `(C-2025-118, 비고, 갱신 협의 중)`, 그리고 사람이 «김하늘이 맞다»고 **정정**한 `(C-2025-118, 담당, 김하늘)`

### 흔한 방법 A — `naive_replace()`

"그 문서에서 나온 것 전부 지우고 새 추출값을 넣는다."

```python
def naive_replace(old, new, doc):
    kept = {t for t in old if t[0] != doc}
    return kept | new
```

사람 입력은 출처가 `manual`이라 지워지진 않지만, 새 추출값 `담당: 박서준`이 그냥 들어와서 **담당이 2개**(김하늘, 박서준)가 된다. 충돌이 **조용히** 남는다 — 질의가 둘 다 돌려주거나 하나만 골라 주는데, 어느 쪽인지 예측이 안 된다.

## 방법 B — `careful_merge()`

```python
def careful_merge(old, new, manual, doc):
    """사람이 손댄 것은 지키고, 나머지만 교체한다."""
    manual_keys = {(t[1], t[2]) for t in manual}                    # ① 사람이 손댄 (주어, 술어) 키
    kept = {t for t in old if t[0] != doc}                          # ② 그 문서 출처 트리플만 제거
    incoming = {t for t in new if (t[1], t[2]) not in manual_keys}  # ③ 키에 안 걸리는 것만 반영
    conflicts = {t for t in new if (t[1], t[2]) in manual_keys}     # ④ 키에 걸리는 것은 충돌로 분리
    return kept | incoming, conflicts
```

동작을 단계별로 보면:

1. **보호 키 수집** — 사람 입력(MANUAL)에서 `(주어, 술어)` 쌍만 뽑아 `manual_keys`를 만든다. 예: `{("C-2025-118", "비고"), ("C-2025-118", "담당")}`
2. **문서 단위 제거** — 기존 그래프에서 해당 문서(`d01`) 출처인 트리플만 지운다. `manual` 출처는 자동으로 살아남는다.
3. **선별 반영** — 새 추출값 중 보호 키에 **해당하지 않는** 것만 그래프에 넣는다. `금액: 5000000`은 들어온다.
4. **충돌 보고** — 보호 키에 해당하는 새 추출값(`담당: 박서준`)은 넣지 않고 `conflicts`로 반환해 **사람에게 보낸다**.

결과: 사람이 정정한 `담당: 김하늘`은 그대로 유지되고, `담당: 박서준`은 «문서가 사람 정정과 다르게 말한다»는 충돌 1건으로 보고된다. 담당이 둘이 되는 일도, 사람 입력이 덮이는 일도 없다.

## 왜 이게 가능한가 — 출처(provenance)가 전제 조건

이 장의 핵심 교훈: **트리플마다 출처를 저장해 둬야 한다** (문서, 위치, 누가, 언제).

- 출처가 없으면 무엇이 자동 추출이고 무엇이 사람 것인지 구분할 수 없다.
- 구분할 수 없으면 재추출할 때마다 사람이 손댄 것이 통째로 날아간다.
- 저자는 이 사고를 세 번 겪고 나서야 출처를 저장하기 시작했다고 말한다.

`careful_merge()`에서 트리플의 첫 원소 `t[0]`이 바로 출처(`"d01"` 또는 `"manual"`)이고, 이 필드가 있어야 ②의 "그 문서 것만 지우기"와 ①의 "사람 입력 골라내기"가 성립한다.

## 설계 원칙 요약

| 원칙 | 구현 |
|---|---|
| 사람 입력은 기계가 함부로 덮지 않는다 | 보호 키(`manual_keys`)에 걸리는 새 값은 반영 제외 |
| 충돌은 숨기지 말고 드러낸다 | 제외한 값을 버리지 않고 `conflicts`로 반환해 사람 검토로 |
| 키는 값이 아니라 (주어, 술어) 쌍 | 값이 달라도(김하늘 vs 박서준) 같은 슬롯이면 충돌로 잡힘 |
| 출처가 모든 것의 기반 | 출처 필드로 문서분/사람분을 분리 |
