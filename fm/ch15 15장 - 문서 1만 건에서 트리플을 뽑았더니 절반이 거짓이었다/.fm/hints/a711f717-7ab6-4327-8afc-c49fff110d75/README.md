# ex5_incremental.py — 방법 A(전부 지우고 교체)의 문제

## 질문
`ex5_incremental.py`의 방법 A(전부 지우고 교체)는 어떤 문제를 낳는가?

## 답
사람이 정정한 값과 새 추출값이 함께 남아 '담당'이 두 개가 되고, 충돌이 조용히 남는다. 질의가 어느 쪽을 줄지 예측할 수 없다.

---

## 상황 설정

예제 5는 "문서가 수정되면 이미 추출해 둔 트리플을 어떻게 갱신할까"를 다룬다. 트리플마다 첫 칸에 **출처**(`d01` = 문서, `manual` = 사람 입력)가 붙어 있다.

- **V1 (문서 d01의 첫 추출)**: `담당 = 김하늘` 등 3건
- **V2 (문서가 수정된 뒤 재추출)**: 담당자가 `박서준`으로 바뀌고 `금액 5000000`이 추가됨
- **MANUAL (사람이 손으로 넣은 것)**: `비고 = 갱신 협의 중`, 그리고 **"김하늘이 맞다"는 정정**으로 `담당 = 김하늘` — 출처는 `manual`, 문서에는 없는 값이다

## 방법 A의 동작

```python
def naive_replace(old, new, doc):
    """흔한 방법: 그 문서에서 나온 것 전부 지우고 다시 넣는다."""
    kept = {t for t in old if t[0] != doc}
    return kept | new
```

"그 문서(`d01`)에서 나온 트리플을 전부 지우고 새 추출 결과(V2)를 통째로 넣는다." 얼핏 깔끔해 보이고, 실제로 사람이 넣은 `manual` 트리플은 출처가 `d01`이 아니라서 **살아남는다**. 그런데 바로 그 지점에서 문제가 생긴다.

## 무엇이 잘못되는가

1. **'담당'이 두 개가 된다.** 사람이 정정한 `(manual, C-2025-118, 담당, 김하늘)`과 새 추출값 `(d01, C-2025-118, 담당, 박서준)`이 그래프에 동시에 존재한다. 계약 하나에 담당자가 둘이다.
2. **충돌이 조용히 남는다.** 방법 A는 두 값이 모순된다는 사실을 어디에도 알리지 않는다. 에러도, 로그도, 검토 큐도 없다. 책의 표현대로 "«담당»이 둘이 되고 아무도 모른다."
3. **질의 결과를 예측할 수 없다.** "C-2025-118의 담당자는?"이라는 질의가 둘 다 돌려줄 수도 있고, 저장소 구현·정렬 순서에 따라 하나만 골라 줄 수도 있다. 어느 쪽이 나올지 그래프를 쓰는 쪽에서는 알 길이 없다.

## 대비: 방법 B (careful_merge)

방법 B는 사람이 손댄 `(주어, 술어)` 키를 먼저 확보한 뒤, 새 추출값 중 그 키와 겹치는 것을 **그래프에 넣지 않고 충돌 목록으로 분리**해 사람에게 보낸다. 사람 입력을 함부로 덮지 않으면서 모순을 드러내는 것이다.

## 교훈

이 예제가 겨냥하는 핵심은 **트리플마다 출처(provenance)를 저장하라**는 것이다. 문서·위치·누가·언제. 출처가 없으면 무엇이 자동 추출이고 무엇이 사람의 정정인지 구분할 수 없고, 구분할 수 없으면 재추출할 때마다 사람이 고쳐 놓은 값이 날아가거나(통째 삭제 시) 방법 A처럼 모순이 조용히 쌓인다. 표준 어휘로는 W3C의 [PROV-O](https://www.w3.org/TR/prov-o/)가 이런 출처 표현을 다룬다.
