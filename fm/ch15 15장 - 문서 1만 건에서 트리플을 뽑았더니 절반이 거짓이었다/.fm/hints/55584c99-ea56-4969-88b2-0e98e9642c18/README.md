# 추출 파이프라인에서 가장 먼저 해야 할 일

**질문**: 추출 파이프라인에서 가장 먼저 해야 할 일은 무엇인가?

**답**: 재는 것이다. 정답 40건을 손으로 만드는 이틀이 나머지 전부를 구한다.

## 왜 「재는 것」이 첫 번째인가

15장의 출발점은 실패담이다. 사내 위키 1만 2천 건에서 나흘에 걸쳐 트리플 47만 개를 뽑았는데, 절반가량이 거짓이었다. 그런데 더 아픈 문제는 따로 있었다 — **무엇이 거짓인지 알 방법이 없었다**. 근거도 없고, 비교할 정답도 없었기 때문이다. 결국 전부 버리고 다시 만들어야 했다.

두 번째 시도에서 배운 첫 번째 교훈이 이것이다:

> 먼저 재세요. 정답 40건을 손으로 만드는 이틀이 나머지 전부를 구합니다.

측정 없이는 다음이 전부 불가능하다:

- **정밀도(precision)를 못 잰다** — 뽑은 것 중 몇 개가 맞는가?
- **재현율(recall)을 못 잰다** — 있어야 할 것 중 몇 개를 뽑았는가?
- **개선했는지 모른다** — 프롬프트를 고치든 모델을 바꾸든, 좋아졌는지 나빠졌는지 판별할 기준이 없다.

즉 「측정 기준(골드셋)」이 없는 파이프라인은 개선 자체가 불가능한 파이프라인이다.

## 골드셋: 사람이 손으로 만든 정답

책의 예제 코드 `docs.py`가 이 원칙을 그대로 구현한다. 문서 5건을 사람이 직접 읽고 확정한 트리플 9개를 `GOLD` 집합으로 적어 둔다:

```python
# 사람이 문서를 읽고 확정한 트리플. (문서, 주어, 술어, 목적어)
GOLD = {
    ("d01", "가온테크", "체결", "C-2025-118"),
    ("d01", "C-2025-118", "체결일", "2025-06-02"),
    ("d03", "다올물산", "대표", "최민준"),
    # ... d05 는 «알려져 있으나 공시된 바는 없다» — 사실로 확정할 수 없다. 정답에서 뺀다.
}
```

주목할 점: **정답 만들기 자체가 판단 작업**이다. d05 문서의 「마루상사는 다올물산의 자회사로 알려져 있으나, 공시된 바는 없다」는 사실로 확정할 수 없으므로 정답에서 뺀다. 이런 경계 사례를 사람이 미리 정해 두는 것이 골드셋의 가치다.

「정답 40건에 이틀」은 규모의 감각을 준다 — 1만 2천 건 전체를 검수하는 건 불가능하지만, 대표 샘플 수십 건의 정답은 이틀이면 만들 수 있고, 그것으로 파이프라인 전체를 평가할 수 있다.

## 재는 것만으로는 부족하다: 오류를 종류별로 나눠라

측정의 두 번째 반쪽은 **오류 분류**다. `ex1_measure.py`가 보여 주듯 「정밀도 0.64」라는 숫자 하나만으로는 어디를 고쳐야 할지 알 수 없다. 틀린 4개를 종류별로 나누면:

| 틀린 트리플 | 오류 종류 | 처방 |
|---|---|---|
| «계약체결일자: 2025-06-02» | 어휘 밖 술어 (뜻은 맞다) | 어휘에 매핑하면 정답이 된다 (→ 예제 3, 보류함) |
| «업종: IT 서비스» | 지어냄 (원문에 없다) | 버려야 한다 (→ 예제 2, 근거 검사) |
| «협업: 나루소프트» | 어휘 밖 + 근거 약함 | 보류함 |
| «모회사: 다올물산» | 추측을 사실로 (공시된 바 없다) | 버려야 한다 (단정 여부 검사) |

같은 「틀림」이라도 처방이 전혀 다르다. 「계약체결일자」는 매핑 한 줄로 살릴 수 있고, 「업종」은 진짜 거짓이라 버려야 한다. **오류를 분류하는 게 개선의 첫 단계**다.

## 정밀도 0.64가 의미하는 것

정밀도 0.64는 「열에 서넛이 거짓」이라는 뜻이다. 이 상태로 그래프에 적재하면 질의가 거짓을 답하고, 사용자는 한 번 겪으면 다시 안 쓴다. 측정은 이 위험을 **적재하기 전에** 숫자로 드러내 준다.

## 기억 포인트

1. **순서가 핵심**: 근거 검사(15.2), 보류함(15.3), 표 세기(15.4), 증분 갱신(15.5) — 이 모든 기법보다 측정이 먼저다. 재지 않으면 그 기법들이 효과가 있는지조차 알 수 없다.
2. **비용 대비 효과**: 정답 40건 × 이틀이라는 작은 투자가 파이프라인 전체의 방향타가 된다.
3. **숫자 하나로 끝내지 말 것**: 정밀도·재현율을 재고, 틀린 것을 종류별로 나눠야 비로소 「무엇을 고칠지」가 보인다.
4. 이 원칙 덕에 저자의 2차 결과는 1차보다 트리플 수가 33% 적었지만 **쓸 수 있는 개수로는 더 많았다** — 개수를 KPI로 두지 말라는 교훈과 연결된다.
