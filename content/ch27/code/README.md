# 27장 — 에이전트에게 기억을 주는 가장 싼 방법

`5부 · 두 그래프가 만나는 곳` · [책 전체 목차](../../../README.md) · [출처 링크 모음](../../../SOURCES.md)

> 「지난번에 말씀드렸는데요.」

이 장은 그다음 이야기입니다. *기억을 어떤 모양으로 둘 것인가.* 그리고 여기서 이 책의 두 트랙이 처음 만납니다. 1~3부에서 만든 지식 그래프가 4부에서 만든 에이전트의 기억이 됩니다.

## 이 장의 절

| 절 | 제목 |
|---|---|
| 27.1 | 모양이 답할 수 있는 질문을 정한다 |
| 27.2 | 벡터와 그래프는 다른 질문에 강하다 |
| 27.3 | 기억에는 시각이 붙어야 한다 |
| 27.4 | 언제부터 그래프가 값을 하나 |
| 27.5 | 무엇을 잊을 것인가 |

## 한 장 요약

- 기억의 모양이 답할 수 있는 질문을 정합니다. 평평한 텍스트는 여러 줄을 못 잇고, 키-값은 미리 만든 칸에만 답하고, 그래프는 저장할 때 몰랐던 경로를 따라갑니다.
- 그래프를 기억으로 쓰는 이유는 한 문장입니다. *저장할 때 질문을 몰라도 되기* 때문입니다.
- 다만 그래프는 모호한 것을 못 담습니다. 사용자가 말한 것은 그래프로, 내가 추론한 것은 원문으로 두세요.
- 벡터와 그래프는 다른 질문에 강합니다. 비슷한 것은 벡터, 이어진 것과 「전부」와 「없음」은 그래프. 실무에서는 벡터로 시작점을 찾고 그래프로 넓힙니다.
- 기억에는 유효 시각이 붙어야 합니다. 오래된 것을 지우는 게 아니라 끝나는 시각을 적으세요. 그리고 새 사실을 넣을 때 옛 사실을 닫으세요. 단일 값 관계 목록을 코드에 두면 됩니다.
- 처음부터 그래프로 가지 마세요. 사실 1,000개쯤부터 값을 합니다. 그 전에는 평평한 목록이 싸고, 옮기는 데는 이틀이면 됩니다.
- 스키마를 위에서 설계하지 말고 아래서 자라게 하세요. 질의를 아는 도메인은 질의 우선이 맞지만, 대화 기억은 데이터가 먼저 쌓이고 스키마가 따라와야 합니다.
- 무엇을 잊을지는 나이가 아니라 종류로 정합니다. 일회성은 일주일, 선호와 관계는 1년, 제약은 사실상 영구. 하나의 정책으로 다 다루면 어느 쪽이든 틀립니다.

## 키워드와 1차 출처

| 키워드 | 상태 | 출처 |
|---|---|---|
| 장기 기억 | [사실상 표준] | [long-term memory](https://docs.langchain.com/oss/python/langgraph/memory) |
| 에피소드 기억 | [실험] | [episodic memory](https://arxiv.org/abs/2404.13501) |
| 시간 인식 지식 그래프 | [실험] | [temporal knowledge graph](https://arxiv.org/abs/2501.13956) |
| 하이브리드 검색 | [사실상 표준] | [hybrid retrieval](https://neo4j.com/docs/cypher-manual/current/indexes/semantic-indexes/vector-indexes/) |
| 망각 곡선 | [실험] | [decay policy](https://arxiv.org/abs/2310.08560) |
| 개체 해상도 | [사실상 표준] | [entity resolution](https://www.w3.org/TR/owl2-syntax/#Individual_Equality) |
| 유효 시간 | [표준] | [valid time](https://www.iso.org/standard/76583.html) |

상태 표시는 **[표준]** 공식 명세, **[사실상 표준]** 명세는 없지만 업계가 널리 쓰는 것, **[실험]** 아직 자리를 잡는 중이라는 뜻입니다.

## 예제 실행

<!-- 실행 가이드 시작 — 사람이 쓴 부분. gen-docs.py 가 건드리지 않는다. -->

확인 시점 2026년 8월. Python 3.9 이상.

```bash
cd content/ch27/code
pip install kuzu

python3 ex1_memory_shapes.py     # 같은 기억을 세 모양으로
python3 ex2_graph_vs_vector.py   # 벡터와 그래프가 강한 질문이 다르다
python3 ex3_temporal_memory.py   # 「언제부터 언제까지 참이었나」
python3 ex4_memory_cost.py       # 사실 수에 따른 두 방식의 하루 비용
python3 ex5_forgetting.py        # 잊기 정책 세 가지 (의존성 없음)
```

`ex2` 의 «임베딩»은 손으로 적은 3차원 좌표입니다. 진짜 임베딩 모델을 쓰면
숫자는 달라지지만 «벡터가 못 하는 것»(전부 세기, 없음 확인)은 그대로입니다.

`ex4` 는 실행할 때마다 조회 시간이 조금씩 달라집니다. 이 규모에서는
측정 잡음이 지배하기 때문이고, 그 자체가 예제의 요점입니다.
