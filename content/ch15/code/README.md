# 15장 — 문서 1만 건에서 트리플을 뽑았더니 절반이 거짓이었다

`3부 — 지식 그래프 엔지니어링 (트랙 1)` | [책 전체 목차](../../../README.md) | [출처 링크 모음](../../../SOURCES.md)

> 사내 위키 1만 2천 건에서 트리플을 뽑았습니다. 나흘 걸렸고 47만 개가 나왔어요.

더 아팠던 건 다음이었습니다. 무엇이 거짓인지 *알 방법이 없었어요*. 트리플에 근거가 안 붙어 있었거든요. 47만 개를 다 검수할 수도 없고, 그렇다고 반쯤 거짓인 걸 쓸 수도 없었습니다. 결국 전부 버리고 다시 만들었습니다. 이 장은 그 두 번째 시도에서 배운 것들입니다.

## 이 장의 절

| 절 | 제목 |
|---|---|
| 15.1 | 재지 않으면 개선했는지도 모른다 |
| 15.2 | 근거를 같이 내놓게 하라 |
| 15.3 | 보류함이 파이프라인의 심장이다 |
| 15.4 | 모델이 말하는 확신은 믿을 게 못 된다 |
| 15.5 | 문서가 바뀌면 무엇을 지울까 |

## 한 장 요약

- 먼저 재세요. 정답 40건을 손으로 만드는 이틀이 나머지 전부를 구합니다. 그리고 오류를 종류별로 나누세요. 「정밀도 0.64」만으로는 어디를 고칠지 모릅니다.
- 근거 문장을 같이 내놓게 하고 원문과 대조하세요. 문자열 비교라 싸고 결과가 매번 같습니다. 검사할 때는 주어가 아니라 *목적어*가 근거 문장에 있는지 보세요.
- 어휘 밖 술어는 버리지 말고 보류함에 넣으세요. 빈도 상위 10개만 주에 한 번 보면 됩니다. 그리고 보류율이 곧 「우리 어휘가 현실과 어긋나는 정도」의 지표입니다.
- 모델의 자기 보고 확신도는 거짓에도 높은 값을 줍니다. 여러 번 돌려 표를 세는 쪽이 낫고, 비싸니까 애매한 것에만 쓰세요.
- 재추출할 때 문서 단위로 통째 교체하면 사람이 정정한 값이 날아갑니다. 트리플마다 출처를 저장하세요. 문서, 위치, 누가, 언제. 넷이면 됩니다.
- 그리고 트리플 개수를 KPI로 두지 마세요. 제 2차 결과는 1차보다 33% 적었는데, 쓸 수 있는 개수로는 더 많았습니다.

## 키워드와 1차 출처

| 키워드 | 상태 | 출처 |
|---|---|---|
| 정보 추출 | [사실상 표준] | [information extraction](https://aclanthology.org/D19-1522/) |
| 근거 기반 생성 | [사실상 표준] | [grounded generation](https://arxiv.org/abs/2005.11401) |
| 자기 일관성 | [사실상 표준] | [self-consistency](https://arxiv.org/abs/2203.11171) |
| 출처 표현 | [표준] | [PROV-O](https://www.w3.org/TR/prov-o/) |
| 정밀도와 재현율 | [표준] | [precision, recall](https://www.iso.org/standard/35736.html) |
| 구조화 출력 | [사실상 표준] | [structured output](https://docs.claude.com/en/docs/agents-and-tools/tool-use/overview) |
| 그래프 추출 파이프라인 | [사실상 표준] | [Microsoft GraphRAG indexing](https://github.com/microsoft/graphrag) |

상태 표시는 **[표준]** 공식 명세, **[사실상 표준]** 명세는 없지만 업계가 널리 쓰는 것, **[실험]** 아직 자리를 잡는 중이라는 뜻입니다.
